    references to the table region, all relocated:
      TFE: base (0x3ad9a), count (0x3ad7b, 0x3ae30), 0x602192b4 (0x3ad68).

STARTUP-SCRIPT DESIGN - checked
  * Include syntax: Croteam's own scripts nest includes three deep with
    single-backslash paths, e.g. Addons\Default.ini -> GLSettings\Initial.ini.
    Both Engine.dll files carry "Script files nested too deeply" and
    "Cannot load script file".
  * A missing Game_FleetRes.ini is non-fatal. The catch paths (TSE 0x6013c2d8,
    TFE 0x601d2f88) call CShell::ErrorF, which only CPrintFs (no FatalError
    call), then do BEGIN(INITIAL) and continue scanning.
  * Order: CGame::Initialize includes PersistentSymbols.ini first (client
    only), then always includes Game_startup.ini.
      TSE GameMP.dll: 0x608f2565, then 0x608f2602.
      TFE Game.dll:   0x604b0286, then 0x604b0323.
    Game_FleetRes.ini therefore runs last.
  * In TSE, sam_strIntroLevel and sam_strGameName are PERSISTENT. Every box
    that ran with the truncated script has persisted TFE's defaults, and the
    restored shipped lines override them at the next start.
  * PROVEN LIVE: an undeclared identifier does not stop later lines. The
    dev-host ssam-tse-server logs "Game_startup.ini(3): Identifier
    'sam_strTechTestLevel' is not declared" 140 times. A read-only \status\
    query on UDP 25611 still answers gamename=serioussamse. Only line 4 of
    that file sets it; DedicatedServer.exe's own default is "serioussam", and
    it never loads PersistentSymbols. So the builder's "keep gfx_iRefreshRate
    last because of the error flag" is harmless but not load-bearing.
  * DedicatedServer.exe also runs Game_startup.ini. The box-hosted TSE LAN
    server (the Host launcher) has therefore been advertising TFE's gamename
    "serioussam" since the launcher truncated the file. The include design
    restores "serioussamse" (predicted; the hw plan checks it read-only).
  * FLEETRES vs GAMERES: gr_w_cfg compares SETTING lines with comments
    excluded, and it CREATES a missing cfg when Scripts\ exists. The launcher
    echo lines and gr_cfg_body("ssam") carry the same four settings, so there
    is no fight. Game_FleetRes.ini is not staged, so GAMESYNC never touches
    it.
  * Multiplayer:
      - The TFE server log shows a real join ("Sent CRC challenge (7k)" then
        "CRC check OK").
      - Both server trees' Engine.dll are byte-identical to the library.
      - No engine file stream opens Bin\*.dll.
      - A dedicated server never enumerates display modes.
    Server-side change needed: none.

FIXED IN apply.py (and its test)
  1. --install-server overwrote Bin\Engine.dll IN PLACE (shutil.copyfile
     truncates the same inode). The ssam-* servers are Wine processes that
     bind-mount the tree and have it mapped, so that risked a SIGBUS. It now
     writes a temp file, verifies it, and os.replace()s it (new inode), after
     checking the pins and the backup.
  2. After --publish, --build crashed ("unexpected original") and the share
     tests turned into skips. The original is now read from
     _patches/<Title>/originals-2026-09-29/, verified against the pin. A
     patched library copy with no valid backup FAILS.
  3. --publish now refuses, before the first write, any manifest entry that
     is not the reviewed (original, patched) md5 pin.
     --check / build_one now also fail if a rebuild is not the pinned md5.
  4. --build refuses an OUTDIR inside any git work tree. Verified: it refused
     .claude/evidence-1080p/..., which is inside the main repo.
  5. The shipped include comment told TFE readers about "the TSE lines above"
     and carried parentheses. It is now title-neutral, with no backslash,
     quote or parenthesis. This is why the startup md5s changed.
  Also: the docstring's "no fleet box can ever pass" DualHead claim now cites
  the inventory check (no 102B/Matrox in any published record) and names the
  cost if one appears.
