Windows XP SP3, **Intel Pentium 4 2.80 GHz** (family 15 model 2), 509 MB RAM,

A:, CD at D:.

| | |
|---|---|
| 2D / display | **Intel 82865G** onboard, driver 6.14.10.4396, 1280×1024×32 @85 Hz |
| 3D | **two 3dfx Voodoo 2** on PCI bus 1, devices 0 and 1 |

## This box hides from a normal sweep — use ARP

It was missing from repeated discovery sweeps while sitting powered on and
cabled. Two independent reasons, both worth knowing:

- **It needs ~9 s to answer a TCP connect.** Sweeps using 2–4 s timeouts drop
  it with no error. The chat daemon already uses 8 s for exactly this reason.
- **Its agent does not always come up on its own** (see below), and UDP
  broadcast discovery can only see agents that are *running*.

When a box is believed on but answers nothing, read the neighbour table —
layer 2 sees it even with every TCP port closed:

```bash
ip neigh show dev enp129s0          # dev host drops ICMP; ping proves nothing
grep -i '^0013 20' /usr/share/ieee-data/oui.txt    # 00:13:20 = Intel
```

Full method: fleetbook `a-fleet-box-can-be-invisible-to-a-tcp-sweep-short-timeouts-a`.

## Voodoo 2 pair (installed 2026-08-28)

Both cards share **one** PCI device key with two *instance* subkeys — a
top-level enumeration shows only one entry, so always descend:

```
SYSTEM\CurrentControlSet\Enum\PCI\VEN_121A&DEV_0002&SUBSYS_00000000&REV_02
    4&1c660dd6&0&00F0     PCI bus 1, device 0
    4&1c660dd6&0&08F0     PCI bus 1, device 1
```

As found, **neither card had a driver**: instance 0 was `Class=Unknown` with
`ConfigFlags=64` (`FAILEDINSTALL`), instance 1 was classified `MEDIA` but had
no `Service` bound, and `fxgpio`/`fxptl`/`Ntremap` did not exist at all.

Installed the 3dfx **Win2K 1.02.00** kit (the one that works on XP) with
`drvupd.exe`, using the HWID the INF actually lists — `PCI\VEN_121A&DEV_0002`,
no SUBSYS. Then moved all three services to `Start=1` (system), because the
Win2K display driver is core-level and **fails silently on XP** at the INF's
`Start=2`.

Verified after reboot:

| Check | Result |
|---|---|
| `DeviceDesc` (both) | `Voodoo2 3D Accelerator` |
| `Service` / `ConfigFlags` (both) | `Ntremap` / `0` |
| `fxgpio` `fxptl` `Ntremap` | all `Start=1` |
| `Services\Ntremap\Enum` | **`Count=2`** — the loaded driver owns both cards |

`Count=2` is the check that matters: it is the kernel driver's own device list.

**SLI is not confirmed.** The official 3dfx driver does **not** support
mismatched SLI (different vendor or RAM size), the ribbon cable has not been
verified, and no Glide title has been run. Two bound cards is not the same as
working SLI.

## Board identity (measured 2026-08-29)

Read from the hardware with `SSTV2_INITDEBUG=1` +
`SSTV2_INITDEBUG_FILE=<path>` and *any* Glide program — the stock retail
`glide3x.dll` has this compiled in:

```
sst1DeviceInfo: Board ID: 9
sst1DeviceInfo: FbiConfig:0x2, TmuConfig:0xca54
sst1DeviceInfo: FBI Revision:4, TMU Revison:4, Num TMUs:2
sst1DeviceInfo: FBI Memory:4, TMU[0] Memory:4, TMU[1] Memory:4
sst1DeviceInfo: Dac Type: ICS ICS5342
sst1DeviceInfo: SLI Detected:0
```

**12 MB** (4 MB FB + 2 × 4 MB TMU). `fbiBoardID` **9** is the PCB design strap,
`(fbiInit5 >> 5) & 0xf`. **Not a Canopus** — `CANOPUS_ID` is `0x10`, and that
code path is AT&T-DAC-only while this board probes ICS.

> **The brand is NOT determinable in software, on this or any Voodoo 2.** The
> "Chuck" FBI chip has no PCI subsystem registers (Spec r1.16 §6 marks config
> `0x14-0x3b` Reserved) and no expansion ROM, so *every* Voodoo 2 reports
> `SUBSYS_00000000&REV_02`. Read the PCB silkscreen instead. Full detail and the
> SLI matching rules: [`scripts/voodoo2/README.md`](../../scripts/voodoo2/README.md).

## Benchmarks (Quake II demo1, 640×480×16, vsync OFF, 689 frames)

| renderer | fps |
|---|---|
| stock 3dfx MiniGL (`gl_driver 3dfxgl`) | **90.7** |
| our clean-room ICD (`gl_driver retrogl`, 0.1.60) | **57.2** |
| Intel 865G onboard (`gl_driver opengl32`) | 58.8 |

Frame budget at 640×480: **~2.4 ms fixed CPU + ~15.1 ms fill**, i.e. **5.12 ×
screen pixels touched** and the CPU idle ~69% of every frame — the card is the
wall. `r_fullbright 1` (no lightmap pass) reaches **92.9 fps**, so single-pass
rendering is worth ~+62% and would beat the MiniGL.

> **Force `gl_swapinterval 0` for any measurement here.** With vsync on, every
> renderer reads ~59 fps and the comparison is meaningless — that masked the
> real numbers for hours.

Full optimisation log, including seven refuted theories:
[`voodoo-cleanroom/OPTIMIZATIONS-VOODOO2.md`](../../voodoo-cleanroom/OPTIMIZATIONS-VOODOO2.md).

## Auto-login

`HKLM\SOFTWARE\Microsoft\Windows NT\CurrentVersion\Winlogon`:

| Value | Data |
|---|---|
| `AutoAdminLogon` | `1` |
| `ForceAutoLogon` | `1` |
| `DefaultUserName` | `Administrator` (the real console account) |
| `DefaultDomainName` | `NSC-5B996B81319` — **was empty**, set 2026-08-28 |
| `DefaultPassword` | `password` (fleet convention, plaintext) |

`net user Administrator password` was applied together with these so the
account password and `DefaultPassword` cannot diverge. Verified working: after
the 2026-08-28 reboot the box auto-logged in and the agent was back on 9898 in
**59 s**, unattended.

> **`REGWRITE` cannot reach this key** — the path contains a space
> (`Windows NT`) and the agent parses the path with `%511s`. Use
> `EXEC reg add "…" /v NAME /t REG_SZ /d DATA /f`. `REGREAD` truncates the same
> path at the space and returns a misleading partial result.

## Known quirks

- **The clock is wrong** — reported `Mon 11/08/2004` while installing. Anything
  that reasons about file timestamps or certificate validity on this box will
  misbehave until it is set.
- No share mapped (`net use` empty); the driver was uploaded directly.
- `query user` is unavailable (XP Home-style tooling absent); use `net user`.
