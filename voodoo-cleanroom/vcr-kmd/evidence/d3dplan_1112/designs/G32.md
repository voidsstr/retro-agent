## 0. Summary

- **The defect is real and large for big fog gradients.** Today vertex fog sends a *synthetic* 1/W per vertex
  that lands on an identity ramp in the fog table (`KMD/include/vcr_fog.h:10-14`,
  `KMD/display/vcrdd_3d.c:202-209`). The value is right **at each vertex** (proven on silicon: `fogvertex`
  3/3 at 16 and 32 bpp, §1.3), but the chip interpolates **1/W** across the triangle and the table is
  logarithmic in it. On a triangle whose fog runs from none to full, the midpoint gets fog alpha **≈16/255
  instead of ≈128** (§1.2). Every large or long polygon with a real fog gradient (floors, terrain, roads) is
  under-fogged in its interior and "jumps" near its far vertices.
- **The hardware has the right input.** fogMode[4:3] is a source mux for the fog alpha (SPEC L2848-2849,
  L2885), and the W iterator's integer part is wired to the fog unit (fbzColorPath bit 28 text, SPEC L2791).
  3dfx's own HAL routes Z-buffered vertex fog as `fogMode = ENFOGGING|FOG_Z|FOG_ALPHA|FOG_DITHER` (**0x59**)
  with **Wb = 255 − specular alpha** (`VH5/D3FOG.C:215-222`, `VH5/D6TRI2I.C:904-906`). That code dates from the
  1998 Banshee/Voodoo3 driver and was branched for Napalm (`W9X/D3FOG.C:58, 91`).
- **The one open fact (S1).** SPEC §8.22 says that with both bits set "bit(4) takes precedence" (Z). That
  sentence contradicts 3dfx's code, SPEC §8.20, and the 86Box/MAME emulators (inferred), and looks inherited
  from SST-1. **One d3dprobe draw settles it**: a fog gradient carried in Wb, a constant depth and a constant
  diffuse alpha, each of which predicts a *different* colour (§5).
- **The fix is single pass and tiny in register terms:** for vertex fog, `fogMode` 0x41 → **0x59**,
  `sOowfbi` = `(float)(255 − sa)` instead of the ramp's 1/W, and **no fog-table load at all**. The vertex
  write count, setupMode, the TMU W and every other register stay the same.
- **Gating.** Default **OFF** behind a `Diag\D3DFeat` bit (`FOGITER`), together with the new ShadeCaps
  `FOGGOURAUD | FOGFLAT`. Off, the register stream and the caps are byte-for-byte today's (pinned). It
  graduates to default-on after one supervised `.124` boot passes the new probes at 16 and 32 bpp and an
  in-game A/B shows no regression. Counters and two of the new probes (`fogmix`, `fogvpersp`) are
  log/test-only and land default-on.
- **Other parts of the gap:** FOGGOURAUD rides the same bit (advertising it on the ramp path could switch a
  title *into* the approximation, §3.5). "No fog without a specular FVF" is kept; whether D3D means "no fog" or
  "full fog" there is measured on a GeForce box with the same probe (§11 Q3). Under a future W-buffer (G23),
  vertex fog moves to the Z carrier, which this design specifies and host-tests now (§3.8).
- **Priority P2, effort M.** No staged title is *measured* to use vertex fog on `.124` yet (UT2003/UT2004 log
  `Using w- pixel fog`, so they are not affected). Hidden & Dangerous Deluxe, BF1942, Max Payne, AvP, Red
  Faction and Rainbow Six all carry fog code and are the candidates (§10). The counters in §3.6 turn that into
  a measurement. Promote to P1 if a staged title shows vertex-fogged triangles.

## 1. The defect, as computed and measured

### 1.1 What the HAL does today

| step | code |
|---|---|
| FOGENABLE with FOGTABLEMODE NONE → "vertex fog": `fogMode = FM_ENABLE \| FM_DITHER` (0x41), the fog table set to the RAMP (`VCR_FOG_RAMP`, entry i = i/63), `c->fog_vertex = 1` | `KMD/display/vcrdd_d3d.c:1000-1016` |
| no specular in the FVF → `fogMode = 0` (no fog) | `KMD/display/vcrdd_d3d.c:1358-1360` |
| the ramp table is built and loaded (32 writes) whenever it is not the cached one | `KMD/display/vcrdd_3d.c:86-101` |
| per vertex, `sOowfbi = vcr_fog_ramp_oow(1 − sa/255)`, the 1/W whose table entry is the vertex's own fog amount | `KMD/display/vcrdd_3d.c:202-209`, `KMD/common/vcr_fog.c:75-92` |
| the stated reason: "the one a fog unit that only knows W allows" | `KMD/include/vcr_fog.h:13-14` |
| `setupMode` always carries `SM_Z \| SM_WFBI`; a textured draw also `SM_W0 \| SM_ST0` (TMU0 gets the real rhw) | `KMD/display/vcrdd_d3d.c:1021-1022`, `KMD/display/vcrdd_3d.c:210-221` |
| ShadeCaps: COLORFLATRGB, COLORGOURAUDRGB, ALPHAFLATBLEND, ALPHAGOURAUDBLEND (D3D8 shows `00004008`) — no FOGFLAT/FOGGOURAUD | `KMD/display/vcrdd_d3d.c:2032-2033`; `KMD/evidence/d3dplan_1112/caps_124.txt` |

### 1.2 How wrong it is: a full gradient

The fog table is indexed by the normalised float of the iterated 1/W (SPEC L2867). Glide's entry curve
(`vcr_fog_index_w`, `w = 2^(3+i/4)/(8−i%4)`) puts the four entries of each octave at 1/W = 2^-k·{1, 7/8, 6/8,
5/8}: the index is **logarithmic** in 1/W, linear only inside an octave. Interpolating 1/W linearly between
two vertices therefore bends the fog profile. A quad from fog 0 (sa 0xff, Wb 1.0) to full fog (sa 0x00, Wb
1.907e-5), sampled at the pixel columns of the proposed probe (computed for this design from the code's own
functions and a model of the table lookup; Python, IEEE single precision):

| x (t) | D3D fog amount ×255 | today (ramp + synthetic 1/W) | iterated W (this design) |
|---|---|---|---|
| 56 (0.125) | 31.9 | **4** | 31 |
| 80 (0.25) | 63.8 | **8** | 63 |
| 104 (0.375) | 95.6 | **12** | 95 |
| 128 (0.5) | 127.5 | **16** | 127 |
| 152 (0.625) | 159.4 | **24** | 159 |
| 176 (0.75) | 191.3 | **32** | 191 |
| 200 (0.875) | 223.1 | **49** | 223 |
| 222 (0.990) | 252.3 | **108** | 252 |

Moderate gradients are wrong too, only less: fog 0.2 → 0.4 gives 0.252 at the midpoint instead of 0.30
(12/255), and 0.2 → 0.6 gives 0.262 instead of 0.40 (35/255). That is visible as fog seams where a large
polygon meets small ones at the same depth (inferred).

### 1.3 What is already proven on silicon (and stays proven)

The per-vertex values are right. `d3dprobe render` on `.124`, 2026-11-12, constant-fog quads:

| run | `fogvertex` half fog (want 80007f, tol 40) |
|---|---|
| `ONBOX/d3dprobe_render_640x480x16.txt` | 7b007b ok |
| `ONBOX/d3dprobe_render_1024x768x32_clean.txt` | 7f007f ok |
| `ONBOX/d3dprobe_render_windowed_desktop32_clean.txt` | 7f007f ok |

The current test has no gradient, so it cannot see §1.2. (The 0x7b at 16 bpp is the ramp's own per-vertex
quantisation plus 5-bit output; the iterated-W path gives 127 → 0x80 there, inferred.)

### 1.4 The rest of the gap

- **"Off without a specular FVF"**: D3D carries the vertex fog factor only in the specular alpha. What a driver
  should do when the FVF has none is not written anywhere this design could read. 3dfx reads past the vertex
  (`FVFO_SPECULAR` = 128 when absent, `VH5/D6DP2.C:1099-1102`, then `pA[FVFO_SPECULAR]` in
  `VH5/D6TRI2I.C:904`). Ours is defined (no fog). Kept, and measured against a reference driver (§6.4, §11 Q3).
- **FOGGOURAUD** is unreported although fog is interpolated per vertex. 3dfx reported FOGFLAT and FOGGOURAUD
  (`VH5/D3INIT.C:3013-3014`). See §3.5 for why it rides the new bit.
- **fogMode bits 3+4**: the evidence conflict of `REP/hw.md` Q15 and `REP/vendor.md` §7.4, settled by §5.

## 3. Design

### 3.1 Scope

Changes: the carrier and fogMode of **D3D vertex fog** (FOGENABLE, FOGTABLEMODE NONE, specular present), the
ShadeCaps fog bits, a skip of the fog-table load for an iterated source, counters, and probe tests.

Does not change: table fog (LINEAR/EXP/EXP2 on W, G31's subject), fogColor, the fog table generator and its
cache semantics, setupMode, the TMU W path, texture/colour combine, clears, flips, SLI, Glide/OpenGL.

### 3.2 The register words

| source (`vcr_fogsrc.h`) | when | fogMode | per vertex | fog table |
|---|---|---|---|---|
| `VCR_FOGV_NONE` (0) | fog off, or vertex fog with no specular in the FVF | `0` | `sOowfbi = rhw` | untouched |
| `VCR_FOGV_RAMP` (1) | **default** (bit off) | `0x41` = ENABLE\|DITHER | `sOowfbi = vcr_fog_ramp_oow(1 − sa/255)` | RAMP, loaded when not cached |
| `VCR_FOGV_W` (2) | `FOGITER` armed, depth not on W | **`0x59`** = ENABLE\|DITHER\|ALPHA\|Z | **`sOowfbi = (float)(255 − sa)`** | **not loaded, not consulted** |
| `VCR_FOGV_Z` (3) | Wb is the depth (a W-buffer, **G23 only**) | `0x51` = ENABLE\|DITHER\|Z | `sVz = (float)((255 − sa) << 8)` at 16 bpp, `<< 16` at 32 bpp (28.4, **inferred**); `sOowfbi = rhw` | not loaded |

Notes:

- **Wb range.** 0.0 … 255.0 at the vertices. Pixels inside a triangle are convex combinations of the
  vertices, so W stays in [0, 255] up to the iterator's 32 fractional bits. The bit-28 wrap rule then gives
  exactly `floor(W)`, and maps the two possible rounding edges (−ε → 0, 256 → 0xff) safely (SPEC L2793-2798).
  **fbzColorPath bit 28 stays 0**, as 3dfx left it: setting it would also clamp RGBA and Z, and Z's clamp to
  `[0,0xffff]` is documented only for the 16-bit Z (SPEC L2784-2789); at a 24-bit Z it is an unknown nobody
  needs here.
- **FM_DITHER** stays set: it dithers the fog blend term (SPEC L2851), which matters at 16 bpp.
- **TMU W.** `sWb` reaches every TMU, then `sWtmu0`/`sWtmu1` override it when `SM_W0`/`SM_W1` are set (SPEC
  L3781-3786; 86Box `voodoo_setup.c:191-199`). The HAL sets `SM_W0` (and `SM_W1`) whenever it textures and
  writes `sOow0`/`sOow1` = rhw after `sOowfbi` (`vcrdd_3d.c:202-221`). So a fog value in Wb never reaches
  texture perspective. That is already true of today's synthetic Wb, but nothing tests it on silicon:
  `fogvpersp` (§6.3) does.
- **Per-vertex accuracy also improves:** sa 0x80 sends 127.0, so the fog alpha is 127 and the blend
  (Afog+1)/256 = 0.5, against the ramp's per-vertex 0x7b at 16 bpp (inferred blend formula).

### 3.3 New header `KMD/include/vcr_fogsrc.h` (integer only, Win32-free, host-tested)

```c
/* where D3D VERTEX fog travels to the fog unit (fogMode[4:3], SPEC 8.22). The factor
 * arrives in the specular alpha (255 = no fog); the carrier holds the fog AMOUNT. */
#define VCR_FOGV_NONE  0    /* no fog: fog off, or vertex fog without a specular colour  */
#define VCR_FOGV_RAMP  1    /* proven default: ramp table + synthetic 1/W (vcr_fog.h)    */
#define VCR_FOGV_W     2    /* Diag\D3DFeat FOGITER: Wb = 255 - sa, fogMode[4:3] = 3     */
#define VCR_FOGV_Z     3    /* Wb is the depth (W-buffer, G23): sVz carries it, [4:3]=2  */

static __inline unsigned vcr_fogv_source(unsigned armed, unsigned depth_is_w)
{
    if (depth_is_w)
        return VCR_FOGV_Z;          /* reachable only once G23 passes depth_is_w = 1 */
    return armed ? VCR_FOGV_W : VCR_FOGV_RAMP;
}
static __inline unsigned vcr_fogv_mode(unsigned src)    /* fogMode */
{
    return src == VCR_FOGV_RAMP ? FM_ENABLE | FM_DITHER
         : src == VCR_FOGV_W    ? FM_ENABLE | FM_DITHER | FM_ALPHA | FM_Z
         : src == VCR_FOGV_Z    ? FM_ENABLE | FM_DITHER | FM_Z : 0;
}
static __inline unsigned vcr_fogv_amount(unsigned spec_alpha) { return 255u - (spec_alpha & 0xffu); }
static __inline unsigned vcr_fogv_z_shift(unsigned rt32) { return rt32 ? 16u : 8u; } /* Z[27:20] */
```

`KMD/include/vcr_3dregs.h` gains `FM_FOGADD (1u<<1)`, `FM_FOGMULT (1u<<2)`, `FM_ALPHA (1u<<3)`, `FM_Z (1u<<4)`,
and `FM_ENABLE`'s comment stops saying "Afog from the W table" (it is the table *or* the [4:3] source).

The decision header has no float, so the integer-only HAL object (`-mgeneral-regs-only`) can include it.
The one float conversion stays in `vcrdd_3d.c` (the FPU object, `test_floats_live_in_one_object…`).

### 3.5 Caps

When `pd->fog_iter`, after `prim_caps(&d->dpcTriCaps)` (`:2071`):
`d->dpcTriCaps.dwShadeCaps |= D3DPSHADECAPS_FOGFLAT | D3DPSHADECAPS_FOGGOURAUD;` (constants present in the
mingw `d3dcaps.h`:143-144). Line caps are left to G16. D3D8 then reports **ShadeCaps `00084008`**
(FOGFLAT has no D3D8 bit); DX7 clients see `0x000c500a`.

**Why the cap rides the bit and is not "added now".** FOGGOURAUD is what DX5/DX6-era device pickers test.
H&D Deluxe's `Bin/igraph2.dll` names `D3DPSHADECAPS_FOGGOURAUD` in its caps dump, beside FOGVERTEX, FOGTABLE,
WFOG, ZFOG and FOGRANGE, and AvP's `avp.exe` prints "Can%s support fog in the Gouraud shading model" (strings
of `LIB`, read for this design). A title that gates vertex fog on the cap would switch *into* the §1.2
approximation the moment the cap appears on the ramp path. FOGFLAT is honest on both paths: D3D interpolates
the specular alpha even under SHADEMODE FLAT (inferred from the DX8 SHADEMODE documentation), and the carrier
is per vertex whatever G24 later does to the colours.

### 3.6 Instrumentation (log-only, default-on)

- `vcr_d3dctx` gains `fogv_tris`, `fogv_nospec_tris`, `fogt_tris`. `tri()`/`imm_tri()` (`:1367-1381`) count
  each triangle actually drawn, tested in this order:
  1. vertex-fogged: `w->d.fog_vertex` (either source);
  2. vertex fog dropped for want of a specular: `c->fog_vertex && !w->d.fog_vertex`;
  3. table-fogged: `c->regs.fogMode & FM_ENABLE` (the ramp's 0x41 never gets here, because step 1 caught it).

  Integer adds only. This is the gap-specific slice of G76.
- `ctx_free` (`:1210-1216`) logs, only when one is non-zero, a new event 513 `what` (next free; G05 proposes
  24/25): "context %u fog: %u vertex (%s), %u vertex w/o specular, %u table". The `%s` is `ramp` or `w`,
  under the 95-character limit.
- `VcrDd2dInit` (`KMD/display/vcrdd_2d.c:442-473`) logs another new `what` once when armed:
  "armed (Diag\\D3DFeat %x): vertex fog on the W iterator".
- `vcr_events.h`'s 513 description string gains both; the "event codes never renumbered" test keeps holding.

### 3.7 The old path

Off (`FOGITER` clear, today's default and every Banshee/Voodoo3 without the bit):

- `compute_regs` stores 1 and 0x41;
- `prepare` stores the same 0/1;
- `vertex` runs the same ramp lines;
- `VcrDd3dState`'s new term is constant-true;
- the caps are unchanged.

Register traffic is byte-for-byte today's, which §7.2 pins. The only new bytes anywhere are the context-gone
fog line in the flight recorder ring.

### 3.8 Consumers this design prepares (no code of theirs lands here)

- **G23 (W-buffer).** Wb becomes the depth, so vertex fog must leave it, exactly as 3dfx's row 5 does. G23
  passes `depth_is_w = 1` and adds the `VCR_FOGV_Z` write in `vertex()`:
  `sVz = (float)(vcr_fogv_amount(sa) << vcr_fogv_z_shift(rt32))`, `sOowfbi = rhw`. The 32 bpp shift is
  inferred from the 28.4 Z format. 3dfx sends `<< 8` at every depth (`VH5/D6TRI2I.C:880`), which by SPEC
  L2554 would fog nothing at 32 bpp, a likely vendor bug. G23's boot must run `fogvgrad` with the W-buffer
  at both depths.
- **G25 (specular).** 3dfx's second additive pass switches the fog to `FOGADD` so that FOG(T1+T2) holds
  (`REP/vendor.md` §8.2). With the W carrier both passes carry the same per-vertex Wb, so `fogMode` for pass 2
  is `vcr_fogv_mode(src) | FM_FOGADD`.
- **G24 (flat shading).** The carrier must stay per vertex when the colours are flattened. It does, because
  G24 touches sRed..sAlpha and never Wb.
- **G31 (Z-unit table fog), an option (inferred).** For LINEAR fog with Z-unit start/end, the fog amount is
  linear in z, and z is screen-linear. The W carrier with per-vertex `(z − start)/(end − start)·255` is then
  exact per pixel inside [start, end]. A triangle that crosses start or end needs per-pixel clamping (bit 28,
  whose Z side-effect at 32 bpp is unknown) or a split. That is G31's to decide.

## 4. Gating

- **Switch.** `HKLM\SYSTEM\CurrentControlSet\Services\vcrmp\Diag\D3DFeat`, bit `VCR_D3DFEAT_FOGITER`.
  - The bit number is allocated at landing in `vcr_d3dfeat.h`. Bits taken so far by other designs: 0 G15,
    1 G08, 4 G16, 6-8 G12, and G13 provisionally 7. So this design proposes **bit 10 (0x400)** provisionally.
    `vcr_d3dfeat.h`'s one-bit-each test catches a collision.
  - Read at boot (FindAdapter), like `D3DBigTex`, so the ShadeCaps a title reads at the desktop match its
    fullscreen PDEV's.
  - A positive flag: absent means off, and an older miniport never arms it.
- **Honoured on every chip**, not only `pd->napalm`. The routing is 3dfx's H3 (Banshee/Voodoo3) code, and the
  86Box Voodoo3 bed can then run the new probes before silicon. There is no Voodoo3 silicon in the fleet
  today, so this costs nothing.
- **Arming:** `REGWRITE HKLM SYSTEM\CurrentControlSet\Services\vcrmp\Diag D3DFeat REG_DWORD <bit | bits already armed>`.
  Read it back (`REGREAD` of the key), then the activation check, then `scripts/fleet/safe-reboot.py`. One
  Diag change per clean boot.
- **Is it safe to land default-on?** **Not at first.** It is a pure correctness fix, and the probe proves it
  exactly. But the register semantics it relies on are precisely the open question (S1), and arming it can
  change which fog a title picks (FOGGOURAUD). So it lands default-off.
- **Graduation** (default-on, the bit then a kill switch per the plan-level D3DFeat convention: a default mask
  in the miniport, or a `D3DFeatOff` mask) when all of these hold:
  1. Boot B passes §8 at 640x480x16 and 1024x768x32, fullscreen and windowed, with `"fog_source":"exact"`;
  2. the in-game A/B (§8.4) shows no regression on every title the counters flag;
  3. the 86Box bed and a GeForce reference agree with the probe's arithmetic (§6.4).
- **Lands default-on immediately**, because no register changes: the counters (§3.6), `fogmix` and
  `fogvpersp` (§6), which test the *current* path as well, and the `vcr_fog.h` comment fix.

## 5. The S1 experiment: what settles fogMode[4:3] = 3, and what each outcome means

**The draw** (d3dprobe `fogvgrad`, §6.1): the fog factor varies across the primitive (carried in Wb on the
armed path), the depth is a constant z = 0.25, and the diffuse alpha is a constant 0xC0. Each hypothesis
predicts a different picture (red base, blue fog colour, so blue ≈ the fog alpha):

| hypothesis | fog alpha the chip uses | what the probe reads at every sample |
|---|---|---|
| **W** (3dfx, 86Box) | floor(W) = 255·t | a ramp: B 0 → 252 along x and down the triangle's axis, matching D3D within tol |
| **Z precedence** (SPEC L2885 literally) | Z[27:20] = 0x3f (z 0.25 → 0x3fff at 20.12, 0x3fffff at 28.4: 0x3f at **both** depths) | constant ≈ bf0040: R ≈ 191, **B ≈ 64** |
| **alpha precedence** | iterated alpha 0xC0 | constant ≈ 3f00c0: **B ≈ 192**, R ≈ 63 |
| **ramp** (bit not armed) | table(1/W) | the §1.2 curve: B 4, 8, 12, **17** at the midpoint, 50 at x=200 |

The probe classifies and reports `"fog_source": "exact" | "z" | "alpha" | "ramp" | "unknown"`. It runs at 16
and 32 bpp, with Z and with `--noz`; setupMode always iterates Z, so the Z hypothesis stays testable without a
depth buffer.

**Outcomes:**

- **exact (W)** → the design stands. Record "fogMode[4:3]=3 selects iterated W on VSA-100 silicon; SPEC §8.22's
  precedence sentence is wrong" in `retro-3dfx/FINDINGS.md`, in the `vcr_3dregs.h` comment and in the
  `KMD/README.md` Findings section.
- **z** → disarm (`D3DFeat` back without the bit). W cannot reach the fog unit through this mux. Then:
  - Z-buffered draws keep the ramp;
  - draws with no depth test and no depth write could use the Z carrier (`VCR_FOGV_Z` with the 16/28.4 shift),
    which is exact. That needs a `depth_unused` input to `vcr_fogv_source` and its own probe pass;
  - W-buffered draws (G23) use the Z carrier as designed.
  - Correct `vcr_fog.h` and the 3.8 notes. The FOGGOURAUD cap stays off until a carrier that is exact for
    Z-buffered draws exists.
- **alpha** → the same disarm. FOG_ALPHA alone is a carrier only for draws with no alpha consumer: no alpha
  blend factor reading source alpha, no alpha test, no BLENDDIFFUSEALPHA, and no dest-alpha use at 32 bpp.
  It is designable but **not recommended**: too many conditions for the gain.
- **unknown** → disarm. Save the ring and the probe log. A second pass with a slow gradient (Wb 0 … 1) or a
  steep one (0 … 1023) tells whether the chip reads other W bits ([31:24] or [47:40]). The constant z/alpha
  values already rule out the two documented alternatives.

No hang is expected: fogMode is a pixel mux, and 3dfx shipped exactly 0x59 on Banshee, Voodoo3 and Voodoo5
(inferred from the shared source).

## 6. d3dprobe tests (`KMD/tools/d3dprobe.c`)

Helpers to add:

- `VSF { x, y, z, rhw; DWORD c, s; }` with `FVF_S` (exists, `:241-251`), drawn with per-vertex specular
  (`quad_fogv(x0,y0,x1,y1,z,rhw_l,rhw_r,c,s_tl,s_tr,s_bl,s_br)`, `tri_fogv(...)`);
- `VST { x, y, z, rhw; DWORD c, s; float u, v; }` with `D3DFVF_XYZRHW|DIFFUSE|SPECULAR|TEX1`;
- a 64x64 R5G6B5 "column ramp" texture: column cell c (8 texels wide) = (36c, 0, 255 − 36c);
- a global `g_fogsrc` written into the RESULT like `max_texture`. `d3dprobe_run.py` prints the whole RESULT,
  so it needs no change.

All tests use pretransformed vertices with `FOGENABLE TRUE`, `FOGCOLOR 0xff0000ff`, `FOGTABLEMODE NONE`,
`FOGVERTEXMODE NONE` (the factor is the specular alpha), and `untextured()` unless stated. The scene is
analytic, and every reference is computed in the probe. Tolerance per channel is **12 at 16 bpp** (5-bit
R/B plus fog dither, as the existing fog tests) and **5 at 32 bpp**.

### 6.1 `fogvgrad`: the S1 draw and the exactness proof (explicit until graduation)

- **A:** quad x 32..224, y 32..112, z 0.25, rhw 1, diffuse `0xc0ff0000`, specular alpha left 0xff, right
  0x00. Checks at y = 72, x = 32, 56, 80, 104, 128, 152, 176, 200, 222 (t = (x−32)/192).
- **B:** triangle (32,128) sa 0xff, (224,128) sa 0xff, (128,224) sa 0x00, z 0.25, rhw 1, diffuse
  `0xc0ff0000`. Checks at x = 128, y = 140, 152, …, 212 (t = (y−128)/96). This covers the y gradient and the
  setup unit's planes.
- **Want:** `R = round(255·(1−t))`, `G = 0`, `B = round(255·t)`. Examples: x=128 → 800080, x=200 → 2000df,
  x=222 → 0300fc.
- **Pass:** 16/16 within tol, and `fog_source` = `exact`.
- **On the old path it fails, and that is the point.** The midpoint reads ≈ ee0011 and x=200 ≈ cd0032 (§1.2),
  so Boot A records the old-buggy curve on silicon.
- The log prints the implied fog alpha (B) per sample for the record.

### 6.2 `fogvgrad_tex` (explicit until graduation)

- Quad A again, textured: stage 0 `MODULATE(TEXTURE, DIFFUSE)` with a white 64x64 R5G6B5 texture, point
  filtered, rhw 1, the same wants and 9 checks.
- Proves the fog stage after the texture combine (`CP_TEXTURE`, `SM_W0|SM_ST0`) is unchanged.

### 6.3 `fogvpersp`: Wb must never reach texture perspective (default list after Boot A)

- Quad x 32..224, y 32..224, u 0→1 along x, v 0→1 along y, **rhw 1.0 left, 0.25 right**, the column-ramp
  texture, `SELECTARG1(TEXTURE)`, point filter, vertex fog on with specular alpha **0xff** on every vertex
  (no fog). On the armed path Wb = **0.0** everywhere; on the ramp path Wb = 1.0.
- Checks at y = 44 (cell row 0) and the perspective-correct centres of the eight cells:
  `t = u/(0.25 + 0.75u)` for `u = (c + ½)/8`, i.e. x ≈ 72, 124, 156, 177, 193, 204, 213, 221. Want: the
  cell's 565-expanded colour.
- If TMU0 took Wb instead of its own W, the ramp path would map affinely (x=124 would read cell 3, 36 levels
  off) and the armed path would divide by zero. Both fail.

### 6.4 `fogmix`: switching, caching and the no-specular rule (default list after Boot A)

One frame with four quads, in this order:

1. table fog LINEAR 1..5 at rhw 1/3 → want 80007f (tol 40, as `fogtable`);
2. vertex fog, constant sa 0x40 → want **4000bf** (tol 12/5);
3. table fog with the **same** table at rhw 1/8 → want 0000ff. On the armed path this is a cache hit after a
   draw that must not have touched the table; on the ramp path it is a reload after the ramp;
4. vertex fog, FVF `XYZRHW|DIFFUSE` (no specular): **report-only**. Log `none` (ff0000) or `full` (0000ff).

**Validate on a reference driver first** (as G05 §5.3): run `d3dprobe render --tests
fogvgrad,fogvgrad_tex,fogvpersp,fogmix` on a GeForce box (`.133` GeForce4 Ti or `.143`'s GeForce 6800), at
16 and 32 bpp. With rhw constant, its fog must read `exact`. That proves the probe's arithmetic, and quad 4
gives the de facto answer to §11 Q3. The same run on the 86Box Voodoo3 bed with the bit armed checks our
HAL's emission before silicon.

### 6.5 `caps`

No probe change is needed. Armed, the RESULT reads `"ShadeCaps":"00084008"`; off, `00004008`.

## 9. Risk to proven paths

| path | risk |
|---|---|
| default 16 bpp (bit off) | **none**: register stream and caps byte-for-byte today's (§3.7, pinned by §7) |
| 32 bpp / D3D32 | the fog unit does not depend on renderMode; the Z carrier (G23) does, and is not reachable here |
| armed, non-fog draws | none: fogMode is 0 there exactly as today |
| armed, table fog | none: same fogMode, same table, same cache |
| armed, vertex fog | the S1 unknown. The worst case is a wrong fog *amount* in those draws while armed (cosmetic, reverted by the bit). A hang is not expected: a pixel mux, and 3dfx's shipped word |
| texture perspective | Wb ≠ rhw is not new (the ramp already sends a synthetic Wb). `fogvpersp` now proves on silicon that TMU W is separate, for both paths |
| Glide/OpenGL coexistence | fogMode is rewritten at every D3D state flush, and Glide writes its whole shadow. The W path never writes the fog table, which *removes* vertex fog's exposure to G41's stale-table cache |
| SLI (G51), CMDFIFO (G47), strips (G49) | none: the carrier is one per-vertex value in the Wb slot, broadcast like every other |
| flip path | untouched |
| caps | FOGGOURAUD/FOGFLAT may switch a title's fog choice; covered by §8.4. Fallback: split the caps into their own `D3DFeat` bit |
| performance | the same writes per vertex; 32 fewer table writes per vertex↔table fog switch |

## 11. Open questions

1. **S1:** does fogMode[4:3] = 3 select iterated W on VSA-100 silicon? Boot B's `fogvgrad` answers it, for
   16 and 32 bpp, with and without Z. An optional vendor cross-check: the same probe under 3dfx's own HAL on
   `.143`'s V5 5500, if d3dprobe gains `--adapter` (the V5 is the second adapter there).
2. **The Z carrier at 32 bpp** (G23): is the fog alpha Z[27:20] of the 28.4 iterator, so `<< 16`? And was
   3dfx's `<< 8` a 32 bpp bug?
3. **Vertex fog with no specular in the FVF:** D3D's intended result, no fog (ours) or full fog (a default
   specular of 0)? Read from the GeForce run of `fogmix` quad 4. If the reference says full fog, change the
   `prepare()` rule in its own small item.
4. **Perspective:** D3D's reference may interpolate the fog factor perspective-correctly. The W carrier is
   screen-linear, as 3dfx's was (inferred hardware limit for single-pass). Does any title look different
   because of it? (Inferred: no; the probes keep rhw constant so the question does not bias them.)
5. **Which staged titles use vertex fog on `.124`,** and does FOGGOURAUD change any title's fog choice? The
   counters in Boots A and B answer this.
6. **Floor or round:** does the fog alpha use the integer part of W (floor, by SPEC) or round it? The
   tolerance absorbs either; record what Boot B reads at x=128 (127.5).
7. **FOGRANGE:** under software vertex processing the runtime computes range fog. Could the HAL advertise
   D3DPRASTERCAPS_FOGRANGE honestly? Max Payne and H&D look for it. 3dfx did not (`REP/vendor.md` §7.3).
   Out of scope here.
8. **Plan level:** the final `D3DFeat` bit number, the event `what` numbers, and the D3DFeat graduation
   convention.
