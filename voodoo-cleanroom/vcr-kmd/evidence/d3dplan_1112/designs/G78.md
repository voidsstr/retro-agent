## 0. Verdict

**The gap is real.** With the user's choice of vsync on, every number the stack can produce today either
saturates at the refresh or is missing:

1. **No D3D game has a driver-side frame count.** All four 11-12 game sessions ended `DestroyDDLocal: ... flips of
   0` (UT2003 `ring_decoded.txt:1021`, Halo `:1024`, UT2004 `:1019`, `:1019`): the flip counters count vsync'd flips
   only (`KMD/include/vcr_flip.h:142-143`) and those games presented `DDFLIP_NOVSYNC`.
2. **A game's flip-counter lines do not survive its own teardown.** They are logged at the *first* end point
   (exclusive end / mode off, `KMD/display/vcrdd_ddraw.c:589`, `KMD/display/vcrdd.c:611`). In a game teardown that
   point comes *before* ~1000 DEBUG `CreateSurfaceEx` entries, and the ring holds 1024
   (`KMD/include/vcr_log.h:33`). The four game rings start inside that flood and end with `context gone`,
   `DrvDisableDirectDraw`, `DestroyDDLocal`; the d3dprobe ring, whose teardown is short, kept its `511/12-13`
   lines (`ONBOX/ring_after_probes_decoded.txt:192-193`).
3. **The refresh actually used is recorded nowhere.** d3dprobe's monitor gate prints the highest listed refresh
   ("the worst the pick can land on", `KMD/tools/mode_sweep.py:536-578`) as the plan: `640x480x16@120`
   (`ONBOX/d3dprobe_perf_640x480x16_vsync.txt:2`). The runtime chose 85 Hz in every run. UT2003 chose
   `640x480x16@120` (`ONBOX/games/UT2003_flyby/UT2003.log:101`) while its ini says `DesiredRefreshRate=60`, and
   UT2004 logs no refresh at all (`ONBOX/games/UT2004_statfps/UT2004.log:30-32`).
4. **No per-frame work time.** Average fps cannot tell 0.3 T of work from 0.95 T at the refresh, and with today's
   render-after-flip rule a frame of 1.05 T still shows at ~0.89 x the refresh (§3.2).
5. **The perf scenes the plan needs exist only as specifications, in five dialects across eight designs**
   (`--mode setup`, `--scene setup`, `--prim`, `--state`, `--mode texbind`, `--fill --mip`, `vsync`). The only
   scene built, `perf` (`KMD/tools/d3dprobe.c:1497-1530`), is fill-bound and verifies nothing: in the 11-12
   stale-FIFO state, where every triangle vanished and clears still worked, it would have reported a speed.
6. **The game routes do not end.** UT2004 `-benchmark -seconds=60` never ends and ignores WM_CLOSE, Halo's
   `-timedemo` had not finished at 485 s, UE1's `-benchmark` never exits (`PLAN:94`). 3DMark is on the share, not
   staged.

## 3. The method: what "runs well with vsync on" means

### 3.1 The frame, defined in the driver

Per PDEV, per session (a session ends where the flip counters' sessions end today: exclusive end, mode off,
DirectDraw disabled, the owner's `DestroyDDLocal`):

| symbol | definition | where it comes from |
|---|---|---|
| present n | a successful `Dd_Flip` | `KMD/display/vcrdd_ddraw.c:315-361` |
| t_n | the clock read after the start-address write | the `now` that `flip_sample` already reads (`:352`) |
| I_n | t_n − t_{n−1}: present to present | |
| V_n | time inside **wait spans** in (t_{n−1}, t_n]. A span opens when any completion check (`flip_done`, `:246-256`, used by Flip, GetFlipStatus, Lock and Blt) answers "still drawing", and closes at the next check that answers "done" | the D3D8 runtime waits in Flip's `DDFLIP_WAIT` retries (262,965 polls for 300 flips, `ONBOX/ring_after_probes_decoded.txt:193`); a DirectDraw 2D game waits in `Lock(DDLOCK_WAIT)` on the old front (`:647-660`). Both are vsync wait |
| W_n | I_n − V_n: game + runtime + HAL + the engine drain inside the flip | |
| F_n | t_n − entry of the successful call: today's in-flip cost (`VcrDd2dSync` at `:334`, the flip IOCTL, a TRACE log IOCTL, one vblank IOCTL) | |
| T | one refresh: `qpf / pd->freq` (`KMD/display/vcrdd.c:407`), refined by the vsync clock (§4.3) | |
| L_n | refreshes between the latch of the previous **shown** frame and this frame's latch; 0 = superseded, never shown | the vsync clock (§4.3) |
| headroom_n | 1 − W_n / T | |
| capacity | 1 / W (p50 and p95) | |

A present by `Dd_Blt` to the primary (a COPY swap effect) is counted (`blt_presents`) but not paced. A session
that presents that way then reads "presents by Blt: N", never "0 frames".

### 3.2 The latch model, under today's flip rule

The chip latches the start address at the next vsync (`KMD/include/vcr_flip.h:9-16`). Today `Dd_Flip` returns
as soon as the *previous* flip has latched, and the next frame renders at once (render-after-flip, G55). That
behaves like triple buffering for throughput. The model (`tests/native/test_vcr_kmd_flip.c:429-444`,
`d3d_pattern`) gives, for constant work at the nominal deadline rule (frame + 1/8):

| W per frame | what the flip rule does | L sequence | on time | present rate |
|---|---|---|---|---|
| 0.5 T | waits ~0.5 T in Flip retries; each write just after a vsync | 1, 1, 1 … | 100 % | refresh |
| 0.9 T | waits 0.1 T | 1, 1, 1 … | 100 % | refresh |
| 1.05 T | no retrace seen in time; completes by the 1.125 T deadline; writes slide 0.125 T a frame | about eight 1s, then a 2 | ~89 % | ~0.89 x refresh (the D3D pattern of `vcr_flip.h` THE DEADLINE; G59 §7) (model) |
| 1.5 T | done by deadline at entry; a write every 1.5 T | 1, 2, 1, 2 | 50 % | 0.67 x |
| 2.5 T | | 2, 3, 2, 3 | 0 % | 0.4 x |

Average fps misleads both ways. At 1.05 T it reads 75.6 fps at 85 Hz, with judder every ninth frame. With
G54's correct double buffering, the same W gives L = 2 always (42.5 fps). **W does not depend on the flip rule, L
does,** so the record keeps both, and a verdict is re-measured whenever the flip rule changes (G54, G55).

### 3.3 What is reported, and the verdict

Per title x mode x build, vsync on:

| verdict | rule |
|---|---|
| **holds N Hz** | on time ≥ 99 % **and** W p95 ≤ 0.9 T. Report headroom p50/p95 |
| **holds, with judder** | on time 90-99 % |
| **below the refresh** | on time < 90 %. Report capacity p50/p95 (fps) and the L histogram |
| **invalid run** | novsync presents in a vsync-on run; a mode or refresh other than planned; a focus loss in the timed window (ring 511 a=4 `exclusive 0` mid-run, or WINLIST); the verification frame failed (d3dprobe); a Glide session since the last clean engine |

Vsync-off rows are diagnostics only: uncapped fps and the W distribution, labelled `vsync:off`, never a verdict.

### 3.4 Why the driver, and not the game or FRAPS

- **The games do not report it.** UE2 writes its CSV only under `-benchmark` and only at exit; UT2004's `stat fps`
  is a one-second average on screen; Halo writes nothing until its timedemo ends; the DX5-DX7 titles report
  nothing.
- **FRAPS** (`benchmarks.json` "giants") hooks the process (inferred) and is not on `.124`.
- **The driver sees every present** of every API version, and needs no escape during a game, no screenshot and
  no display lock.

## 4. Part A: the frame record (`KMD/include/vcr_frames.h`)

### 4.1 Data and API

Win32-free, integer-only (the display DLL is `-mgeneral-regs-only` outside `vcrdd_3d.c`), host-tested, in the
pattern of `vcr_flip.h`. **`vcr_flip.h` is not modified**, so no completion answer can change.

```c
#define VCR_FR_WBINS      68   /* W/T: 64 bins of T/32 over [0,2T), then [2,3) [3,4) [4,8) [8,inf) T */
#define VCR_FR_VBINS      16   /* V/T: T/16 steps; the last is >= 15/16 T */
#define VCR_FR_FBINS      15   /* F: log2 microseconds, <16 us .. >=128 ms */
#define VCR_FR_LBINS       5   /* L: 0 (superseded), 1, 2, 3, 4+ refreshes */
#define VCR_FR_GAP_S       4   /* no present for 4 s ends a segment (loading, menus, alt-tab) */
#define VCR_FR_MIN_SEG     2   /* a segment of fewer presents is counted, not logged */

typedef struct vcr_vsclock {          /* section 4.3 */
    vcr_ticks t_anchor, t_ref;  vcr_s32 idx_anchor, idx_ref;
    vcr_ticks period_q10;             /* ticks per refresh x 1024: nominal until measured */
    vcr_ticks period_nom_q10;
    vcr_u32   samples, minority, anchors;  vcr_u8 sense;   /* 0 unknown 1 pulse=in_vblank 2 inverted */
} vcr_vsclock;

typedef struct vcr_frames_acc {       /* one segment */
    vcr_u32   seg, owner, frames, vsync, novsync, blt_presents, waited, retries, racing;
    vcr_u32   w[VCR_FR_WBINS], v[VCR_FR_VBINS], f[VCR_FR_FBINS];
    vcr_u32   l_exact[VCR_FR_LBINS], l_est32[VCR_FR_LBINS];   /* the estimate in 1/32 frames */
    vcr_u64   w_sum, v_sum, f_sum;  vcr_ticks w_max, t_first, t_last;
    vcr_u32   ms_at[5];               /* milliseconds to present 100, 500, 1000, 2000, 5000 */
} vcr_frames_acc;

typedef struct vcr_frames {
    vcr_u32   on, forced_novsync, w, h, bpp, hz;   vcr_ticks qpf, t_nom;
    vcr_u32   waiting;  vcr_ticks wait_t0, v_cur;  /* the open wait span; V of the frame in progress */
    vcr_s32   idx_pend, idx_shown;  vcr_u8 pend_phased, have_prev;  vcr_ticks t_prev;
    vcr_u32   segs, short_segs, gaps;  vcr_ticks gap_max;
    vcr_vsclock vs;
    vcr_frames_acc acc, closed;  vcr_u32 closed_valid;
} vcr_frames;

void vcr_frames_init(vcr_frames *, vcr_ticks qpf, vcr_u32 hz, vcr_u32 w, vcr_u32 h, vcr_u32 bpp,
                     int on, int forced_novsync);
void vcr_frames_check(vcr_frames *, int done, vcr_ticks t_poll0, vcr_ticks t_poll1); /* every flip_done */
void vcr_frames_present(vcr_frames *, vcr_ticks t_entry, vcr_ticks t_done, int novsync,
                        int post_in_pulse, vcr_u32 pid);      /* every successful Dd_Flip */
void vcr_frames_blt_present(vcr_frames *);
void vcr_vs_sample(vcr_vsclock *, int have, int in_vblank, vcr_ticks t);              /* every vblank read */
int  vcr_frames_freeze(vcr_frames *);                    /* exclusive end / mode off: 1 if anything closed */
int  vcr_frames_emit_due(const vcr_frames *, int point); /* DD disabled / owner's DestroyDDLocal / new session */
int  vcr_frames_novsync(int flag_novsync, int forced);   /* part A' */
vcr_u32 vcr_frames_quantile_permille(const vcr_u32 *bins, int n, vcr_u32 permille);  /* upper bin edge, in ‰ of T */
void vcr_frames_summary(const vcr_frames_acc *, vcr_ticks t_nom, vcr_ticks qpf, vcr_frames_sum *out);
```

**Quantiles are the upper edge of the bin that holds the rank**, in permille of T: a conservative bound
("p95 W ≤ 0.84 T"), exact and integer, at 1/32 T resolution (0.37 ms at 85 Hz). Means come from the 64-bit
sums. Over `[2,8) T` the bins coarsen; `≥ 8 T` reads as the sentinel "≥ 8 T".

**Segments.** A present that follows 4 s without one (`VCR_FR_GAP_S`) closes the current segment. Its lines are
logged now and the accumulators start again. The gap is counted (`gaps`, `gap_max`), not binned. This splits a
game's menu, its load and its gameplay with no host-to-driver signal at all. d3dprobe uses it on purpose: it
sleeps 5 s between the levels of a sweep, so one device and one pair of mode switches serve every level (§5.5).

### 4.2 Glue (`KMD/display/vcrdd_ddraw.c`)

- **`Dd_Lock` / `Dd_Blt` / `Dd_GetFlipStatus`** reach the wait spans through `flip_done` and need nothing else.
- **`Dd_Blt`** adds `vcr_frames_blt_present` when the destination is the visible primary.
- **`vcr_frames_init`** runs where the PDEV's mode is known (`vcrdd.c:407-425`), with `EngQueryPerformanceFrequency`.
- **The IOCTL sequence, the register traffic and every `ddRVal` are unchanged.** The python test pins the ordered
  call list of `Dd_Flip` (§10.2).

### 4.3 The vsync clock: knowing which refresh a write latched in

L needs the phase of each write against the vsyncs. There is no interrupt, so the clock is built from the
samples the flip path already takes: every poll during a wait, plus one sample after every write.

- **Sense.** Count the samples and the minority state. Duty ≤ 5 % means the pulse reads `in_vblank` = 1, as
  modelled today. Duty ≥ 95 % means inverted, which is the vendor's polarity model at positive-vsync modes, G59 §3.
  Anything between is "unknown": no anchors, and the L estimate below is used. Decided after 256 samples. Over a
  waited frame the D3D pattern polls about 877 times (`ONBOX/ring_after_probes_decoded.txt:193`); an always-late
  game gives about 2 samples a present.
- **Anchors.** A sample in the pulse state puts a vsync start within one pulse width before it. That is 3 lines:
  ~35 µs at 1280x960@85 (G59 §1.2), ~69 µs at 640x480@85 (inferred from the VESA timing). The poll that
  completes a waited flip is such a sample, so every waited frame anchors. Arbitrary-phase samples land in the
  pulse 0.3-0.6 % of the time, which still anchors an always-late session every few hundred presents.
- **Period.** Nominal `qpf/hz` to start. It is refined from anchor pairs, first with spans ≤ 32 refreshes (rounding
  is safe up to the +1.12 % / −0.29 % that every timing in `vcr_modes.c` computes to, `vcr_flip.h` THE DEADLINE),
  then with longer ones. It is kept only within 1/64 of nominal, the same trust band as `VCR_FLIP_TRUST_SHIFT`.
- **Latch index** of a write at t: `idx_anchor + ceil((t − t_anchor) / period)`. It is **phased** when the anchor is
  less than 512 refreshes old.
- **L.**
  - **Exact** when both ends are phased. A write whose index equals the pending frame's supersedes it (bin 0).
  - **Estimated** otherwise. I_n in refreshes splits between floor and ceil in proportion to its fraction, in 1/32
    units (`l_est32`). That is the expectation for a uniform phase; it keeps mean(L) = mean(I/T).
  - A write whose post-write sample was in the pulse (`racing`) is counted. It may latch now or one refresh later;
    the flip rule already treats it as one refresh late (`vcr_flip.h` THE ORDER).
- **On time** = L == 1 among the shown frames of vsync'd presents. Exact and estimated counts are logged separately.

The host test runs the clock against the CRT model's ground truth, `latch_after()` at
`tests/native/test_vcr_kmd_flip.c:224-229` (§10.1). When G54's hardware swap lands, `fbiSwapHistory` replaces the
estimate with the chip's own count.

### 4.4 Surviving the teardown: freeze early, emit late

| point (today) | where | in a game teardown | what part A does |
|---|---|---|---|
| exclusive end | `vcrdd_ddraw.c:589` | before the flood | **freeze**: copy `acc` to `closed`, reset `acc` |
| mode off (`DrvAssertMode` FALSE) | `vcrdd.c:611` | before the flood | **freeze** |
| ~1000 DEBUG `CreateSurfaceEx` | | | |
| context gone | `vcrdd_d3d.c:1210-1220` | after (UT2003 `ring_decoded.txt:1015`) | nothing: `c->pd` may be stale (G43) |
| `DrvDisableDirectDraw` | `vcrdd_ddraw.c:737-743` | after (`:1016`) | **emit** `closed` |
| owner's `DestroyDDLocal` | `vcrdd_d3d.c:1970-1977` | after (`:1021`) | **emit** (freeze first if never frozen: a same-mode session) |
| the next session's first present | | | **emit** a still-closed record before reusing it: never lost, never merged |

`DrvDisableDirectDraw` is a PDEV callback, so the record is read while its PDEV is alive, by construction.
**Mid-session segments** (§4.1) are logged when the gap is detected. They survive only if the ring holds until the
fetch, which needs G52's logging gate (the per-`D3DTSS_TEXTUREMAP` DEBUG event, `vcrdd_d3d.c:1603`), `LogLevel` 2,
or G76. The final segment, the one that matters for a run ended from gameplay, needs neither.

The same freeze/emit move would also save the `511/12-13` flip counters in game sessions. That is offered to
G59/G76, not done here.

### 4.5 What is logged

There is one new event, `VCR_EV_DD_FRAMES`. It takes the next free 5xx code at landing: 514 is claimed twice
(G02, G04), and G46 claims one. Tools key on the name, which `vcrlog.py` reads from `vcr_events.h`. Every line
carries the owner pid in the entry and the segment number in `a`'s high half; `a`'s low half is the line kind.
Messages stay inside `VCR_LOG_MSG_LEN` (96).

| a (kind) | b, c, d | message |
|---|---|---|
| 1 session | frames, owner pid, measured refresh mHz (0 = none) | `seg %u: frames %u (vsync %u, novsync %u, blt %u) %ux%ux%u@%u Hz, %u ms%s` (`" NOVSYNC FORCED"`) |
| 2 work | W p50, p95, p99 in ‰ of T | `work/refresh p50 %u p95 %u p99 %u permille; mean %u us, max %u ms` |
| 3 latch | on-time ‰, frames with L ≥ 2, superseded | `refreshes/frame 0:%u 1:%u 2:%u 3:%u 4+:%u (exact %u, est %u, racing %u)` |
| 4 wait | V p50 µs, V p95 µs, waited frames | `vsync wait p50 %u us p95 %u us, retries %u; flip p50 %u us max %u us` |
| 5, 6 hist | three of the coarse W/T counts each | `W/T <.5 %u <.75 %u <.9 %u <1 %u <1.25 %u`, `W/T <1.5 %u <2 %u <3 %u <4 %u >=4 %u` |
| 7 time | ms to present 100, 500, 1000 | `presents 100/500/1k/2k/5k at %u/%u/%u/%u/%u ms; gaps %u (max %u s)` |
| 8 clock | anchors, duty ‰, sense | `vsync clock: %u anchors, %u samples, duty %u permille (%s), T %u.%03u ms (nominal %u.%03u)` |

That is eight INFO lines per logged segment, and no line per frame.

### 4.6 Switch, cost, the old path

- **`Diag\FrameStats`** (DWORD, **absent = 1 = on; 0 = off**).
  - Read at every `IOCTL_VCR_INFO`, like `Accel2DPattern`.
  - Carried as a negative bit, `VCR_PERF_F_NO_FRAMES` (bit 16), in the `vcr_info` word G46 appends (`d3d_perf`).
    If G78 lands first, it appends that word under G46's name.
  - An older miniport therefore means on, and an older DLL ignores the bit.
  - There is precedent for default-on switches: `Accel2DPattern`, `GdiGamma`, `CoreClock` (`KMD/README.md:116-120`),
    and the 511/12-13 counters themselves.
- **Cost per present:**
  - at most one `EngQueryPerformanceCounter`, only when no poll ran in the call;
  - about 40 integer operations and one 64-bit divide;
  - no IOCTL, no register access.
- **Cost per poll:** about 6 integer operations, beside a 13.4 µs IOCTL (`ring_after_probes_decoded.txt:193`).
- **Per logged segment:** 8 log IOCTLs. **Memory:** about 1.3 KB per PDEV (`acc` + `closed`).
- **Off (`FrameStats`=0):** every `vcr_frames_*` call returns at its first branch. The flip path is today's
  instruction for instruction except that branch and `flip_sample`'s extra out-parameter.

### 4.7 Interface rules for the siblings

1. **One frame boundary.** G46's per-frame accumulators (HAL share, chip statistics) close at
   `vcr_frames_present`, so "HAL ms per frame" and W refer to the same frame.
2. **HAL time excludes wait spans.** G46 brackets `Dd_Flip`/`Dd_Lock`/`Dd_Blt`. With vsync on, those brackets
   include `WASSTILLDRAWING` polling, which is vsync wait, not HAL work: the HAL share would read near 100 % on a
   light scene. HAL share = (HAL time − V) / W.
3. **Any new flip path classifies its waits.** G54's throttle on `status[30:28]` is engine back-pressure, not the
   display. It goes to F, never to V, so V stays "waiting for the screen".
4. **G59's 511 a=15/16 lines** are not added when part A is in. Their content (presents by vsync/novsync, waits,
   the interval histogram) is lines 1, 3 and 4. G54's planned 511 a=15..19 collide with G59's a=15/16; part A uses
   its own event, so neither is affected.

### 4.8 Optional: a live record (only with G04)

Segments remove the need for host-side windows. Watching a *running* game is G04's job: its heartbeat writes
`Diag\Live\D3DBeat` once a second. If that lands, the same IOCTL may carry the current `acc` as
`Diag\Live\D3DFrames` (REG_BINARY, volatile) under G04's own switch. That adds no Diag change.

### 4.9 Part A': `Diag\D3DNoVsync` (diagnostic, default OFF, self-clearing)

- **Read** by the miniport at boot (`FindAdapter`, beside `D3DBigTex`, `KMD/miniport/vcrmp.c:244`). It is written
  back to 0 at once, flushed (`VcrDiagSet(..., TRUE)`, as the boot bookkeeping at `vcrmp.c:105-117` does), so **an arm lasts exactly one boot**. This is
  G46's `D3DPerfTest` pattern.
- **Logged** as a WARN at boot, and in every frame record (`NOVSYNC FORCED`).
- **Passed** as bit 17 of the same word (`VCR_PERF_F_NOVSYNC`, positive).
- **Effect:** `vcr_frames_novsync(flag, forced)` = `flag || forced`. Every DirectDraw flip completes like a
  `DDFLIP_NOVSYNC` flip: never pending, so Lock and Blt do not wait for it. Every D3D and DirectDraw title tears;
  Glide/OpenGL do not use `Dd_Flip`.
- **Why:** an uncapped number for DX5-DX7 titles that have no vsync setting. The vendor's equivalent is
  `SWAPINTERVAL` = 0 (`VH5/DDINIT.C:796-800`, `VH5/DDFLIP.C:153`).
- **Used once per title class**, to check that W predicts uncapped fps (§12, stage 2). Never in a normal state.

## 5. Part B: the d3dprobe perf framework

### 5.1 One grammar, with the siblings' dialects as aliases

```
d3dprobe perf [--mode S] [scene options] [--full] [--res WxH] [--bpp 16|32] [--hz N] [--novsync]
              [--frames F] [--warmup K] [--repeat R] [--work-us U | --work-sweep a,b,...] [--pace MS]
```

| written in | form | canonical |
|---|---|---|
| d3dprobe today | `perf` (no mode) | `--mode classic`: **the timed loop byte for byte**, plus a verification frame after it |
| G47 | `--scene setup` | `--mode setup` |
| G49 | `perf --prim P` | `--mode setup --prim P` |
| G53 | `--state none\|tex\|blend\|z [--per-frame K]` | `--mode state --what X --per-frame K` |
| G52 | `--mode texbind --binds K` | `--mode state --what texbind --per-frame K` |
| G26, G60 | `--fill --mip M`, `--blend --alpha0 --atest` | `--mode fill` with those options |
| G59 | `d3dprobe vsync ...` | `perf --mode flip ...` (`vsync` stays accepted as a mode name) |

### 5.2 RESULT schema, `perf_v` 1

`{"mode":"perf","perf_v":1,"scene","pid","adapter","driver","full","res","bpp","fmt","zfmt","hz_req","opened_hz",
"vsync","frames","warmup","frames_run","seconds","ft":{"p50","p95","p99","max","hist":{"sub","1","2","3","4+"}},
"present_ms":{"p50","p95"},"work_us","client_work_us":{"p50","p95"},"kpi":{...},"verify":{"pass","what","detail"},
"focus_lost","error"}`

| field | meaning |
|---|---|
| `opened_hz` | `IDirect3DDevice8_GetDisplayMode` after `CreateDevice` |
| `hz_req` | `--hz`, or 0 for the runtime's pick |
| `ft` | the client's present-to-present intervals (QPC around every `Present`), the histogram in units of `1/opened_hz` |
| `kpi` | scene-specific (`fps`, `us_per_tri`, `tris_s`, `mpix_s`, `us_per_change`, `mb_s`, ...) |
| `pid` | lets `framestats.py` find this run's frame record |

**Rule: `kpi` is `null` unless `verify.pass`.** A run that drew nothing never reports a speed.

### 5.3 Rules every scene follows

- **One fullscreen device per run.** That is one pair of paced mode switches (`vcr_pace.h`; `--pace` passes through).
- **Warm-up and timed loop.** `--warmup K` frames, then `--frames F` timed frames.
- **One verification frame** after the timed loop, its back buffer locked and checked against analytic values.
- **`--hz N`** sets `FullScreen_RefreshRateInHz` = N, and the host gate checks exactly N. Without it, the runtime
  picks, the gate checks its worst case, and `opened_hz` records the pick.
- **`--novsync`** sets `D3DPRESENT_INTERVAL_IMMEDIATE`, as today (`d3dprobe.c:1454-1455`). Otherwise the scene uses
  `D3DPRESENT_INTERVAL_ONE`.

### 5.4 Scenes: one implementation, the owners' specifications

The timed-loop driver, the client clock, the verification hook and the RESULT writer are G78's. Each scene supplies
setup, draw and verify callbacks from its owner's specification.

| scene | specified by | KPI | verification (analytic reference) |
|---|---|---|---|
| `classic` | today (`d3dprobe.c:1497-1530`) | fps (continuity: 151 novsync, 85.1/84.4 vsync) | one known quad + two clear pixels |
| `flip` (= `vsync`) | **G78 §5.5** with G59 §7's fields | the client histogram per work level; the part-A cross-check | quad texels + clear colours |
| `setup` | G48 §5.1 (geometry: P x P right triangles on a 4-px grid, 1024-triangle calls, empty-frame calibration); G49 (`--prim list\|strip\|fan\|ilist\|ilist_strip`); G47 | µs/tri, tris/s | **G46 §3.5's lit-pixel count**: exactly the analytic count, so a triangle missing or doubled moves it |
| `fill` | G50 §4.3 (variants `t0,t1,t1z,t1zb,t2`, L layers, F frames, the clear-alone subtraction); G26 (`--mip`); G60 (`--blend --alpha0 --atest`) | Mpix/s; px/clk from `vcrctl clock` read **before** the run | every pixel = the last layer's colour; with G46's `D3DStats`, Σ `fbiPixelsIn` = W x H x L x F |
| `state` | G53 (`none\|tex\|blend\|z`, 2x2-px triangle per change); G52 (`texbind`) | µs per change | the last triangle's pixels |
| `upload` | G56 (`--tex-kb S --per-frame K`) | MB/s, µs per upload | the last uploaded texel pattern sampled 1:1 |
| `xform`, `clip`, `game` | G46 §3.5 | µs/vertex, µs/clipped triangle, fps | G46's references |
| `overlap` | G54 | frame ≤ 1.15 x max(CPU, GPU) | G54's |

Where two specifications differ, the union of their options applies, with the defaults of the design that runs
first. For `setup`, G48's geometry is used with G46's lit-pixel check (one geometry, one reference).

### 5.5 The `flip` scene (G78's own): checks part A against the client's own clock

```
d3dprobe perf --mode flip --full --res WxH --bpp B --hz 85 [--work-sweep 0,0.25,0.5,0.9,1.05,1.5,2.5]
              [--frames 600] [--warmup 60] [--novsync]
```

**The device:**
- fullscreen, `D3DSWAPEFFECT_FLIP` with one back buffer;
- `PresentationInterval` ONE, or IMMEDIATE with `--novsync`;
- `RefreshRateInHz` = `--hz`, default 85 (the rate every 11-12 run actually got);
- software vertex processing.

**Steps:**
1. **The raster window.** G59 §7's 0.5 s of `GetRasterStatus` gives `raster_hz` and `invb_duty`.
2. **Each work level** w, in refreshes of `opened_hz`: `--warmup` frames, then `--frames` frames. Each frame is:
   - a target `Clear` alternating two colours;
   - one 64x64 checker quad (the texture is **set once**, before the loop, so the DP2 stream carries no
     per-frame `TEXTUREMAP` and no DEBUG event, `vcrdd_d3d.c:1603`);
   - `Present`;
   - a QPC busy-wait of w x T.
3. **Between levels, 5 s with no `Present`.** The driver closes a segment per level (§4.1), so one device and two
   mode switches serve the whole sweep.
4. **One verification frame** at the end.

**Per level, the RESULT gives:**
- the frames;
- `ft`, `ratio` (= present rate / `raster_hz`);
- G59's `slow_frames`, `two_frame`, `fast_frames`;
- `client_work_us` (from the return of `Present` n−1 to the call of `Present` n).

### 5.6 `d3dprobe_run.py`

- **Grammar.** `--mode` and every option and alias of §5.1 pass through.
- **`--pace MS`** (folding in `ONBOX/d3dprobe_paced.py`).
- **`--hz N`:**
  - the gate checks N, not the highest listed rate;
  - the plan line prints `gate: worst case X Hz; asked: N | the runtime's pick; opened: M`;
  - a mismatch between asked and opened stops further switches through `mode_sweep.lab_halt`'s `want_hz` rule,
    as for glidelab's `opened_hz` (`KMD/tools/mode_sweep.py:581-600`).
- **`--fetch-ring`.** After the probe has exited (never during), `vcrlog.py fetch`, then
  `framestats.py --against <RESULT>` matched by `pid`. The printed JSON gains `frames_check`.

## 7. Part D: the game harness (`KMD/tools/d3dbench.py`) and the decoder (`KMD/tools/framestats.py`)

`d3dbench.py <host> --recipe R [--runs 3] [--warmup-runs 1] [--attended] [--out EV/d3dbench/<date>]`

The harness promotes `ONBOX/gamerun.py` out of the evidence folder. It reuses `v56k_bench.UT99Bench` for UE1, and
writes everything under the repository (never the scratchpad).

### 7.1 Protocol (per run)

**Before the run:**
1. `PING`.
2. `PROCLIST`: no game or lab running.
3. `WINLIST`: a screensaver in front is dismissed with `UIKEY SHIFT` (`ScreenSaverIsSecure` = 0 on `.124`).
4. The driver-bench quiesce: `AI_DISABLE`, and stop `retro-infer.exe`, `wuauclt.exe`, `daemon.exe`, `wmiprvse.exe`,
   `dwwin`/`dumprep` **by pid**.
5. **The clean-engine gate** (G01's job once it lands): `vcrctl reg 80024` must read 0.
   - This is an escape, so it runs only while no D3D client runs.
   - After any Glide or OpenGL session, D3D runs are refused until a clean `vcrctl modeseq` or a cold boot.
6. `vcrctl clock`, once per session.
7. `DISPLAYCFG get`, recorded.
8. A `vcrctl mark d3dbench:<recipe>:<run>` before the launch. It anchors host time to ring time, and the ring's
   `513/16`, `513/18` and armed lines record the Diag state.

**During the run:**
- **No `SCREENSHOT` and no `vcrctl` in the timed window.** A GDI capture takes the display lock the game holds for
  most of its frame (G46 §1.3) and would perturb the number. Quality frames (G73) come from separate, untimed runs.
- `WINLIST` every 10 s (agent-internal): a foreground change is a focus loss, and the run is invalid.
- 120 s of agent silence stops everything (as `gamerun.py`).

**After the run:**
- The recipe's exit: console `exit` only with the game focused; WM_CLOSE by pid; a forced kill by pid only after
  20 s. Never a kill by image name.
- `DISPLAYCFG` must read the desktop mode again.
- Then `vcrlog.py fetch`.
- `DOWNLOAD` of the result files through `command_binary`: status 1 is "binary OK", the 11-12 `agentcall.py`
  lesson.
- Parse, decide the verdict, write the row.

**Repetition:**
- 1 warm-up run (discarded) and 3 timed runs; report the median and the range.
- One Diag change per clean boot.
- Never compare hosts. Every row is labelled with the stack that produced it (CLAUDE.md, "Benchmark numbers belong
  to the stack that produced them").

## 11. The d3dprobe check: `perf --mode flip` (test key `frame_accounting`)

**Runs:**
- `--work-sweep 0,0.25,0.5,0.9,1.05,1.5,2.5 --hz 85 --frames 600 --warmup 60` at **640x480x16@85** (negative
  vsync) and **1280x960x16@85** (positive vsync, the staged mode of JK, MotS and Shogo);
- one `--novsync` run at 640x480x16.

The probe gives each level its own segment (§5.5). `framestats.py --against` matches the segments to the levels by
order and frame count.

**What it draws:** a target clear alternating two colours and one checker quad a frame. The verification frame
checks the quad's texels and the clear pixels.

**Pass criteria (reference values):**
1. **Count.** Every segment's `frames` = the level's `warmup + frames`, exactly; `vsync` = frames (`novsync` = 0),
   or the reverse for `--novsync`. This is the decisive check: today's counters would read `flips 0` for the
   novsync run.
2. **Work.** |W p50 − `client_work_us` p50| ≤ 0.5 ms + 2 %. The driver's W also holds the DP2 flush the runtime
   makes inside `Present`.
3. **Refresh.** Measured T within 0.1 % of `1/raster_hz` (G59's raster window) and of `opened_hz`.
4. **Light levels** (w ≤ 0.9): on time ≥ 99 %, and the client `ratio` between 0.98 and 1.02. G59's reference is
   the 11-12 85.1 fps at 85 Hz.
5. **Heavy levels** (w = 1.05, 1.5, 2.5): the L histogram (exact + estimated) within 5 points per bin of
   `framestats.py --model`'s prediction for the measured W and T under the deadline rule actually in force
   (nominal, or `FlipDeadline`).
6. **Novsync run.** W p50 matches the client's frame time within 5 %; `superseded` > 0.
7. **Continuity.** `--mode classic` at 640x480x16 gives 85.1 ± 0.5 vsync and 151 ± 2 novsync, as before.

## 13. Risks to proven paths

| path | risk |
|---|---|
| **default 16 bpp D3D and every fresh install** | no register traffic, no new IOCTL and no return value change. Part A adds integer work per present and per poll, and at most one QPC per present. A bug in the pure logic could fault in kernel mode: it is host-tested over degenerate inputs (0/1 Hz, QPF extremes, hour-long sums, empty histograms), touches only the PDEV's own struct, and divides only by guarded values |
| **the flip path** | completion answers cannot change, because `vcr_flip.h` is untouched and the call order is pinned. A.' is off by default and clears itself at the boot that honours it |
| **Glide/OpenGL coexistence** | no effect: they do not call `Dd_Flip`. The harness enforces the clean-engine gate between a Glide session and D3D runs (G01's lesson) |
| **SLI state** | none: no register is read or written |
| **the ring** | 8 INFO lines per logged segment. The emit-late move changes *when* lines are written, not what any other event logs |
| **measurement perturbation** | none on the drawing path. The harness takes no screenshot or escape in timed windows |
| **box stability** | the harness runs what 11-12 ran safely (13 probes and 4 games, no hang), with the same exits. Max Payne stays attended-only. 3DMark is supervised (vintage-lane history). Mode switches: one pair per d3dprobe run, paced by `vcr_pace.h`; the flip sweep uses segments instead of a device per level |

## 15. Open questions

1. **UE2 `-benchmark`:** does it advance a fixed step, so that frame k is the same view in every run? Settled on the
   host by `ue2stats.py --compare` on two runs' CSVs.
2. **UT2004:** does it write `avgfps`/CSV when a `-benchmark` run is ended by console `exit`, as UT2003 did? If
   not, the driver record is UT2004's only number.
3. **Halo `-timedemo`:** how many frames, and where are its results written? Until it finishes inside a cap, the
   milestones stand in.
4. **The pulse polarity** (G59 F-P): is it the vendor's model? The vsync clock's `sense` answers it at both
   polarities in stage 1, read-only.
5. **Blt presents:** does any staged title present by Blt in fullscreen (a COPY swap effect)? `blt_presents`
   answers it. If one does, the wait for those presents (`WaitForVerticalBlank`) needs the same span treatment.
6. **The screensaver:** does it start during an exclusive-mode D3D run longer than its 10 minutes (3DMark suites run
   13-18 min)? A focus loss is detected (ring 511 a=4, WINLIST). The open question is whether the harness must
   suspend the screensaver for long runs, and whether the agent's `retrowall` keep loop re-enables it.
7. **3DMark batch:** what are the command-line batch interface and result file of 3DMark2000 Pro and 2001 SE? In
   2001 SE's free build, batch runs are a Pro nag.
8. **Default-on:** will the reviewer accept part A default-on from its first boot (log-only, unchanged path), or
   ship that first boot with `FrameStats`=0?
9. **QPF on `.124`:** is it the ACPI PM timer (3,579,545 Hz, as `vcr_flip.h` assumes) or a TSC-rate counter? The
   record logs T in ms, and the tests cover both.
10. **Mid-session segment lines:** should they wait for G52/G76, or should d3dprobe's sweep alone rely on them?
    d3dprobe's ring is quiet, because the texture is set once.
11. **After G54:** its swap throttle must report engine back-pressure as F, not V (§4.7, rule 3). Does XP's D3D8
    runtime then still spin in `Flip`, or does it wait in `GetFlipStatus`/`Lock`? `flip_done` covers all of them.
