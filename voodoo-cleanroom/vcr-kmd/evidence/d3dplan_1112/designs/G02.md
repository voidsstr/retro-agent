## 1. Verdict

**The gap is real and fixable. Priority P0.** One bounded wait that runs out turns the 2D engine,
DirectDraw acceleration and the whole Direct3D HAL off for the life of the PDEV. Nothing tells the
game: it keeps running behind a frozen picture. The cure for the wedge is already in the kernel and
proven on silicon (`VcrHwResetEngine`, 0xa5f -> 0x5f twice). It is simply never called from the place
that detects the wedge.

The fix has four parts:

| part | what | gate |
|---|---|---|
| **A. Record** | every give-up becomes a flushed registry phase plus a box-lifetime counter, so it survives the ring wrap and a reboot | **default-on**, log-only, no register write |
| **B. Recover** | the give-up asks the miniport for the engine reset, under a pacing policy and never under a Glide client or SLI; the chip is re-armed only if it then reads idle with its PCI FIFO back to the init count | `Diag\D3DSafe` **bit 2**, default off |
| **C. Report** | while the engine stays lost, DrawPrimitives2/Clear2 and a flip/present of a 3D surface answer `DDERR_SURFACELOST`; ContextCreate retries once and refuses **once per loss**, then accepts and answers lost | `Diag\D3DSafe` **bit 2**, default off |
| **D. Test hooks** | a fault-injection escape that makes the HAL take exactly the give-up path, soft or with a real 2D stall | `Diag\D3DSafe` **bit 7**, test only |

**Evidence on silicon** (ONBOX, 2026-11-12, `.124`, `vcrdd.dll` 95678704):

- `ring_after_probe_windowed_decoded.txt` seq 25058: `ERR DD_2D 9, why 2, status 00000a1f, ops 0x13a`
  ("2D engine never went idle"). The windowed d3dprobe ran on for another 5.4 s (its context: 30
  DrawPrimitives2, 8 triangles, 6 clears, seq 25112). Every check from `tex` on read black, the
  clears included (`d3dprobe_render_windowed_desktop32.txt`), and no Clear or BeginScene failure was
  printed (d3dprobe prints those; it does not check Present's result).
- `ring_after_probe_ii_b_decoded.txt` seq 25127 and 25134: `GetDriverInfo 7de41f80 -> 88760028`
  (`DDERR_CURRENTLYNOTAVAIL`), and `d3dprobe_render_1024x768x32_after_reset.txt`:
  `GetDeviceCaps(HAL) 8876086a`, no mode switch.
- `ring_after_modeseq_decoded.txt` seq 25146: `engine reset (busy at mode set): idle again`
  (0xa5f -> 0x5f), after which the same probes were 40/40, 42/42, 40/40.

**One correction to the gap text.** The HAL disappeared through the **live** `GetDriverInfo` answer
(`vcrdd_d3d.c:2136`), not through `DrvGetDirectDrawInfo` (`:2058`): the ring shows no new
"DirectDraw HAL: heap" line (511 a=1) after the give-up. So the HAL comes back **as soon as `g2d_ok`
does**, with no new PDEV. Part B therefore also restores the HAL for new applications.

**Why this matters for Max Payne (G04, H4).** After a give-up every draw returns at once, so the
game loop spins. If the game also runs above normal priority (H2), normal-priority work crawls.
That combination matches every symptom of 2026-10-04: a frozen, pixel-identical picture; Num Lock
alive; the escape blocked for 25 s; `taskkill` slow at normal priority and instant at high priority
(`history.md` section 4.2; FIND 2026-10-04). This is inferred: no ring was kept. Part A makes the
next occurrence decidable without the ring.

## 3. Design

### 3.0 Switch and plumbing

- `Diag\D3DSafe` (DWORD, absent = 0) is read **once at boot** in `VcrFindAdapter`, beside
  `D3D32`/`Reset3D` (`KMD/miniport/vcrmp.c:238-239`): `x->d3dsafe = VcrDiagGet(L"D3DSafe", 0);`.
  G01 introduces the same read for bit 0; whichever item lands first adds it.
  - **bit 2 (0x4)** = parts B and C of this item.
  - **bit 7 (0x80)** = part D (the fault-injection escape). Test only; never left armed.
- **How the display DLL learns the bits.** Recommended: append `vcr_u32 d3dsafe;` to `vcr_info`
  (the struct only grows at the end, and `IOCTL_VCR_INFO` already answers `min(size)`,
  `vcrmp.c:789-799`). `VcrDd2dInit` takes it only when `info.size` covers the field, so an older
  miniport arms nothing. This removes the per-bit `VCR_INFO_F_*` allocation race in section 3.7.
  If the integrator keeps one flag per bit (G01's `VCR_INFO_F_FIFOGUARD 0x8000`), bit 2's flag is the
  next free bit; `test_vcr_kmd_abi.c` `every_vcr_info_flag_owns_one_bit` catches a collision.
- `VcrDd2dInit` sets `pd->eng_safe = (d3dsafe >> 2) & 1`, `pd->eng_fault_ok = (d3dsafe >> 7) & 1`,
  zeroes `pd->el` (the policy state, section 3.1), and logs 514 what 1 "armed". It leaves the
  existing FIFO-learn loop and the `g2d_ok` line (`vcrdd_2d.c:482-491`) byte-for-byte as they are.

### 3.1 Pure policy: `KMD/include/vcr_englost.h` (Win32-free, host-compiled)

```c
#define VCR_EL_RESETS_PER_WINDOW 3u        /* resets allowed in any 60 s on one PDEV */
#define VCR_EL_WINDOW_MS         60000u
#define VCR_EL_GAP_MS            2000u     /* at least this long between two resets */
#define VCR_EL_SETTLE_READS      20000u    /* ~12 ms of status reads after the reset */
#define VCR_EL_IDLE_READS        3u        /* = VCR_IDLE_READS (vcr_3dseq.h); pinned equal */

#define VCR_EL_DD_OK             0x00000000u
#define VCR_EL_SURFACELOST       0x887601c2u  /* DDERR_SURFACELOST = MAKE_DDHRESULT(450) */
#define VCR_EL_NOTAVAIL          0x88760028u  /* DDERR_CURRENTLYNOTAVAIL = MAKE_DDHRESULT(40) */

#define VCR_EL_WHY_ROOM   1u   /* the PCI FIFO never drained (VcrDdRoom, mono_room) */
#define VCR_EL_WHY_IDLE   2u   /* never went idle (VcrDd2dSync) */
#define VCR_EL_WHY_INJECT 3u   /* VCR_ESC_ENGINE_FAULT (Diag\D3DSafe bit 7) */
#define VCR_EL_WHY_RETRY  4u   /* a later attempt on a lost engine */

#define VCR_EL_R_RECORDED 0u   /* recorded only (no reset asked) */
#define VCR_EL_R_IDLE     1u   /* reset: idle again */
#define VCR_EL_R_BUSY     2u   /* reset: STILL BUSY */
#define VCR_EL_R_SLI      3u   /* refused: SLI/AA live */
#define VCR_EL_R_GLIDE    4u   /* refused: a live Glide client maps the board */
#define VCR_EL_R_NOENGINE 5u   /* refused: not a Voodoo backend */
#define VCR_EL_R_NOIOCTL  6u   /* display side: the miniport predates the IOCTL */

#define VCR_EL_ACT_RECORD 0u   /* switch off: record, stay given up - TODAY'S PATH */
#define VCR_EL_ACT_RESET  1u   /* ask the miniport for VcrHwResetEngine */
#define VCR_EL_ACT_LOSE   2u   /* no reset now: lost, answer DDERR_SURFACELOST */

typedef struct vcr_englost {
    vcr_u32 gaveups, resets, recovered, refused, answers, ctx_refusals;
    vcr_u32 lost;                          /* given up and not recovered */
    vcr_u32 win_start_ms, win_resets, last_reset_ms;
    vcr_u32 last_why, last_status, last_result;
    vcr_u32 block, inject, leaving;        /* test block; injection countdown; PDEV leaving the screen */
} vcr_englost;

static __inline unsigned vcr_el_decide(const vcr_englost *e, unsigned armed,
                                       unsigned exclusive_pid, unsigned now_ms)
{
    unsigned in_win;
    if (!armed)
        return VCR_EL_ACT_RECORD;
    if (e->block || e->leaving || exclusive_pid)
        return VCR_EL_ACT_LOSE;
    in_win = (now_ms - e->win_start_ms) < VCR_EL_WINDOW_MS ? e->win_resets : 0u;
    if (in_win >= VCR_EL_RESETS_PER_WINDOW)
        return VCR_EL_ACT_LOSE;
    if (e->resets && (now_ms - e->last_reset_ms) < VCR_EL_GAP_MS)
        return VCR_EL_ACT_LOSE;
    return VCR_EL_ACT_RESET;
}
static __inline void vcr_el_note_reset(vcr_englost *e, unsigned now_ms);   /* window + gap bookkeeping */

/* re-arm only an idle chip whose PCI FIFO is back at the count learnt at init */
static __inline int vcr_el_rearm_ok(unsigned result, unsigned idle_run,
                                    unsigned fifo_now, unsigned fifo_init)
{
    return result == VCR_EL_R_IDLE && idle_run >= VCR_EL_IDLE_READS &&
           fifo_init != 0 && fifo_now >= fifo_init;
}
/* DP2 / Clear2, after a walk that itself said DD_OK */
static __inline unsigned vcr_el_answer(unsigned armed, unsigned lost)
{ return armed && lost ? VCR_EL_SURFACELOST : VCR_EL_DD_OK; }
/* Flip / Blt: a 3D surface only - a DirectDraw-only game is never told lost */
static __inline unsigned vcr_el_present_answer(unsigned armed, unsigned lost, unsigned is_3d)
{ return armed && lost && is_3d ? VCR_EL_SURFACELOST : VCR_EL_DD_OK; }
/* ContextCreate on an engine still lost after its own retry: refused ONCE per loss */
static __inline unsigned vcr_el_ctx_answer(unsigned armed, unsigned g2d_ok, unsigned ctx_refusals)
{ return armed && !g2d_ok && ctx_refusals == 0 ? VCR_EL_NOTAVAIL : VCR_EL_DD_OK; }
```

Why these numbers. One reset per wedge is what the silicon has needed so far. The 2 s gap bounds
one DDI call to **at most two** `SPIN_CAP` spins (the first give-up, its reset, and one more give-up
that then finds the gap closed). The 60 s window lets a long session survive an occasional wedge
(a per-PDEV-lifetime cap would make the fourth wedge of an evening fatal) while stopping a
wedge-every-frame loop after three resets. All three are chosen, not measured (open question 4).

### 3.2 Miniport

1. **`IOCTL_VCR_ENGINE_LOST`** = `VCR_CTL(0xa11)` (`include/vcr_ioctl.h`; G01 takes 0xa10). Structs:

   ```c
   typedef struct vcr_englost_req { vcr_u32 size, why, where, status, ops, flags, excl_pid; } vcr_englost_req;
   #define VCR_EL_REQ_RESET 0x1u          /* only ever set by a display driver with bit 2 */
   typedef struct vcr_englost_res { vcr_u32 size, result, status_before, status_after, owner_pid, total; } vcr_englost_res;
   ```

   Handler in `vcrmp.c`, at PASSIVE_LEVEL in StartIO like every IOCTL:
   - `status_before` = chip 0 status (Voodoo backend only).
   - If `flags & VCR_EL_REQ_RESET`:
     - not `VCR_HW_VOODOO` -> `R_NOENGINE`;
     - `x->sli_chips != 0` -> `R_SLI`;
     - `VcrGlideLiveOwners(x, &pid) != 0` -> `R_GLIDE` (G01's liveness helper:
       `PsLookupProcessByProcessId`, same EPROCESS, same create time,
       `PsGetProcessExitStatus == STATUS_PENDING`, `ObfDereferenceObject`; all four are in
       `KMD/tools/xp_exports/ntoskrnl.exe.txt`; whichever of G01/G02 lands first adds it, in
       `vcrmp_map.c` beside `proc_find`, `:19-47`);
     - else `VcrHwResetEngine(x, 0, "display give-up")` (`vcrmp_hw.c:181-201`, **unchanged**) ->
       `R_IDLE` or `R_BUSY`.
   - **Always** (switch or not): `x->eng_lost_total++` (initialised at boot from
     `Diag\EngineLostCount`; a `why = RETRY` request is phased but not counted as a new loss),
     `VcrDiagSet(L"EngineLostCount", total, FALSE)`,
     `VcrDiagSet(L"EngineLostLast", (boot << 16) | (why << 8) | result, FALSE)`, one ring entry
     `VCR_EV_ENGINE_LOST` (WARN; ERROR when not recovered), then
     `VcrPhase(VCR_EV_ENGINE_LOST, why << 24 | result << 16 | (total & 0xffff), status, "engine lost")`.
     `VcrPhase` flushes the Diag key (`vcrmp_log.c:141-158`), which covers the two values. The phase
     lands in `PhaseLog` (64 slots), and the boot after a hang copies it to `PrevPhaseLog`.
   - **The registers the reset writes** are exactly the proven sequence: `cmdFifo0.baseSize`
     (CMDAGP + 0x24) = 0; `miscInit1 |= SST_CMDSTREAM_RESET` (bit 19); `miscInit0 |= GRX_RESET |
     FBI_FIFO_RESET | 2D_RESET` (bits 0, 1, 5); 10 us; both restored; then up to 20,000 status reads
     for idle (`vcrmp_hw.c:190-196`). This is the engine half of GPL Glide's `h3InitResetAll`
     (`GL5/cinit/h3cinit.c:1308-1340`); video, memory timing and VGA timing are not reset, so the
     desktop keeps scanning and a latched flip survives.
2. **Event `VCR_EV_ENGINE_LOST` = 804** (8xx "safety"; appended, nothing renumbered):
   "a=why<<24|result<<16|count b=status at give-up c=g2d ops d=status after".
   `tools/vcrlog.py` and `vcrphases.py` decode it from the table.
3. `fill_info` appends `eng_lost_total`, `eng_lost_last` and `d3dsafe` to `vcr_info`.
4. `VCR_ESC_RESET_ENGINE` / `IOCTL_VCR_RESET_ENGINE` (`vcrdd_escape.c:323-324`, `vcrmp.c:865-867`)
   are unchanged.

### 3.3 Display DLL

**`give_up()`** (`vcrdd_2d.c:83-89`) keeps its ERROR line and `pd->g2d_ok = 0;` (both pinned by
`tests/python/test_vcr_kmd_2d.py:62-66, 162-166`) and gains one last statement:

```c
    VcrDdEngineLost(pd, why, status);   /* the record always; the reset with Diag\D3DSafe bit 2 */
```

**`void VcrDdEngineLost(VCR_PDEV *pd, ULONG why, ULONG status)`** (new, `vcrdd_2d.c`):

1. `pd->el.gaveups++`; `last_why/status` set. `act = vcr_el_decide(&pd->el, pd->eng_safe,
   pd->exclusive_pid, el_now_ms())`. `el_now_ms` uses `EngQueryPerformanceCounter/Frequency`, which
   the DLL already imports (`vcrdd_ddraw.c:221-226`).
2. One `IOCTL_VCR_ENGINE_LOST` with `flags = act == RESET ? VCR_EL_REQ_RESET : 0`. With bit 2 off the
   request is a record and nothing else. If the IOCTL fails (an older miniport), the result is
   `R_NOIOCTL`.
3. `act == RECORD` (bit 2 off): log 514 what 2 at DEBUG (so a ring decode says which arm handled the
   give-up) and return. **This is today's path plus the record and one log line.**
4. `act == LOSE`, or a reset that was refused: `el.lost = 1`, `el.refused++`, `g2d_busy = 0` (the
   second 1.2 s spin of today's path buys nothing on a dead engine), log 514 what 4 once per loss.
5. A reset was made (`R_IDLE` or `R_BUSY`): `vcr_el_note_reset()`, bump the **shared reset
   generation** `g_vcr_eng_resets` (G01 section 3.3), `pd->fog_valid = 0`, `g2d_busy = 0`. Then
   read only: the max of 64 FIFO-free reads (`VcrDd2dInit`'s loop, duplicated so the proven one stays
   as it is) and up to `VCR_EL_SETTLE_READS` reads of `vcr_idle_run` against the **init**
   `g2d_fifo_full`.
6. `vcr_el_rearm_ok(...)`: `g2d_ok = 1`, `el.lost = 0`, `el.recovered++`, `ctx_refusals = 0`, log
   514 what 3 (WARN, "engine reset after the give-up: idle again - acceleration back"). Otherwise
   `el.lost = 1`, log 514 what 4 (ERROR, "the reset did not bring it back - Direct3D answers
   DDERR_SURFACELOST until a mode set").

The call that gave up still returns FALSE, so its operation is dropped: a GDI op falls back to
software, a DirectDraw blit to the HEL (`vcrdd_ddraw.c:457-461`), a triangle is not drawn. The next
call finds the engine back.

**Mid-walk recovery: re-prepare and continue** (as G01 specifies). `prepare()` (`vcrdd_d3d.c:1322`)
compares `g_vcr_eng_resets` with the context's last seen value and sets `w->prepared = 0` when it
moved, so the next triangle re-sends target, state, TMU registers and (because `fog_valid = 0`) the
fog table. The triangles in flight at the wedge are lost (the reset discards up to 31 FIFO entries,
1-4 triangles); the rest of the batch draws. `clear_rects` re-sends the target itself
(`vcrdd_d3d.c:1416`). A second wedge inside the same call meets the 2 s gap, is lost, and the rest of
the walk drops fast because `VcrDdRoom` returns at once.

**Other entry points** (all only with `pd->eng_safe`; with it off every row is today's code):

| entry | change |
|---|---|
| `D3d_ContextCreate` (`vcrdd_d3d.c:1163`), before the slot search (after G01's stale-FIFO guard, if landed) | if `!pd->g2d_ok`: `VcrDdEngineRetry(pd, AT_CTX)` (one policy-gated attempt). Then `r = vcr_el_ctx_answer(1, pd->g2d_ok, pd->el.ctx_refusals)`. On `NOTAVAIL`: `ctx_refusals++`, log 514 what 6, `p->ddrval = DDERR_CURRENTLYNOTAVAIL` (the code `GetDriverInfo` already answers). On a second attempt within the same loss: accept, log 514 what 7. The context is then answered lost, never silent. |
| `D3d_DrawPrimitives2` (`:1821`) | at entry, if `el.lost`: `VcrDdEngineRetry(pd, AT_DP2)`. The walk runs as today (state tracking, `lpdwRStates`, TEXBLT's CPU copies). After it, `if (hr == DD_OK) hr = vcr_el_answer(1, el.lost)`. Log 514 what 5 once per context; `c->lost_answers++`. |
| `D3d_Clear2` (`:1873`) | same retry; `p->ddrval = vcr_el_answer(1, el.lost)` replaces the bare `DD_OK` at `:1901`. |
| `VcrDdD3dDriverInfo` (`:2129`) | if `el.lost`: `VcrDdEngineRetry(pd, AT_INFO)` before the `g2d_ok` gate, so a new application can bring the HAL back. The gate itself is unchanged. |
| `Dd_Flip` (`vcrdd_ddraw.c:315`), after the WASSTILLDRAWING test, before `VcrDd2dSync` | `vcr_el_present_answer(1, el.lost, lpSurfTarg has DDSCAPS_3DDEVICE)` -> `DDERR_SURFACELOST`, no flip. D3D8 chains carry it (ring: caps 0x1000601c fullscreen, 0x6040 windowed). |
| `Dd_Blt` (`:468`), at entry | a **source** with `DDSCAPS_3DDEVICE` (a windowed Present) -> `DDERR_SURFACELOST`. Fills and 2D blits are untouched. |
| `DrvAssertMode` (`vcrdd.c:570`) | FALSE: `el.leaving = 1` before its `VcrDd2dSync`, so a give-up there is recorded but never reset (the mode set that follows resets a busy chip itself, `vcrmp_hw.c:571-572`). | `HWCRLSEXCLUSIVE` (`vcrdd_escape.c:134-201`), after a good `RESTORE_MODE` | the same read-only re-arm. |

| `VcrDdGlideReset3d` (`:400-428`), text path (`vcrdd_punt.c:437, 464`) | classify by the generation, not by `g2d_ok`, so a recovered give-up is not reported as DONE or as a glyph fault. |

`VcrDdEngineRetry(pd, where)` is `VcrDdEngineLost` with `why = RETRY`, a fresh status read, and no
`gaveups++`. It runs only when `el.lost`, `pjRegs`, `!g2d_disabled` and the policy says RESET.

### 3.4 Fault injection (`Diag\D3DSafe` bit 7)

`VCR_ESC_ENGINE_FAULT` = `VCR_ESC_BASE + 13` (G01 takes +12). `supported()` (`vcrdd_escape.c:32-43`)
widens its range. Input `{size, mode, arg}`; output the `vcr_2d_stats` struct after the action. It
returns 0 unless `pd->eng_fault_ok`, `pd->pjRegs` and no `exclusive_pid`.

| mode | what it does |
|---|---|
| 0 LIFT | clears `el.block` and the reset window (test only) |
| 1 SOFT | `VcrDd2dSync` first (nothing of ours left in flight for the reset to discard), then `give_up(pd, VCR_EL_WHY_INJECT, status now)`: the HAL's give-up path with no hardware change |
| 2 HARD | a real stall: a mono host-to-screen blit (`VCR_TEXT_CMD`, transparent) of 64x1 on the desktop's row 0, which needs two dwords; one zero dword is written to the launch area, then `VcrDd2dSync` gives up for real (why 2, status busy). No pixel is written. |
| 3 BLOCK | `el.block = 1`, then SOFT: the lost path |
| 4 ARM_ROOM | `el.inject = arg`: the arg-th `VcrDdRoom` from now calls `give_up(pd, INJECT, status)` and returns FALSE. This puts the give-up **inside** the next DP2 walk. |

`VcrDdRoom` gains one test after its `g2d_ok` check: `if (pd->el.inject && !--pd->el.inject) {
give_up(...); return FALSE; }`. It is a load and a branch per call against 5-8 us of PIO, and the
field is never set without bit 7. HARD is the first host-to-screen blit on VSA-100 silicon
(`Accel2DText` is default off and has never run on `.124`), so it runs on the 86Box bed first and on
`.124` only attended.

### 3.5 Counters and tools

- `vcr_2d_stats` (VCR_ESC_2D_STATS) grows at the end (`VCR_2DS_SIZE_V2`): `eng_flags` (armed, fault,
  lost), `eng_gaveups`, `eng_resets`, `eng_recovered`, `eng_refused`, `eng_answers`,
  `eng_ctx_refusals`, `eng_last_why`, `eng_last_status`, `eng_last_result`, `eng_generation`.
- `vcr_info` gains `eng_lost_total`, `eng_lost_last`, `d3dsafe`. The PDEV counters die with a
  fullscreen game's PDEV; the box-lifetime ones do not.
- `d3dprobe caps` prints `"engine":{...}` from both. `d3dprobe_run.py` reads `Diag\EngineLostCount`
  by `REGREAD` before and after every run (no escape, so this is allowed even around a game) and
  prints `ENGINE GAVE UP n TIME(S) DURING THIS RUN` when it rose. G11's PhaseLog accounting
  (`designs/G11.md` 4.3) reads the same key.
- Sweeps (G79) add the same before/after `REGREAD` per title: a title whose count rose is not a
  rendering verdict.
- `vcrctl engine` (optional): prints both blocks.

### 3.6 The old path (bit 2 off)

Everything in section 2 stays as it is: DP2 and Clear2 answer `DD_OK` and draw nothing,
ContextCreate accepts a dead engine, flips continue, `GetDriverInfo` withholds the HAL, and recovery
waits for a new PDEV. The only difference is part A: one IOCTL per give-up (at most two per PDEV,
because `VcrDdRoom` stops spinning after the first) that writes a flushed phase and two DWORDs, and
one DEBUG log line (514 what 2). No register is written and no answer changes.

### 3.8 Considered and rejected

- **Return the loss code without trying a reset.** Every wedge on record (Glide killed mid-stream,
  stale command FIFO made busy) was cured by `VcrHwResetEngine`. Reporting alone turns a curable
  1.2 s hitch into a dead game.
- **Stop drawing for the rest of the walk after a recovery.** Safe, but it drops up to a whole frame
  for no reason once the re-send is complete; G01 already re-prepares.
- **Refuse ContextCreate every time while lost.** G11 measured that the D3D8 runtime sets the
  fullscreen mode before ContextCreate and reverts it on a refusal. A game that retries `Reset()` in a
  loop would then flap the 1998 CRT. Refusing once per loss tells the game and bounds the flaps.
- **Shorten `SPIN_CAP` now that recovery exists.** It is pinned and proven; the cost of a wedge is
  dominated by how rare it is, not by the 1.2 s.
- **Reset from a timer or work item.** It would run without the display lock, under live GDI
  register sequences (G01 3.4 says the same).
- **The vendor's model.** VH5 has no hang recovery: its command-FIFO wait was unbounded, and the
  vintage lane's 2M-spin break in `VH5/CFIFO.C:186-350` "recovers the CPU" by pretending there is
  room, writing into a stuck FIFO. Not to copy. VH5 answers `DDERR_SURFACELOST` only in Win9x code
  (`DDSURF.C:1733-1742`, `DDOVL32.C:230-250`, both `#ifndef WINNT`); on NT it left loss to dxg. A
  driver-originated `SURFACELOST` on XP is therefore unmeasured ground, which is why part C is
  measured before it is trusted.

## 4. Gating

- **Part A: default-on.** It is log-only on an error path. It writes no register and changes no
  answer, which is the Phase 0 category in `hal.md` section 10. It is pinned by tests (the request
  never carries `VCR_EL_REQ_RESET` without bit 2). It is what G04's experiment needs whichever way the
  switch is set.
- **Parts B and C: default off** behind `Diag\D3DSafe` bit 2, read at boot. They add an engine reset
  from a new call site, new kernel code (the liveness check) and new answers that games see. None of
  that has run on silicon.
- **Part D: bit 7, test runs only.** It is disarmed on the boot after the test.
- **Promotion.** After one supervised clean boot passes (section 7, boot B), recommend bit 2's
  **recovery** for default-on: it acts only after a give-up, where today's state is strictly worse
  (no acceleration and no HAL until a mode set). Part C's answers go default-on only after the
  fullscreen measurement shows how the runtime reacts (open questions 1 and 2), with a `MOVED_DIAG`
  entry in `tests/python/test_vcr_kmd_integration.py` and the evidence.
- Not a pure correctness fix that a d3dprobe test alone could justify landing default-on: it writes
  the engine reset registers mid-session.

## 5. d3dprobe tests (`KMD/tools/d3dprobe.c`)

New explicit tests, never in the default list (so the 40/40 and 42/42 gates do not change). Each is
**skipped**, not failed, when `VCR_ESC_ENGINE_FAULT` is refused (bit 7 off, or another driver). They
use `ExtEscape` on the probe's own window DC, between frames, from the probe's own thread. That is
not a tool running beside a game. Every frame uses colours that differ from the frame before, so a
stale back buffer can never pass. Tolerance is +/-8 per channel (+/-12 at 16 bpp).

1. **`lost_recover`** - a give-up between frames.
   - Frame A: clear `0000ff`, the `flat` quad green `00ff00`. Expect (128,128) `00ff00` and (8,8)
     `0000ff`.
   - Inject SOFT. The returned stats: `gaveups +1`, `resets +1`, `recovered +1`, `lost 0`,
     generation +1.
   - Frame B: clear `ff0000`, quad yellow `ffff00`. Expect (128,128) `ffff00` and (8,8) `ff0000`;
     Clear, BeginScene, DrawPrimitiveUP, EndScene and Present all `D3D_OK`.
   - **Old-buggy value** (bit 2 off, bit 7 on: the 86Box bed): frame B reads `00ff00`/`0000ff`
     (frame A, nothing drew, not even the clear) with every HRESULT `D3D_OK`. Reported as
     `"silent"`, FAIL.
2. **`lost_midframe`** - a give-up inside a DP2 walk.
   - Frame A: clear blue, 40 green 16x16 quads in an 8x5 grid, **one** `DrawPrimitiveUP(TRIANGLELIST,
     80)` (one DP2 walk). Expect all 40 centres green.
   - Inject ARM_ROOM with arg 60 (inside the first quarter of the next walk).
   - Frame B: clear red, the same quads yellow. Expect: every quad from index 20 on yellow (the walk
     continued with a complete re-send), at most 4 quads not fully yellow (the triangles the reset
     discarded), and every sample between the cells red (no garbage). Stats: `recovered +1`.
   - Frame C: clear blue, quads magenta. Expect all 40 magenta.
   - **Old-buggy value:** frame B's quads from the injection on stay red, and frame C shows frame B.
3. **`lost_report`** - the lost path and the way back.
   - Inject BLOCK. Stats: `lost 1`, `refused +1`.
   - Frame C: clear green, quad white. Time and record the HRESULT of Clear, DrawPrimitiveUP,
     EndScene and Present, then `TestCooperativeLevel`.
   - `Reset()` #1 with the same parameters: record it. Expect a failure (ContextCreate's retry is
     blocked, and this is the one refusal); stats `ctx_refusals 1`.
   - Inject LIFT; wait 2.5 s (the gap); `TestCooperativeLevel` up to 5 s; `Reset()` #2: expect
     `D3D_OK` (ContextCreate's retry resets and re-arms).
   - Frame D: clear cyan `00ffff`, quad magenta. Expect those colours.
   - **Pass:** every timed call returned in under 2 s; at least one of the frame-C calls or
     `TestCooperativeLevel` reported failure ("the application was told"); Reset #1 failed; Reset #2
     succeeded; frame D is right; `lost` is back to 0. The exact codes are recorded in the RESULT as
     `"runtime_mapping"`: that is open question 1's answer.
   - **Fullscreen only:** G11's PhaseLog accounting reports `mode_sets` and `quick_resyncs` between
     the probe's ring marks around Reset #1 and #2. That is open question 2's answer, and the input
     to the decision rule in section 10.
   - **Old-buggy value:** every call `D3D_OK`, `TestCooperativeLevel` `D3D_OK`, Reset #1 `D3D_OK`
     (ContextCreate accepts the dead engine), frame D not drawn.
4. **`lost_hard`** - a real wedge: as `lost_recover`, with HARD instead of SOFT. Expect
   `last_why 2`, `last_status` with the busy bit (bit 9) set, `last_result 1` (idle again), and frame
   B right. This is the only one that proves the reset clears a real stall. It runs on 86Box first,
   and on `.124` attended, as the first silicon host-to-screen blit.

`caps` gains the `"engine"` block (section 3.5). It also warns `FAULT INJECTION ARMED` when bit 7 is
set.

## 8. Risk to proven paths

- **The default 16 bpp path, and every path with bit 2 off.** No register traffic changes and no
  answer changes. Added: one generation compare per triangle in `prepare()` (shared with G01, about
  1 ns against 5-8 us of PIO per vertex), one injection compare per `VcrDdRoom` (the field is always 0
  without bit 7), and part A's IOCTL plus one flushed registry write (15-30 ms) per give-up, on the
  error path only. Boot A proves it.
- **Glide/OpenGL coexistence.** The reset is the only new hardware write. It is refused under the
  PDEV's `exclusive_pid`, under any live Glide mapping (the miniport's liveness check, which also
  covers a client between GETLINEARADDR and HWCSETEXCLUSIVE and an alt-tabbed game), and while SLI
  is live. The residual risk is a wrong verdict from the liveness check. A recycled pid is caught by
  the EPROCESS and create-time comparison; a terminated process still held by a handle reads as dead,
  which is right because it has no threads left to feed the FIFO (G01's open question 6 verifies this
  on the bed). A stale command FIFO **is** cured by the reset (`cmdFifo0.baseSize = 0` is its first
  write).
- **SLI state.** Refused while `x->sli_chips != 0`. The reset is chip 0's, the same call as the
  proven mode-set reset. Slaves are not touched.
- **The flip path.** The reset does not touch the video unit, so scan-out and a latched flip
  continue. A flip is refused only in the lost state, and only for a 3D surface. DirectDraw-only
  games (Red Alert 2, Tiberian Sun, StarCraft, Warcraft II) are never told lost; they keep their
  software fallbacks as today, and get the engine back sooner.
- **Work the engine had already accepted** is discarded by the reset: 1-4 triangles, or the tail of
  a 2D blit queued before the wedge. That is one damaged frame, or a partly blitted surface the game
  rewrites.
- **Latency and the watchdog.** Worst case per DDI call: two `SPIN_CAP` spins (about 2.4 s) plus one
  reset (10 us plus up to 20,000 status reads) plus one registry flush, all under the display lock.
  That is within today's bound plus about 50 ms, and far inside the ~30 s THREAD_STUCK limit noted in
  `VH5/CFIFO.C`. The policy allows at most 3 resets a minute.
- **The CRT.** New answers can make a fullscreen game call `Reset()`. A refused Reset may make the
  runtime revert and set the mode (G11). Refusing once per loss bounds this to one revert per loss
  regardless of the runtime, and boot B measures it attended. New applications cannot reach the
  refusal: the HAL is withheld up front, with no mode switch (measured, 10:11:03).
- **Bit 7 left armed.** Any process could inject a give-up. `caps` warns, the README row says
  "never deployed", and boot C disarms it.

## 10. Open questions

1. **How do XP's runtimes treat a driver-originated `DDERR_SURFACELOST`?** D3D8 for D3D8/9 titles,
   and `d3dim700` for the DX5-7 titles, from DrawPrimitives2/Clear2 versus Flip/Blt: device lost
   (Present `D3DERR_DEVICELOST`, TestCooperativeLevel `DEVICENOTRESET`), or an error at the call?
   The vendor never did this on NT. `lost_report`'s `runtime_mapping` answers it for D3D8. G75's
   DX7 probe would answer it for the DX5-7 titles.
2. **Does a fullscreen D3D8 `Reset()` whose ContextCreate is refused switch the mode** (set and
   revert, as a refused CreateDevice does)? **Decision rule:** if boot B shows a mode set around
   Reset #1, change the one refusal to "accept and report" before bit 2 leaves supervised runs.
3. **Does `VcrHwResetEngine` cure every wedge class?** Proven: a Glide client killed mid-stream
   (0xa5f) and a stale command FIFO made busy (0xa1f/0xa5f). Unknown: a 3D pipeline lockup caused by
   a HAL state combination. Impossible: a bus that reads 0xffffffff (the reset then reports STILL
   BUSY, and the engine stays lost, as designed).
4. **The policy constants** (3 resets per 60 s, a 2 s gap, 20,000 settle reads) are chosen, not
   measured.
5. **Is part A acceptable default-on** under the default-off convention? The alternative is to put it
   under bit 2 too, but then G04's no-recovery observation run needs the switch armed.
6. **How does the display learn the D3DSafe bits:** an appended `vcr_info.d3dsafe`/`d3dfeat`
   (recommended, no bit race) or one `VCR_INFO_F_*` bit each? Five sibling designs already collide on
   0x8000/0x10000, on 513/24-25 and on event 309. **G01's 512/10 collides with the existing text-punt
   line** (`vcrdd_punt.c:549`). These numbers need one central allocation at integration.
7. **Is a first silicon host-to-screen blit (`lost_hard`) acceptable on `.124`**, or does the
   real-wedge proof stay with the 86Box bed plus the two silicon recoveries already on record (and
   the optional G01 E1 run)?
8. **Does the GRX reset clear `combineMode`, `aaCtrl` or the fog RAM?** The HAL re-sends what it owns;
   G03's baseline covers the rest. This only decides whether part B can rely on power-on defaults
   (see also G01's E3).
9. **After a reset on the 6000**, confirm that chips 1-3 are untouched: a `vcrctl reg` dump of the
   slaves before and after `lost_recover` on boot B, outside any game.
