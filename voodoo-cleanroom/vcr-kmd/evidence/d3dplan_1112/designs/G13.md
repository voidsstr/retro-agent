## 1. Verdict

1. **The gap is real.** `ARG_KIND(a) = a & D3DTA_SELECTMASK` (`KMD/display/vcrdd_d3d.c:671`) strips bit 4 (COMPLEMENT) and
   bit 5 (ALPHAREPLICATE) from every argument, in `color_path` (`:678-681`) and `stage1_combine` (`:852-853`).
   - A complemented argument is drawn as `x`, not `1 - x`.
   - An alpha-replicated **colour** argument is drawn with its RGB, not its alpha.
   - ALPHAREPLICATE on an **alpha** argument is a no-op in D3D, so dropping it there is already correct. The fix
     must keep it that way.
2. **It is fixable, single-pass, on the VSA-100**, but only cleanly in the **extended combine** (`combineMode`),
   which is G12's work.
   - COMPLEMENT is an XOR on one invert field, or a toggle of the multiplier's REVERSE_BLEND bit.
   - ALPHAREPLICATE adds a constant to one select field (each RGB source is followed by its alpha), or swaps
     `MRGBTMU` for `MATMU`.
   - 3dfx's own HAL did exactly this (`VH5/D6MT.C:4535-4639`, `:5032-5160`, `:5192-5320`).
   - The legacy combine our HAL uses today (`combineMode` = 0) can express only a handful of cases. Section 4.4 lists
     them as a conditional Plan B.
3. **No staged title has yet been measured using a modifier.**
   - UT2003's 26 logged set-ups (`KMD/evidence/d3dtune_1014/sweep_1108/UT2003_combos_unaligned.txt`) have no modifier
     bit on any stage-0 argument. Stage 1's arguments are not logged at all (`log_combo`, `vcrdd_d3d.c:909-913`).
   - Halo's and UT2004's set-up logs did not survive: the ring wrapped (`onbox.md` section 6).
   - So step 0 below **measures first**. It is log-only.
4. **The Halo glow square (onbox-07, G17) is one of at least four explanations, and G13 is not the likeliest.**
   - The frame (`ONBOX/games/Halo_timedemo/Halo_timedemo_060s.png`) shows a **uniform** translucent teal square: the
     sprite's shape is gone from both colour and alpha.
   - The other explanations:
     - G12: stage 1 is dropped when stage 0 has no texture;
     - G34: Halo names `a8`/`y8`/`ay8` bitmaps we do not offer, and Halo is known to draw "white" for a format it
       lacks (`games.md` section 4.2);
     - G14: TFACTOR next to a texture.
   - Plausibility for G13: `halo.exe` embeds the D3DX effect token table with `ALPHAREPLICATE` and `COMPLEMENT`, and
     its effects are an encrypted `SHADERS/fx.bin`, so it **can** use the modifiers. Whether it does is unknown.
   - Step 0's log settles this (section 4.1).
5. **Gating:** a new positive bit in G12's `Diag\D3DFeat`, called `argmod` here and default **off**. It is honoured
   only while G12's extended combine is armed.
   - With it off, or with the extended combine off, the proven path is byte-for-byte unchanged.
   - It is **not** safe to land default-on by itself, because it rides on G12's new register traffic.
   - It follows G12 to default-on once its d3dprobe cells pass on silicon.
6. **Priority P2, effort M on top of G12.** Promote to **P1** if step 0 finds a modifier in a common scene of a
   staged title. Step 0 (log only) and the d3dprobe tests can land now.

## 2. The defect, precisely

| D3D set-up (stage 0, one stage) | correct | what our HAL draws today | code |
|---|---|---|---|
| `SELECTARG1(TEXTURE\|COMPLEMENT)` | 1 - tex | tex | `color_path :692-696` with `a1` masked |
| `SELECTARG1(TEXTURE\|ALPHAREPLICATE)` | (a_tex, a_tex, a_tex) | tex RGB | same |
| `MODULATE(TEXTURE\|ALPHAREPLICATE, DIFFUSE)` | a_tex x diffuse | tex x diffuse | `:714-716` |
| `MODULATE(TEXTURE, DIFFUSE\|COMPLEMENT)` | tex x (1 - diffuse) | tex x diffuse | `:714-716` |
| alpha `SELECTARG1(TEXTURE\|COMPLEMENT)` | 1 - a_tex | a_tex | `:727-731` |
| alpha `...(TEXTURE\|ALPHAREPLICATE)` | a_tex | a_tex | correct by accident, must stay so |
| stage 1 `MODULATE(TEXTURE\|ALPHAREPLICATE, CURRENT)` | a_tex1 x current | tex1 x tex0 (`TM_TC_MULT`), then stage 0's op | `stage1_combine :849-874` |

Related facts:

- `ValidateTextureStageState` answers "1 pass, `DD_OK`" to everything (`vcrdd_d3d.c:1905-1910`). A game that validates
  never learns that a modifier is ignored.
  - D3DX-effect titles such as Halo pick a technique by `ValidateDevice` (inferred from the D3DX effect framework).
  - UE2's `D3DDrv.dll` carries `D3DERR_UNSUPPORTEDALPHAARG` strings, but those belong to the D3DX error table, so this
    proves nothing.
- **Silicon evidence that the gap bites:** the first version of `d3dprobe dxt*_decode` read the alpha back through
  ALPHAREPLICATE, and on `.124` "the alpha pass fails only because the HAL ignores D3DTA_ALPHAREPLICATE"
  (`docs/v56k-benchmark-plan.md:124-128`; `retro-3dfx/FINDINGS.md:43-44`). It was rewritten to go through the blender
  (`KMD/tools/d3dprobe.c:735-737`, commit `76d36e7`).
- D3D has **no capability bit** for either modifier, in DX6 through DX9. Applications just use them, and the only
  contract is validation.

## 3. What the hardware does

### 3.1 The datapath (one combine unit; the same shape in the FBI and in each TMU)

SPEC, combineMode register and the colour-combine datapath figure (hw.md Q2):

    out = invert_output( clamp_0..255( ((A' + B') x C' + D') << outshift ) )
    A' = zero_other ? 0 : invert_other(other)    invert_other [10:9]: 0 = x, 1 = 0-x, 2 = 1-x, 3 = x-1/2
    B' = sub_clocal ? invert_local(local) : 0    invert_local [12:11]: 0 = 0-x, 1 = x, 2 = 1-x, 3 = x-1/2
    C' = reverse_blend ? m : 1-m                 m from mselect (fbzColorPath / textureMode) or mselect_7 (combineMode)
    D' = add_clocal: local, add_alocal: a_local; invert_add_local [13] makes it 1-D'
    (alpha unit: the same with otherselect [17:16], localselect [20:18], invert_other [22:21],
     invert_local [24:23], invert_add_local [25], outshift [27:26])

- The FBI takes `other`/`local`/`mselect_7` from `combineMode` only when bit 31 is set. Otherwise it takes them from
  `fbzColorPath` (SPEC: "Color Combine Mode MUX selection control (0=use fbzColorPath, 1=use combineMode)").
- **In a TMU, the other, local and mselect_7 controls "always come from the combineMode register"** (SPEC, same
  page). A TMU `combineMode` of 0 is the legacy TMU combine: other = upstream TMU, local = own texture, local entering
  as `0-x`.
- Bit 30 must be set when the new combine is used (SPEC, §21.8 programming note; hw.md Q2). Bit 29 (2 pixels per
  clock) stays clear throughout this design.

### 3.2 COMPLEMENT: which field, and when it is exact

The complement of an argument is applied **wherever that argument enters the unit**:

| the argument enters as | field | operation | exact when |
|---|---|---|---|
| OTHER (A) | `invert_other` | XOR 2 (x <-> 1-x) | the table's base is x (0) or 1-x (2). Base 0-x or x-1/2 has no complement encoding: refuse |
| LOCAL in the subtract position (B, `sub_clocal`) | `invert_local` | XOR 3 (x(1) <-> 1-x(2)) | base x (1) or 1-x (2). Base 0-x (0): the complement would be x-1. Base x-1/2: it would be 1/2-x. Neither exists: refuse |
| LOCAL in the add position (D, `add_clocal`) | `invert_add_local` | XOR 1 | always |
| the multiplier (C) | `reverse_blend`: `fbzColorPath` bit 13 (RGB) / bit 22 (A) in the FBI, `textureMode` bit 17 / bit 26 in a TMU | toggle (m <-> 1-m) | always |

This is 3dfx's rule. The table entries carry XOR masks `COMP_OTH` = `INVERT_OTHER_ONE_MINUS_X`,
`COMP_LOC_SUB` = `INVERT_LOCAL_X_MINUS_HALF` used as an XOR of 3, `COMP_LOC_ADD` = `INVERT_ADD_LOCAL` and
`COMP_MSEL` = `REVERSE_BLEND` (`VH5/D6MT.C:504-516`, `:600`). They are applied by XOR at
`:4535-4543`/`:4575-4583` and refused by validation at `:3527-3537`, `:3621-3631`, `:3660-3670`, `:3767-3777`.

The rule derives exactly the refusal set 3dfx documented. SWARCH: "Complement for arg2 is not supported for:
ADD_SIGNED, ADD_SIGNED2X, SUBTRACT, BLENDTEXTUREALPHA, BLENDFACTORALPHA, BLENDCURRENTALPHA". BLENDDIFFUSEALPHA is
refused by the shipped table as well (no `ARG2_COMP` in its flags, `D6MT.C:664`). In all of these arg2 enters LOCAL as
`0-x` or `x-1/2`. The host test pins this equality (section 7).

### 3.3 ALPHAREPLICATE: each select lists an RGB source, then its alpha

| unit / input | RGB source -> alpha twin | arithmetic |
|---|---|---|
| FBI `cc_otherselect` [2:0] | IRGB 0 -> IA 4, TRGB 1 -> TA 5, C1_RGB 2 -> C1_A 6 | +4 |
| FBI `cc_localselect` [5:3] | IRGB 0 -> IA 3, C0_RGB 1 -> C0_A 4, TRGB 2 -> TA 5 | +3 |
| FBI `cc_mselect_7` [7:6] | IRGB 0 -> IA 2, C1_RGB 1 -> C1_A 3 | +2 |
| FBI `fbzColorPath` cc_mselect [12:10] | MRGBTMU 5 -> MATMU 4 | substitute |
| TMU `tc_otherselect` [2:0] | OTHER_TRGB 0->1, LOCAL_TRGB 2->3, IRGB 4->5, CR_RGB 6->7 | +1 |
| TMU `tc_localselect` [5:3] | LOCAL_TRGB 0->1, OTHER_TRGB 2->3, IRGB 4->5, CK_RGB 6->7 | +1 |
| TMU `tc_mselect_7` [8:6] | IRGB 4->5, CR_RGB 6->7. **LOCAL_TRGB 0 and OTHER_TRGB 2 have no twin** (1 = ZERO, 3 = ZERO3) | +1 or none |

`H3DEFS:385-530`, `:310-334`, `:801-830`; 3dfx: "The nature of the register allows us to add to the field to select
alpha arg instead of color arg" (`VH5/D6MT.C:4596-4639`, TMU forms `:5092-5160`, `:5252-5320`).

**The TMU M7 texture case** ("MuxM is not supported for arep for tmu", `D6MT.C:540`). 3dfx falls back to
`textureMode` `tc_mselect` = MALOCAL or MAOTHER (`D6MT.C:5104-5125`). Its own comment says that this yields "the alpha
selected by this stage's ACU Local Mux ... seems wrong". Glide's API presents the same encodings as *the local/other
texture's* alpha (`G5/gtex.c` `grTexColorCombineExt`, c = `GR_CMBX_LOCAL_TEXTURE_ALPHA` -> `SST_TC_MALOCAL`). The
semantics are therefore unsettled. This design avoids depending on them (section 4.2.4).

### 3.4 These fields already run on this silicon

Our MesaFX ICD programs the same fields through Glide's extended combine on every textured draw on a Napalm. The
fields are: invert modes `GR_FUNC_MODE_ONE_MINUS_X`, the `*_ALPHA` selects for `GL_SRC_ALPHA` operands, and the
`c_invert` -> `REVERSE_BLEND` path (`build/retro3dfx-gl/src/mesa/drivers/glide/fxsetup.h:40-160`, "Napalm Single
texturing: setup standard grColorCombineExt/grAlphaCombineExt"; `G5/gglide.c` `_grCCExtcombineMode`;
`G5/gtex.c:1499-1880`).

So the register semantics are exercised on `.124` by the OpenGL lane, which lowers the hardware risk. Which GL titles
reach the `1-x` forms was not checked.

The question is whether any staged title sets a modifier, in which set-up, and whether that set-up is Halo's glow.

### 4.2 Step 1: the modifier pass inside G12's extended-combine compiler

G12 builds a Win32-free compiler, called `include/vcr_xcomb.h` here. It maps both stages' TSS to:

- `combineMode` for the FBI (chip field `0x400`, offset `0x608`), TMU0 (`0xA08`) and TMU1 (`0x1208`);
- `fbzColorPath`;
- both `textureMode`s.

G13 adds one pass to that compiler, plus the validation rules it implies.

#### 4.2.1 The routing contract with G12

For each combine unit (FBI-RGB, FBI-A, TMUn-RGB, TMUn-A) and each D3D argument, G12's compiler records where the
argument entered. It records **every** position, as a bitmask, because some ops use one argument twice. For example,
ADDSMOOTH uses LOCAL in both B and D, and MODULATEALPHA_ADDCOLOR uses arg1's RGB and its alpha.

```c
#define XC_IN_OTHER      0x01   /* A: *_otherselect */
#define XC_IN_LOCAL_SUB  0x02   /* B: *_localselect through invert_local (sub_clocal set) */
#define XC_IN_LOCAL_ADD  0x04   /* D: *_localselect through add_clocal / invert_add_local */
#define XC_IN_M7         0x08   /* C: combineMode *_mselect_7 (mselect = CMSELECT7) */
#define XC_IN_M          0x10   /* C: fbzColorPath / textureMode mselect itself (MRGBTMU, MATMU, MALOCAL, ...) */
typedef struct vcr_xc_unit {
    unsigned kind;          /* XC_FBI_RGB, XC_FBI_A, XC_TMU_RGB, XC_TMU_A */
    unsigned *cm;           /* the unit's combineMode word (its RGB or alpha half is used) */
    unsigned *path;         /* fbzColorPath (FBI) or textureMode (TMU) */
    unsigned in[2];         /* XC_IN_* of arg1, arg2 */
    unsigned commutative;   /* MODULATE/2X/4X, ADD: arg1 and arg2 may swap muxes */
} vcr_xc_unit;
```

Contract: G12 compiles with the **selector bits only** (`& D3DTA_SELECTMASK`, as today). G13's pass then reads bits 4
and 5 of the raw TSS value and edits the compiled words. With the pass disabled, or with no modifier bits present, the
output is G12's output, word for word (section 7, invariant e).

#### 4.2.2 COMPLEMENT (`vcr_xc_complement(u, k)`, returns 0 or a refusal)

For each position bit of argument k:

- `XC_IN_OTHER`: base = `invert_other` field. If base is 0 or 2, `cm ^= 2 << 9` (RGB) or `2 << 21` (A). Else refuse.
- `XC_IN_LOCAL_SUB`: base = `invert_local`. If base is 1 or 2, `cm ^= 3 << 11` or `3 << 23`. Else refuse.
- `XC_IN_LOCAL_ADD`: `cm ^= 1 << 13` (RGB) or `1 << 25` (A).
- `XC_IN_M7` / `XC_IN_M`: toggle REVERSE_BLEND. In the FBI that is `fbzColorPath` bit 13 (RGB) or bit 22 (A). In a
  TMU it is `textureMode` bit 17 or bit 26.
- If any position refuses, nothing is changed. The refusal goes to validation (4.3) and to the draw rule (4.2.5).

Alpha arguments use the same rule on the alpha unit.

#### 4.2.3 ALPHAREPLICATE on a colour argument (`vcr_xc_arep(u, k)`)

- Only the RGB units are affected. On an alpha argument the bit is ignored (correct).
- `XC_IN_OTHER`: FBI `+4`, TMU `+1` on `*_otherselect`. LOCAL: FBI `+3`, TMU `+1` on `*_localselect`. One mux edit
  covers both B and D.
- `XC_IN_M7`: FBI `+2`. TMU `+1` only from IRGB or CR_RGB; a texture source goes to 4.2.4.
- `XC_IN_M` in the FBI: `MRGBTMU` -> `MATMU` (`fbzColorPath` [12:10] 5 -> 4).
- Every edit is checked against the twin table in 3.3. A select already on an alpha, ZERO or LFB is never "+N"-ed;
  that case refuses.

#### 4.2.4 The TMU M7 texture case, without relying on MALOCAL/MAOTHER semantics

1. **Commutative op** (MODULATE, MODULATE2X, MODULATE4X, and their alpha forms): swap the two arguments' muxes so that
   the alpha-replicated texture argument sits on OTHER, which has a twin, and the other argument sits on M7. The
   other argument is a texture, IRGB or CR, all M7-selectable. Example: stage 1
   `MODULATE(TEXTURE, CURRENT|ALPHAREPLICATE)` becomes `tc_otherselect` = OTHER_TA (1), `tc_mselect_7` = LOCAL_TRGB
   (0).
2. **Both arguments alpha-replicated textures, or a non-commutative op:** use `textureMode` `tc_mselect` = MALOCAL (3)
   or MAOTHER (2). This applies **only if** the same TMU's alpha unit already selects that same texture's alpha on the
   matching mux:
   - `tca_localselect` = LOCAL_TA for MALOCAL;
   - `tca_otherselect` = OTHER_TA for MAOTHER.

   Then both readings of the semantics (3.3) give the same value.
3. **Otherwise** refuse.

Other cases to refuse:

- `CURRENT|ALPHAREPLICATE` in stage 1 while stage 0's ALPHAOP is DISABLE. 3dfx did not handle it either
  (`D6MT.C:4364`), and D3D calls that state undefined.
- Any DIFFUSE-in-a-TMU or TFACTOR-in-a-TMU modifier before G58 (packed `sARGB`, so the TMU sees iterated colour) and
  G14 (TFACTOR in TMU `chromaRange`/`chromaKey`) exist. G12 refuses those arguments in TMUs anyway until then.

#### 4.2.5 What is drawn for a refused set-up

- The modifier is **masked**, which is exactly today's result.
- One WARN per context and set-up records it (`what 27`, "modifier not representable: stage s arg k").
- No draw is skipped: an application that ignores validation sees no regression.

### 4.3 Validation (G15 owns the plumbing; G13 owns the modifier rules)

With the extended combine and `argmod` on, `D3d_ValidateTextureStageState` looks up `p->dwhContext`. It runs the same
compile on the context's current TSS: one code path for drawing and validating, so they cannot disagree.

- A complement or alpha replicate the pass refuses gives `D3DERR_UNSUPPORTEDCOLORARG` (a colour argument) or
  `D3DERR_UNSUPPORTEDALPHAARG` (an alpha argument), with `dwNumPasses` 0.
- 3dfx returned `...COLORARG` for alpha arguments too (`D6MT.C:3663-3665`). That is a vendor slip not to copy (G95).
- Otherwise the answer is G12/G15's: today "1 pass, OK".
- With `argmod` off and G15 landed, every modifier on an argument that is read is refused. A validating title (a
  D3DX-effect title) then picks another technique.

**That last point may fix Halo's glow without any G13 code**, if Halo validates. Run that check first (section 8,
step 2).

### 4.4 Plan B (conditional; only if step 0 shows a staged title needs it and G12 is far off)

The legacy single-stage FBI combine can express these cases **exactly**. The formula is
`((zo ? 0 : other) - (sub ? local : 0)) x f + add`, with local = iterated diffuse, `f = REVERSE ? m : 1-m`:

| set-up | `fbzColorPath` CC bits |
|---|---|
| `SELECTARG1(x\|COMPLEMENT)` | sel(x), `M(ONE)`, `CP_CC_INVERT` |
| `MODULATE(TEXTURE\|ALPHAREPLICATE, DIFFUSE)` | `RGBSEL_ITER`, `M(ATMU)`, `REVERSE` |
| `MODULATE(TEXTURE\|ALPHAREPLICATE\|COMPLEMENT, DIFFUSE)` | `RGBSEL_ITER`, `M(ATMU)`, no `REVERSE` |
| `MODULATE(TEXTURE, DIFFUSE\|ALPHAREPLICATE)` | `RGBSEL_TMU`, `M(ALOCAL)`, `REVERSE` (alocal = iterated) |
| `MODULATE(TEXTURE, DIFFUSE\|COMPLEMENT)` | `RGBSEL_TMU`, `M(CLOCAL)`, no `REVERSE` |
| `MODULATE(TEXTURE\|COMPLEMENT, DIFFUSE)` | `ZERO_OTHER\|SUB_CLOCAL\|M(RGBTMU)\|REVERSE\|ADD_CLOCAL` = diffuse - diffuse x tex |
| `SELECTARG1(DIFFUSE\|ALPHAREPLICATE)` | `ZERO_OTHER`, `M(ONE)\|REVERSE`, `ADD_ALOCAL` |
| `SELECTARG1(TEXTURE\|ALPHAREPLICATE)` | `ZERO_OTHER\|SUB_CLOCAL\|M(ATMU)\|ADD_CLOCAL\|CP_LOCAL_C0`, with `c0` = `0xffffffff` (`c0` is otherwise unused, `vcrdd_d3d.c:1019`) |
| alpha `SELECTARG1(x\|COMPLEMENT)` | `CP_CCA_INVERT` |
| alpha `MODULATE(TEXTURE, DIFFUSE\|COMPLEMENT)` | `CCA M(CLOCAL)`, no `CCA REVERSE` |

- The same `argmod` bit gates it.
- Every set-up without a modifier is unchanged (the same host invariance test).
- Everything else stays masked.
- It is a fallback, not the plan: it duplicates G12 and is stage 0 only.
- A related open question: whether the FBI honours `combineMode`'s invert and outshift fields while bit 31 is 0
  (inferred possible, since `fbzColorPath` has no such fields). That would make legacy COMPLEMENT simpler. **Do not
  rely on it** without a probe cell.

## 5. Gating

- `Diag\D3DFeat` gets a new bit, `argmod`, as a positive flag (absent = off). Provisionally it is bit 7 (`0x80`),
  right after G12's extended-combine bit 6 in hal.md's Phase 3 numbering; G12 and the D3DFeat owner fix the final
  number.
- It is honoured only when the extended combine is armed (`pd->xc_on`) and on a VSA-100.
- **It is not safe to land default-on by itself:** its effect exists only on G12's new register path.
- It is proven in one supervised clean boot in which `argmod` is the only Diag change. The extended combine must
  already have been proven in an earlier boot.
- It flips default-on together with, or right after, G12's bit, when all of these hold:
  - d3dprobe `areplicate`, `complement`, `areplicate2` and `complement2` pass 100%, fullscreen 16 bpp and 32 bpp and
    windowed, with `--expect-argmod`;
  - the default render matrix and `tex2mod`/`tex2add` are unchanged;
  - the Halo and UE2 frames show no regression.
- **Safe default-on now:** step 0's log lines, and the d3dprobe tests themselves (they change no register).

## 6. d3dprobe tests

All four are explicit (`--tests ...`) and never in the default list, because they fail on today's HAL by design. Each
cell does the following:

1. Set the stage state, then call `IDirect3DDevice8_ValidateDevice`. Record `hr` and passes in the RESULT JSON.
2. Draw the textured quad `Q0..Q1` with point sampling (MIN/MAG POINT, MIPFILTER NONE).
3. Read back two texels' screen centres, `tpx(4,64)` and `tpx(12,64)`, through the existing `readback`/`expect`
   (256x256 window).

Verdicts:

- `ok`: within ±12 per channel, as the `tex` tests use.
- **`MASKED`**: within ±12 of the old-buggy value (the modifier ignored). The log then says "modifier ignored", not just
  FAIL.
- `wrong`: neither.

Validation handling: with `--expect-argmod`, a must-accept cell that fails validation is a FAIL, and a must-refuse
cell that passes validation is a FAIL. Without the flag, a refused cell is SKIPPED: a driver that honestly refuses is
within the contract.

**Textures.** A8R8G8B8 when `CheckDeviceFormat` offers it (`.124`: D3DBigTex bit 2), else A4R4G4B4, which is always
offered.

- A 64x64 checker of 8-texel cells: **P = `0xCCFF3300`**, **Q = `0x440099FF`**. The 4444 encodings are `0xCF30` and
  `0x409F`; they expand to the same values if the TMU replicates nibbles.
- Before the modifier cells, one **calibration** frame reads back P and Q unmodified: RGB by `SELECTARG1(TEXTURE)`, and
  alpha through the blender (SRCALPHA, ZERO) as the decode tests do.
- Every expected value is recomputed from the calibrated texels with D3D's formula (8 bit, x·y/255,
  complement = 255 - x). This keeps a 4-bit expansion quirk from reading as a modifier fault.
- Inputs: diffuse D = `0x80FF8040`; TEXTUREFACTOR F = `0x60FF0000`.
- Stage-0 texture for the two-stage cells: an A8R8G8B8 or A4R4G4B4 checker of R0 = `0x88FF0000` and
  B0 = `0x880000FF`.

## 7. Host regression tests

**`tests/native/test_vcr_kmd_xcomb_argmod.c`** (new). It compiles `include/vcr_xcomb.h` Win32-free and includes a
bit-level **model of one combine unit**: the formula in 3.1, 8-bit inputs, factor `(rev ? m : 255-m) + 1`, `>> 8`
truncation, outshift, clamp, invert_output. This model is shared with G12/G77; whoever lands first owns it. The
assertions:

a. **Each d3dprobe cell above, fixed and old-buggy.**
   - Compile with `VCR_XC_ARGMOD`, evaluate on P/Q/D/F, and assert the "want" column (±2).
   - Compile with the modifier bits stripped (the old masking) and assert the "old-buggy" column.
   - Pin the register words too. Examples:
     - A1: FBI `cc_otherselect` = TA (5), old TRGB (1).
     - C3: `fbzColorPath` bit 13 clear, old set.
     - C4: `invert_local` = 2, old 1.
     - A7: TMU0 `tc_otherselect` = LOCAL_TA (3), old LOCAL_TRGB (2).
     - A8: TMU0 `tc_otherselect` = OTHER_TA (1) and `tc_mselect_7` = LOCAL_TRGB (0), old LOCAL_TRGB / OTHER_TRGB.
b. **Exhaustive sweep.** Cover every op G12 compiles x arg kinds {DIFFUSE, CURRENT, TEXTURE, TFACTOR} x modifiers
   {none, COMP, AREP, COMP|AREP} on arg1/arg2/both x {one stage FBI, stage 0 TMU1, stage 1 TMU0}. Each case either
   refuses with a documented code, or evaluates to D3D's reference within ±2 on 8 input vectors. Pin the refusal
   count, so a change that refuses more cases shows.
c. **The refusal set equals SWARCH's list** (arg2 COMP of ADDSIGNED, ADDSIGNED2X, SUBTRACT, BLENDTEXTUREALPHA,
   BLENDFACTORALPHA, BLENDCURRENTALPHA) plus BLENDDIFFUSEALPHA, for colour and alpha ops, and nothing else for FBI
   COMPLEMENT.
d. **Field arithmetic.**
   - +4/+3/+2 (FBI), +1 (TMU), MRGBTMU -> MATMU.
   - XOR masks `2<<9`, `3<<11`, `1<<13` and their alpha forms; the REVERSE bits 13/22 and 17/26.
   - No compiled word ever sets `combineMode` bit 29 (2PPC).
e. **No-modifier invariance.** For every set-up with no modifier bits, the output with `VCR_XC_ARGMOD` equals the
   output without it, word for word.

## 9. Risk to proven paths

- **The default 16 bpp path and a fresh install:** none. With the extended combine off, `color_path`/`stage1_combine`
  run unchanged, which pins the old behaviour. Python source pins and native invariance (e) back this.
- **Extended combine on, `argmod` on:** only set-ups that carry a modifier bit change, and they are drawn wrong today.
  A wrong encoding could make an effect worse than masked (for example, a black square instead of a teal one). The cell
  matrix, the native model and the kill bit contain that risk.
- **Glide/OpenGL coexistence:** no new register.
  - G13 changes values in the three `combineMode` words G12 already writes at every state flush.
  - Glide re-initialises `combineMode` at every open on a Napalm (`G5/gsst.c:913-925`, `:1370-1377`), so D3D -> Glide
    is safe.
  - Glide -> D3D (a stale `combineMode`) is G03's and G12's: every D3D flush rewrites all three words.
- **SLI:** none. D3D draws on chip 0. The chip field addresses units inside chip 0, and `chipMask`/`sliCtrl` are
  G03's.
- **Flip path:** none.
- **Performance:** none. The same number of writes as G12.
- **Behaviour change through validation:**
  - With honest refusals, a D3DX-effect title can pick another technique and look different in places that have nothing
    to do with the modifier. That is intended, but it widens what a test pass must look at.
  - The refusal set is kept to what cannot be expressed exactly.
