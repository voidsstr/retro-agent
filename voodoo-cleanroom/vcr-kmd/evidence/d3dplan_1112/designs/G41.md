# G41: the fog-table cache is never invalidated (design)

Lane: **clean-room** (`vcr-kmd`, our DX7-level NT D3D HAL in `vcrdd.dll`).
Source: `reports/hal.md` R5 (hal-05, lines 171-176) and section 8 (lines 431-443). Companion
notes: `designs/G03.md` (table row at line 118, notes at 291 and 588), `designs/G01.md`
3.3, `designs/G02.md` (lines 241, 256, 596, 636).
This is a design only. Nothing was edited, built or deployed, and no box was contacted.

Path aliases: `KMD` = `voodoo-cleanroom/vcr-kmd`, `VH5` = `retro-3dfx/3dfx Driver Code/H5/W2K/Src/Video/Displays/H5`,
`GLIDE` = `voodoo-cleanroom/build/retro3dfx-glide/glide3x/h5`, `RING` =
`KMD/evidence/d3dplan_1112/onbox/ring_start_decoded.txt`.

## 0. Verdict

- **The defect is real in the code.** `pd->fog_valid`/`fog_loaded` (`KMD/display/vcrdd.h:78-79`)
  start at zero only because the PDEV is allocated with `FL_ZERO_MEMORY` (`KMD/display/vcrdd.c:397`).
  `VcrDd3dState` skips the 32-register table load whenever the key matches (`KMD/display/vcrdd_3d.c:86-101`).
  No event ever clears the flag: not a Glide session (`vcrdd_escape.c:126-206`), not
  `DrvAssertMode` (`vcrdd.c:570-618`), not an engine reset or a register poke escape
  (`vcrdd_escape.c:311-324`).
- **The gap's headline trigger cannot happen with our stack.** "A D3D title with fog after an
  OpenGL/Glide game on the same PDEV" does not occur, because every Glide session runs on a PDEV
  of its own, and the PDEV D3D uses after it is new (section 2). No staged `.124` title can reach
  the stale state today.
- **Reachable today:**
  - the harness's `reset-engine` and `reg` poke escapes on a live desktop PDEV;
  - a re-asserted PDEV (fast user switching, a full-screen console), never once recorded on this box.
- **Reachable tomorrow:** G01/G02's planned same-PDEV engine resets. Their designs already clear
  the cache themselves (`designs/G01.md:161`, `designs/G02.md:241`).
- **The fix is still worth landing.** It is about 15 lines, CPU-only, and produces identical register
  writes on every flow recorded on `.124`. It gives G01/G02 one named hook to call.
  It also moves the "valid" flag after the last table write, so a load that stops halfway never
  claims a table.
- **Recommendation:** land it **default-on with no Diag switch**, in the same commit as G01 or
  G03. **Priority P3**, because no staged title needs it.

## 1. What the code does today

| where | what |
|---|---|
| `vcrdd.h:78-79` | `ULONG fog_loaded[4]` (VCR_FOG_* mode, FOGSTART, FOGEND, FOGDENSITY as float bits) and `ULONG fog_valid`, per PDEV |
| `vcrdd.c:397` | `EngAllocMem(FL_ZERO_MEMORY, ...)`: the only place either is reset |
| `vcrdd_d3d.c:1000-1018` | `compute_regs`: table fog keys `{LINEAR/EXP/EXP2, start, end, density}`. Vertex fog keys `{0,0,0,0}` (= `VCR_FOG_RAMP`), **a constant**, so any two vertex-fogged draws on one PDEV share it |
| `vcrdd_3d.c:86-101` | if `FM_ENABLE` and (`!fog_valid` or the key differs): build the table, write `fogTable` 0x160-0x1dc (32 writes, `VcrDdRoom(8)` every 8), then `memcpy` the key and set `fog_valid = 1` |
| `vcrdd_d3d.c:1361` | the **only** caller of `VcrDd3dState` is `prepare()`. It runs only when `w->drawable`, which requires `!pd->exclusive_pid` (`:1748, 1859, 1887`). So the table can only be (re)loaded by a DP2 walk on a PDEV with no Glide owner |

The fog table is write-only, so the HAL cannot read it back. The cache is a claim about chip state
that nobody else is meant to change. Glide does change it:
- `grFogTable` writes all 32 registers, broadcast (`GLIDE/glide3/src/gglide.c:4044-4083`). Grep
  that ISO-8859 file with `grep -a`: a plain grep calls it binary and reports nothing.
- MesaFX calls `grFogTable` whenever GL fog is on and its mode or parameters change
  (`build/retro3dfx-gl/src/mesa/drivers/glide/fxsetup.c:2018-2051`).

A latent second defect is inside `VcrDd3dState` itself:
- `fog_valid` stays 1, holding the **previous** key, while a new table is half written.
- If `VcrDdRoom` gives up mid-load (`return FALSE` at `:93-94`), the cache still claims the old key
  over a chip holding half of each table.
- Today that is unreachable: a give-up turns acceleration off until a new PDEV (`vcrdd_2d.c:83-89`).
- G02's same-PDEV recovery (`designs/G02.md:230-262`) makes it reachable.

## 2. When can the cache actually be wrong?

The gap lists three events. The recorded evidence shows that none of them reaches a PDEV that D3D
draws on afterwards.

**Fact 1: XP builds a new PDEV at every mode change and frees the old one within ~60 ms.**
- `RING` lines 49-99 (seq 23653-23703): `DrvAssertMode(FALSE)`, then `DrvEnablePDEV mode 159`, the
  mode set, `DrvEnableSurface`, then `DrvDisableSurface` + `DrvDisablePDEV` of the old PDEV.
- Across every ring and 86Box log in `KMD/evidence`: 38 `DrvEnablePDEV`, 37 `DrvDisablePDEV`.
- 93 `DrvAssertMode` calls are recorded (30 on silicon, 63 on the 86Box bed). **All 93 are
  `bEnable = FALSE`.** No PDEV has ever been re-asserted on this hardware or the bed.

**Fact 2: our Glide always changes the display mode, even at the desktop's resolution.**
- Glide takes the screen with DirectDraw `SetDisplayMode` and gives it back with
  `RestoreDisplayMode` (`GLIDE/minihwc/win_mode.c:326-352, 381`; `KMD/tools/glidelab.c:493-496`).
- 3dfx's "DDraw communication hack" (`win_mode.c:200, 220-234`): when the **registry** desktop
  resolution equals Glide's, Glide asks DirectDraw for **8 bpp**. vcr-kmd lists 8 bpp modes
  (`KMD/common/vcr_modes.c:364`).
- So a Glide session never shares the desktop's mode, and so never shares its PDEV.
  - `RING` 316-369: `DrvEnablePDEV mode 156` (1280x960x32@85), the desktop PDEV destroyed, then
    `HWCSETEXCLUSIVE` from pid 1892 on the **new** PDEV (seq 23973).
  - `RING` 914-964: the session's end is another mode change to a **new** desktop PDEV (mode 159).
  - That session never sent `HWCRLSEXCLUSIVE`. Its owner died with the PDEV it ran on.

**Fact 3: the table is reloaded only by a drawable DP2** (section 1). So while a Glide owner holds a
PDEV, nothing on that PDEV can re-validate the cache.

**What can still make a valid cache lie on a live PDEV:**

| trigger | reachable on `.124` today? | the fix's hook |
|---|---|---|
| A Glide/OpenGL session on the same PDEV | **no** (Facts 1 and 2). The only exception is a theoretical in-process D3D -> Glide -> D3D switch that keeps the D3D device alive across Glide; UE1 releases its old render device first (inferred) | `HWCSETEXCLUSIVE`, `HWCRLSEXCLUSIVE` |
| A process holding the register window without exclusive ownership | yes, but only during someone else's Glide session: pid 1700 mapped 14 views for 2.4 s while pid 1892 owned the chip (`RING` seq 24436-24469). Its PDEV dies at the session's end | `GETLINEARADDR`, `UNMAP_MEMORY` |
| A PDEV switched away and back: fast user switching, a full-screen console via `RESET_DEVICE`/VgaSave (`KMD/miniport/vcrmp.c:677-695`), a failed mode change | not used on this box: 0 of 93 calls were re-asserts. Another session's D3D or Glide could load its own table meanwhile | `DrvAssertMode` (both directions) |
| `vcrctl reset-engine` (`VCR_ESC_RESET_ENGINE`): graphics-core reset on the live desktop PDEV (`KMD/miniport/vcrmp_hw.c:181-204`) | yes, from the lab. Whether a graphics-core reset keeps the fog RAM is unknown (`designs/G02.md:636`) | `VCR_ESC_RESET_ENGINE` |
| `vcrctl reg` MMIO poke (`VCR_ESC_REG`, needs `Diag\AllowPoke = 1`) | yes, from the lab | `VCR_ESC_REG` write |
| G01/G02 same-PDEV engine resets (stale FIFO, 2D give-up recovery) | after those land | `VCR_FOGC_ENG_RESET`, called by them |
| A load cut off by a FIFO give-up, then a recovery on the same PDEV | after G02 lands | begin/done ordering |

**Not a G18 candidate.** UE2's white sky cannot come from this. Each UE2 launch gets a new PDEV at
`SetRes`, and within a session the HAL reloads at every key change. Calling that out saves the G18
investigation a detour.

## 3. Vendor guidance

3dfx's own V5 HAL treats the fog table as belonging to whoever last used the 3D engine:

- `VH5/HWCEXT.C:1302-1310` (`hwcExecuteFifo`): "notify D3D that glide is executing so the hw state may
  have changed". It sets `pRc->hwStateChanged = SC_STATE | SC_FOGALL | SC_BUFFERS; _D3(lastContext) = 0;`.
  `SC_FOGALL = SC_FOGCOLOR | SC_FOGTABLE` (`VH5/D3GLOBAL.H:1195-1196`).
- `VH5/D6DP2.C:6372-6377`: a context that is not `lastContext` re-sends fog with
  `UPDATE_FOG_STATE(SC_FOGALL)`.
- `VH5/DDSLIBLT.C:2125-2130`: after its own 3D-engine SLI blit, `UPDATE_FOG_STATE(SC_FOGALL)`.
- `VH5/DDFXNT.C:2445-2449, 2496-2501`: entering and leaving fullscreen exclusive set `_D3(lastContext) = 0`
  ("since we may have entered SLI mode").
- The load itself is one 32-dword PK1 packet (`VH5/D3FOG.C:430-456`), built by
  `createTableAndLoad` (`:472-517`).

We keep our per-PDEV, keyed cache. Unlike the vendor's per-context reload, two contexts with the same
fog do not reload on every switch. We adopt the vendor's rule: **every foreign use of the chip
forgets it.** Our Glide path is exclusive-mode, not `EXECUTEFIFO` (which we do not support:
`vcrdd_escape.c:252`), so the hook points are the ownership and mapping escapes.

## 4. The change

### 4.1 `KMD/include/vcr_fogcache.h` (new; Win32-free, host-tested)

```c
#include "vcr_types.h"
#define VCR_FOGC_KEY          4u    /* VCR_FOG_* mode, FOGSTART, FOGEND, FOGDENSITY (float bits) */
/* why the table was forgotten: last_why, event 513 what 40 b */
#define VCR_FOGC_NONE         0u
#define VCR_FOGC_GLIDE_MAP    1u    /* GETLINEARADDR granted: a process holds the register window */
#define VCR_FOGC_GLIDE_OWN    2u    /* HWCSETEXCLUSIVE */
#define VCR_FOGC_GLIDE_RLS    3u    /* HWCRLSEXCLUSIVE accepted (RESTORE_MODE ran, or failed) */
#define VCR_FOGC_GLIDE_UNMAP  4u    /* UNMAP_MEMORY */
#define VCR_FOGC_ASSERT_OFF   5u    /* DrvAssertMode(FALSE): RESET_DEVICE, VgaSave, another session */
#define VCR_FOGC_ASSERT_ON    6u    /* DrvAssertMode(TRUE): its mode set may reset a busy engine */
#define VCR_FOGC_ENG_RESET    7u    /* VCR_ESC_RESET_ENGINE; G01/G02's resets */
#define VCR_FOGC_REG_POKE     8u    /* VCR_ESC_REG MMIO write accepted */

typedef struct vcr_fogcache {
    vcr_u32 key[VCR_FOGC_KEY];      /* the table on chip 0, when valid */
    vcr_u32 valid;
    vcr_u32 loads;                  /* tables written (32 register writes each) */
    vcr_u32 forgets;                /* forgets that dropped a VALID table */
    vcr_u32 last_why;               /* VCR_FOGC_* of the last forget */
} vcr_fogcache;

/* 1: write the table before this draw. Fog off never loads; a new key reloads. */
static __inline int  vcr_fogc_need(const vcr_fogcache *c, vcr_u32 fog_on, const vcr_u32 *key);
/* BEFORE the first fogTable write: a load that stops halfway claims no table */
static __inline void vcr_fogc_begin(vcr_fogcache *c);              /* valid = 0 */
/* AFTER the 32nd write */
static __inline void vcr_fogc_done(vcr_fogcache *c, const vcr_u32 *key);  /* key, valid = 1, loads++ */
/* someone else may have written the table, or a reset may have lost it */
static __inline void vcr_fogc_forget(vcr_fogcache *c, vcr_u32 why);       /* forgets++ if valid; valid = 0; last_why */
static __inline const char *vcr_fogc_name(vcr_u32 why);                   /* for the log line */
```

The key comparison is an explicit 4-word loop: no `memcmp`, no CRT, and no FPU in any unit that
includes it.

### 4.2 `VCR_PDEV` and `vcr3d_regs`

- **`KMD/display/vcrdd.h:78-79`.** Replace the two fields with:
  - `vcr_fogcache fogc;`
  - `ULONG serial;` (filled by `DrvEnablePDEV` from a session-global `++g_pdev_serial`;
    only so a stats reader can tell "same PDEV" from "new PDEV").
  - Add `#include "../include/vcr_fogcache.h"`.
- **`KMD/display/vcrdd_3d.h:38`.** `ULONG fog_table[4]` becomes `vcr_u32 fog_table[4]`. It is the
  same size on ILP32, and the change lets it go to `vcr_fogc_*` without a pointer-type warning.
  - Its two writers are unchanged: `compute_regs` assigns `DWORD`s, and `fbits()` takes the values.
- **`vcrdd.h`, after the `VcrDd` declaration:**

```c
/* G41: the fog table on chip 0 may no longer be ours - the next fogged draw
 * reloads it. CPU only: no register, no IOCTL except the log line, which is
 * written only when a VALID table is dropped. Every event that hands the chip
 * to someone else, or may reset it, calls this; nothing else writes fogc.valid. */
static __inline void VcrDdFogForget(VCR_PDEV *pd, ULONG why)
{
    if (pd->fogc.valid)
        VcrDd(VCR_LV_DEBUG, VCR_EV_DD_D3D, 40, why, pd->fogc.loads, pd->fogc.forgets + 1,
              "fog table forgotten (%s): the next fogged draw reloads it", vcr_fogc_name(why));
    vcr_fogc_forget(&pd->fogc, why);
}
```

### 4.3 `VcrDd3dState` (`KMD/display/vcrdd_3d.c:86-101`): the same writes, in the same order

```c
    if (vcr_fogc_need(&pd->fogc, r->fogMode & FM_ENABLE, r->fog_table)) {
        unsigned char t[VCR_FOG_TABLE_ENTRIES];
        ULONG i;
        vcr_fogc_begin(&pd->fogc);          /* a load cut off by a give-up claims no table */
        vcr_fog_table((int)r->fog_table[0], fbits(r->fog_table[1]), fbits(r->fog_table[2]),
                      fbits(r->fog_table[3]), t);
        for (i = 0; i < 32; i++) {
            if ((i & 7) == 0 && !VcrDdRoom(pd, 8))
                return FALSE;
            w3(pd, V3D_FOGTABLE + 4 * i, vcr_fog_reg(t, (int)i));
        }
        vcr_fogc_done(&pd->fogc, r->fog_table);
        if (!VcrDdRoom(pd, 4))
            return FALSE;
    }
```

**Register writes are unchanged:**
- same 32 values `(e1<<24)|(d1<<16)|(e0<<8)|d0` (Glide's packing, `vcr_fog.c:66-73`);
- same order, same `VcrDdRoom` waits;
- same skip when the key matches and nothing intervened.

Only the moments the CPU flag changes move.

### 4.4 The forget points

| # | where | call | condition |
|---|---|---|---|
| 1 | `hwc()` `VCR_HWC_GETLINEARADDR` (`vcrdd_escape.c:101-112`) | `VcrDdFogForget(pd, VCR_FOGC_GLIDE_MAP)` | after `rs->resStatus = VCR_HWC_OK` (a mapping was granted) |
| 2 | `VCR_HWC_HWCSETEXCLUSIVE` (`:126-132`) | `VcrDdFogForget(pd, VCR_FOGC_GLIDE_OWN)` | after `pd->exclusive_pid = pid`. **This alone covers every Glide session, released, failed or killed**: no DP2 can re-validate while the owner exists (section 1) |
| 3 | `VCR_HWC_HWCRLSEXCLUSIVE` (`:134-201`) | `VcrDdFogForget(pd, VCR_FOGC_GLIDE_RLS)` | **after** the non-owner refusal block (`:156-161`, which stays textually unchanged and writes nothing) and **before** `IOCTL_VCR_RESTORE_MODE` (`:164`). Covers the owner's release, a release with no owner, and a failed restore. `RESTORE_MODE`'s mode set resets a busy engine (`vcrmp_hw.c:568-572`) |
| 4 | `VCR_HWC_UNMAP_MEMORY` (`:203-206`) | `VcrDdFogForget(pd, VCR_FOGC_GLIDE_UNMAP)` | after the IOCTL |
| 5 | `DrvAssertMode` (`vcrdd.c:570`) | `VcrDdFogForget(pd, bEnable ? VCR_FOGC_ASSERT_ON : VCR_FOGC_ASSERT_OFF)` | first statement, both directions. FALSE: the chip goes to `RESET_DEVICE`/VgaSave and possibly another session's PDEV. TRUE: `VcrDdSetMode` may reset a busy engine. Today it only ever runs on a PDEV about to be destroyed |
| 6 | `DrvEscape` `VCR_ESC_RESET_ENGINE` (`vcrdd_escape.c:323-324`) | `VcrDdFogForget(pd, VCR_FOGC_ENG_RESET)` | always: a reset that ends "STILL BUSY" was still pulsed |
| 7 | `DrvEscape` `VCR_ESC_REG` (`:311-313`) | `VcrDdFogForget(pd, VCR_FOGC_REG_POKE)` | when the request (read **before** the IOCTL into locals) is `kind == VCR_REG_MMIO32 && write`, and the IOCTL returned 0 |
| - | G01 `VcrDdFifoGuard` RESET, G02 engine-lost reset | `VcrDdFogForget(pd, VCR_FOGC_ENG_RESET)` | **instead of** the `pd->fog_valid = 0` their designs write (`G01.md:161`, `G02.md:241`) |
| - | G51 (D3D in SLI), when it lands | forget on entering and leaving SLI, and broadcast the load | chips 1-3 never receive our table (D3D renders on chip 0 today); Glide's `grFogTable` broadcasts |

**Considered and left out:**
- `VCR_ESC_PCI` writes: config space cannot reach the 3D register file.
- `VCR_ESC_CLOCK`: it refuses while there is an owner, and writes the PLL, not the 3D unit.
- `VCR_HWC_SLI_AA_REQUEST`: only ever inside an exclusive session, which #2 already covers.
- `DrvEnableSurface`: once per PDEV, which is born zeroed.
- Normalising the key (density ignored for LINEAR, start/end ignored for EXP/EXP2): it would save
  reloads, but no cost has been measured. Not done.

### 4.5 Instrumentation (small, read-only)

- **Event 513 (`VCR_EV_DD_D3D`):**
  - `what 40`: "fog table forgotten: b = why, c = loads so far, d = forgets", DEBUG, valid drops only.
  - `what 41`: in `DrvDisableSurface`, before `VcrDd2dTerm`, at INFO, only when `loads || forgets`:
    "fog table: %u loads, %u forgotten while loaded (last %s)".
  - Append both to the event's description string in `KMD/include/vcr_events.h:75`.
  - Sub-codes 1-23 are taken, and G01 proposes 24/25. **Allocate centrally at integration**
    (`G02.md` open question 6).
- **`VCR_ESC_DD_STATS` (`vcrdd_escape.c:367-374`):**
  - Today it answers 4 ULONGs. A caller asking for 8 also gets `[4] serial`, `[5] fogc.loads`,
    `[6] fogc.forgets`, `[7] fogc.last_why`. A 16-byte caller is unchanged.
  - Keep the existing `return 4 * sizeof(ULONG);` and `cjOut < 4 * sizeof(ULONG)` text. Three
    tests pin it: `test_vcr_kmd_text.py:181-182`, `test_vcr_kmd_sli_glue.py:389-395`.
  - Also keep `3dfxctl.c:331`'s `dd[4]` read and `vcrctl info`'s 16-byte query as they are.
    `vcrctl info` adds a **second**, 32-byte query and prints `pdev_serial`, `fog_loads`,
    `fog_forgets` and `fog_last_why`, or `null` from an older driver.
  - G76 may fold these into its own counters.

### 4.6 What does not change

- Caps: no cap changes.
- Register fields and values: none change. Single pass.
- `Diag` switches: none added or changed.
- `Diag\Reset3D` and its call site: unchanged.
- The refused-release block: unchanged.
- The 16 bpp target sequence, the flip path, SLI: untouched.
- **On the old path, meaning every flow recorded on `.124`,** the chip sees byte-for-byte the same
  writes:
  - every forget in those flows lands on a cache that is already invalid (a Glide PDEV), or on a
    PDEV about to be freed (`DrvAssertMode(FALSE)`);
  - the begin/done move changes no write.

## 5. Gating

**Default-on, no Diag switch.** This is the convention's second branch: "the proven path
byte-for-byte unchanged when off". Here the proven path is unchanged **with the fix on**:
- every recorded flow produces the same register writes (4.6);
- a forget can at worst cause one extra 32-write load at the next fogged draw. That is the same
  load the first fogged draw of every new PDEV makes, which runs at every game launch.

A kill switch would only restore a cache that is known to be wrong, so it is not a safety net.
`hal.md` R5 (line 176) and `G03.md` line 291 both ask for default-on. If integration insists on a
switch anyway, `Diag\D3DFogForget = 0` would skip only the `vcr_fogc_forget` calls. Keep
begin/done regardless.

The silicon proof (section 7) needs no Diag change. The vcrdd.dll swap is the boot's one change,
and it can ride the same clean boot as G01 or G03.

## 6. Regression tests

**`tests/native/test_vcr_kmd_fogcache.c` (new; auto-found by `tests/run_all.sh`).** It compiles
`include/vcr_fogcache.h` and models the chip's table as a 4-word key; Glide's table is `P`.
- `draw(c, K)` stands for the HAL's state send: `if (vcr_fogc_need(c, 1, K))` load K into the
  model chip, then report whether the chip held K at draw time.
- Test cases:
  - `a_fresh_pdev_loads_once_then_skips`: need = 1, load, need = 0. The proven skip stays.
  - `glide_between_two_same_key_draws`, both arms on one timeline:
    - **old** (no forget): `draw(K)`, chip = P, `draw(K)` returns **0**. The cache skipped and the
      chip held Glide's table. This asserts the buggy value.
    - **fixed**: `draw(K)`, chip = P, `forget(GLIDE_OWN)`, `draw(K)` returns **1**, with
      `loads == 2`, `forgets == 1`, `last_why == GLIDE_OWN`.
    - Run it with `K = {VCR_FOG_RAMP,0,0,0}` (vertex fog: a constant key, the easy victim) and with
      a LINEAR key.
  - `every_forget_reason_forces_exactly_one_reload`: loop over `VCR_FOGC_GLIDE_MAP..REG_POKE`.
  - `a_load_cut_off_halfway_claims_nothing`:
    - **fixed**: K1 loaded, `begin()`, chip = half K2, no `done()`; `need(K1) == 1`.
    - **old ordering**, modelled as in the old code (no begin, valid set only at the end):
      `need(K1) == 0` over a mixed table. This asserts the buggy value.
  - `fog_off_never_loads`: need(fog_on = 0) is 0, both fresh and after a forget.
  - `a_new_key_reloads`.
  - `forget_counts_only_valid_drops`: on a fresh cache, `forgets` stays 0 and `last_why` is still recorded.

## 7. d3dprobe test and on-box verification

### 7.1 `vcrctl fogpoison` (`KMD/tools/vcrctl.c`): what a fogging Glide client does to the chip, and nothing else

It reuses `hwc()`, `hwc_open()` and `hwc_close()` (`vcrctl.c:699-778`) and the pace gate, as
`sliaa off` already does. Steps:

1. **Refuse before sending anything** if:
   - `VCR_ESC_DD_STATS` shows an exclusive owner;
   - GETDEVICECONFIG is not 3dfx;
   - the pace gate refuses.
2. `hwc_open`: GETDEVICECONFIG and GETLINEARADDR.
3. Read `cmdFifo0.baseSize` through `base0`. **Refuse** if `SST_CMDFIFOEN` is set. That is G01's
   state: a poke would race a live command stream.
4. `HWCSETEXCLUSIVE`.
5. Wait for the chip to go idle, bounded.
6. Write 32 times `base0 + 0x200000 + 0x160 + 4i = 0xff00ff00`. That value is every entry 255:
   all fog, a table no D3D key produces. Wait for 8 free PCI-FIFO slots (status[4:0]) before every 8th write.
7. `HWCRLSEXCLUSIVE`: `RESTORE_MODE` restores the current mode. This is the run's **one paced
   switch**, the same one `sliaa off` makes. Then `vcr_pace_mark()`.
8. `hwc_close` (UNMAP).
9. Confirm `exclusive_pid == 0`.

It answers with one JSON line: `ok`, `value`, `writes`, `owner_after`, `paced_ms`.

- The writes are register writes only: no command FIFO, no combine, no stencil. So G01 and G03
  cannot contaminate the result.
- It takes `--value` to override the poison.

### 7.2 d3dprobe tests `fogcache` and `fogcache_table` (`KMD/tools/d3dprobe.c`)

Both are explicit: they are not in the default list, because they need the helper and cost a
paced switch.

**Steps:**
1. **Pass 1**:
   - The control: an unfogged red strip (FOGENABLE FALSE), x 16-240, y 208-240.
   - The three quads of `fogvertex` (`:1097-1120`): red toward blue (FOGCOLOR 0xff0000ff), y 64-192.
     - `fogcache` uses specular alpha 0xff, 0x80, 0x00, so the key is the constant RAMP.
     - `fogcache_table` uses LINEAR start 1, end 5 at rhw 1, 1/3, 1/8.
   - Read back; `expect()` each value.
2. Read `VCR_ESC_DD_STATS` with 32 bytes, if answered: `s1` (`serial`, `loads`, `forgets`).
3. Run the poison: `--poison PATH`, default `C:\vcr\vcrctl.exe fogpoison`.
   - `CreateProcess` with `CREATE_NO_WINDOW`, so a fullscreen device keeps the focus.
   - Wait up to 60 s and parse its JSON.
4. **Inconclusive (counted as SKIPPED, which fails an explicit `--tests` run in `d3dprobe_run.py`)** if:
   - the helper is missing or answers `ok:false`;
   - `TestCooperativeLevel != D3D_OK` (the device was lost, so the PDEV changed);
   - the stats `serial` changed.
5. **Pass 2**: the same draws. **The same key is the first fogged draw after the poison.**
   - If the control strip is not red (±12), the fog checks are SKIPPED with "D3D draws nothing
     after the HWC session (G01/G03), not a fog-cache verdict".
6. Read the stats again (`s3`), if answered:
   - `s2.forgets > s1.forgets`, with `last_why` one of the GLIDE reasons (UNMAP on a full sequence);
   - `s3.loads == s2.loads + 1`: exactly one reload in pass 2.

**Pass criterion.** Pass 2 must equal pass 1's reference values (`fogvertex`'s own):

| quad | reference (±tolerance) | old-buggy signature |
|---|---|---|
| "no fog" | `0xff0000` ±12 | `0x0000ff` (all fog) |
| "half fog" | `0x80007f` ±40 | `0x0000ff` |
| "all fog" | `0x0000ff` ±12 | `0x0000ff` (cannot tell) |
| control | `0xff0000` ±12 | `0xff0000` |

The RESULT carries `"fogcache":{"pdev_serial":[..],"loads":[..],"forgets":[..],"last_why":N,"poison":{..},"signature":"reloaded"|"stale"|"other"}`.
`stale` means the pass-2 "no fog" quad is within ±12 of the fog colour.

`d3dprobe_run.py` passes `--poison` from its existing `--tool` (`C:\vcr\vcrctl.exe`, line 246) and
budgets one more pace in its EXECW timeout. `d3dprobe`'s build line gains `-Iinclude`, for
`VCR_ESC_DD_STATS` from `vcr_ioctl.h`.

## 8. Risk to proven paths

**Default 16 bpp path, 32 bpp path, flip, SLI, `Reset3D`:**
- untouched;
- register writes identical in every recorded flow (4.6).

**Glide/OpenGL coexistence:**
- the escape handlers gain CPU flag writes only, after their existing syncs;
- no register access and no IOCTL;
- the refused-release path is unchanged, and its existing test still pins that it writes nothing.

**Performance:**
- one 32-write load (about 0.2 ms, inferred from 5-8 µs per write) at the first fogged draw after a
  forget, on a PDEV that survives the event;
- never observed on `.124`;
- one DEBUG IOCTL per valid drop (G52), and one INFO line per PDEV teardown.

**Type change** (`fog_table` from ULONG to `vcr_u32`): same width on ILP32. The three users are
listed in 4.2.

**The lab helper** pokes chip-0 registers from user mode, which is what Glide and `vcrctl sliaa`
already do:
- it refuses with an owner present or the command FIFO on;
- its one switch is paced;
- run it supervised.

**Overall: low.**

## 10. Open questions

1. **Can anything on `.124` re-assert a surviving PDEV?** All 93 recorded `DrvAssertMode` calls were
   FALSE. Fast user switching or a full-screen console would re-assert one. The fix covers both
   either way; the answer only tells whether `ASSERT_ON` is ever exercised.
2. **Does a graphics-core reset (`VcrHwResetEngine`: GRX + FBI FIFO + 2D + command stream) keep the
   fog-table RAM?** This is the same question as `G02.md:636`, answered by experiment E7. Does
   `RESET_DEVICE`/VgaSave keep it? Neither answer changes the design.
3. **Event numbers** 513/40 and 513/41 need central allocation with G01 (24/25) and the other sibling
   designs.
4. **`VCR_ESC_DD_STATS` slots 4-7 versus G76's planned statistics:** merge at integration.
5. **Is forgetting at `GETLINEARADDR`/`UNMAP` broader than needed?** A mapped process can write any
   register (`RING` seq 24436-24469: pid 1700, 14 views, 2.4 s, no exclusive). Confirm that no client
   maps per frame. `3dfxctl` polls `DD_STATS` only, at 2 s (`scripts/3dfx/3dfxctl/3dfxctl.c:3505`).
6. **Is a user-mode register poke by `vcrctl fogpoison` acceptable on `.124`** for a supervised run?
   - The alternative is the `VCR_ESC_REG` route with `Diag\AllowPoke = 1`.
   - That route has no mode set, but costs a Diag change and a boot.
   - It tests forget point 7 rather than the HWC points.
7. **The conclusion that each Glide session gets its own PDEV rests on two things:** 3dfx's 8 bpp hack
   (`win_mode.c:220-234`) and vcr-kmd listing 8 bpp modes. If a future mode-list change drops 8 bpp,
   Glide's open at the desktop resolution would **fail**; it would still not share the PDEV. Worth a
   line in the README beside the mode list.
