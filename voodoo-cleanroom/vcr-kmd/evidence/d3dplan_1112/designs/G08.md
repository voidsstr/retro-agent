## 0. Summary

- **The gap is real and fixable, in a single pass, with register combinations the HAL already writes.**
  - A DX5/DX6 title's texture filter, address mode and texture blend arrive as render states 3, 17, 18, 21, 44
    and 45, plus `D3DTSS_ADDRESS` (12).
  - `set_rs` stores them and nothing reads them (`vcrdd_d3d.c:1393-1406`), so stage 0 keeps the context
    defaults: point sampling, WRAP, MODULATE with texture alpha (`ctx_defaults`, `:1126-1161`; stage 0 at `:1138-1146`).
  - The fix copies each of them onto stage 0's texture stage states when it arrives, as Microsoft's NT sample
    does (`MSP2/d3dstate.c:583-740`, called for every render state at `:1836`) and as 3dfx's NT HAL does
    (`VH5/D3RSTATE.C:2168-2340, 2645-2720, 2851-2945`). It adds 3dfx's private "legacy MODULATE" alpha rule:
    texture alpha if the texture has alpha, otherwise vertex alpha.
  - `compute_regs` then builds the registers from those stage states exactly as it already does for every
    TSS-driven title. That means `textureMode` bits 1, 2, 6 and 7, and `fbzColorPath` values `color_path`
    already produces.
- **Four findings in this design go beyond the reports:**
  1. **XP's runtime sends the legacy states raw to the DP2 driver.** Its own DP2 software rasterizer maps them
     itself (D3DIM, section 2). For the device-creation stream this is now read, not inferred.
  2. **Mysteries of the Sith can ask for filtering ONLY through `TEXTUREMAG`/`TEXTUREMIN`.**
     - It is an `IDirect3D2` + execute-buffer title (`RPT/runtime.md` §1), so it has no texture-stage API.
     - Its Display menu has no filtering option (`FBS/mots_display.png`).
     - Its in-game frame is point-sampled: at native size, the crop x 940-1100, y 200-320 of `FBS/mots_game.png`
       shows hard texel blocks on the near wall.
     - This settles the games-20/21 versus visual-06 disagreement in visual-06's favour. MotS is not "bilinear
       because JK has an option".
  3. **Our legacy `dwTextureFilterCaps` name the wrong mip mode** (`vcrdd_d3d.c:2036-2040`).
     - It advertises `D3DPTFILTERCAPS_LINEARMIPNEAREST` (0x10): point texels, blended between two mip levels.
       The HAL cannot draw that, because it has no trilinear (G26).
     - It omits `D3DPTFILTERCAPS_MIPLINEAR` (0x08): bilinear within the nearest mip level. That is exactly what
       the HAL draws for `MINFILTER LINEAR` + `MIPFILTER POINT`.
     - All three reference mappings agree on what the names mean: `D3DFILTER_MIPLINEAR` becomes MIN LINEAR + MIP
       POINT (`MSP2/d3dstate.c:714-717`, `VH5/D3RSTATE.C:2280-2283`, D3DIM 0x6d927836).
     - So a DX5 title that picks its filter from the caps cannot select "bilinear + mipmaps" and may land on a
       point-sampled mode even after the mapping.
     - The fix adds 0x08 under the same switch. The D3D8 and D3D9 caps do not define these low bits
       (`DDK8/d3d8caps.h:277-286`), so D3D8/9 titles cannot see the change.
  4. **No d3dprobe test samples with bilinear filtering or CLAMP addressing.**
     - Every test sets `D3DTEXF_POINT` and the default WRAP (`KMD/tools/d3dprobe.c:576-578, 748-750, 849-851,
       971-973, 1023-1025, 1076-1084`).
     - So the TSS path the legacy states are mapped onto has no silicon check of its own. The only evidence that
       it works is NewDark Thief II's D3D9 frame, which is bilinear (`FBS/thief2_d3d9_armed_4.png`).
     - Section 6 adds `bilinear` and `clamp` to d3dprobe as controls.
- **Gating.**
  - The mapping goes behind `Diag\D3DFeat` bit 1 (0x2), default OFF, read at boot. The bit position follows
    `RPT/hal.md` §10 Phase 2 ordering; the integrator owns the final bit map.
  - With the bit off, register traffic is byte-for-byte what 95678704 sends.
  - The Phase 0 counters that say which titles send which states are log-only and land default-ON.
  - The mapping is a candidate to graduate to default-ON after one supervised proof boot (section 5).
- **Priority, effort, dependencies.**
  - Priority **P1.** It is a visible quality defect in every scene of JK, MotS and Rainbow Six, and probably of
    Thief Gold, SS2 and Shogo. It does not stop any title.
  - Effort **M.**
  - Hard dependency **G75** (a DX5/DX6 probe: D3D8 cannot send these states). Operational dependencies
    **G01/G03** (a stale Glide FIFO voids a D3D run). Soft dependencies **G76** (counters) and **G07** (mip
    chains).

## 1. What the HAL does today (verified in the code)

| input | where it lands | what is drawn | what the title wanted |
|---|---|---|---|
| `D3DRENDERSTATE_TEXTUREMAPBLEND` (21) | `c->rs[21]` only (`:1393-1406`) | stage-0 defaults: MODULATE(TEXTURE, CURRENT), alpha SELECTARG1(TEXTURE) (`:1138-1143`) | DECAL/COPY: texture colour, not texture x vertex. MODULATEALPHA: texture alpha x vertex alpha. DECALALPHA: blend by texture alpha. ADD: texture + vertex. MODULATE: **vertex alpha when the texture has none** |
| `TEXTUREMAG` (17), `TEXTUREMIN` (18) | `c->rs[]` only | `MAGFILTER`/`MINFILTER` stay POINT (`:1145-1146`), `MIPFILTER` stays 0 (= no mip, `tex_view :779`) | bilinear and/or mipmapping |
| `TEXTUREADDRESS` (3), `TEXTUREADDRESSU/V` (44/45) | `c->rs[]` only | `ADDRESSU/V` stay WRAP (`:1144`) | CLAMP (sky boxes, HUD sprites, edges). Repeats wrap: seams |
| `D3DTSS_ADDRESS` (12), any stage | `c->tss[12]` / `c->tss1[12]` (`:1591-1611`) | `tex_view` reads 13/14 only (`:792-795`, `:830-833`) | both U and V (DDKHELP D3DTEXTURESTAGESTATETYPE: "overrides any values set for ADDRESSU and ADDRESSV") |
| `WRAPU/V` (5/6), `BORDERCOLOR` (43), `MIPMAPLODBIAS` (46), `ANISOTROPY` (49) | `c->rs[]` only | nothing | cylindrical wrap (G86), border colour (no hardware, G86), LOD bias (G27), anisotropy (impossible, G85) |
| legacy caps (DX5/6/7 apps only) | `prim_caps :2036-2045` | blend 0xcb, filter low byte 0x17 | blend modes promised and not drawn. MIPLINEAR not offered, LINEARMIPNEAREST offered (section 0, finding 3) |

**What `color_path` already draws correctly.** Once stage 0 holds the mapped ops, it draws all of them
(`:676-745`): SELECTARG1/2, MODULATE(TEXTURE, DIFFUSE), ADD, BLENDTEXTUREALPHA with TEXTURE as arg1, and the
alpha ops MODULATE and SELECTARG1/2. These are the cases `RPT/hal.md` §6 lists as correct. The legacy blends
need no new combine work.

## 2. Evidence that the states reach the HAL raw

1. **Execute-buffer streams.**
   - JK, MotS and Rainbow Six reach DP2 as `D3DNTHALDP2_EXECUTEBUFFER` streams (`DDK8/d3dnthal.h:865`), ending
     in `D3DOP_EXIT` (`vcrdd_d3d.c:1773-1782`).
   - `D3DOP_STATERENDER` is opcode 8 = `D3DNTDP2OP_RENDERSTATE` (`RPT/runtime.md` §6.1). The application's own
     `D3DRENDERSTATE_*` pairs therefore arrive in `set_rs`.
2. **D3DIM, the device-creation stream.** Read in this design from the disassembly.
   - The DP2 device's vtable at 0x6d9115e8 has, at slot +0x80, 0x6d91a6d8. That function writes one
     `bCommand = 8` (RENDERSTATE) token into the DP2 command buffer (0x6d91a77e).
   - At device creation, the loop 0x6d922344-0x6d922361 calls slot +0x80 for every render state 1-135 with the
     runtime's current values. The legacy 3, 5, 6, 17, 18, 21, 43-46 and 49 are included.
   - Only after that, and only when `[0xf4c] >= 2`, does the loop 0x6d922375-0x6d92239c send the texture-stage
     states 0-23 of each stage through 0x6d91ac84, which writes a `bCommand = 0x19` token at 0x6d91ad22.
   - **So a DP2 driver receives the legacy states raw, and the runtime's TSS initialisation follows them.**
3. **D3DIM: Microsoft's own DP2 consumer maps them itself.** Inferred role: d3dim.dll's built-in software
   rasterizer.
   - Function 0x6d9280bd is called from DP2 token parsers: 0x6d929655 walks `TEXTURESTAGESTATE` records and
     0x6d92981a walks `RENDERSTATE` records.
   - It keeps render states at +0x8c and stage-0 TSS at +0x48c.
   - The mapping:
     - rs 3 is copied to TSS 12/13/14.
     - rs 44/45 to TSS 13/14.
     - rs 43 to TSS 15.
     - rs 46 to TSS 19.
     - TSS 12 (as id 0x10c) is copied to 13 and 14.
     - rs 17/18 go through 0x6d9277e1.
     - rs 21 goes through 0x6d927f66. It also sets a "legacy blend" flag at +0x590, which later selects a
       separate pixel routine (0x6d946d40).
   - The driver-side mapping is how Microsoft built it. That matches the DDKHELP D3DTEXTUREBLEND page, which
     tells drivers to do the LEGACY_ALPHAOVERRIDE mapping themselves.
4. **Still inferred, to be measured by the Phase 0 counters (section 4.4):**
   - that app-time `IDirect3DDevice2/3::SetRenderState(TEXTUREMAPBLEND, ...)` calls are forwarded and not
     filtered as redundant;
   - which states and values each title actually sends;
   - whether the D3D7/8/9 runtimes ever put a legacy state into their contexts.

   The DDKHELP pages for TEXTUREMIN/MAG/ADDRESSU say these states are "only used on Windows 95/98 when
   supporting legacy run-times". Item 2 shows XP's d3dim.dll sending them all the same.

## 3. The mapping

### 3.1 `TEXTUREMAPBLEND` (21) onto stage 0

Three implementations were read: the MS NT sample (`MSP2/d3dstate.c:598-648`), 3dfx (`VH5/D3RSTATE.C:2860-2945`)
and d3dim's rasterizer (D3DIM 0x6d927f66). The table also gives the DDK formula (DDKHELP D3DTEXTUREBLEND).

| mode | COLOROP (ARG1, ARG2) | ALPHAOP (ARG1, ARG2) | notes |
|---|---|---|---|
| DECAL (1), COPY (7) | SELECTARG1 (TEXTURE, unchanged) | SELECTARG1 (TEXTURE, unchanged) | All three implementations agree. The DDK table (as quoted in `VH5/D3RSTATE.C:2756-2766`) gives vertex alpha for an RGB texture. The implementations give texture alpha (1.0). Follow the implementations; open question 5 |
| MODULATE (2) | MODULATE (TEXTURE, DIFFUSE) | **`VCR_TOP_LEGACY_MODULATE`** (TEXTURE, DIFFUSE) | the DDK's LEGACY_ALPHAOVERRIDE: texture alpha if the texture has alpha, else iterated alpha. MSP2 uses 0x7fffffff, 3dfx keeps 0x7ffffffe in a side variable. Ours: 0x7ffffffe stored in `tss[ALPHAOP]`, so a later TEXTUREMAPBLEND or a direct stage-0 ALPHAOP replaces it, as DDKHELP requires |
| DECALALPHA (3) | BLENDTEXTUREALPHA (TEXTURE, DIFFUSE) | SELECTARG2 (TEXTURE, DIFFUSE) | all three agree |
| MODULATEALPHA (4) | MODULATE (TEXTURE, DIFFUSE) | MODULATE (TEXTURE, DIFFUSE) | all three agree |
| DECALMASK (5) | BLENDTEXTUREALPHA (TEXTURE, DIFFUSE) | SELECTARG2 (TEXTURE, DIFFUSE) | **not advertised** by us or by 3dfx (PRS 8369). The implementations disagree: 3dfx gives SELECTARG1 + alpha-mask bit; d3dim and MSP2 give DECAL or nothing. The DDK formula `lsb(aTex) ? cTex : cSrc, aSrc` is exact for 1-bit-alpha textures with this choice. Counted by Phase 0 |
| MODULATEMASK (6) | MODULATE (TEXTURE, DIFFUSE) | SELECTARG2 (TEXTURE, DIFFUSE) | not advertised. DDK `aPix = aSrc`. The colour is exact where `lsb(aTex) = 1` |
| ADD (8) | ADD (TEXTURE, DIFFUSE) | SELECTARG2 (TEXTURE, DIFFUSE) | All three implementations agree. The DDK table says `aSrc + aTex`. Follow the implementations; open question 5 |
| 0, 9+ | no change | no change | as 3dfx's `CHECK_STATE_LIMITS` and MSP2's switch. d3dim maps unknown values as DECAL; we do not |

### 3.2 Filters

| state | value | MAGFILTER | MINFILTER | MIPFILTER |
|---|---|---|---|---|
| TEXTUREMAG (17) | NEAREST (1), MIPNEAREST (3), LINEARMIPNEAREST (5) | POINT | | |
| TEXTUREMAG (17) | LINEAR (2), MIPLINEAR (4), LINEARMIPLINEAR (6) | LINEAR | | |
| TEXTUREMIN (18) | NEAREST | | POINT | NONE |
| | LINEAR | | LINEAR | NONE |
| | MIPNEAREST | | POINT | POINT |
| | MIPLINEAR | | LINEAR | POINT |
| | LINEARMIPNEAREST | | POINT | LINEAR (drawn as nearest mip: G26) |
| | LINEARMIPLINEAR | | LINEAR | LINEAR (drawn as nearest mip: G26) |

- **TEXTUREMIN.** All three implementations agree (`MSP2/d3dstate.c:699-729`, `VH5/D3RSTATE.C:2263-2296`,
  D3DIM 0x6d927800-0x6d927866).
- **TEXTUREMAG.** They differ for the MIP* values:
  - MSP2 maps every non-NEAREST value to LINEAR (`MSP2/d3dstate.c:681-697`);
  - d3dim maps only LINEAR to LINEAR;
  - 3dfx uses the named within-level filter (`VH5/D3RSTATE.C:2179-2195`).
  - We take 3dfx's rule, which matches two of the three implementations in each case. DDKHELP says only NEAREST
    and LINEAR are valid for MAG anyway.
- **What MIPFILTER > NONE does in the HAL.** It walks a chain only when the driver packed it (`SF_MIP_TOP`,
  `tex_view :777-786`). A chain left to DirectDraw keeps sampling its top level, as today.

### 3.3 Addressing and the inert mirrors

- **Address states.**
  - TEXTUREADDRESS (3) sets ADDRESSU and ADDRESSV (and TSS 12).
  - TEXTUREADDRESSU (44) sets ADDRESSU; TEXTUREADDRESSV (45) sets ADDRESSV.
  - Values 1-4 are copied raw; anything else is ignored. MIRROR and BORDER keep falling back to WRAP in
    `tex_view` (G33, G86).
- **`D3DTSS_ADDRESS` (12).** On stage 0 and stage 1 it is copied into that stage's 13 and 14 (`VH5/D7DP2.C:1602-1605`,
  `VH5/D6DP2.C:1490-1494`, `MSP2/d3dstate.c:62-66`).
- **Inert mirrors, as MSP2 does.** BORDERCOLOR (43) goes to TSS 15, MIPMAPLODBIAS (46) to TSS 19, and ANISOTROPY
  (49) to TSS 21. Nothing reads those TSS today, so they change no register. They become live with no further
  work when G27 (LOD bias) or G86 lands.
- **WRAPU/WRAPV (5/6) are NOT mapped by G08.** They are cylindrical wrap (`VH5/D3RSTATE.C:2567-2640` feeds
  them into `TS[0].wrap`, not into the address mode). That is G86's CPU-side coordinate fix. G86 must OR
  `rs[5]`/`rs[6]` into stage 0's wrap flags. G08 only counts them.

## 4. Implementation

### 4.1 A pure header: `KMD/include/vcr_legacy.h` (new)

The header is integer-only and Win32-free, like `vcr_rtfmt.h`, so that `tests/native` can compile it as it is.

```c
/* d3dtypes.h values; vcrdd_d3d.c pins each against the DDK with VCR_STATIC_ASSERT */
#define VCR_LRS_TEXTUREADDRESS     3u
#define VCR_LRS_TEXTUREMAG        17u
#define VCR_LRS_TEXTUREMIN        18u
#define VCR_LRS_TEXTUREMAPBLEND   21u
#define VCR_LRS_BORDERCOLOR       43u
#define VCR_LRS_TEXTUREADDRESSU   44u
#define VCR_LRS_TEXTUREADDRESSV   45u
#define VCR_LRS_MIPMAPLODBIAS     46u
#define VCR_LRS_ANISOTROPY        49u
/* also VCR_TSS_*, VCR_TOP_*, VCR_TA_*, VCR_TFG/TFN/TFP_*, VCR_FILTER_*, VCR_TBLEND_*, VCR_TADDRESS_* */
#define VCR_TOP_LEGACY_MODULATE   0x7ffffffeu   /* private: never a D3DTOP (FORCE_DWORD is 0x7fffffff) */

typedef struct { unsigned idx, val; } vcr_tsswr;

/* the stage-0 writes a legacy render state stands for: n (0..6) pairs in w[].
 * 0 = not a mapped state, or a value outside its enum (left alone). */
static __inline unsigned vcr_legacy_map(unsigned rs, unsigned v, vcr_tsswr w[6]);
/* D3DTSS_ADDRESS (any stage): the ADDRESSU/ADDRESSV pair, 0 if v is not 1..4 */
static __inline unsigned vcr_legacy_tss_address(unsigned v, vcr_tsswr w[2]);
/* the alpha op/arg1 that is actually drawn: resolves VCR_TOP_LEGACY_MODULATE */
static __inline void vcr_legacy_alpha(unsigned aop, unsigned arg1, int tex_has_alpha,
                                      unsigned *aop_out, unsigned *arg1_out);
/* "the texture has alpha" for that rule: an alpha mask or DDPF_ALPHAPIXELS, or any DXT */
static __inline int vcr_legacy_has_alpha(unsigned ddpf_flags, unsigned alpha_mask, int is_dxt);
/* Phase 0: slot 0..5 for rs 3/17/18/21/44/45 (-1 otherwise), value bit (v < 15 ? v : 15) */
static __inline int vcr_legacy_slot(unsigned rs);
static __inline unsigned vcr_legacy_valbit(unsigned v);
```

The pairs-out shape keeps the header free of DWORD/`unsigned long` pointer types. The caller applies the writes
to its own `DWORD tss[]`.

### 4.2 `KMD/display/vcrdd_d3d.c`

1. **`set_rs`** (`:1393-1406`). After the existing store, when `c->pd->d3d_feat & VCR_D3DFEAT_LEGACY`:
   - call `vcr_legacy_map(st, v, w)`;
   - for each pair whose value differs from `c->tss[idx]`, store it and set `c->dirty = 1`.

   The mapping runs **on every receipt, not only on a change**. DDKHELP says the override "is assigned ... when
   the driver receives" TEXTUREMAPBLEND = MODULATE. The runtime's TSS initialisation (section 2) can replace it
   after a first identical value, and the application's next MODULATE must restore it.
2. **`walk`, `D3DNTDP2OP_TEXTURESTAGESTATE`** (`:1591-1611`). For `st == D3DTSS_ADDRESS` on stage 0 or 1, under
   the same bit, also apply `vcr_legacy_tss_address(v)` to that stage's array.
3. **`compute_regs`** (`:921-1029`). Just before `r->fbzColorPath = color_path(c, tex) | CP_PARMADJUST;` (`:977`):

   ```c
   c->tex0_alpha = tex && vcr_legacy_has_alpha(t->lpGbl->ddpfSurface.dwFlags,
                                                t->lpGbl->ddpfSurface.dwRGBAlphaBitMask,
                                                dxt_class(surf_fcc(t)) != 0);
   ```

   `tex0_alpha` is a new context field. The call keeps its exact text, which `test_the_colour_path_always_carries_parmadjust`
   pins (`tests/python/test_vcr_kmd_d3d.py:198`).
4. **`color_path`** (`:676-745`). Right after `aop`/`b1` are read, under the bit, apply
   `vcr_legacy_alpha(aop, b1, c->tex0_alpha, &aop, &b1)`.
   - The sentinel becomes SELECTARG1(TEXTURE) when the texture has alpha, and SELECTARG1(DIFFUSE) otherwise.
     Both are register cases `color_path` already emits (`:726-732`).
   - Any other op passes through unchanged.
   - Gating the resolver too (not only the mapper) keeps the bit-off path exact, even for an application that
     sends 0x7ffffffe itself.
5. **Caps** (`VcrDdD3dHalInfo :2049-2113`). After `prim_caps`, under the bit:
   - `dwTextureBlendCaps |= D3DPTBLENDCAPS_DECALALPHA`, giving 0xcb → 0xcf, which equals 3dfx's (`VH5/D3INIT.C:3065-3077`);
   - `dwTextureFilterCaps |= D3DPTFILTERCAPS_MIPLINEAR`, low byte 0x17 → 0x1f.
   - Both go on the triangle caps and on the line caps (the line caps are a copy, `:2072`).
   - LINEARMIPNEAREST stays as it is: it belongs to trilinear, G26.
6. **Pins.** One `VCR_STATIC_ASSERT` per header constant against the DDK name, as `display/vcrdd_punt.c:302-307`
   does. For example `VCR_STATIC_ASSERT(lrs_mapblend, VCR_LRS_TEXTUREMAPBLEND == D3DRENDERSTATE_TEXTUREMAPBLEND)`.
   A wrong number in the header then fails the driver build.

### 4.4 Phase 0: which titles send what (log-only, default ON)

The counters are new `vcr_d3dctx` fields, zeroed by ContextCreate's `memset`. They are updated in `set_rs`, the
TSS handler, `D3d_ContextCreate` and `D3d_DrawPrimitives2`. **They write no register.** If G76 lands first,
these fields join its per-context record with the same meaning.

| field | meaning |
|---|---|
| `lgc_vals[6]` / `lgc_n[6]` | a value bitmask and a token count for rs 3, 17, 18, 21, 44, 45. The runtime's initial write shows as `n = 1`; a title that uses the state shows `n > 1` |
| `lgc_tss12` | value bitmask of `D3DTSS_ADDRESS`, stage 0 in the low half and stage 1 in the high half |
| `lgc_misc` | 0x1 WRAPU/V non-zero, 0x2 BORDERCOLOR non-zero, 0x4 MIPMAPLODBIAS non-zero, 0x8 ANISOTROPY > 1, 0x10 rs 42 (DX5's ALPHABLENDENABLE, retired) non-zero, 0x20 COLORKEYENABLE non-zero (G09), 0x40 a state-override token (rs >= 256, execute buffers: `VH5/D6DP2.C:1338-1355`; ours drops them at `:1396`), 0x80 a stage-0 COLOROP/ALPHAOP arrived as a TSS token, **0x100 a legacy texture state arrived AFTER such a TSS token** |
| `lgc_hctx_in` | `p->dwhContext` as ContextCreate receives it, read before `:1198` overwrites it. The NT header calls it "in/out" (`DDK8/d3dnthal.h:278`); whether XP puts the D3D interface version there is unknown **(inferred possibility)** |
| `lgc_dp2_flags` | OR of every DP2 `dwFlags` (2 = EXECUTEBUFFER) |

at 95678704). The message is split because a ring message holds 95 characters (`include/vcr_log.h:32`). The
values also go in b/c/d for `vcrlog.py`. Both events are added to the 513 description in `include/vcr_events.h:75`.

### 4.5 Unchanged when the bit is off

- Every register value and the order and count of writes are unchanged.
- The counters are CPU-only bookkeeping; the cost is one switch per render-state token, never per triangle.
- The mapper and resolver run only under the bit.
- The caps are unchanged (blend 0xcb, filter 0x03010317 as D3D8 reports it, `caps_124.txt`).
- `ctx_defaults` is unchanged.
- Nothing touches `vcrdd_3d.c`, the target sequence, SLI, the flip, Clear2 or the Glide hand-over.

## 5. Gating, and when the mapping can go default-ON

- **The Phase 0 counters (4.4) land default-ON.** They are log-only, the pattern `RPT/hal.md` §10 Phase 0 asks
  for. A Python source test pins that they never write a register.
- **The mapping lands default-OFF**, behind `Diag\D3DFeat` bit 1, read at boot. It is armed alone, one Diag change
  in one supervised clean boot.
- **It may graduate to default-ON**, as a kill switch `Diag\D3DLegacyStates` = 0 (absent = on, the
  Accel2DPattern/GdiGamma pattern), once all four of these hold on `.124`:
  1. the DX5/DX6 probe legacy tests pass at 640x480x16 fullscreen, and on the 86Box Voodoo3 bed;
  2. the d3dprobe D3D8 default matrix is unchanged with the bit on (40/40 at 1024x768x16 and x32), plus
     `bilinear` and `clamp`;
  3. Phase 0 shows that D3D7/8/9 contexts get no legacy token after a TSS token (`lgc_misc` 0x100 never set).
     Then the mapping is inert for them by construction;
  4. JK and MotS in game (and Thief Gold if it sends the states) show no regression in sky, HUD or translucency.
- **Why it can.** It is a pure state-translation fix: no new register combination, no timing, no new memory
  access. That is the class the plan calls "correctness quick wins" (`RPT/hal.md` §10 Phase 2).
- **If check 3 fails** (a D3D7/8/9 runtime sends a legacy state after its TSS):
  - scope the mapping to contexts whose `lgc_hctx_in` says interface ≤ 3, if Phase 0 shows that field carries
    the version;
  - or else to contexts that have seen `D3DNTHALDP2_EXECUTEBUFFER` or a non-default legacy value;
  - and re-prove before default-ON.

### 6.2 d3dprobe (D3D8) controls for the destination path: `bilinear`, `clamp`

D3D8 cannot send the legacy states, so d3dprobe tests what they are mapped onto. These are new tests, explicit at
first (`--tests bilinear,clamp`), in the style of `draw_cells` (`KMD/tools/d3dprobe.c:565-588`).

- **`bilinear`.**
  - Scene: a 2x2 R5G6B5 texture (column 0 black, column 1 white), drawn at x/y 64..192 (128 px, 64 px a texel).
    Settings: MAG/MIN LINEAR, MIP NONE, WRAP, SELECTARG1(TEXTURE), dither off, no blending.
  - Readback: row 128.
  - Reference: D3D texel centres give grey = 255 · clamp(2u − 0.5, 0, 1), with u = (x + 0.5 − 64)/128. That is
    26, 77, 128, 179, 230 at u = 0.30, 0.40, 0.50, 0.60, 0.70 (x = 102, 115, 128, 141, 154), tolerance ±24.
  - Pass:
    1. those five values within tolerance;
    2. a monotone ramp over x 96..160;
    3. at least 8 distinct levels in it.
  - The same scene with POINT must read only 0 and 255 (±12) and serves as the control.
  - The RESULT records the 50 % crossing. A half-texel shift fails check 1 and passes checks 2 and 3: that is G81
    evidence (the texel-centre half), not a G08 failure.
- **`clamp`.**
  - Scene: a 2x1 texture (black | white), POINT filtering, quad x 32..224 with u from −1 to 2.
  - Samples at u = −0.25, 0.25, 0.75, 1.25 (x = 80, 112, 144, 176).
  - CLAMP must read 0, 0, 255, 255 (±12); WRAP reads 255, 0, 255, 0.
  - The same again on V with a 1x2 texture, ADDRESSV CLAMP and ADDRESSU WRAP, which also proves INDEPENDENTUV.

## 8. Risks to proven paths

| path | risk | why / mitigation |
|---|---|---|
| default 16 bpp path, bit off | none | register traffic byte-for-byte unchanged; the counters are CPU-only; pinned by the Python tests |
| D3D8/D3D9 titles, bit on | low | they cannot set retired states. A runtime-injected legacy token after the TSS would be the only exposure: Phase 0 bit 0x100 detects it, and the d3dprobe matrix and UT2004/Halo menus must stay unchanged in boot B |
| DX5/DX6 titles, bit on | intended change; a wrong mode mapping would show | every mode is probed against analytic values; supervised in-game check of JK, MotS and Thief Gold |
| mip chains | low to medium | MIP* legacy values make DX5/6 titles walk chains for the first time, but only chains the driver packed (`SF_MIP_TOP`). If a chain's packing were wrong (G07), distant surfaces could show noise (the G06 class). `legacy_min` and d3dprobe `mip` must pass first; the in-game check includes distant surfaces |
| Glide/OpenGL coexistence, SLI, flip | none | no new register, no sequence or timing change; chip 0 only, as before |
| stability (the Max Payne class) | none added | no new memory access, FIFO use or wait |
| performance | none | bilinear and mip selection are free on the TMU (one bilinear footprint a pixel, `RPT/hw.md` Q14). Mipmapping can only reduce texture-cache misses |

## 10. Open questions

1. Does XP's d3dim forward application-time legacy `SetRenderState` calls from `IDirect3DDevice2/3` without
   filtering redundant ones? The device-creation stream is proven (section 2); Phase 0 `n > 1` and `legacy_order`
   answer the rest.
2. Do d3dim700, d3d8 or d3d9 ever put a legacy state into a D3D7/8/9 context after the TSS (`lgc_misc` 0x100)?
   d3dim700 has a render-state re-send loop over states 2-135 (0x7394f28c), whose consumer was not followed.
3. Does `dwhContext` on input to ContextCreate carry the runtime's interface version on XP? If it does, it is the
   clean scope for the mapping.
4. What does a DX5/DX6 title that never sets TEXTUREMAPBLEND get for stage-0 alpha?
   - The runtime's TSS initialisation sends SELECTARG1(TEXTURE) after its RS initialisation (section 2), so it
     gets alpha 1.0 for an R5G6B5 texture, as today.
   - DDKHELP says the DX6 default "matched" legacy MODULATE.
   - Optional reference: run the DX6 probe once on a fleet box with a vendor WHQL driver (same d3dim). This is
     read-only; it is not a benchmark comparison.
5. DECAL's alpha for a texture without alpha (implementations: 1.0; DDK table: vertex) and ADD's alpha
   (implementations: vertex; DDK table: sum). This follows the implementations, and the probe records both.
6. State overrides (rs ≥ 256, execute buffers) and rs 42 (DX5 ALPHABLENDENABLE).
   - If Phase 0 shows a title using either, that is a follow-up: 3dfx's override set (`VH5/D6DP2.C:1338-1355`),
     and 42 → 27 for legacy contexts.
   - Translucency driven by raw 42 would be off today, independent of G08.
7. Should G08 also drop `D3DPTFILTERCAPS_LINEARMIPNEAREST`, which the HAL draws as point + nearest mip? It is
   left to G26, which may make it real with LOD dither.
