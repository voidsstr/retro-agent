## 1. Verdict

1. **The defect is real.** `compute_regs` enables depth only for `ZENABLE == D3DZB_TRUE` (`KMD/display/vcrdd_d3d.c:986`),
   so `D3DZB_USEW` (2) draws with no depth test at all; `WINFO` (opcode 29) is skipped by size (`:1556`); `WBUFFER` is
   not in the raster caps (`:2019-2020`; live caps `00100191`).
2. **But no staged title sends USEW today, so "depth off" has no measured victim.** Every engine on the box that can
   W-buffer asks for `D3DPRASTERCAPS_WBUFFER` first (Thief Gold's Dark engine, Unreal 1's D3DDrv), and the D3D8/9 titles
   never ask for W at all (section 3). The bug becomes live only if a title sets USEW blindly, or once we advertise the cap.
3. **Step 1 (interim, default-ON): USEW draws as a Z-buffer.** One rule change, emitting exactly the register values the
   HAL already writes for `D3DZB_TRUE` (proven on silicon by every `ztest`); every other ZENABLE value stays
   byte-for-byte as today. Safe to land default-on with its d3dprobe check.
4. **Step 2 (the real W-buffer, default-OFF behind `Diag\D3DFeat` bit WBUF): native, single pass.**
   `fbzMode` bit 3 (`WBUFFER`) + bit 4, bit 21 left 0; the FBI's 1/W carries `rhw * aW + bW` from WINFO (3dfx's range
   remap, sanitized); the fog table is rebuilt in the chip's W domain; vertex fog moves from the W iterator to the Z
   iterator (`fogMode` bit 4, `FOG_Z`); `D3DPRASTERCAPS_WBUFFER` is reported only while armed.
5. **What arming changes:** Thief Gold and (inferred, same engine) System Shock 2 switch from a 16-bit Z to the W-buffer -
   the depth precision they had on 3dfx's own driver. The dormant Unreal 1 D3D renderers (Deus Ex, Unreal Gold, UT 436)
   would too. No D3D8/9 title changes.
6. **Two vendor bugs are not to be copied:** 3dfx's WINFO remap divides by `dvWNear`, so the runtime's own default WINFO
   `{0, 1}` gives `bW = NaN` (`VH5/D6DP2.C:1733-1734`); and its linear fog table under a W-buffer applies the 1/W remap to
   a W value (`world_w = WSCALE(world_w)`, `VH5/D3FOG.C:404`), which is dimensionally wrong (section 5).
7. **Priority P2, effort M** (Step 0 + Step 1: S). Promote to P1 if Step 0's counters catch a title sending USEW without
   the cap, or if Thief Gold / SS2 in game (G73) show distance z-fighting at 16 bpp that the armed W-buffer removes.

## 2. The defect, precisely

| ZENABLE | D3D meaning | today (`vcrdd_d3d.c:986-990`) | Step 1 (default) | Step 2 (WBUF armed) |
|---|---|---|---|---|
| 0 `D3DZB_FALSE` | no depth | no depth | no depth (unchanged) | no depth (unchanged) |
| 1 `D3DZB_TRUE` | Z-buffer | `FZ_DEPTH \| FZ_ZFUNC \| [FZ_ZAWRITE]` | unchanged, byte for byte | unchanged, byte for byte |
| 2 `D3DZB_USEW` | W-buffer | **no depth test, no Z write** | same bits as TRUE (Z-buffer) | `+ FZ_WBUFFER`; Wfbi = remapped 1/w |
| other | invalid | no depth | unchanged (no depth) | unchanged (no depth) |

- The guard `c->target.z_on` stays first: no accepted aux buffer, no depth, for every value.
- `WINFO` (`D3DNTHAL_DP2WINFO {D3DVALUE dvWNear, dvWFar}`, 8 bytes, the DDK sends one record) is skipped by
  `rec_size` (`:1556`). The DDK: "The driver should update the w-buffer portion of its internal rendering context with the
  w ranges specified in this structure. The driver can use this information to scale the w-buffer" (W2K DDK
  `D3DNTHAL_DP2WINFO`).
- `dvMaxVertexW` is already 65536 (`:2152, 2163`), the chip's W limit. Nothing to change there.

**Runtime side (XPRT).** All three XP runtimes build WINFO themselves from the projection matrix, with one formula:

- d3d8.dll `0x6d9e2640` (a DDI-layer vtable method; `push $0x8; push $0x1d; call` reserves the record),
  d3dim700.dll `0x739557bf`, d3dim.dll `0x6d91af6e` (`movb $0x1d` header, `wStateCount` 1).
- `{dvWNear, dvWFar} = {0.0, 1.0}` when `_33 == _34` or `_33 == 0.0` (the constant at d3d8 `0x6d9a1404` is 0.0f);
  otherwise `dvWNear = _44 - _34*_43/_33`, `dvWFar = _44 + _34*(_44 - _43)/(_33 - _34)`.
- A standard perspective matrix gives `{Zn, Zf}`; the identity (the default for an application that never sets one)
  gives `{1, 1}`.
- When the runtimes call it (on `SetTransform(PROJECTION)`, at device creation, for TL-only applications) was not traced.
  Step 0 logs it. d3d9.dll was not checked (Halo and NewDark do not use USEW).

So: the gap's "inferred: Dark engine, DX6 titles, UE2, Halo" list is half right. The Dark engine and Unreal 1 *would*
W-buffer, but only with the cap, so today they Z-buffer correctly. UE2 and Halo never W-buffer.

## 4. What the hardware does

- **`fbzMode` bit 3, W-buffer select** (SPEC §8.25 "fbzMode Register"; `INC:713`; ours `FZ_WBUFFER`,
  `KMD/include/vcr_3dregs.h:108`): "When bit(3)=1 enabling w-buffering, the inverse of the normalized w iterator is used
  for the depth-buffer comparison. This in effect implements a floating-point w-buffering scheme utilizing a 4-bit
  exponent and a 12-bit mantissa. The inverted w iterator is used so that the same depth buffer comparisons can be used as
  with a typical z-buffer." So `ZFUNC`, `ZAWRITE` and the clears keep their meaning.
- **`fbzMode` bit 21, depth float select** (`INC:733`): 0 = the unclamped W iterator is converted to the 4.12 float,
  1 = the Z iterator is. We keep it 0 (3dfx's D3D HAL does, `VH5/D3RSTATE.C:1114-1116`). Glide h5 uses bit 21 = 1 *with
  bit 3 cleared* for its fog-coordinate W-buffer (`G5/gglide.c:3758-3762`, sending `depth_range*(1-oow)`,
  `G5/fxcmd.h:1579-1585`). Those are different, unverified semantics, and this design does not use them.
- **The W is the FBI's 1/W (`sOowfbi`, setup bit 3)**, the same iterator that indexes the 64-entry fog table ("the MSBs
  of a normalized floating point representation of (1/W)", SPEC §8.22). The TMUs' own 1/W (`sOow0/1`) is separate, so
  perspective texturing never sees the remap.
- **Range:** the 4.12 float covers 1/W in [2^-16, 1), i.e. W in (1, 65536]. 1/W ≥ 1 encodes as 0 (nearest), below 2^-16
  as 0xFFFF (farthest), per the long-standing Voodoo model (MAME/86Box; the Napalm SPEC gives no more detail). Hence 3dfx's
  `WMIN = 1`, `WMAX = 65520` (`VH5/D3GLOBAL.H:1230-1232`).
- **32 bpp:** D3DXLS row 83: "24-bit W (w/8-bit stencil): Napalm Yes, render target must be 32bpp"; Glide's
  `NAPALM_WDEPTHVALUE_FARTHEST 0xFFFFFF` (`G5/diget.c:783-791`). The exact 24-bit encoding is not documented. It does not
  matter for comparisons, and clears to 0.0/1.0 stay nearest/farthest under any monotonic encoding.
- **Fog sources, `fogMode[4:3]`** (SPEC §8.22): 0 = the W table; bit 3 = iterated alpha; **bit 4 = "the upper 8 bits of
  the iterated Z component"**; both = iterated W per 3dfx's code (hw.md Q15; SPEC's own sentence disagrees, G32's
  business). Under a W-buffer the Z iterator is free, so vertex fog rides in Z.
- **Z iterator format:** 20.12 at 16 bpp, **28.4 at 32 bpp** (SPEC §8.5 "startZ and fstartZ registers": "when 32-bit
  rendering is enabled (renderMode[1:0]=0x2) then the startZ register is assumed to be in a 28.4 format"). The setup unit takes `sVz` as a float in depth units at both depths (ours:
  `z * 65535` / `z * 16777215`, `KMD/display/vcrdd_3d.c:201, 292`; proven at both depths).

## 5. What 3dfx did, and what not to copy

| 3dfx (`VH5`) | take it? |
|---|---|
| `zEnable`: USEW → `(fbzMode & ~SST_DEPTH_FLOAT_SEL) \| ENDEPTHBUFFER \| WBUFFER` (`D3RSTATE.C:1114-1116`); Z writes follow ZWRITEENABLE for TRUE and USEW alike (`:1164-1188`) | **yes** |
| caps: `D3DPRASTERCAPS_WBUFFER \| WFOG` for DX ≥ 6 (`D3INIT.C:2924-2927`) | **yes, only while armed** (we already report WFOG) |
| WINFO → `minW/maxW`; when `[minW, maxW]` does not fit `[1, 65520]`: `aW = (minW*maxW/(minW-maxW))*(1/WMAX - 1)`, `bW = 1/WMIN - aW/minW`, else identity (`D6DP2.C:1621-1741`); vertex `wfbi = rhw*aW + bW` (`D6TRI2I.C:873`, `CLIPREND.H:264`, lines and points too) | **yes, sanitized:** the formula divides by `minW`. The runtimes' default WINFO `{0, 1}` (section 3) gives `aW = 0`, `bW = 1 - 0/0 = NaN`, i.e. every W-buffered pixel compares against NaN. Ours treats any range that is not finite, positive and increasing as identity |
| The Voodoo3-only clamp `maxW > WMAX → WMAX` (PRS 12663, Roll Cage II, `D6DP2.C:1640-1641`, `!IS_NAPALM`) | **no** (Napalm path; the general remap handles any range) |
| `FnZTable` (`D3FOG.C:202-239`): table fog + W-buffer = W table on the remapped `wfbi` (row 8); **vertex fog + W-buffer = `ENFOGGING \| FOG_Z \| FOG_DITHER` with `sVz = (255 - specular.a) << 8`** (row 5; `D6TRI2I.C:880`, the same in `W9X/D6TRI2I.C:883`) | **yes, as a routing table** (6.3.4). At 32 bpp the Z is 28.4 and the vendor's `<< 8` lands below the bits the fog unit reads under either reading of SPEC (inferred), so ours uses `<< 16` there, settled by a probe |
| Linear fog table under W: `world_w = WSCALE(world_w)` (`D3FOG.C:404`) | **no**: WSCALE is the 1/w map, and applying it to a W does not give the eye-space W. For `{0.1, 1000}` the chip's W 65520 (the far plane) is treated as w = 6552 instead of 1000. With linear fog 100..1000, entry 54 (eye w ≈ 567) reads all fog (255) where D3D says 132. Exp/exp2 ignore the remap entirely (`:291-358`). Ours inverts the map exactly (6.3.4) |
| `initNewRC`: `aW = 1, bW = 0` (`D3RSTATE.C:3873-3874`) | **yes**: no WINFO = the raw 1/w. This is what Thief Gold was tested against on 3dfx hardware |

Remapping only when the range does not fit (vendor parity) keeps a title that sends `W ∈ [1, 65520]` on exactly the
depth values it saw on a real Voodoo, and keeps the fog table byte-identical in that case. Always remapping would spread
narrow ranges over all 16 octaves; that is open question 6.

## 6. Design

### 6.1 Step 0: measure (log only, default-on, no register change)

- **Parse WINFO instead of skipping it** (`walk`, `vcrdd_d3d.c:1572`; drop it from `rec_size :1556`):
  ```c
  case D3DNTDP2OP_WINFO:                      /* n x {dvWNear, dvWFar}: the W range, float BITS */
      NEED(n * 8);
      if (n) {
          DWORD wn = rd(p + (n - 1) * 8), wfar = rd(p + (n - 1) * 8 + 4);
          c->winfo_n++;
          if (wn != c->winfo[0] || wfar != c->winfo[1]) {
              c->winfo[0] = wn;
              c->winfo[1] = wfar;
              if (c->pd->d3d_wbuf)            /* only an armed HAL re-sends state for it */
                  c->dirty = 1;
          }
      }
      p += n * 8;
      break;
  ```
  The HAL stays integer-only (`-mgeneral-regs-only`): it stores float bits, as it already does for FOGSTART/END.
  `ctx_defaults` sets `winfo = {0, 0}` ("none", which sanitizes to identity).
- **Counters** in `vcr_d3dctx`: `usew_sets` (`set_rs`: ZENABLE set to 2), `winfo_n`, plus the last WINFO bits.
- **Two events (513, the next free `what`)**: the first WINFO of a context at INFO (`ctx %u WINFO near %x far %x`), and at
  `ctx_free` (only when `usew_sets || winfo_n`) `ctx %u depth: USEW %u drawn as %s, WINFO %u last %x %x`. Both are once
  per context (G52's logging cost is per call, so nothing per draw).
- With `D3DFeat` WBUF off, register traffic is identical: a WINFO never sets `dirty`.

Purpose: confirm section 3 dynamically during G73's in-game pass (which titles send USEW, which receive WINFO, with which
range), and answer open questions 1-3.

### 6.2 Step 1: USEW draws as a Z-buffer (default-on)

A Win32-free header so a native test can execute the rule (the `vcr_rtfmt.h`/`vcr_3dseq.h` pattern; G77):

```c
/* include/vcr_depth.h - D3D ZENABLE -> fbzMode depth bits (integer only) */
#define VCR_ZB_FALSE 0u
#define VCR_ZB_TRUE  1u
#define VCR_ZB_USEW  2u
static __inline unsigned vcr_depth_bits(unsigned zenable, unsigned zfunc3, unsigned zwrite,
                                        unsigned z_on, unsigned wbuf_armed, unsigned *wbuf)
{
    unsigned b;
    *wbuf = 0;
    if (!z_on || (zenable != VCR_ZB_TRUE && zenable != VCR_ZB_USEW))
        return 0;
    b = FZ_DEPTH | FZ_ZFUNC(zfunc3) | (zwrite ? FZ_ZAWRITE : 0);
    if (zenable == VCR_ZB_USEW && wbuf_armed) {
        b |= FZ_WBUFFER;                /* bit 21 stays 0: the float is of W */
        *wbuf = 1;
    }
    return b;
}
```

`compute_regs` replaces `:986-990` with
`r->fbzMode |= vcr_depth_bits(c->rs[ZENABLE], cmp(c->rs[ZFUNC]), c->rs[ZWRITEENABLE], c->target.z_on, c->pd->d3d_wbuf, &r->wbuf);`.
With WBUF off, USEW yields `FZ_DEPTH | FZ_ZFUNC | [FZ_ZAWRITE]`, the TRUE values. Nothing else in the vertex path changes:
the Z is the runtime's `sz`, which software vertex processing always computes from the projection.

### 6.3 Step 2: the W-buffer (default-off, `Diag\D3DFeat` bit WBUF)

#### 6.3.1 Depth

`vcr_depth_bits(..., wbuf_armed = 1)` adds `FZ_WBUFFER` for USEW and reports `r->wbuf = 1`. The choice is per context
state (ZENABLE) and never per fog mode or per draw, so one depth buffer never holds a mix of W and Z values between clears.
Both depths: 16-bit W at 16 bpp (and in the 16-over-32 case, `vcr_rt_format(1,16,32) = 16`), 24-bit W at 32 bpp
(D3DXLS row 83). Single pass.

#### 6.3.2 The W range: `common/vcr_wbuf.c` (FPU, host-testable, like `vcr_fog.c`)

```c
#define VCR_WMIN 1.0f
#define VCR_WMAX 65520.0f
/* WINFO's float bits -> rhw' = rhw * aw + bw. [1/wfar, 1/wnear] maps onto [1/65520, 1] when
 * [wnear, wfar] does not fit [1, 65520] (3dfx D6DP2.C), identity otherwise - and for any range
 * that is not finite, positive and increasing (the runtimes' {0,1} default; 3dfx: NaN). 1 = remapped */
int vcr_wbuf_scale(unsigned near_bits, unsigned far_bits, float *aw, float *bw)
{
    float n = vcr_fbits(near_bits), f = vcr_fbits(far_bits);
    *aw = 1.0f;
    *bw = 0.0f;
    if (!(n > 0.0f) || !(f > n) || !(f < 3.0e38f))      /* NaN fails every compare */
        return 0;
    if (n >= VCR_WMIN && f <= VCR_WMAX)
        return 0;
    *aw = (n * f / (n - f)) * (1.0f / VCR_WMAX - 1.0f / VCR_WMIN);
    *bw = 1.0f / VCR_WMIN - *aw / n;
    return 1;
}
/* the eye-space w whose remapped 1/w is 1/wchip (the fog table's inverse map) */
float vcr_wbuf_eye_w(float wchip, float aw, float bw)
{
    float d = 1.0f / wchip - bw;
    return d > 0.0f ? aw / d : 3.0e38f;                  /* beyond infinity: all fog */
}
```

Worked values (Python check of the formula): `{0.1, 1000}` → `aW = 0.100008, bW = -8.47e-5`, so 1/0.1 maps to 1.0 and
1/1000 to 1/65520; `{0.5, 50}` → `aW = 0.505043, bW = -0.0100856`; `{1, 1000}` → identity; `{0, 1}`, `{1, 1}` → identity.
Precision: for far geometry `aW*rhw + bW` cancels, but the float error (~6e-11 absolute) is far below the 4.12 mantissa
step (2.4e-4 relative). Cost: one multiply-add per vertex.

#### 6.3.3 The vertex path (`vcrdd_3d.c vertex()`, `:201-209`)

```c
    wf(pd, V3D_SVZ, d->fog_z ? (float)(255u - (*(const ULONG *)(v + d->spec_off) >> 24)) * d->fogz_scale
                             : p[2] * d->z_scale);
    if (d->wbuf)
        wf(pd, V3D_SOOWFBI, oow * d->w_a + d->w_b);     /* W-buffer depth and fog-table index */
    else if (d->fog_vertex)
        ... unchanged (synthetic 1/W on the ramp) ...
    else
        wf(pd, V3D_SOOWFBI, oow);
```

- Same registers, same order, same count; with `wbuf = fog_z = 0` it is today's sequence write for write. The TMU W
  (`sOow0/1`, `:212, 218`) stays the raw `oow`.
- `vcr3d_draw` gains `ULONG wbuf, fog_z; float w_a, w_b, fogz_scale;`. A new `VcrDd3dDrawWbuf(d, regs, target)` in
  `vcrdd_3d.c` fills them from `regs.winfo` through `vcr_wbuf_scale`. `prepare()` calls it inside the DP2 walk's FPU
  bracket (`vcrdd_d3d.c:1861-1868`), as it already calls `VcrDd3dTexScale`.
- `fogz_scale` = 256 at 16 bpp (the vendor's `<< 8`: Z[27:20] of 20.12) and 65536 at 32 bpp (Z[27:20] of 28.4, which is
  also "the top 8 bits of the 24-bit depth"). The 32 bpp value is the one the `wbuffer_fogv` probe settles (open question 4).
- No clipping is added: the runtime clips (software VP), or the application supplies TL vertices. An `rhw'` outside
  [1/65520, 1] clamps to nearest or farthest; it cannot fault.

#### 6.3.4 Fog routing: one table, shared with G32

A pure helper in `include/vcr_fog.h`, the equivalent of 3dfx's `FnZTable`, so G23 and G32 edit one place:

| fog | depth | carrier | fogMode | table |
|---|---|---|---|---|
| off | any | none | 0 | none |
| table | Z / none | `WTABLE`: Wfbi = raw rhw | `FM_ENABLE \| FM_DITHER` | D3D fog of w (today) |
| vertex | Z / none | `WRAMP`: synthetic 1/W (today; G32 may change this row) | `FM_ENABLE \| FM_DITHER` | ramp (today) |
| **table** | **W** | `WTABLE`: Wfbi = `rhw*aW + bW` | `FM_ENABLE \| FM_DITHER` | **D3D fog of `vcr_wbuf_eye_w(w_chip(i))`** |
| **vertex** | **W** | **`ZTOP`**: `sVz = (255 - a_spec) * fogz_scale` | **`FM_ENABLE \| FM_DITHER \| FM_FOG_Z`** (new `#define FM_FOG_Z (1u << 4)`) | not consulted |

- **Table generation:** `vcr_fog_table_ws(mode, start, end, density, aw, bw, out)`. For entry i, the chip's W is
  `w_chip = vcr_fog_index_w(i)`, and the fog is D3D's function of `w_eye = aW / (1/w_chip - bW)`. **Identity is
  special-cased to `w = vcr_fog_index_w(i)`**, so `vcr_fog_table()` (now a wrapper with `(1, 0)`) stays byte-identical;
  `aw/(1/w)` could differ by an ulp.
- **Fog cache** (`VcrDd3dState :86-101`, `pd->fog_loaded[4]`): the key gains `r->wbuf` and `r->winfo[2]` (new
  `pd->fog_wbuf`, `pd->fog_winfo[2]`). `compute_regs` copies the context's WINFO into `r->winfo` only when `r->wbuf`, so
  with WBUF off both are always 0 and hits and misses are exactly today's. Under `FM_FOG_Z` no table is loaded.
- **Vertex fog without a specular FVF** stays as today (no fog, `prepare :1358-1360`).

#### 6.3.5 Caps and plumbing

- `prim_caps(c, pd)`: `if (pd->d3d_wbuf) c->dwRasterCaps |= D3DPRASTERCAPS_WBUFFER;` (tri and line caps). Expected
  D3D8 RasterCaps on `.124` armed: `0x00140191`.
- `Diag\D3DFeat` (the shared D3D feature DWORD the other designs propose: G05 §4.2, G12; bits allocated in
  `include/vcr_d3dfeat.h`, carried whole in an appended `vcr_info.d3dfeat`, because `vcr_info.flags` is full at 0x7fff).
  Bit `VCR_D3DFEAT_WBUF`, provisionally the first free one after G12's 6-8 (9, 0x200). The final number is assigned in that
  header.
- `VcrDd2dInit`: `pd->d3d_wbuf = (info.d3dfeat & VCR_D3DFEAT_WBUF) && !pd->d3d_disabled`. **Every chip with the 3D
  engine**: fbzMode bit 3 and FOG_Z exist since SST-1, and D3DXLS lists 16-bit W for Voodoo3. That lets the 86Box Voodoo3
  bed (which emulates the W-buffer and FOG_Z) run the 16 bpp probes before silicon. Event 513 "armed: W-buffer
  (Diag\D3DFeat bit N)".
- If `D3DFeat` does not exist yet when this lands, G23 creates it per G05 §4.2, with the ABI test.

## 9. Regression tests

### 9.1 `tests/native/test_vcr_kmd_wbuf.c` (new; includes `vcr_depth.h`, `common/vcr_wbuf.c`, `common/vcr_fog.c`)

- **`usew_enables_depth`**: `vcr_depth_bits(2, 3, 1, 1, 0, &w) == 0x470` (`FZ_DEPTH|FZ_ZFUNC(3)|FZ_ZAWRITE`), `w == 0`
  (**fixed**). A local `old_depth_bits()` that reproduces `vcrdd_d3d.c:986` gives **0** for USEW (**the bug**). For
  ZENABLE in {0, 1, 3, 0xffffffff} the new rule equals the old one (unchanged). Armed: USEW → `0x478`, `w == 1`; TRUE
  armed stays `0x470`; bit 21 never set; `z_on = 0` → 0 for every value.
- **`wbuf_scale`**: `{1, 1000}` → (1, 0), not remapped; `{0.1, 1000}` → `aW*10 + bW == 1` and
  `aW*0.001 + bW == 1/65520` (relative 1e-5); `{0, 1}`, `{1, 1}`, `{1000, 0.1}`, NaN, ±inf, negatives → identity. 3dfx's
  formula evaluated on `{0, 1}` **is NaN** (asserted, documenting the vendor bug not copied).
- **`wfloat_model`**: a model of SPEC's 4.12 inverse-W float (labelled a model, not silicon) is non-decreasing over the
  remapped `[WNear, WFar]`. W 900 vs 902 encode differently (0x9dcc vs 0x9dd6) while their 16-bit hyperbolic Z
  (Zn 1, Zf 1000) is equal (65527): the precision gap the W-buffer closes.
- **`fog_table_identity_is_todays`**: `vcr_fog_table_ws(m, s, e, d, 1, 0)` == `vcr_fog_table(m, s, e, d)` byte for byte,
  for LINEAR/EXP/EXP2/RAMP over a parameter grid (old path unchanged).
- **`fog_table_in_the_w_domain`**: for `{0.1, 1000}` and linear fog 100..1000, entry i fogs as D3D's function of
  `vcr_wbuf_eye_w(w_chip(i))`. The vendor's `WSCALE(world_w)` table is also computed, and the test asserts it is wrong:
  entry 54 is 255 there against 132 (the second bug not copied).
- **`fog_route`**: the five rows of 6.3.4. The three Z/none rows return today's fogMode bits (**old values**); the two
  W rows return the new ones. `fogz_scale(16) == 256`, `(32) == 65536`; amount 128 at 16 bpp → `((128*256) << 12 >> 20)
  & 0xff == 128`; at 32 bpp (28.4) → `((128*65536) << 4 >> 20) & 0xff == 128`.

## 10. On-box verification (`.124`; supervised; activation check, then `safe-reboot.py`; no Glide session before the probes, G01)

1. **Step 0 + 1 build on `.124`.** First, before the driver swap, run the new `d3dprobe --tests usew` on the deployed driver

   deploy, and run `d3dprobe render --full --res 640x480 --bpp 16` and `--res 1024x768 --bpp 32` with the default gate

   LogLevel 2: the context-end events should show USEW 0 for all (section 3), and which of them receive WINFO.
2. **Arm `Diag\D3DFeat` = WBUF** (REGWRITE, read back), reboot: `d3dprobe caps` → RasterCaps `0x00140191`; `render
   --full` at 640x480x16 and 1024x768x32 with the default gate plus

   only). The ring shows a WINFO of about (0.1, 100) for `wbuffer_near` (bits near `0x3dcccccd`, `0x42c80000`; the

## 11. Risk to proven paths

- **Default 16 bpp path:** Step 0/1 change no register traffic for ZENABLE ≠ 2. WINFO parsing adds a bounded record read
  (the old skip used the same size and the same NEED check). With WBUF off nothing in Step 2 executes.
- **Glide/OpenGL coexistence:** `fbzMode` and `fogMode` are composed whole at every state send (`compute_regs :978`,
  `:1002`), so a Glide session's `WBUFFER`/`DEPTH_FLOAT_SEL`/`FOG_Z` bits cannot leak into D3D, and ours cannot leak into
  Glide (Glide writes its own). A fog table Glide left in the chip is G41's (unchanged here).
- **SLI:** none; D3D is chip 0 (G51). The registers involved are ordinary broadcast state for a future SLI D3D.
- **Flip path:** untouched.
- **Armed risks:** (a) a title whose TL vertices have w < 1 and that gets no WINFO collapses near geometry to depth 0 under
  W. That is 3dfx-identical behaviour (identity default), visible in game, never a hang; disarm restores Z. (b) The 32 bpp
  FOG_Z scale (probe). (c) Z bias under W (G22) must be expressed in W-float units; nothing uses it before G22.
  Stability: the W-buffer uses the same aux buffer, the same addresses and the same command sequence; no new memory access.

## 13. Open questions

1. Does the D3D8/9 runtime pass `ZENABLE = USEW` to a DX7 driver that does not report WBUFFER, or rewrite it?
   (d3dprobe `usew` with the Step 0 event naming the value received.)
2. When do the runtimes send WINFO: on `SetTransform(PROJECTION)`, at device creation, for TL-only applications? The
   formula and the `{0,1}`/`{1,1}` defaults are read from d3d8/d3dim700/d3dim; the call sites are not.
3. Does Thief Gold (DX6, TL vertices) produce a WINFO, and what W range do its vertices span? If w < 1 near the camera
   without a WINFO, W-buffering collapses that geometry, as it did on 3dfx's driver.
4. FOG_Z at 32 bpp: `<< 16` (this design; Z[27:20] of 28.4 = top 8 bits of the 24-bit depth) or the vendor's `<< 8`.
   `wbuffer_fogv --bpp 32` decides.
5. The 24-bit W encoding at 32 bpp (SPEC describes only 4.12). It matters only for clears other than 0/1 and for G22.
6. Vendor parity (remap only out of [1, 65520]) or always remap (all 16 octaves for narrow ranges)? Start with parity;
   revisit only if an in-game title shows W z-fighting with a narrow range.
7. Should 32 bpp USEW simply draw through the 24-bit Z if the 32 bpp probes misbehave? A 24-bit Z already resolves 0.06 %
   at the far plane for Zn/Zf = 1e-4, so the W-buffer's value is at 16 bpp.
8. Shogo and AvP were not resolved statically (execute buffers, wrappers). Step 0 covers them.
