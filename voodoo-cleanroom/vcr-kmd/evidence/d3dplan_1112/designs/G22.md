## 0. Summary

**The gap is real and fixable, and the fix is small.** `ZBIAS` (render state 47) is stored in `c->rs[]` like
every other state and never read; `FZ_ZBIAS` is defined and never set; the cap is not reported. The VSA-100 has a
native constant depth bias (fbzMode bit 16 + zaColor), and 3dfx's own V5 HAL used it.

**The design, in one paragraph.** A new Win32-free header, `KMD/include/vcr_zbias.h`, turns (ZBIAS, ZFUNC, the
target's 3D pixel size) into one zaColor value: `level << 1` at 16 bpp, `level << 9` at 32 bpp (3dfx's scale,
the same fraction of the depth range in both), negative ("toward the viewer") for every compare function except
GREATER/GREATEREQUAL, level clamped to 0..16. `compute_regs` sets `FZ_ZBIAS` and carries that value only for a
depth-tested draw whose ZBIAS is non-zero, and only when `Diag\D3DFeat` bit 2 is set. `VcrDd3dState` writes
`zaColor` with the rest of the state for such a draw (one extra PCI write). `prim_caps` reports
`D3DPRASTERCAPS_ZBIAS` under the same bit. **Nothing changes in the clear:** zaColor is FASTFILL's depth too, but
every clear already marks the state dirty and forces a full state re-send before the next triangle
(`KMD/display/vcrdd_d3d.c:1419-1420`), so the bias goes back with the state, by construction. A draw without a
bias, and every draw with the switch off, is byte-for-byte today's register traffic.

**Facts this design adds to the brief:**

1. **Unreal Engine 2 already sends ZBIAS to our HAL, whatever the caps say (measured in the binaries).**
   `FD3DRenderInterface::SetZBias(INT ZBias)` stores `min(max(ZBias * 5, 0), 15)` into its deferred
   render-state slot 14, and the commit calls `SetRenderState(0x2f = D3DRS_ZBIAS, v)` through the device
   vtable (+0xc8) whenever the value changed. Neither step looks at the caps. The cap is read once, into a
   member at +0x50, and for the "D3D Driver: Supports Z biasing" log line. Same code in both builds
   (`LIB/UT2004/System/D3DDrv.dll` md5 b6bb4d87…: SetZBias at VA 0x100167e0, the commit's `push 0x2f` at
   0x1001a809, the cap read at 0x10010ba0 and its log line at 0x10010ec1; `LIB/UT2003/System/D3DDrv.dll` md5
   04c412ca…: SetZBias at 0x10014470, commit at 0x10017aa9; read with `i686-w64-mingw32-objdump -d`). So UE2
   asks for biases of 5, 10 or 15 today, and our HAL draws them unbiased. Who reads the +0x50 flag was not
   traced.
2. **The hardware adder is signed and saturating, and the biased depth is also what a passing pixel writes.**
   SPEC's depth-unit diagram: "1. Sign extend 16-bit zaColor to 18 bits / 2. Convert 16-bit depth to 18-bit
   {underflow,underflow,depth} / 3. Add 18-bit values / 4. Clamp to 0-FFFF". SPEC fbzMode bit 20: "Regardless of
   the state of fbzMode bit(20), the biased iterated Z/W is written into the depth buffer if the depth buffer
   function passes."
3. **3dfx's sign rule breaks an EQUAL pass.** 3dfx negates only for LESS/LESSEQUAL (`VH5/D3RSTATE.C:1291-1296`).
   A LESSEQUAL pass at ZBIAS b writes `z - 2b`; an EQUAL pass over it at the same ZBIAS then tests `z + 2b`
   and never matches. This design negates for everything except GREATER/GREATEREQUAL, and a probe test pins it.
4. **3dfx keyed the scale to the primary's depth** (`GETPRIMARYBYTEDEPTH`, `VH5/D3RSTATE.C:1285-1288`). A 16 bpp
   target on a 32 bpp desktop then got `<< 9`: 256 times the bias. This design keys it to the target's 3D pixel
   size, the depth the engine actually iterates. That also covers the 16/16-in-32 case (a 16 bpp target over a
   32-bit Z is drawn with a 16-bit depth, `KMD/include/vcr_rtfmt.h:70-78`) and G10's promoted D16 at 32 bpp.
5. **Which titles call it:** UE2 (above); Battlefield 1942 calls `SetRenderState(0x2f, …)` from a cached value
   (`LIB/BF1942/BF1942.exe` md5 a56d63e8…, VA 0x603bd9 and 0x604a3b); **Red Faction does not** (no immediate
   0x2f among the 53 `SetRenderState` call sites of `LIB/RedFaction/rf.exe`, md5 0ba3b15d…; inferred: it
   offsets its decal geometry itself). Halo is D3D9 and uses `DEPTHBIAS` (string in `halo.exe`); its per-card
   `DecalZBiasValue`/`DecalSlopeZBiasValue` exist only for Radeon 9500-9800 (`LIB/Halo/config.txt:311-329,
   375-378`); the 3dfx entry carries only `DisableRenderTargets` (`:115-118`). Whether the D3D9 runtime turns
   `DEPTHBIAS` into ZBIAS for a DX7-DDI driver is unknown.

**Gating:** `Diag\D3DFeat` bit 2 (value 4, hal.md §10 Phase 2 numbering), default OFF, read at boot.
**Effort:** M. **Priority:** P1. **Depends on:** G01, for verification only.

## 1. The defect, as measured

| what | where |
|---|---|
| ZBIAS is stored and never read | `set_rs` stores state 47 like any state < 256 (`KMD/display/vcrdd_d3d.c:1393-1406`); `compute_regs` (`:921-1029`), the only reader of `c->rs[]`, has no reference to it (grep -i `zbias` over `KMD/display` and `KMD/include`: only `FZ_ZBIAS`'s define) |
| `FZ_ZBIAS` is never set | defined at `KMD/include/vcr_3dregs.h:115`; depth is `FZ_DEPTH \| FZ_ZFUNC \| FZ_ZAWRITE` only (`vcrdd_d3d.c:986-990`) |
| zaColor is written only by the clear | `KMD/display/vcrdd_3d.c:160` (FASTFILL's depth); `vcr3d_regs` has no zaColor field (`KMD/display/vcrdd_3d.h:36-44`) |
| the cap is absent | built RasterCaps `0x001001b1` (`vcrdd_d3d.c:2019-2020`); D3D8 reports `00100191` (`caps_124.txt`); no `0x4000` |
| UE2 sees no Z biasing | `ONBOX/games/UT2003_flyby/UT2003.log:30-42`: the D3DDrv capability lines end with "Supports BLENDDIFFUSEALPHA"; no "Supports Z biasing" |
| UE2 sends ZBIAS anyway | section 0, fact 1 (binary) |

**What it costs in game (inferred).** A biased draw is drawn at its own depth. Where a decal or projector
re-uses the surface's own triangles, LESSEQUAL passes anyway. Where its triangles differ (a projector clipped to
its frustum, a decal mesh, a blob shadow), the 16-bit depth of the two surfaces differs by rounding, and the decal
flickers ("z-fights") or vanishes. UE2 runs at 16 bpp with D16 on this card (`ONBOX/session_log.md`, UT2003 at
10:23 and UT2004 #2 at 10:40: "back-buffer format 23 (16-bit) / depth-buffer format 80 (16-bit)"), the depth with
the least slack. No 11-12 frame isolates a decal: G05 (half-bright lighting), G06 (block noise) and G18 (white
sky) dominate those frames.

## 3. Design

### 3.1 Scope

- **In:** ZBIAS on every Z-buffered D3D draw (DP2 triangles, strips, fans, indexed, immediate); the cap; two
  per-context counters; four d3dprobe tests; host tests; docs.
- **Out, by the hardware:** D3D9 `SLOPESCALEDEPTHBIAS` (no register; a DX7 DDI never receives it anyway).
- **Out, later items:** the W-buffer (G23). Today `ZENABLE = USEW` turns depth off (`vcrdd_d3d.c:986`), so no
  bias can apply there. When G23 sets `FZ_DEPTH | FZ_WBUFFER`, this same rule adds zaColor to the 4.12 float W
  depth (SPEC: "irrespective of Z or 1/W"). That is a relative bias of `2·level` mantissa steps, sensible for
  decals (inferred). G23 keeps or changes the rule with its own `wbuffer`+`zbias` probe. This answers vendor.md
  §16 gap 4: the SPEC does say the bias applies to W.
- **Lines and points (G16)** must draw through `prepare()`; they then get the bias for free.

### 3.2 The decision: `KMD/include/vcr_zbias.h` (new)

Integer-only and Win32-free, like `vcr_rtfmt.h` and `vcr_3dseq.h`. The HAL (`-mgeneral-regs-only`) decides with
it, and the native test compiles it as is.

```c
/* vcr_zbias.h - Direct3D's Z bias (D3DRENDERSTATE_ZBIAS, render state 47) on
 * the 3D engine's depth bias: fbzMode bit 16 adds zaColor's depth field -
 * [15:0] at 15/16 bpp, [23:0] at 32 bpp, signed - to every pixel's depth; the
 * clamped sum is compared AND written (SPEC fbzMode bits 16/20, zaColor).
 *   magnitude: 2 units of a 16-bit depth per step, 512 of a 24-bit one - the
 *     same fraction of the range (3dfx D3RSTATE.C zbias). Keyed to the
 *     TARGET's 3D pixel size, the depth the engine iterates (vcrdd_3d.c
 *     VcrDd3dDrawTarget), never to the desktop (3dfx: 256x the bias for a
 *     16 bpp target on a 32 bpp desktop) or to the Z surface's storage (a
 *     16 bpp target over a 32-bit Z is drawn 16/16, vcr_rtfmt.h).
 *   sign: "in front" (DDK) is toward 0 for every compare function but
 *     GREATER/GREATEREQUAL. (3dfx negated for LESS/LESSEQUAL only: an EQUAL
 *     pass at the same ZBIAS over a biased LESSEQUAL pass never matched.)
 *   range: 0..16 (DDK); above 16 is held at 16, a negative LONG is 0.
 * VCR_ZBIAS_OFF: no bias - fbzMode bit 16 stays clear and zaColor is not
 * written, so the draw is the proven one, register for register. A real
 * bias is never 0. */
#ifndef VCR_ZBIAS_H
#define VCR_ZBIAS_H
#include "vcr_rtfmt.h"                      /* VCR_RT_16 / VCR_RT_32, vcr_rt_zmax */

#define VCR_ZBIAS_OFF           0u
#define VCR_ZBIAS_MAX           16u
#define VCR_ZFUNC_GREATER       5u          /* d3dtypes.h D3DCMP_GREATER */
#define VCR_ZFUNC_GREATEREQUAL  7u          /* d3dtypes.h D3DCMP_GREATEREQUAL */

static __inline unsigned vcr_zbias_level(unsigned rs)
{
    if (rs & 0x80000000u)                   /* a negative LONG */
        return 0;
    return rs > VCR_ZBIAS_MAX ? VCR_ZBIAS_MAX : rs;
}

static __inline unsigned vcr_zbias_zacolor(unsigned rs, unsigned zfunc, unsigned fmt)
{
    unsigned lvl = vcr_zbias_level(rs), mag, mask;
    if (!lvl || (fmt != VCR_RT_16 && fmt != VCR_RT_32))
        return VCR_ZBIAS_OFF;
    mag = fmt == VCR_RT_32 ? lvl << 9 : lvl << 1;
    mask = vcr_rt_zmax(fmt);                /* 0xffff / 0xffffff */
    if (zfunc == VCR_ZFUNC_GREATER || zfunc == VCR_ZFUNC_GREATEREQUAL)
        return mag & mask;
    return (0u - mag) & mask;
}
#endif
```

`vcrdd_d3d.c` pins the two compare values against the DDK's with a compile-time check
(`typedef char zf_gt[D3DCMP_GREATER == VCR_ZFUNC_GREATER ? 1 : -1];`, and the same for GREATEREQUAL).

Values it produces (they are the native test's table):

| ZBIAS | ZFUNC | 16 bpp target | 32 bpp target | 3dfx (same primary) |
|---|---|---|---|---|
| 0 | any | OFF | OFF | 0, ENZBIAS on |
| 1 | LESS / LESSEQUAL | `0xFFFE` (−2) | `0xFFFE00` (−512) | same |
| 5 / 10 / 15 (UE2) | LESSEQUAL | `0xFFF6` / `0xFFEC` / `0xFFE2` | `0xFFF600` / `0xFFEC00` / `0xFFE200` | same |
| 16 | LESSEQUAL | `0xFFE0` (−32) | `0xFFE000` (−8192) | same |
| 17, 1000 | LESSEQUAL | `0xFFE0` (held at 16) | `0xFFE000` | `17<<1` … unclamped |
| 0xFFFFFFFF (−1) | LESSEQUAL | OFF | OFF | `0x0002` (pushed away from the viewer) |
| 1 | GREATER / GREATEREQUAL | `0x0002` | `0x000200` | same |
| 1 | EQUAL / NOTEQUAL / ALWAYS / NEVER | `0xFFFE` | `0xFFFE00` | **`0x0002`** (departure, §3.8) |
| 1, 16 bpp target on a 32 bpp desktop | LESSEQUAL | `0xFFFE` | n/a | **`0xFE00`** (−512 at 16 bits: the primary-keyed bug) |

### 3.3 `compute_regs` (`KMD/display/vcrdd_d3d.c`, right after the depth block at `:986-990`)

```c
    /* Z bias (Diag\\D3DFeat ZBIAS): only a depth-tested draw that asks for one.
     * zaColor is also FASTFILL's depth: it travels with the state, and every
     * clear forces the state back (clear_rects) */
    r->zbias_on = 0;
    r->zaColor = 0;
    if (c->pd->d3d_zbias && (r->fbzMode & FZ_DEPTH)) {
        r->zaColor = vcr_zbias_zacolor(c->rs[D3DRENDERSTATE_ZBIAS],
                                       c->rs[D3DRENDERSTATE_ZFUNC], c->target.fmt);
        if (r->zaColor != VCR_ZBIAS_OFF) {
            r->fbzMode |= FZ_ZBIAS;
            r->zbias_on = 1;
        }
    }
```

- `FZ_DEPTH` is set only with a Z the target accepted (`c->target.z_on`) and `ZENABLE == D3DZB_TRUE`
  (`:986`). A target without a Z, depth off, or USEW never gets the bit.
- ZFUNC and ZBIAS changes already mark the context dirty (`set_rs`, `:1402-1405`). A SETRENDERTARGET that changes
  16 ↔ 32 bpp marks it dirty too (`:1740-1742`), so the scale follows the new target at its next draw.
- `vcr3d_regs` (`KMD/display/vcrdd_3d.h:36-44`) gains `ULONG zaColor, zbias_on;`.

### 3.4 Emission: `VcrDd3dState` (`KMD/display/vcrdd_3d.c:74-129`)

```c
BOOL VcrDd3dState(VCR_PDEV *pd, const vcr3d_regs *r)
{
    if (!VcrDdRoom(pd, r->zbias_on ? 13 : 12))          /* was 12: unchanged when off */
        return FALSE;
    w3(pd, V3D_FBZCOLORPATH, r->fbzColorPath);
    w3(pd, V3D_FBZMODE, r->fbzMode);
    /* ... alphaMode, fogMode, fogColor, c0, c1 - unchanged ... */
    w3(pd, V3D_SSETUPMODE, r->setupMode);
    if (r->zbias_on)                                    /* the bias; a clear left its depth here */
        w3(pd, V3D_ZACOLOR, r->zaColor);
    /* fog table, compressed-texture NOP, TMU0, TMU1 - unchanged */
```

- **Order.** fbzMode (bit 16) and zaColor both land before the next triangle in the same PCI FIFO; no
  triangle sits between them. The new write goes after the eight existing ones, so the first eight stay in
  today's order and a test can pin them.
- **Why the clear needs no change.** `VcrDd3dClear` overwrites zaColor with the clear depth (`vcrdd_3d.c:160`).
  Then:
  - `clear_rects` sets `c->dirty = 1; w->prepared = 0;` after every clear, DP2 CLEAR and Clear2 alike
    (`vcrdd_d3d.c:1419-1420`);
  - the next triangle's `prepare()` runs `compute_regs` + `VcrDd3dTarget` + `VcrDd3dState`
    (`:1335`, `:1361`);
  - every DP2 call also starts with `prepared = 0` (`memset(&w, 0, sizeof w)`, `:1835`).

  So the bias is back before any biased triangle, whichever path the runtime used for the clear. 3dfx needed an
  explicit restore because it shadows registers (`VH5/D7DP2.C:604-610`); this HAL does not (G53). The comment
  at `:1419` becomes "the clear rewrote fbzMode, c1 and zaColor (FASTFILL's depth, and the Z bias)".
- **A constraint on later items.** Any register shadowing (G53) or move to the command FIFO (G47) must treat
  zaColor as clobbered by every clear. d3dprobe `zbias_clear` (§5) is the guard.

### 3.5 Caps

`prim_caps(D3DPRIMCAPS *c)` (`vcrdd_d3d.c:2013`) becomes `prim_caps(D3DPRIMCAPS *c, ULONG zbias)`, with
`| (zbias ? D3DPRASTERCAPS_ZBIAS : 0)` in `dwRasterCaps` (`:2019-2020`). Both calls (`:2071-2072`) pass
`pd->d3d_zbias`. Armed: DX7 RasterCaps `0x001041b1`; D3D8 should report **`00104191`** (the runtime dropped only
SUBPIXEL from today's value, inferred to keep `0x4000`, which exists in `d3d8caps.h`). Off: unchanged. Line caps
are a copy of the triangle caps today (G16); they get the bit too, which is harmless.

### 3.6 Counters (log only, default on)

- `vcr_d3dctx` gains `ULONG zbias_max, zbias_sets;`.
- In `set_rs`, before `c->rs[st] = v`: `if (st == D3DRENDERSTATE_ZBIAS && v != c->rs[st]) { c->zbias_sets++; if
  (v > c->zbias_max) c->zbias_max = v; }`. The compare is unsigned, so a negative LONG becomes the maximum and
  prints negative.
- `ctx_free`'s "context %u gone" line (`:1212-1215`) appends `, ZBIAS max %d over %u changes`.
- No register effect, so it runs whether or not the switch is armed. That is what lets boot A (§7) measure which
  titles send ZBIAS before anything is honoured. If G76's counter block lands first, these two fields join it.

### 3.7 The old path

With `D3DFeat` bit 2 clear (the default), `pd->d3d_zbias` is 0:

- `r->zbias_on` is 0 and fbzMode is today's word;
- `VcrDd3dState` waits for 12 slots and writes exactly today's registers;
- the caps are today's.

The only differences are the counter increments and one longer log line. With the bit set, a draw whose ZBIAS is 0
(nearly every draw) is still byte-identical. Only biased, depth-tested draws change: bit 16 in fbzMode, plus one
zaColor write.

### 3.8 Choices, and the alternatives not taken

| choice | why | alternative and why not |
|---|---|---|
| **lazy**: `FZ_ZBIAS` only on biased draws | unbiased draws stay byte-identical when armed; zaColor's stale clear depth never matters | 3dfx: `ENZBIAS` always on, zaColor always sent → zaColor on every state flush, a changed proven path |
| **scale keyed to the target's `fmt`** | it is the depth the engine iterates (`VcrDd3dDrawTarget`, `vcrdd_3d.c:290-293`) and the one the clear converts to (`:153`) | 3dfx: the primary's depth (256x too big for a 16 bpp target on a 32 bpp desktop; vendor.md §13.7, G95); the Z surface's size (wrong for the 16/16-in-32 case: a 32-bit Z under a 16-bit depth) |
| **3dfx's magnitude** (2 LSB16 per step) | what a V5 user had, tuned for WinBench 99's quality test; UE2 detects 3dfx cards ("D3D Detected: 3dfx video card", `UT2003.log:54`) | another vendor's step: unknown. `zbias_scale` measures a reference card's step (§5.3); revisit only if decals still flicker |
| **sign: negative except GREATER/GREATEREQUAL** | the DDK's "in front" is independent of the compare function. It keeps a biased LESSEQUAL pass and a biased EQUAL/ALWAYS pass at the same ZBIAS consistent, because the biased depth is what gets written (SPEC bit 20) | 3dfx's rule (negative only for LESS/LESSEQUAL). ## 4. Gating

- **Switch:** `HKLM\SYSTEM\CurrentControlSet\Services\vcrmp\Diag\D3DFeat`, bit 2 (`VCR_D3DFEAT_ZBIAS`, value 4),
  as hal.md §10 Phase 2 numbers it (bit 0 ValidateTSS, 1 legacy states, **2 ZBIAS**, 3 specular/flat, 4
  lines/points, 5 alignment; Phase 3 from bit 6, where G05 proposes `CMSHIFT`). Absent = 0 = off. It is a
  positive bit, so an older miniport never arms it.
- **Read at boot** (FindAdapter), like `D3D32` and `D3DBigTex`. The RasterCaps an application reads at the
  desktop then match its fullscreen PDEV's.
- **Any chip.** It is VSA-100-proven only after boot B. On a Banshee/Voodoo3 only the 16-bit path exists.
- **Arming:** `REGWRITE HKLM SYSTEM\CurrentControlSet\Services\vcrmp\Diag D3DFeat REG_DWORD 4`, `REGREAD` it back,
  activation check, `scripts/fleet/safe-reboot.py`. One Diag change per clean boot. If other D3DFeat bits are
  already armed, write the OR of them.
- **Safe to land default-on? Not at landing.** Non-zero zaColor has never been driven by this HAL; at 32 bpp
  nothing on the box has driven it. The cap also moves caps-checking titles onto another path (UE2's +0x50
  flag, BF1942, anything the counters find). **After one supervised armed boot passes** (§7.3: the four probe
  tests at 16 and 32 bpp, the default list unchanged, UE2 no worse), it qualifies as a pure correctness fix:
  - every draw it changes is drawn wrong today, by construction;
  - every draw it does not change is byte-identical.

  Flip the default in a separate commit with its own test, by the plan-wide D3DFeat convention (a default mask
  in the miniport, or a `D3DFeatOff` kill mask, G05 §4.1).
- **Split if needed:** if the cap alone hurts a title (a path change), keep the drawing and drop the cap behind its
  own bit. UE2 sends ZBIAS without the cap, so the drawing half still helps it.

## 5. d3dprobe tests

### 5.1 The tests (explicit `--tests`, never in the default list)

All draw untextured diffuse quads with `quad_c` (`KMD/tools/d3dprobe.c:222`), read the back buffer back
(`readback`, `:292`), and compare against values computed from the design.

- **Without the cap** (`!(g_caps.RasterCaps & D3DPRASTERCAPS_ZBIAS)`), each test is `skipped(t, "ZBIAS not
  reported (Diag\\D3DFeat bit 2)")`. It still draws, and logs every sampled pixel with its expected value
  without counting it. That records the old behaviour on the new binaries: the bias-1 decal loses.
- **`--noz`:** skipped like `ztest`.
- **Depths:** base `z0 = 0.375` (`z0·65535 = 24575.625`, `z0·(2^24−1) = 6291455.625`, both well away from a
  rounding edge). A decal "k units behind" is drawn at `z0 + k/65535.0f`, an exact integer k of 16-bit LSBs
  under floor and round alike. At 32 bpp that is `256.004·k` 24-bit LSBs, and float error stays under 1 LSB.

| test | what it draws | pass (armed) |
|---|---|---|
| `zbias` | `frame_begin(0)` (black, Z 1.0). LESSEQUAL, ZWRITE on, ZBIAS 0: green quad over the whole area at z0. ### 5.2 Running them

- **16-bit path:** `--full --res 640x480 --bpp 16` (R5G6B5 + D16, the UE2 configuration).
- **24-bit path:** `--full --res 1024x768 --bpp 32` (X8R8G8B8 + D24X8), and windowed on `.124`'s 32 bpp desktop.
- **Keyed to the target, not the Z:** `--full --res 640x480 --bpp 16 --zfmt d24x8` (the 16/16-in-32 case) must
  give the 16-bit pattern.
- **G10's case, once G10 lands:** `--bpp 32 --zfmt d16` must give the 24-bit pattern. Until then, never request it
  (it costs the CRT a mode flap, G11).
- Pace 5000 ms (`ONBOX/d3dprobe_paced.py`). A named-but-skipped test is "not a pass" to `d3dprobe_run.py`, which is
  right for boot A.

### 5.3 A reference driver first

d3dprobe is "for any other driver, as the reference" (`d3dprobe.c:1-3`). Run the four tests once on a fleet box

- `zbias_func` shows its EQUAL and GREATER behaviour, which is the evidence for the sign rule. If the reference
  disagrees on EQUAL, reconsider before graduation; GREATER is near-irrelevant to games of this era.

## 6. Host regression tests

### 6.1 `WT/tests/native/test_vcr_kmd_zbias.c` (new; compiles `KMD/include/vcr_zbias.h`)

`tests/run_all.sh` builds every `tests/native/test_*.c`, so no registration is needed.

1. **The fixed table** of §3.2, cell by cell, at 16 and 32 bpp. It includes UE2's 5/10/15, the clamp (17, 1000 →
   16), a negative LONG → OFF, ZBIAS 0 → OFF, and a refused format (0, 24) → OFF.
2. **The old values, asserted as different.**
   - `old_hal()` returns OFF for everything (the HAL ignored state 47).
   - `vendor_zbias(state, zfunc, primary_bytes, zmask)` is a transcription of `VH5/D3RSTATE.C:1283-1309`. The
     test asserts the three cells where ours differs: 16 bpp target on a 32 bpp primary (vendor `0xFE00`, ours
     `0xFFFE`); 32 bpp target on a 16 bpp primary (vendor `0xFFFFFE`, ours `0xFFFE00`); EQUAL (vendor `0x0002`,
     ours `0xFFFE`).
   - It also asserts that the two agree in every LESS/LESSEQUAL/GREATER/GREATEREQUAL cell whose primary matches
     the target.
3. **Exhaustive properties.** For ZBIAS 0..20 plus 0x80000000 and 0xFFFFFFFF, ZFUNC 0..9, fmt {0, 16, 24, 32}:
   - OFF exactly when the level or the format is 0/invalid;
   - |value| = min(level,16) << (fmt 32 ? 9 : 1);
   - the value fits the Z width and is never 0 when on;
   - the sign follows the rule.
4. **The SPEC adder model.** `biased16(d, za)` = clamp(d + (int16)za, 0, 0xFFFF); `biased24` sign-extends bit 23
   (inferred). Using it:
   - a coplanar decal at every level 1..16 passes LESS against the depth it lies on, for depths away from 0;
   - a decal more than 2·level LSB16-equivalents behind fails;
   - GREATER mirrors this;
   - at depth 0 the clamp makes the decal tie (it loses LESS), which is the hardware's semantics;
   - an EQUAL pass at the same level matches the depth a biased LESSEQUAL pass wrote under our rule, and not
     under 3dfx's.

### 6.2 `WT/tests/python/test_vcr_kmd_d3d.py` (source pins)

- `test_zbias_is_one_default_off_d3dfeat_bit`:
  - the miniport reads `VcrDiagGet(L"D3DFeat", 0)` and fills `v->d3dfeat`;
  - `VCR_D3DFEAT_ZBIAS` is a single bit, and no two D3DFeat bits share one;
  - `VcrDd2dInit` zeroes `info` before the IOCTL and sets `pd->d3d_zbias` only from that bit. No other line
    assigns it.
- `test_zbias_reaches_fbzmode_only_through_the_header`:
  - `FZ_ZBIAS` appears in `vcrdd_d3d.c` exactly once, inside the `if (c->pd->d3d_zbias && (r->fbzMode &
    FZ_DEPTH))` block;
  - the call is `vcr_zbias_zacolor(c->rs[D3DRENDERSTATE_ZBIAS], c->rs[D3DRENDERSTATE_ZFUNC], c->target.fmt)`.
    A desktop `pd->bpp` or a Z-surface size there fails the test.
- `test_zacolor_goes_with_the_state_only_for_a_biased_draw`:
  - `VcrDd3dState` waits for `r->zbias_on ? 13 : 12`;
  - its zaColor write sits under `if (r->zbias_on)`;
  - its first eight writes are today's, in today's order (the old value: 12 slots, eight writes, no zaColor).
- `test_every_clear_forces_the_bias_back`:
  - `VcrDd3dClear` still writes `V3D_ZACOLOR`;
  - `clear_rects` sets `c->dirty = 1;` and `w->prepared = 0;` after it;
  - `prepare()` re-sends target and state when `!w->prepared`;
  - both D3D entry points start from `memset(&w, 0, sizeof w)`.
  This chain is the restore. The test fails if a later change (G53 shadowing, G47 FIFO) breaks a link without
  revisiting it.
- `test_zbias_cap_follows_the_switch`: `D3DPRASTERCAPS_ZBIAS` appears only as `(zbias ? D3DPRASTERCAPS_ZBIAS : 0)`
  in `prim_caps`, and both calls pass `pd->d3d_zbias`.
- `test_d3dprobe_zbias_tests_are_analytic`:
  - the four names are in d3dprobe's dispatch and header list;
  - each sets `D3DRS_ZBIAS` and is skipped without the cap;
  - `zbias_scale`'s expectation is `k < 2 * b`;
  - none of them is in the default list.
- `test_zbias_counters_are_log_only`: the counters are updated in `set_rs` with no `dirty` side effect, and
  printed by `ctx_free`.

## 8. Risk to proven paths

| path | risk |
|---|---|
| **default 16 bpp lane, 32 bpp lane, a fresh install** | none. Bit off: same writes, same waits, same caps; pinned by §6.2 and measured in boot A |
| **armed, draws with ZBIAS 0** | none. Byte-identical (the lazy rule) |
| **armed, biased draws** | new register traffic: bit 16 plus one zaColor write. | **Glide/OpenGL coexistence** | no new interaction. The HAL already rewrites zaColor in every clear, so Glide must already restore its own from its shadow (it writes its state at open and validation, inferred). A D3D biased draw always writes its own zaColor at each DP2's first triangle, so Glide's value never reaches it. Checked in boot B's last step |
| **SLI** | none. D3D draws on chip 0, written through chip field 0 like every other state register (G51 unchanged) |
| **flip path** | none |

## 10. Open questions

1. **Does the D3D8 runtime pass ZBIAS to a DX7 driver that does not report the cap?** UE2 sends it regardless
   (binary); boot A's counter answers the runtime half.
2. **Does the D3D9 runtime turn `DEPTHBIAS` into ZBIAS for a DX7-DDI driver** (Halo, NewDark)? A partial read of
   `d3d9.dll` 5.3.2600.5512 did not settle it; boot B's counter does.
3. **Sign for EQUAL/NOTEQUAL/ALWAYS** (a departure from 3dfx) **and GREATER:** confirm on the reference card
   (§5.3) before graduation.
4. **Magnitude:** is 3dfx's 2 LSB16 per step (UE2's 15 → 30 LSB16) the right size for UE2 at 16-bit Z? Its
   flicker (too small) or bleed-through (too large) shows in boot B; the reference card's `zbias_step` is the
   comparison.
5. **The 24-bit field's sign extension at 32 bpp** (inferred from 3dfx's masks and Glide). The 32 bpp probe rows
   settle it; plan B is the vertex offset.
6. **Does 86Box emulate fbzMode bit 16?** It decides whether the bed can prove the 16-bit path.
7. **Who reads UE2's "supports Z bias" flag (+0x50)?** If arming the cap makes UE2 draw passes it skipped, the fps
   and frame comparison of boot B shows it; trace it in `Engine.dll` only if it matters.
8. **Do any staged titles send ZBIAS > 16 or a negative value?** `zbias_max` records it; the clamp is the DDK range.
9. **A slope-aware software bias** (per triangle, from the screen-space vertices) could cover grazing-angle decals
   that a constant bias cannot. No DX7 state asks for it. Consider it only if boot B shows grazing-angle flicker
   on UE2 terrain decals.
