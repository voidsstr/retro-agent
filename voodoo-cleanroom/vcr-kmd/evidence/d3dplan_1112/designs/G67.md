## 0. Verdict

1. **The gap is real.** No frame of player-controlled Halo exists from `.124`. The 11-11 readiness round
   did not launch it there: "Not launched: d3d124=true ... Halo has never joined a game there (menu only)"
   (`RND/Halo.result.json`). The round put four other boxes in one Blood Gulch game the same afternoon.
2. **The binaries settle four of the gap's questions before any box time** (§1.2):
   - **The renderer.** `.124` already runs Halo's most basic renderer: the legacy, single-stream,
     fixed-function one. Halo picks its renderer from `IDirect3D9::GetDeviceCaps(HAL)`. XP's `d3d9.dll`
     builds a DX7 driver's caps with `MaxStreams` = 0, `VertexShaderVersion` = 0xfffe0000 and
     `PixelShaderVersion` = 0xffff0000. So `-useff`, `-use00`, `UseFixedFunction` and `ForceShader` select
     nothing new on `.124`, and `timedemo.txt` will print `Shader=Fixed Function` whatever is passed.
     **The gap's idea of pinning a safe shader path for `0x121a:0x0009` has no target left.**
   - **SSE2.** Every SSE2 instruction in `halo.exe` sits behind a CPU check: the static CRT's
     `__sse2_available`, D3DX's PSGP tables (the Athlon XP gets the 3DNow! table), or a SEH-guarded probe.
     The requires.json premise, "an /arch:SSE2 build", is refuted for the exe. The DLLs were counted, not traced.
   - **The white 60 s frame is not Halo's art.** A reference menu from another box has a **dark** space
     backdrop. On `.124` the backdrop is white, except for a dark planet disc. G17 has found the menu's
     starfield to be an X8R8G8B8 bitmap, a format our HAL has never offered. The frame with no logo or
     cursor is that pass caught in the back buffer by a GDI capture (G79). **Two defects, not "its animated menu".**
   - **The three workarounds are already explained by sibling designs.**
     - `DisableRenderTargets` cannot be lifted inside the DX7 DDI (G36: five of Halo's eight render-target
       textures are X8R8G8B8, which XP's runtime never grants this PCI id).
     - `-novideo` hides a software stretch (G56; the fix is G61's 2D stretch).
     - The SSE2 floor is wrong for the exe (above).
3. **What is left needs Halo itself, in a real game, with a person.** That means:
   - what gameplay asks of Direct3D on the legacy renderer;
   - which of its creations fail;
   - whether common scenes render right;
   - whether a 30-minute session stays up;
   - how fast it runs.

   The HAL alone cannot answer the first two: the D3D9 runtime refuses formats and render targets
   **before** the driver is asked.
4. **What this design delivers:**
   - **`d3d9spy`** (§3.1): a game-local, log-only D3D9 interposer. It records Halo's own view: caps,
     every refused creation, a render-state/stage/sampler census, frame times, and complete in-process
     frame captures. It needs no `vcrctl`, no escape and no GDI. This is G36's E7 spy, specified here.
   - **`d3d9probe capture9` and `caps9 --halo`** (§3.2): they prove the capture path, and the renderer
     choice, on our HAL.
   - **A reference set** (§4.1): Halo on vendor drivers, launched with `-use00`, which runs the same legacy
     renderer as `.124`.
   - **Two supervised `.124` sessions:**
     - a baseline on today's driver (§4.2), with a person playing a 15-scene checklist in a real
       multiplayer game on `haloded` (§4.3);
     - the same after G17 and G06 land (§4.4).
   - **The decisions** (§4.5, §8):
     - `blk` → `MP` for `.124`;
     - the SSE2 floor;
     - `DisableRenderTargets` stays;
     - `-novideo` goes after G61.
5. **Priority P1, effort L.** Nothing here can harm a proven path, because no driver code changes. The
   session risks are the usual D3D-on-`.124` ones (G01, G04) and a leftover `d3d9.dll` in the game tree (§9).

### 1.2 New, from the binaries (this design)

#### 1.2.1 Halo picks its renderer from `GetDeviceCaps(HAL)`, and `.124` gets the legacy one

- **The caps.** `IDirect3D9::GetDeviceCaps(adapter, devtype, 0x7c10c0)` is called at `0x516b86-0x516b94`
  (vtable `+0x38` = index 14, checked against mingw's `d3d9.h`). Device type 1 is HAL; 2 is used with `-useref`.
  - `D3DCAPS9` offsets, from a compiled `offsetof`: `MaxStreams` +0xBC, `VertexShaderVersion` +0xC4,
    `PixelShaderVersion` +0xCC.
  - So **`0x7c117c` = MaxStreams** and **`0x7c118c` = PixelShaderVersion**.
- **The switches** (parsed at `0x516c0c-0x516dbc`):
  - `-useff` (`0x516c2f`) clears ForceShader and forces the pixel-shader version to 0.
  - The same happens for **`UseFixedFunction`** (config handler `0x57d170` → `0x722b34`), **`SafeMode`**
    (`0x57d230` → `0x722b60`) and **`-safemode`** (`0x7196f4`); the test is at `0x516c4a-0x516c60`.
  - `-use00` (`0x516c83`) forces PS 0 **and writes 1 to MaxStreams** (`0x516ca8`,
    `c7 05 7c 11 7c 00 01 00 00 00`).
  - `-use11` forces 1.1 (`edi` = 0xffff0101 at `0x516cf2`). `-use14`, `-use20` and `-use2a` force the
    higher versions; their exact values were not read here, and none of them matters on a PS 0.0 device.
  - The effective PS version is min(caps, forced) (`0x516dbe-0x516dda`).
- **The renderer table** (`0x516810-0x516847`):
  - MaxStreams ≤ 1 → `0x51fd80`;
  - otherwise PS ≥ 1.1 → `0x51f3e0`;
  - otherwise → `0x51fad0`.

  `-use00` therefore means "treat this as a single-stream, pre-DX9 device".
- **`timedemo.txt`'s machine-info line** (`%dMHz, %dMB, %dM %s %s (DeviceID=0x%04x) Driver=%d.%d.%d.%d
  Shader=%s`, `0x4c71c7-0x4c71e9`) prints:
  - "2.0a" for ForceShader 2a;
  - **"Fixed Function" for any PS below 1.1**;
  - "%d.%d" otherwise.
- **XP's `d3d9.dll` builds a legacy driver's `D3DCAPS9`** in the function containing `0x4fdfb2fc-0x4fdfb44b`:
  - `xor edi,edi`;
  - `MaxStreams` (+0xBC) = edi (`0x4fdfb416`); MaxVertexShaderConst = edi;
  - `VertexShaderVersion` = 0xfffe0000 (`0x4fdfb441`);
  - `PixelShaderVersion` = 0xffff0000 (`0x4fdfb44b`).

  The last two are the values the D3D8 runtime reports for our HAL (`EV/caps_124.txt`). That is why this
  is read as the builder our DX7 HAL goes through **(inferred link; `caps9 --halo` measures it in a second,
  §3.2)**.
- **Conclusion.** On `.124`, Halo takes **`0x51fd80`, its legacy single-stream fixed-function renderer**,
  and writes `Shader=Fixed Function`.
  - `-useff`, `-use00`, `UseFixedFunction` and `ForceShader` change nothing there. `SafeMode`/`-safemode`
    only lower the settings.
  - The levers that remain:
    - the video options, set in Halo's Settings menu and printed by `timedemo.txt`: Specular, Shadows,
      Decals, Particles, Texture quality, Framerate throttle;
    - `DisableSpecular` in `config.txt`;
    - the resolution;
    - `-noSSE` (§1.2.2).
- **Corollary for references.** A DX9 box takes `0x51f3e0` (shaders) by default. **Launched with `-use00` it
  takes `0x51fd80` too**: the same renderer as `.124`, on a vendor driver with richer caps (more stages,
  X8R8G8B8, cube maps, DOT3). How far the legacy renderer reads caps beyond this choice was not traced, so
  that it uses them is inferred. `-use00` on a reference box is the right reference for `.124`.

#### 1.2.2 Every SSE2 instruction in `halo.exe` is behind a CPU check

- **The floor's premise.** `requires.json` reads 298 SSE2 instructions (scalar-double `mulsd/addsd/movlpd`)
  as "the signature of an /arch:SSE2 build", and takes the conservative reading. Its own count of **19 `cpuid`
  sites** is, by `scripts/gamegate/SCHEMA.md` §`cpu_features` ("3-19 sites: runtime dispatch - not a floor"),
  a dispatch signature.
- **Classified here.** There are 395 SSE2-class instructions; this classifier also counts the xmm forms of
  the shared integer ops, hence more than 298. They fall in 29 contiguous runs, all in the places below:

| where | what | guarded by |
|---|---|---|
| `0x623e80...`, `0x626830...` (incl. tails `0x6268b2`, `0x6268f1`), `0x6328a0-0x6333b5`, `0x635d60-0x635fe4` | the statically linked MSVC CRT's SSE2 `floor`/`ceil` and transcendental routines | - Every entry (`0x623e40`, `0x6267f0`, `0x628380`, `0x6283c0`, `0x628d00`, `0x628d3c`) begins `cmp dword [0x723a20],0` (`83 3d 20 3a 72 00 00`) and falls to the x87 path.<br>- `0x723a20` (`__sse2_available`) is zeroed at `0x62a6e5`.<br>- It is set at `0x62a74b` (`89 35 20 3a 72 00`) only after CPUID.1:EDX bit 26 (`f6 45 e7 04` at `0x62a6ec`) and an OS check (`0x62a65c`).<br>- The other code that branches into these ranges goes through those entries or reaches non-SSE2 neighbours (scan in Appendix A). |
| `0x5d9a63`, `0x5d9b04`, `0x60d891` (xmm integer + packed) | D3DX9's SSE2 function table: D3DX is linked into `halo.exe` | - Installed only by `0x5bf9d3`, called once, from `0x592dc4`.<br>- The order of checks: the `DisablePSGP`/`DisableD3DXPSGP` registry values first; then `IsProcessorFeaturePresent(7)`, 3DNow!, at `0x592d9c` (`6a 07 ff d6`; IAT `0x63a1a8`) → the 3DNow! table `0x5bfc1b`. **That is what an Athlon XP gets.**<br>- Otherwise the CPUID helper `0x592c55` → the SSE2 table; otherwise `IsProcessorFeaturePresent(6)` → the SSE table. |
| `0x54092b` `xorpd xmm0,xmm0` (`66 0f 57 c0`) | the DirectX-SDK CPU-feature probe | inside a SEH try block, after the feature query `0x5402a0(0x1e)`; a #UD is caught and answers "no" |

- **Halo's own engine dispatches too.** `0x4cd3fb-0x4cd45c` installs one of three routines into `0x696664`
  from `0x5402a0(0x1d)`/`(0x1a)`, and **`-noSSE`** (`0x4cd41e`, string `0x66b96c`) keeps the generic one.
  That is a ready lever if a SIMD fault ever shows.
- **The DLLs were counted, not traced:**
  - `binkw32.dll` 266, `Keystone.dll` 422, `ksimeui.dll` 16 and `msvcr71.dll` 518 SSE2-class instructions;
  - `Strings`, `vorbis`, `vorbisfile`, `ogg`, `mgspid`, `eula` and `unicows`: 0.

  The dynamic record on `.124` (Athlon XP 2400+, SSE, no SSE2):
  - Bink played intros for 13+ minutes (09-28);
  - Keystone draws the menu overlay;
  - the menu and 485 s of in-engine cutscenes ran (11-12);

  all with no fault.
- **Conclusion.** For `halo.exe` the floor's premise is wrong. FINDINGS' rule still stands: "do not relax the
  floor before gameplay is seen" (`FIND:443-445`). Phase 2's soak (§4.2) is that evidence, and §4.5 is the
  decision.

#### 1.2.3 The menu is not white by design

- **The reference.** `.139`'s Halo main menu (Windows 11, a modern GPU, the shader renderer;
  `.claude/evidence-139-gametest/Halo_Combat_Evolved.png`) puts the logo and the blue menu text over a
  **dark** backdrop: the Pillar of Autumn's hull, the ring and a nebula. The blue text is made for a dark
  background.
- **`.124`.** Every menu frame has a **white** backdrop with a dark planet disc:
  - `sweep_1108_fixed/.../Halo_Combat_Evolved_30s.png`;
  - `RES/day/fbshots/halo_libdeploy_15.png`, `halo_novideo_1.png` and `halo_camp.png`: one image,
    md5 `a2602aed…`, luma mean 243.6.
- **The likely cause.** G17 §2.4 lists two of `ui.map`'s bitmaps as X8R8G8B8:
  - the starfield `sky\space\bitmaps\stars` (256x256);
  - `sky\sky_x10\bitmaps\space` (128x128).

  Our HAL has never offered X8R8G8B8, so Halo's `CreateTexture` fails and the stage is drawn untextured in
  its vertex colour (G17 §2.2-2.3). An untextured sky is the likely white **(inferred)**.
- **The all-white frame.** The (255,255,255) frame with no logo, text or cursor is then that sky pass caught
  before the UI pass. The agent's GDI `SCREENSHOT` reads GDI's primary memory, which after a flip is the back
  buffer half the time (G79) **(inferred)**.
- **What changes.** G17 owns the texture; G67 verifies it on the menu (§4.4) and supplies an unambiguous
  capture (§3.1).

  The gap proposed recapturing with `fbshot --probe`. **This design drops that:** it is a `vcrctl` tool
  under a running D3D game, which the project rules forbid, and Max Payne's freeze happened in exactly that
  kind of session (G04).

#### 1.2.4 Details the protocol relies on

- **Exports.** `D3D9` exports exactly 14 names:
  - `CheckFullscreen`;
  - `D3DPERF_BeginEvent/EndEvent/GetStatus/QueryRepeatFrame/SetMarker/SetOptions/SetRegion`;
  - `DebugSetLevel`, `DebugSetMute`;
  - `Direct3DCreate9`, `Direct3DShaderValidatorCreate9`;
  - `PSGPError`, `PSGPSampleTexture`.

  `halo.exe` calls `GetProcAddress(…, "DisableD3DSpy")` at `0x54164d`, and only calls the result if it
  exists. The real runtime has no such export, so **an interposer must not export it either**, or Halo's
  behaviour changes.
- **Halo's config flags** (the table at `0x69fe40-0x69ff18`, name → handler → global):
  - `UseFixedFunction` 0x722b34; `SafeMode` 0x722b60;
  - `UnsupportedCard` 0x722b3c, which raises dialog 103 at `0x516df8`;
  - `DisableSpecular` 0x722b6c; `MinMaxBlendOpIsBroken` 0x722b7c;
  - `DisableRenderTargets` 0x722b70; `DisableAlphaRenderTargets` 0x722b74;
  - `ForceShader`, whose handler parses "2a"/"2A" (`0x57d0c0`).
- **The timedemo.** It loads campaign maps:
  - `map_name d20` and `map_name c10` sit beside `timedemo.txt` (file `0x26b880`, `0x26b890`);
  - `map_name b30` sits beside `init.txt` (file `0x26b224`);
  - G17 identifies the 11-12 lifepod as a30's.

  Which maps run, in which order, and whether the frame sequence is fixed are **unmeasured**.
- **`timedemo.txt` reports:**
  - Resolution, Refresh rate and Framerate throttle;
  - Specular, Shadows, Decals, Particles and Texture Quality;
  - the sound options;
  - `Frames`, `Total Time` and `Average frame rate`;
  - the "Below N fps" table;
  - the machine-info line above.
- **Halo's log files.** Halo names `\network.log`, `\debug.txt` and `dxdiag.txt` (file `0x27128c-0x2712c8`).
  Where it writes them (the tree, or the profile folder) is unmeasured.
- **How it finds Direct3D.** `LoadLibraryA("d3d9.dll")` by bare name (`0x5415ad`, `0x540f1e`; IAT `0x63a0a0`).
  The handle goes to `0x746264`, which the `DisableD3DSpy` lookup then uses. A copy in the application
  directory therefore wins.
- **Startup input.** At startup Halo reads `GetAsyncKeyState(VK_CONTROL)` (`0x541631`; IAT `0x63a420`).

## 3. Instruments

### 3.1 `d3d9spy`: Halo's own view of Direct3D (new, log-only)

**What it is.** A 32-bit DLL built with mingw (`KMD/tools/d3d9spy.c`, `tools/d3d9spy_idx.h`, `tools/d3d9spy.def`),
built `-march=i586`, `-static-libgcc`, with no SSE2. It is copied as `d3d9.dll` beside `halo.exe` for one run,
then deleted. **It is never staged in the library.**
- Halo loads `d3d9.dll` by name through `LoadLibraryA` (IAT `0x63a0a0`), so the application directory wins.
- The spy loads the real runtime by absolute path: `GetSystemDirectoryA` + `\d3d9.dll`.
- It exports the **same 14 names** as `D3D9`: 13 forwarded, plus its own `Direct3DCreate9`. It does
  **not** export `DisableD3DSpy`.
- The `.def` fixes the undecorated names. `tools/check_imports.py`, or a user-mode variant, confirms that
  every import exists on XP SP3.

**How it hooks: vtable patching on the real objects, never wrapping.** The originals are kept and every
hook calls through. The indices come from `d3d9spy_idx.h`, pinned against mingw's `d3d9.h` (§7.2).

| interface | hooked (index) |
|---|---|
| `IDirect3D9` | CheckDeviceType 9, CheckDeviceFormat 10, CheckDepthStencilMatch 12, GetDeviceCaps 14, CreateDevice 16 |
| `IDirect3DDevice9` | TestCooperativeLevel 3, Reset 16, Present 17, CreateTexture 23, CreateVolumeTexture 24, CreateCubeTexture 25, CreateRenderTarget 28, CreateDepthStencilSurface 29, StretchRect 34, SetRenderTarget 37, SetDepthStencilSurface 39, Clear 43, SetRenderState 57, SetTexture 65, SetTextureStageState 67, SetSamplerState 69, ValidateDevice 70, DrawPrimitive 81, DrawIndexedPrimitive 82, DrawPrimitiveUP 83, DrawIndexedPrimitiveUP 84, SetFVF 89, CreateVertexShader 91, SetVertexShader 92, CreatePixelShader 106, SetPixelShader 107 |

The two vtables live in the runtime's read-only data. They are patched once, under `VirtualProtect`, and
the old protection is restored afterwards.

**What it records.** It writes a text log to `C:\vcr\spy\<exe>-<yyyymmdd-hhmmss>.log`. If `C:\vcr\spy` is
missing it writes nothing, so it never writes into the game tree. Fixed-size tables are used: no allocation
in a hook, writes buffered, and a low-priority thread flushes every 2 s and at `DLL_PROCESS_DETACH`.
- **`CAPS`:** the whole `D3DCAPS9` as hex, plus decoded MaxStreams, VS/PS versions, TextureCaps,
  TextureOpCaps, RasterCaps, StencilCaps, PrimitiveMiscCaps and the blend caps.
- **`FMT`:** each `CheckDeviceFormat`, `CheckDeviceType` and `CheckDepthStencilMatch` query with its
  result. These are Halo's probes: X8R8G8B8 RT at an A8R8G8B8 adapter, A8/L8/P8 and so on.
- **`DEV`:**
  - from `CreateDevice`/`Reset`: BackBufferFormat/Count, AutoDepthStencilFormat (which also answers G10's
    "does a D3D9 title pick D16 at 32 bpp?"), FullScreen_RefreshRateInHz, **PresentationInterval** (vsync,
    G65), SwapEffect, MultiSampleType, BehaviorFlags, and the HRESULT;
  - lost-device events: `TestCooperativeLevel` answering other than OK.
- **`NEW`:** every Create* with its arguments (w, h, levels, usage, format, pool) and its HRESULT. **Failures
  are always logged**; successes are counted by key and summarised.
- **`CEN`:** a census, printed every 60 s and at exit:
  - per render state, the first 8 distinct values with their counts. The ones that matter here:
    DEPTHBIAS 195, SLOPESCALEDEPTHBIAS 175, STENCILENABLE 52, TWOSIDEDSTENCILMODE 185, CCW_STENCIL* 186-189,
    SPECULARENABLE 29, FOGENABLE 28, FOGTABLEMODE 35, FOGVERTEXMODE 140, RANGEFOGENABLE 48, BLENDOP 171,
    COLORWRITEENABLE 168, SEPARATEALPHABLENDENABLE 206, POINTSPRITEENABLE 156, SHADEMODE 9, FILLMODE 8,
    SRC/DESTBLEND 19/20, TEXTUREFACTOR 60, DITHERENABLE 26, WRAP0 128;
  - per stage and texture-stage state the same: COLOROP, COLORARG0-2 with their modifier bits, ALPHAOP,
    ALPHAARG0-2, RESULTARG, TEXTURETRANSFORMFLAGS, TEXCOORDINDEX;
  - per stage and sampler state the same: ADDRESSU/V, MAG/MIN/MIPFILTER, MIPMAPLODBIAS, MAXMIPLEVEL;
  - texture binds by stage and format;
  - draws by primitive type: calls, primitives, **lines and points** separately;
  - Clear flags, including STENCIL;
  - render-target and depth switches;
  - shaders created and set. It should read 0 on the legacy renderer, which confirms Q1 from the
    application side.
- **`VAL`:** each `ValidateDevice`, with its HRESULT and pass count, as our HAL answers it today (G15).
- **`FRM`:** once a second: frames presented, min/avg/max frame time from QPC at `Present`, and the frame
  number. This gives the fps without needing `timedemo.txt` to finish.
- **`CAP`:** frame captures, below.

**Frame capture (off unless `VCRSPY` asks for it).** Settings come from the environment, so nothing is
written beside the game. Example: `VCRSPY=capture=lock;frames=50,100,200,400;every=900;hotkey=scroll;max=120`.
- **Arming.** At `CreateDevice`/`Reset` the spy ORs `D3DPRESENTFLAG_LOCKABLE_BACKBUFFER` into the
  presentation flags. **That is the only call the spy ever alters, and only with capture armed.**
- **Capturing.** In the `Present` hook, before the real `Present`, for a frame due by number, or by the
  person pressing **Scroll Lock** (`GetAsyncKeyState`; Halo does not use the key, inferred), it does:
  `GetBackBuffer` → `LockRect(D3DLOCK_READONLY)` → a 24-bit BMP `C:\vcr\spy\<run>\f<frame>.bmp` → `UnlockRect`.
  If the lock fails it falls back to `GetRenderTargetData` into a system-memory surface.
- **What a capture is.** The complete frame Halo is about to present, taken inside the game:
  - no display lock;
  - no probe driver;
  - no front/back ambiguity.

  On our HAL, a Lock drains the engine (`vcrdd_ddraw.c:658`), so each capture costs one engine wait.
- **Space.** At most `max` captures a run; 3.7 MB each at 1280x960.

**What it changes when it is not capturing: nothing.** That is pinned by a source test (§7.2) and checked on
the box: `d3d9probe` gives identical results with and without the spy in its directory (§4.1 R0).

**Decoder.** `KMD/tools/d3d9spy_decode.py` turns a log into JSON. It holds:
- the census;
- the refusals, grouped by format and size;
- the fps series;
- a "used but not supported by `.124`'s caps" table, set against `EV/caps_124.txt` and the `caps9`
  output: MODULATE2X used, DEPTHBIAS sent, specular enabled, and so on.

**Relation to G36.** This is G36's E7 spy. G36's option 2, a Halo-local shim that turns X8R8G8B8
render-target requests into A8R8G8B8, can reuse the hook layer. It must be a **separate binary**, so the
log-only tool never alters calls.

### 4.0 Preconditions for every `.124` session

1. **Before the boot:**
   - an activation check (`safe-reboot.py` reads Windows' own verdict);

2. **No Glide or OpenGL title in this boot before Halo** (G01). Before any D3D program, read `vcrctl reg`
   (read-only):
   - `cmdFifo0.baseSize` bit 8 must be clear and the status idle;
   - otherwise stop, or do a paced `vcrctl modeseq` reset as on 11-12, then re-read.
3. **The desktop and the screen:**
   - `DISPLAYCFG get` = 1280x1024x32@85;
   - dismiss the screensaver (`UIKEY SHIFT`);
   - **a person at the box for the whole session** (G04).
4. **The game tree:**
   - `C:\Games\Halo` has **no** `d3d9.dll` (`DIRLIST`, case-insensitive);
   - `halo.exe` and `config.txt` are the library's (md5 `b7aa8f68…`, `4e33300c…`);
   - `ExitFlag=clean` is written before each launch (as the lanparty bat does);
   - free space on `C:` is at least 1 GB.
5. **During the session:**
   - **no `vcrctl` or ExtEscape while `halo.exe` runs**;
   - mode switches at least 5 s apart;
   - never probe a refused Z/target pair fullscreen (G11);
   - close Halo by WM_CLOSE (`taskkill /pid`, no `/f`). It exits cleanly that way (`FIND:451-452`).
6. **Evidence** goes to `KMD/evidence/halo_g67/<yyyymmdd>/` in the repo, never the scratchpad. Push after

## 7. Tests

### 7.1 d3d9probe: `capture9` (new; explicit-only, never in the default list)

**What it draws.** Three frames on a HAL device with software vertex processing, `D3DPRESENTFLAG_LOCKABLE_BACKBUFFER`,
and `D3DPRESENT_INTERVAL_IMMEDIATE` (as Halo presents). Variants: fullscreen 1280x960 X8R8G8B8 + D24X8;
fullscreen 640x480 R5G6B5 + D16; windowed 256x256 on the 32 bpp desktop. Frame N:
- **Clear** to (16,32,48), (48,32,16), then (32,48,16).
- **Untextured `XYZRHW` quads:**
  - four quadrants, each inset 8 px: red (255,0,0) top-left, green (0,255,0) top-right, blue (0,0,255)
    bottom-left, white (255,255,255) bottom-right;
  - a 1-pixel magenta border on columns 0 and W-1 and rows 0 and H-1;
  - a 16-step grey ramp, 0 to 255 in steps of 17, across the middle row band.

**Three readbacks:**
- **A:** the spy's path. `GetBackBuffer` → `LockRect(READONLY)` before `Present`.
- **B:** `GetFrontBufferData` after `Present` (fullscreen only).
- **C:** `GetRenderTargetData` into a system-memory surface (the spy's fallback).

**Pass criterion: exact values.**
- At 32 bpp every sampled pixel equals the drawn RGB: each quadrant's centre, a 3x3 at each border midpoint
  and corner, and all 16 ramp steps.
- At 16 bpp each equals the 565 quantisation of the drawn value (e.g. ramp step 17 → (16,16,16)).
- **B shows frame N, never N-1**, which tests front/back confusion.
- All four borders are present. They catch the V-01 half-pixel class.

**Failure classes it names:**
- "B shows the previous frame": the G79 kind of confusion;
- a constant row offset: pitch;
- missing borders: edge rasterisation;
- A ≠ C: the lock path.

There is no old-buggy value: the path is new. The test is the spy's acceptance gate on our HAL.

**`caps9 --halo` (report).** Pass on `.124` = MaxStreams 0, VertexShaderVersion 0xfffe0000,
PixelShaderVersion 0xffff0000, renderer "legacy 0x51fd80", `Shader=Fixed Function`, X8R8G8B8
render-target texture refused. The X8R8G8B8 2D texture is refused before G17 bit 3 and **accepted after it**.

## 9. Risk

**To proven paths: none.** No driver code changes.

**In the sessions:**
- **Stale Glide state (G01).** A Glide or OpenGL title earlier in the boot makes every Halo triangle vanish,
  and can escalate to a 2D give-up and loss of the HAL. The guards are §4.0 step 2 and a clean boot.
- **A freeze (G04).** The cause of 10-04 is unknown, so a person stays at the box. No `vcrctl` or escape runs
  while Halo runs. The agent's GDI `SCREENSHOT` worked throughout 11-12's Halo run.
- **A leftover `d3d9.dll` in `C:\Games\Halo`.** GAMESYNC never deletes, so a forgotten spy would ride every
  later Halo launch. The guards:
  - step 7 deletes it and verifies with `DIRLIST`;
  - the session script refuses to start if one is already there, and refuses to report success until it
    is gone;
  - the spy logs its own md5 at load, so an unexplained one is identifiable.
- **Spy bugs.** They can crash Halo, not the box: user mode only, in Halo's process. R0 validates the spy on a
  reference box first, and `capture9` validates it on `.124`.
- **Capture cost.** Each capture is a Lock, which drains the engine. Captures are rare (`max=120`). Disk use is
  bounded.
- **Lost device and mode change (step 6).** These exercise G43's possible use-after-free and the never-tested
  lost-device path. They are done last, deliberately, with the person watching, and skipped if anything
  earlier was unstable.
- **The CRT.** Halo switches to 1280x960@85 (and 640x480@85) at launch and back at exit. Those are two paced
  switches per launch. `capture9`'s fullscreen variants are 5 s apart. No refused pair is probed (G11).
- **MP.** Halo needs one key per simultaneous player: `.124` uses `-8`, distinct from `.110` `-3`, `.123`
  `-5` and `.240` `-6`, and the lanparty bat imports it. `sv_public 0` is required. `.123` may be in use by
  another session, so check first or host on `.145`.
- **SLI and the flip path.** Halo's D3D runs on chip 0, and nothing touches SLI. Item 14 deliberately moves
  Halo onto the vsync'd flip path, which d3dprobe perf has run at 85 fps.
