## 0. Verdict

- **The gap is real, and both halves are measured.**
  - **The ring wraps.** At the deployed `LogLevel` 3 the 1024-entry ring held the last **17.4 s** of the UT2004
    session, the last 62.9 s of UT2003 and the last **0.5 s** of Halo. In each of those last 1024 entries,
    1008-1013 are DEBUG `CreateSurfaceEx` destroy notices (513/3).
  - The UT2004 window fetched after the game began at sequence 96,359, against a mark of 30,121 taken before the
    launch. **At least 66,237 entries were never seen.**
  - **No counters.** The "context gone" line (513/2) carries DP2 calls, triangles, clears, unparsed opcodes and
    texture flushes, and nothing else. Whether a title ever sends ZBIAS, flat shading, lines, state blocks or a DX5
    texture state is unknown for every title on `.124`.
  - Twenty sibling designs each carry their own "step 0" counter slice, and they wait on G76 for a common home.
- **Design.** Three parts, all log-only:
  - **(A) The usage block.** This is a new Win32-free header, `include/vcr_d3duse.h`. It holds two append-only
    X-macro tables: 70 counters, and 33 "conditions" counted in **triangles drawn while the condition held**. They
    are attributed per state epoch, so the drawn-triangle path gets no added instruction. The block is emitted at
    `ctx_free` as about 36 INFO records under a new event code, `VCR_EV_DD_D3DUSE`, right after the unchanged 513/2
    line. There is one extra WARN line when the HAL silently dropped work (G02's signature).
  - **(B) Ring discipline and tooling.**
    - **Logging values for the in-game campaign:** `Diag\LogLevel` = 2 and `Diag\LogEntries` = 8192, both read at
      boot by code that already exists. 8192 entries is 1 MB of non-paged pool, the same values G04's boots use.
    - **`deploy_box.py`** keeps the operator's `LogLevel` instead of forcing 3.
    - **A ring-window helper** marks the sequence number before a title and fetches only that title's entries
      afterwards. It refuses while the title still runs, and it names a wrap with the number of entries lost.
    - **`tools/d3duse.py`** decodes the block, gives the d3dprobe verdict, and builds the title × gap exposure
      matrix.
  - **(C) Optional, with or after G52.** Sample the creation-path DEBUG floods (513/3, 511/7, 513/11/19/20) per
    process, and add a per-process summary at `DestroyDDLocal`. Then a default-level ring keeps a whole session.
- **What does not change:**
  - **no register write:** `vcrdd_3d.c` and every `VcrDd3d*` call are untouched;
  - **no caps bit;**
  - no DDI answer (`ddrval`, `dwErrorOffset`, `dwNumPasses`);
  - no byte of the DP2 walk's consumption;
  - no miniport code.
- **Gating:** safe to land **default-ON** under the project rule's "proven path byte-for-byte unchanged" exception.
  There is precedent for counters on in every build: `log_combo` (INFO, `vcrdd_d3d.c:882-919`) and the flip
  counters (`include/vcr_flip.h`). The first deploy is still one supervised clean boot.
- **Priority P1:** it is the measurement every P0/P1 fix decision on `.124` waits on, and G04's Max Payne ring
  needs it. **Effort M.** It unblocks no title by itself.

## 3. Design

### 3.1 Part A: the usage block, `KMD/include/vcr_d3duse.h` (new)

**Principles.**
1. **Raw facts, not verdicts.** Each row is something the application did, or something this HAL did with it,
   defined by a plain rule. Verdicts ("drawn exactly?") belong to G15's `vcr_tssval` and G12's compiler. When they
   land they append a condition (`tss_inexact`), and they never redefine a row.
2. **One table, append-only, X-macro.** This is the `include/vcr_events.h` pattern: the C side and
   `tools/d3duse.py` parse the same lines, and a row is never renumbered or removed, so old rings keep decoding.
   Each row names the gap it informs, and the report reads the gap id from the row itself.
3. **Integer-only, no OS header, no hardware access.** It includes `vcr_types.h` only. The display DLL compiles it
   under `-mgeneral-regs-only`, and the host test compiles it unchanged.
4. **Triangles, not state writes, for conditions.**
   - A runtime that writes every state at device creation (d3dim, inferred) would make "was ever set" true for
     every title. "Triangles drawn while ZBIAS ≠ 0" is the exposure a fix decision needs.
   - G24 makes the same point for Rainbow Six, which sets FLAT at init.
5. **Attributed per state epoch, never per triangle.** An epoch starts where `prepare()` recomputes the registers,
   which is the only place state can change between triangles. On the drawn path the existing `c->tris++` is the
   only per-triangle work.

**D3D numbers.** The header defines what it needs, `VCR_RS_*`, `VCR_TSS_*`, `VCR_TOP_*`, `VCR_TA_*` and so on (DX7
DDI values). `vcrdd_d3d.c` pins each against the SDK name with `VCR_STATIC_ASSERT`. mingw's `d3dtypes.h` defines the
retired ones too: `D3DRENDERSTATE_TEXTUREMAPBLEND` = 21 at `/usr/share/mingw-w64/include/d3dtypes.h:848`. Also
`VCR_STATIC_ASSERT(dword32, sizeof(DWORD) == 4)`, because the driver hands `c->rs`/`c->tss` to the header as
`const vcr_u32 *`.

**Types and functions** (all `static __inline`):

```c
#define VCR_UC_WORDS 2                       /* condition masks: up to 64 conditions */
typedef struct vcr_d3duse {
    vcr_u32 v[VCR_U__NSLOTS];                /* the slot table, in table order */
    vcr_u32 t[VCR_UC__NCONDS];               /* triangles drawn per condition */
    vcr_u32 epoch_mask[VCR_UC_WORDS];        /* the conditions of the open epoch */
    vcr_u32 epoch_tris;                      /* c->tris when it opened */
    vcr_u32 flags;                           /* VCR_UF_SATURATED ... */
} vcr_d3duse;                                 /* lives in vcr_d3dctx; ContextCreate's memset zeroes it */

typedef struct vcr_use_in {                  /* filled by prepare(); read-only here */
    const vcr_u32 *rs, *tss0, *tss1;         /* c->rs[256], c->tss[32], c->tss1[32] */
    vcr_u32 tex0_bound, tex0_ok, tex0_drawn, tex0_ckey;   /* handle != 0 / view_of ok / prepare drew it / HASCKEYSRCBLT */
    vcr_u32 tex1_bound, tex1_ok, tex1_drawn;
    vcr_u32 fvf_spec, rt32;                  /* the vertices carry specular; the target is 32 bpp */
} vcr_use_in;

void    vcr_use_add(vcr_u32 *x, vcr_u32 n);                  /* saturating; sets VCR_UF_SATURATED */
void    vcr_use_conditions(const vcr_use_in *in, vcr_u32 mask[VCR_UC_WORDS], vcr_d3duse *u); /* + op/arg masks */
void    vcr_use_epoch(vcr_d3duse *u, vcr_u32 tris_now, const vcr_use_in *in);  /* flush the open epoch, open a new one */
void    vcr_use_flush(vcr_d3duse *u, vcr_u32 tris_now);      /* at ctx_free */
void    vcr_use_op(vcr_d3duse *u, vcr_u32 op, vcr_u32 n, const unsigned char *rec, vcr_u32 avail); /* walk() */
void    vcr_use_rs(vcr_d3duse *u, vcr_u32 st, vcr_u32 old, vcr_u32 v);   /* set_rs (st may be >= 256) */
void    vcr_use_tss(vcr_d3duse *u, vcr_u32 stage, vcr_u32 st, vcr_u32 old, vcr_u32 v); /* the TSS walk */
int     vcr_use_record(const vcr_d3duse *u, vcr_u32 ctx, vcr_u32 k,
                       vcr_u32 *a, vcr_u32 *b, vcr_u32 *c, vcr_u32 *d,
                       const char **n0, const char **n1, const char **n2);  /* 0 = no record k */
static const char *const vcr_use_slot_name[VCR_U__NSLOTS];     /* generated from the tables, */
static const char *const vcr_use_cond_name[VCR_UC__NCONDS];    /* no extern, header-only     */
```

Every index is clamped inside the header, never by the caller alone:
- an op ≥ 32 sets mask bit 31;
- an opcode ≥ 96 sets bit 31 of `dp2_ops2`;
- a state ≥ 256 only sets G08's `lgc_misc` 0x40;
- a stage > 1 only counts `tss_dropped`.

`vcr_use_op` reads `wCount` (POINTS) and `dwOperation`/`sbType`/`dwParam` (STATESET) only within `avail`. That is
the byte count `walk()`'s `NEED()` has already proven.

### 3.3 The epoch rule

- In `prepare()`, after the texture-coordinate and fog decisions (`:1338-1360`) and **before**
  `VcrDd3dTarget`/`VcrDd3dState` (`:1361`), the driver fills a `vcr_use_in` and calls
  `vcr_use_epoch(&c->use, c->tris, &in)`. That function:
  1. adds `tris_now - epoch_tris` to `t[b]` for every bit of the **old** mask;
  2. computes the new mask with `vcr_use_conditions`, which also ORs the six op/argument masks;
  3. increments `epochs`.
- `prepare()` reaches that point only when the state is dirty or the walk is not prepared. That happens at every
  state change, SETRENDERTARGET, clear, texture write and new DP2 call (`:1333`, `:1404`, `:1419-1420`,
  `:1602-1607`, `:1741-1742`; a new DP2 call starts with `prepared` 0).
- So every triangle `tri()`/`imm_tri()` draws is attributed to the conditions in force when it was drawn.
- `ctx_free` closes the open epoch with `vcr_use_flush(&c->use, c->tris)` before it emits.
- The cost is about 100-200 integer operations per epoch. UT2003 made about 30 DP2 calls a frame (59,589 over
  1,998 frames), so even at a few epochs per call that is microseconds against a 123 ms frame (inferred estimate).

### 3.4 The records (`ctx_free`)

**A new event `VCR_EV_DD_D3DUSE`, at the next free 5xx code at landing.**
- 514 is contested by G02 and G04, 515 by G43 and G47, and 516 is G13's, so 517 is the provisional number. The plan
  owner assigns it.
- A code of its own keeps G76 off the 513 sub-codes 24-29, which ten designs claim.

All lines are INFO unless noted. They come right after the existing 513/2 line, **which stays byte for byte as
it is**.

| record | a | b, c, d | message (≤ 95 characters) |
|---|---|---|---|
| head | `ctx << 16 \| 0` | nslots, nconds, flags (bit 0 a counter saturated, bit 1 idle context) | `context %u usage: %u counters, %u conditions (vcr_d3duse.h)` |
| slot k (1-based) | `ctx << 16 \| k` | `v[3k-3]`, `v[3k-2]`, `v[3k-1]` | `ctx %u %s=%u %s=%u %s=%u` |
| condition j | `ctx << 16 \| 0x100 + j` | `t[3j-3]`, `t[3j-2]`, `t[3j-1]` | `ctx %u tris %s=%u %s=%u %s=%u` |
| **WARN**, only if `tris_lost` or `dp2_nodraw` | `ctx << 16 \| 0xff` | tris_lost, dp2_nodraw, nodraw_why | `context %u: %u triangles and %u DP2 calls NOT drawn (why %x) - the game was told DD_OK` |

- **Volume:** 1 + 24 + 11 = **36 lines per context**.
- **An idle context** (0 DP2 calls, 0 clears) logs only its head, with flag bit 1, so the runtime's short-lived
  probing contexts cost one line.
- **Message length:** the longest is `ctx 32 ` + 3 × (12 + `=` + 10 + space) = 79 characters, within the 95 that
  `VCR_LOG_MSG_LEN` holds (`vcr_log.h:32`).
- **Decoding:** `ctx` and `k` sit in `a`, so the decoder never parses text. A record's slot names come from the
  table, which is append-only, so a newer table still decodes an older ring.
- **Cost:** 36 `VcrDd` round trips (≤ 26 µs each, G52 §2) once per context, about 1 ms at device release.
- **The emitter reads only the context's own counters and three globals. It never dereferences `c->pd`**, so it
  adds nothing to the PDEV use-after-free hazard of G43. (`ctx_free`'s existing `VcrDd2dSync(c->pd)` is G43's.)

### 3.6 Part B: ring discipline and tooling

**1. Logging values for the in-game campaign** (registry only, read at boot by code that exists):
- `Diag\LogLevel` = **2**. INFO and up are stored: ContextCreate, `log_combo`'s 64 set-ups, the usage block, flip
  statistics and mode sets. Every per-draw and per-surface DEBUG line is dropped.
- `Diag\LogEntries` = **8192**: 1 MB of non-paged pool, the value G04 §4.4 uses. One logging configuration then
  serves both the Max Payne boots and the G73 sweep. 16384 (2 MB, G59) is the code's ceiling and is allowed.
- **Why the size matters:**
  - At level 2 a game session should be roughly 300-1,000 entries (inferred from the INFO sources: 192 combine
    lines, about 36 usage lines and about 50 GetDriverInfo lines per context, plus mode sets). 8192 entries then
    hold several sessions.
  - That margin makes a missed fetch survivable.
- **If the allocation fails** there is no ring and no error: the miniport is fail-safe (`vcrmp_log.c:288-289`). So
  the first check after the boot is the `#vcrlog ... entries=8192` header.

**2. `KMD/tools/deploy_box.py:280`.**
- It writes `LogLevel` only when the value is absent (3, today's deployed default), or when `--loglevel N` is given.
- It prints the value it kept. A redeploy no longer silently resets a campaign to a wrapping ring.

**3. `KMD/tools/ringwin.py` (new; host side, pure functions plus agent calls):**
- `mark(box)`: runs `vcrctl info` and returns `log_next_seq`. It is called **before** the launch, while no D3D title
  runs.
- `fetch(box, mark, dest, alive_pids)`:
  - It **refuses** while any of the title's processes still runs. This is the "no vcrctl while a D3D game runs" rule,
    written into the tool.
  - Then it runs `EXEC cmd /c C:\vcr\vcrctl.exe log <mark> > C:\vcr\ringwin.tsv` and `DOWNLOAD`s the file. The EXEC
    reply stays small, as the project's EXEC rule asks.
  - It saves `dest/ring.tsv` and `dest/d3duse.json`.
- `window_report(mark, entries)`:
  - `wrapped` = the first sequence in the window > mark + 1, with `lost` = how many were never seen;
  - the level histogram, which shows the level in effect: a window with D3D activity and no DEBUG entries is level 2.
  - On the 11-12 UT2004 data it reports **wrapped, 66,237 lost**: the gap, measured by the tool itself.
- `vcrlog.py fetch` gains `--via-file` (the same redirect plus `DOWNLOAD`) for whole-ring reads, for example after a
  freeze.

**4. `KMD/tools/d3duse.py` (new):**
- `load_table()` parses the two X-macro tables from the header: names, kinds, gaps and descriptions.
- `contexts(entries)` groups by (pid, ctx, block). It returns the 513/2 totals and every slot and condition, with
  the triangle share of each condition. Masks are decoded to names (D3DTOP, D3DTA, opcode and state names).
  - A 513/2 line with no block → `usage: null, why: "no D3DUSE records: a build before G76"`.
- `verdict(expect, ctx)`: the d3dprobe check (§5).
- `report(dirs)`: the title × gap matrix as markdown. Each cell is a triangle share or a count, and the columns come
  from the rows' gap ids. It replaces hal.md §11's inferred table.
- `check --combos`: in the same window, every op and argument in a `log_combo` 513/22 line must appear in the
  block's masks. This is a self-consistency check of the instrument against an independent one.
- `vcrlog.py decode` names the event from `vcr_events.h` as it already does, and gains `--d3duse` to append the
  decoded block.

**5. Runners.**
- `KMD/tools/d3dprobe_run.py --ring`. This is G52's flag; one flag serves both, with every registered verdict run
  (G52's `loggate`, G76's `d3duse`). It takes the mark before the upload and fetches after a civil exit.
- `WT/scripts/benchmarks/lan_sweep.py --ring` (and `lan_check.py`) is on by default when `vcrctl info` answers.
  - Per title: mark, launch, close, then fetch into `<outdir>/<title>/`.
  - It prints `ring: N entries, contexts K, wrapped no/yes (lost L), level 2`.
- G73's in-game runner and G04's attended Max Payne runs use the same helper.

**6. After any freeze where the box still answers:** close the game (WM_CLOSE, then a forced kill by pid), wait
for the desktop, then `ringwin.fetch` from the last mark. That saves the ring the 10-04 Max Payne freeze never got.
- `ctx_free` runs at process termination; a forced kill produced the 513/2 line on 11-12.
- A box that is itself hung loses the ring. There, G04's registry heartbeat and the phases are the record.

## 4. Gating

- **Parts A and B land default-ON, with no Diag switch.**

  - There is precedent for counters on in every build: `log_combo` and the flip counters.

  G52.
- **The campaign's `LogLevel` 2 / `LogEntries` 8192** are logging values that existing code reads at boot. They are
  log-only and give one logging change for that clean boot. If the plan owner applies "one Diag change per boot"

- **The first deploy is the standard supervised clean boot.**
  1. `bash tests/run_all.sh` green and `tools/check_imports.py`.

  4. Swap only `vcrdd.dll`, keeping `95678704` as the rollback.

## 5. The d3dprobe test: `usage`

| lines | LINELIST 5 lines + LINESTRIP 3 segments | `lines_seen` = 8; `prim_ops` names the opcodes |
| points | POINTLIST 7 | `points_seen` = 7 |
| totals | everything above | 513/2 triangles = Σ issued; `epochs` ≥ the number of items; `tris_lost` = `tris_badidx` = `dp2_nodraw` = 0 |

**Observed, not gating.** These record what the D3D8 runtime does with a DX7 DDI, as runtime facts. G15 treats its
three-stage cell the same way.
- **usew** (ZENABLE USEW), **stencil** (STENCILENABLE on a target without stencil), **fill** (FILLMODE WIREFRAME:
  `fill` = 2, or the runtime made lines), **projected** (TEXTURETRANSFORMFLAGS COUNT3 \| PROJECTED): each records
  whether it arrives.
- **state block:** `CreateStateBlock(ALL)` plus `ApplyStateBlock`. Expected `ss_*` = 0, because D3D8 emulates state
  blocks for this DDI level (`reports/runtime.md` §9, from disassembly). **A non-zero count is a finding: G40 is then
  real for D3D8 titles.**
- **validate:** one `ValidateDevice`. This records whether D3D8 forwards it to `ValidateTextureStageState` (`validate`
  ≥ 1).
- **Negative controls** must stay 0: `ckey*`, `leg_*`, `lgc_n*`, `legacy_binds` (D3D8 cannot send DX5 states; G75's
  `d3d7probe` covers them), and `tex*_ref`.

**Pass criterion.**
- Every exact row equals the probe's own count of what it issued, and every negative control is 0.
- The block's head is present with `nslots`/`nconds` equal to the host's parsed table.
- Two consecutive runs give **identical** blocks: the counters are per context and zeroed at creation.
- **Reference "old" value:** on build `95678704` the window holds no D3DUSE block, and the verdict says
  `absent: a build before G76` → **FAIL**. So the test separates the builds.
- **Run at:** `--full --res 640x480 --bpp 16` and `--full --res 1024x768 --bpp 32`, where `dither32` changes from
  0 to 2. First on the 86Box Voodoo3 bed at 16 bpp.

## 6. Regression tests

**`WT/tests/native/test_vcr_kmd_d3duse.c` (new).** It compiles `include/vcr_d3duse.h` with munit, as
`test_vcr_kmd_log.c` does, and cites `display/vcrdd_d3d.c:prepare/ctx_free/walk` and the G76 build. `run_all.sh`
picks it up.

1. **`each_condition_has_exactly_its_trigger`** (table-driven, 33 rows). The baseline state (the HAL's
   `ctx_defaults`) gives mask 0. Each trigger sets only its bit, and its nearest non-trigger does not:
   - ZBIAS 1/0; ZENABLE 2/1; SHADEMODE 1/2; FILLMODE 2/3/0;
   - FOGEND 0x3f800000 → `fogt_z`, 0x3f800001 → not, 0xbf800000 (-1.0) → yes;
   - MIPFILTER 3/2, on a drawn stage and on an undrawn one;
   - MODULATE2X/MODULATE; BLENDDIFFUSEALPHA on stage 0 (named) and on stage 1 (`op_other`);
   - a modifier on a used argument, and on an unused one (SELECTARG1 with ARG2 modified → not counted);
   - DITHER at 32/16 bpp; DESTCOLOR as a source (mapped right → no) and as a destination (→ `bl_color1`).
2. **`epochs_attribute_triangles_exactly`:** epochs (A, 5 triangles), (B, 3), (A|B, 2), then a flush → A = 7,
   B = 5, `epochs` = 3.
3. **`the_open_epoch_is_flushed_at_free`:** without `vcr_use_flush` the last epoch's 4 triangles are missing (the
   old-buggy value 0); with it they are counted.
4. **`counters_saturate_and_say_so`:** 0xfffffff0 + 0x20 → 0xffffffff and the flag set, never a wrap.
5. **`records_cover_every_slot_once`:**
   - walking `vcr_use_record` yields each slot and condition exactly once, at `a = ctx << 16 | k` /
     `| 0x100 + j`;
   - the head's counts equal the table sizes;
   - an idle context yields its head alone.
6. **`messages_fit_the_ring`:** names ≤ 12 characters; the worst-case message (ctx 32, all values 0xffffffff)
   < `VCR_LOG_MSG_LEN`.
7. **`stateset_and_points_read_only_what_was_proven`:**
   - `dwOperation` 0-4 → its own slot; 5, 99 and 0xffffffff → `ss_other`; the first record kept;
   - `avail` short of n × 12 → nothing counted;
   - POINTS sums `wCount`.
8. **`out_of_range_inputs_stay_in_bounds`:** op 255, argument 0xff, opcode 200, state 300 and stage 7 each set a
   defined bit or counter, and never index past an array. Run under `-fsanitize=address,undefined` when the host
   compiler has it.

## 8. Risk

| proven path | risk | why |
|---|---|---|
| default 16 bpp D3D path | **none to the picture** | no register, caps or answer changes (§3.9), pinned by tests 4-6 |
| kernel-mode stability | low | the counters run in the display DLL, in kernel mode, where a bad index is a bugcheck. Mitigation: every index is clamped inside the header (native test 8, under sanitizers); POINTS and STATESET read only bytes `NEED()` has proven; the 86Box bed runs first |
| Glide/OpenGL coexistence, SLI, AA | none | no miniport or `vcrdd_3d.c` change |
| flip path | none | Part C touches only `CreateSurface`'s log call |
| CPU time | negligible | about 0.1 µs per epoch (inferred), nothing per drawn triangle, about 1 ms at device release. Boot A step 4 measures it in a real game |
| the ring | intended change | +36 INFO lines per context. Part C removes about 1,000 DEBUG lines per session |
| non-paged pool (campaign boot) | low | 1 MB at DriverEntry on a 256 MB box. A failed allocation leaves no ring (fail-safe), which step 6 catches. 11-08 ran a raised value |
| static data | negligible | about 430 B × 32 contexts in the DLL's `.bss` |
