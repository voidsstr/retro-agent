## 0. Verdict

1. **The gap is real, with the correction the gap itself states.** In-game frames on vcr-kmd exist from two dates, and three things are true of all of them:

   | date | titles | build |
   |---|---|---|
   | 09-28 | JK DF2, MotS, Thief II (D3D9 and DX6) | `b63ea6a5`, before the 11-08 fixes |
   | 11-12 | UT2004, UT2003, Halo's timedemo cutscenes | `95678704` |

   - None was compared with a reference renderer.
   - None has a census of what the title asked the HAL to do (point 3a).
   - None is known to come from a boot without an earlier Glide/OpenGL session (point 3c).
   - The other nine reachable titles have menu, intro or dialog frames only. Max Payne's row belongs to G04.
2. **This is an evidence gap, so the design delivers an investigation and the tools to run it.** No HAL behaviour changes in this item. It delivers four things:
   - **The G73 sweep.** A repeatable, instrumented, supervised in-game pass over every reachable Direct3D title, driven by a versioned **scene book** (§5). Eighteen sibling designs name it as their in-game check (`grep -l G73 designs/`): G04, G06, G18, G20, G23, G29, G31, G42, G44, G45, G52, G55, G59, G61, G64, G65, G66 and G69. G05, G08 and G46 plan in-game checks on the same scenes. So the sweep must be a reusable vehicle with fixed scenes and capture points, not a one-off.
   - **`tools/d3dcensus.py`.** It turns the flight-recorder records of a session into a **census**: per title, which gap states the title really used, with counts, and the context's mode, refusals, give-ups and flip counters. That turns every "(inferred)" requirement in `games.md` §3a into a measurement.
   - **The d3dprobe `census` test**, which calibrates the census against known input before it is trusted on games.
   - **The evidence and the records:** frames, rings, censuses, the person's notes, reference frames, and measured compat rows for build `95678704` or its successor.
3. **Eight things this reading adds to the record:**
   - a. **None of the 11-12 in-game sessions has a census.** Each `ONBOX/games/*/ring.txt` holds the last 1024 entries, and 1020 of them are DEBUG. Each has 0 `combine` lines and 0 `ContextCreate` lines:

      | session | first seq | next_seq |
      |---|---|---|
      | UT2003 flyby | 206545 | 207568 |
      | UT2004 botmatch | 96359 | 97382 |
      | UT2004 statfps | 322630 | 323653 |
      | Halo | 305093 | 306116 |

      The sessions logged roughly 70k-110k events each at LogLevel 3. **The only per-title op census on record is still UT2003's MENU** (`SWP/sweep_1108/UT2003_combos_unaligned.txt`, 26 set-ups).
   - b. **`log_combo` cannot census a game, even at LogLevel 2.**
      - Its key hashes the stage-0 texture's format and size (`vcrdd_d3d.c:882-893`, "a texture shape counts"). A game with hundreds of textures therefore fills the 64 slots (`combo_seen[64]`, `:73`) with texture shapes, not with distinct operations.
      - Stage 1's arguments are never logged (only `s1` COLOROP and ALPHAOP, `:907-911`).
      - No render state is logged at all.

      This is the list of what G76 (and the siblings' Phase 0 counters) must add, §3.2.
   - c. **No Glide-free control exists.**
      - The 11-12 in-game sessions ran in the boot of pid 1892's 4-chip OpenGL session.
      - The `vcrctl modeseq` reset that cured the stale FIFO is `VcrHwResetEngine`, which pulses `GRX_RESET | FBI_FIFO_RESET | 2D_RESET` and `CMDSTREAM_RESET` and writes `cmdFifo0.baseSize = 0` (`miniport/vcrmp_hw.c:181-200`). It writes no combine, stencil or chroma register.
      - G03 shows from the spec that a stale **TMU** `combineMode` rewires `TM_TC_REPLACE/MULT/ADD` whatever bit 31 says. MesaFX leaves an extended combine after every GL frame.
      - Counter-evidence: in the same boot, after the reset, d3dprobe `tex2mod`/`tex2add` passed (40/40).

      So the in-game defects that G05, G06, G17, G18 and G44 attribute to HAL gaps must be **seen again in a Glide-free boot** before those fixes are A/B'd. It is the cheapest discriminator in the plan: three scenes, about 25 minutes.
   - d. **The verdict that called these titles "PASS" cannot tell Direct3D from anything else.** In `SWP/sweep_1108_fixed/20261108_020841/sweep.json`, all of these are `PASS`:
      - Halo at 60 s: one colour, (255,255,255), mean 255.0, std 0.0;
      - UT2003 at 60 s: mean 0.3 (99.5 % black, measured here);
      - JK at 30 s: mean 2.7, an 8 bpp DirectDraw crawl (9 colours, 3.4 % of its pixels hold values no 16 bpp target can produce, measured here);
      - Shogo at 60 s: mean 2.0.

      A G73 verdict therefore needs ring evidence (a live context that drew triangles) and a frame at that context's depth, never luma alone.
   - e. **This is a person-at-the-box procedure.**
      - Only Unreal Engine 2 is known to reach gameplay by script; 11-12 did it.
      - Four titles have script candidates to try, from their binaries:
        - Shogo: `runworld` in `SHOGOP3.REZ`, `Worlds\01_Ambush` in `SHOGO.REZ`;
        - Red Faction: `-level`, with `L1S1.rfl` in `levels1.vpp`;
        - Halo: `-console`, `-exec`, `map_name` and `screenshot` in `halo.exe`. G67 expects retail to refuse `map_name` and owns Halo's in-game check;
        - H&D: `profile` and `mission` in `HDE.exe`'s option table (README-FLEET), but only after a person has created a profile once (its menu is relative-mouse, measured).
      - Rainbow Six's 640x480 menu shell takes absolute clicks (G69's step list), with a person watching.
      - JK, MotS, Thief Gold, SS2, Thief II and AvP need their menus driven by a person.
      - Max Payne stays under G04.
   - f. **The best reference box is `.184`.**
      - It now carries a **GeForce2 GTS** (`10DE:0150`, `docs/fleet-inventory.md:54`). That is the DX7 card class `.124` itself had on 08-31, when the stale compat rows were written.
      - It is the closest feature-level peer of the VSA-100 on the fleet, it runs the same library, and its OS is XP too.
      - Halo is gated there. Halo's references are G67's: `.110` and `.240` launched with `-use00`, which runs the same legacy fixed-function renderer `.124` already runs (G67 §1.2.1; `.171` is not used because it still carries the library key).
      - A same-silicon reference (AmigaMerlin on `.124`) is possible but costs two driver swaps. It is optional (§6.6).
   - g. **Three titles already have their in-game plan in a sibling design, and the sweep reuses it rather than writing a second one:** Halo (G67: `d3d9spy`, a 15-scene checklist, a 30-minute multiplayer session), Red Faction (G68: the black-frame chain and attended play) and Rainbow Six (G69: a scripted step list through Training). G68 and G69 both promote `ONBOX/gamerun.py` to **`KMD/tools/gamerun.py`**. This design extends that one runner (§4.2) instead of adding another.
   - h. **The driver-side census cannot see what the runtime refuses before the driver is asked** (G67 §0.3: the D3D9 runtime refuses formats and render targets itself). For D3D9 titles G67's `d3d9spy` supplies the application side. D3D8 titles (UE2, Max Payne, H&D, Red Faction) would need a `d3d8` counterpart (open question 12).
4. **P1, effort L.** Not P0: the sweep draws nothing differently. It is the measurement that every P0/P1 HAL fix in this plan rides on, and the evidence `.124` needs before its `blk` can be lifted (with G04).

## 2. What "checked in game" means

### 2.1 Verdict classes (one per scene)

| verdict | definition |
|---|---|
| `in_game_ok` | Gameplay (or engine-driven in-level rendering) reached. At least 3 frames at 3 distinct moments show D3D content at the context's depth. A person watched at least 5 minutes. The census is **complete** (§4.1). No refusal, give-up, unparsed command or new Dr. Watson entry. The title exited by its own path. The desktop came back at 1280x1024x32@85. Compared with the reference: no unexplained difference |
| `in_game_defects(Gnn,...)` | As above, but each visible defect is named, located (frame plus crop) and mapped to a gap id. The census says whether the title used that gap's state |
| `in_game_unexplained` | A defect no known gap explains. It becomes a new gap entry with frames, ring and census |
| `menu_only(why)` | Gameplay was not reached. The reason is recorded: a menu nobody could drive, a game dialog, a missing profile or disc |
| `refused` / `no_device` | The HAL refused the target (513/12, 15, 17), the runtime refused (no ContextCreate), or the game reported device creation failed |
| `stalled` / `crashed` | A freeze (G04's bundle) or a crash (Dr. Watson, a game error box, the process gone) |
| `blocked_not_ours` | BF1942 (SafeDisc 2.80, G72) |

### 2.2 The evidence each verdict needs

- **The context, from the ring:**
  - a `ContextCreate` (513/1) for the game's pid, giving width, height, bpp and Z;
  - a `context gone` (513/2) with triangles > 0;
  - the session's mode set (300/303);
  - whether `DirectDraw exclusive` (511/4) went on and off;
  - the flip counters (511/12-13).
- **The frames.**
  - Up to three kinds, each with its own meaning:
    - the **engine's own screenshot** where the title has one (UE2 `shot`; Rainbow Six F2, per G69), or an **in-process capture** where a spy exists (Halo: G67's `d3d9spy`). It is the back buffer the HAL rendered into: the evidence for texture, combine, fog and blend defects.
    - **GDI `SCREENSHOT 0` pairs**, taken one second apart. They may hold either buffer of the flip chain (V-10, G79).
    - **at most one `vcrctl fbshot --probe`** per scene, at a calm moment: what the monitor scanned out. Never for Max Payne, never during a soak; it reads about 1.2 M uncached words, which is G04's H-E.
  - Every frame is kept at **full size**. `visual.md` §2 found 640x480 copies of 1280x960 frames that hide one-pixel defects.
- **Depth agreement.** The frame's quantisation must match the context's bpp (a 565 frame has at most 32/64/32 levels, `visual.md` §2). A mismatch makes the frame `not_this_context`.
- **The person's checklist** (§6.0). It is the only evidence for presentation defects:
  - tearing or half-drawn frames (G55);
  - judder at half rate (G59);
  - garbage at the mode switch (G39).

### 2.3 How a verdict becomes a compat row

`scripts/fleet/compat.py record` writes `origin='measured'`. A `verified` row with no evidence prints a warning (`compat.py:1151-1243`). The report tool (§4.4) **generates** the commands; a person runs them after looking at the frames. The rules:

- **`--runs verified`:** only for `in_game_ok`, or for `in_game_defects` that the person judged cosmetic.
- **`--runs runs`:** for `in_game_defects` that make play impractical (most of the screen wrong), and for `menu_only`. `--detail` names the defects and their gap ids.
- **`--runs failed`:** for `refused`, `no_device`, `stalled`, `crashed` and `blocked_not_ours`.
- **The other fields:**
  - `--renderer d3d`;
  - `--res` from the ContextCreate line, never from the ini;
  - `--refresh` from the session's 300 event;
  - `--fullscreen yes` only when the exclusive mode was seen.
- **`--detail`** always carries:
  - the build (`vcrdd` and `vcrmp` md5);
  - the Diag state (`D3D32=1 D3DBigTex=7` today);
  - "Glide-free boot" or "after <title>";
  - the verdict class.
- **`--evidence`:** the frames and the `census.json`.

### 3.3 Captures

- **G79 owns the frame classifier and the capture tooling.** G73 consumes it.
- **Until G79 lands, G73 uses three things:**
  - the engine screenshot where one exists;
  - GDI pairs one second apart;
  - one `fbshot --probe` per scene, and only where the GDI frames are single-colour or half-drawn.

### 3.4 Stall watch

- **With G04's build:** `d3dwatch.py` runs beside the harness and captures its freeze bundle on a flat beat. It sends no escape while the game lives.

- **The harness never sends an escape while a D3D game runs** (README rule; G04's escape guard enforces it once built).

### 3.5 No driver change in G73

Everything G73 adds is host tooling plus one explicit d3dprobe test (§4.5). The drawing path, the default 16 bpp path, Glide/OpenGL coexistence, SLI and the flip path are untouched.

## 4. The tooling this item adds

### 4.1 `KMD/tools/d3dcensus.py` (host only, pure functions, tested)

**Inputs:**
- the raw `vcrctl log` TSV, parsed with `vcrlog.parse_tsv` so the `pid` column is kept;
- or the bare message lines of an old dump (`UT2003_combos_unaligned.txt`);
- optionally `--pre-seq N`, the `next_seq` taken before the launch;
- optionally `--caps caps_124.txt`.

**Functions:**

| function | what it does |
|---|---|
| `sessions(entries)` | Groups records by pid and context: ContextCreate (513/1, its index in `a`, the size and bpp in the text) up to its `context gone` (513/2: `b` = DP2 calls, `c` = triangles). It attaches the mode sets (300/303), DirectDraw exclusive (511/4), the flip stats (511/12-13), the texture refusals (513/7), the target refusals (513/12, 15, 17), unparsed and short commands (513/5, 6), the give-ups (512/9), the engine resets (308) and every Glide event since boot (604, 607). `log_combo` records carry no context index, so they are placed by pid and sequence order, and **a `combine 1` restarts a context's count**. Two contexts of one pid alive at once is reported as `ambiguous`. |
| `completeness(hdr, entries, pre_seq)` | `complete` only if: (a) the first entry's seq is `pre_seq + 1` (or the header shows `next_seq - entries <= pre_seq`); (b) every `gone` has its `ContextCreate`; (c) no context logged 64 combos. Otherwise it reports `lost_entries`, `missing_create` and `combos_truncated`. All four 11-12 rings come out `complete: false`. |
| `classify_combo(c, caps)` | Maps a set-up to gap keys, from one table that cites the HAL lines. Colour ops not in TextureOpCaps 0x184f, i.e. **not in {1 DISABLE, 2 SELECTARG1, 3 SELECTARG2, 4 MODULATE, 7 ADD, 12 BLENDDIFFUSEALPHA, 13 BLENDTEXTUREALPHA}**: 5/6 → G05, the rest → G12. Alpha ops other than DISABLE/SELECT/ADD/MODULATE → G12. Stage-0 argument modifiers 0x10/0x20 → G13. TFACTOR (3) as an argument of a stage that also reads a texture → G14; TFACTOR alone is the FBI's `c1` and is supported. `am` decoded through `AM_*`/`BF_*` (`include/vcr_3dregs.h:120-136`) into blend-pair names and alpha test. `at & 0xf` → the V-02/G21 placement watch. Aspect above 8:1 → the G18 watch. The `mip` word → the G07 watch. |
| `classify_counters(rec)` | Parses G76's per-context record and the siblings' Phase 0 events into the §3.2 keys, once each parser exists. |
| `census(entries, ...)` | Builds the JSON: per context, `mode`, `dp2s`, `tris`, `clears`, `unparsed`, `tex_flushes`, `flips`, `refusals`, `giveups`, `combos` (each with its gap keys), `gap_keys` (key → count, `UNMEASURED`, or a lower bound), `unrecognised` (every record no parser claimed, **kept verbatim**) and `complete`. |
| `--expect FILE` | Exact comparison of a census with an expected table, for d3dprobe `census`; exit 1 on any difference. |

### 4.2 `KMD/tools/gamerun.py`: one promoted runner, shared with G68 and G69

G68 (§4.3) promotes `ONBOX/gamerun.py` to `KMD/tools/gamerun.py` with `--fetch`, `--regs`, `--ring` and a Red Faction timedemo parser. G69 (§4.3) adds `--steps` with per-title step lists under `KMD/tools/steps/`. G73 adds the sweep features below to **the same file**; whichever of the three lands first creates it, and the others extend it. One change to G68's `--ring`: it must fetch `vcrctl log <pre_seq>` into a file on the box and `DOWNLOAD` it (below), so that a full 16384-entry ring never travels through EXEC's stdout.

**Kept from `gamerun.py`:**
- the wrapper `.bat` (`cd /d`, then start) and `LAUNCH`; never `EXEC` of `start`;
- the screensaver dismissed only when its class is in front;
- WM_CLOSE by pid, a 20 s grace, then a forced kill by pid only, recorded;
- never a kill by image name;
- `DISPLAYCFG get` afterwards;
- the run ends after 120 s of agent silence.

**Added:**

1. **Preflight** (no game running, so escapes are allowed):
   - `PING`;
   - `PROCLIST`: no scene-book image, `vcrctl`, `d3dprobe` or `glidelab` running;
   - `REGREAD HKLM SYSTEM\CurrentControlSet\Services\vcrmp\Diag`: the session plan's values, else refuse;
   - `EXECW 60 C:\vcr\vcrctl.exe reg 80024` and `reg 0`: refuse when `cmdFifo0.baseSize` bit 8 is set (G01's stale FIFO) or when status reads busy. Also record the R/W 3D registers G03 says can be read (stencilMode, stencilOp, clip1);
   - `vcrctl log 4000000000`: with no entry after that seq, `cmd_log` prints only the `#vcrlog` header (`tools/vcrctl.c`). Its `next_seq` is the newest entry's seq (`common/vcr_log.c:73-79`) and becomes `pre_seq`. **Not `4294967295`:** `vcr_log_read` tests `after_seq + 1 > oldest` (`common/vcr_log.c:76`), the sum wraps to 0, and the whole ring comes back through EXEC's stdout. The harness pins the value, and a test asserts it (§8.3). In Glide-free sessions, the boot's ring must hold no 604 a=1 since boot;
   - `vcrctl clock get`: stock;
   - `WINLIST`: no `#32770` dialog left over;
   - `DISPLAYCFG`: 1280x1024x32@85;
   - `bench.quiesce` (`scripts/benchmarks/v56k_bench.py`, the plan's ground rule 6);
   - a timestamp snapshot of the game folder's `*.log`/`*.txt`/`*.cfg`/`*.ini`, written by `dir` to a file and fetched with `DOWNLOAD`.
2. **Launch** through the staged launcher wherever the scene allows, by `call`ing it from the wrapper. Mount launchers, FLEETRES, Halo's per-box key import and Thief II's display swap then run as they do for a player. Otherwise use the scene's recipe line.
   - `reach: person`: the harness prints the person's steps and waits for "in game" (a key on the host, or a `go` file). Meanwhile it polls `PING`/`PROCLIST` every 10 s.
   - `reach: script`: it sends the recipe's keys at the given times, each after a `WINLIST` foreground check (agent 1.91.0+).
3. **During the game** (no escapes): at each capture point,
   - `PROCLIST`;
   - `WINLIST` (the foreground, and new dialogs);
   - two `SCREENSHOT 0`, one second apart;
   - the engine-screenshot key, if the scene has one;
   - `REGREAD ...\Diag\Live` when the beat exists.

   It prints the person's checklist questions and records the answers in `notes.md`.
4. **Close.** The scene's quit path first (console `exit`, or the person's menu quit). Then WM_CLOSE by pid, 20 s, then a forced kill by pid. A forced close is a **finding** for the scene, never silent.
5. **Postflight** (escapes allowed again):
   - wait 6 s;
   - `DISPLAYCFG` back at the desktop mode;
   - no new dialog;
   - the `drwtsn32.log` size unchanged (`lan_check.py` `DRWTSN`);
   - `EXECW 120 cmd /c C:\vcr\vcrctl.exe log <pre_seq> > C:\vcr\g73\<scene>\ring.tsv`, then `DOWNLOAD` it. **Never through EXEC's stdout:** EXEC output is small by contract;
   - `vcrlog.py decode`, then `d3dcensus.py`;
   - `vcrctl reg` again: idle, FIFO off;
   - the folder diff: changed text files up to 1 MB fetched with `DOWNLOAD` (UE2 `System\*.log`, AvP `LOGFILE.TXT`, Rainbow Six `Sherman.log`, and any others the diff shows), and the engine screenshots converted to PNG;
   - `run.json` and `census.json`;
   - at least 10 s before the next scene (the CRT).
6. **`--reference HOST`** runs the same scene on another box. It skips the Diag, `vcrctl`, ring and census steps and keeps the captures, game logs and notes.

## 6. The protocol

### 6.0 Before each boot, and the person's checklist

1. **Activation.** `LICSTATUS` (or `wmic path Win32_WindowsProductActivation get /value`) **before** any reboot.
2. **The PXE hold for `.124`:** MAC `00:d0:b7:40:96:a9` (G04 §4.1), checked with `--list-holds`. Reboot **only** through `scripts/fleet/safe-reboot.py`.
3. **The logging values** of §3.1, each read back. `D3D32=1` and `D3DBigTex=7` stay as deployed. No behaviour switch.
4. **After the boot:**
   - the ring header must show the new `boot_count` and `entries=16384`;
   - `vcrctl reg 80024` must read `baseSize` 0;
   - nothing Glide or OpenGL has run since boot (no 604 events).
5. **Calibration:** d3dprobe `render --full --res 1024x768 --bpp 32` (40/40), then `census` (§8.1). If either fails, **no game runs in that boot**.

**The person's checklist,** printed at every capture point and recorded in `notes.md`:
- Does it look like the reference frame shown on the host?
- Name each defect you see: what it is and where.
- Is motion smooth, or does it judder? Any tearing or half-drawn frames?
- Was there garbage on screen between the mode switch and the first frame?
- Is sound playing? Does input respond?
- At a freeze: does the cursor move, does Num Lock toggle, when was it first noticed (G04's list)?
- How did it end?

The person also moves the mouse every 8 minutes. Whether XP's 10-minute screensaver fires under a D3D exclusive-mode app is unknown (G04 H-I; open question 5).

### 6.1 Session A (boot 1, Glide-free): the control, then the scripted titles (about 2.5 h)

1. **The control** repeats the 11-12 scenes exactly, with the same lines and the same capture times:
   - `ut2004_antalus_spec` (11-12 run #19's 40/60/80/100 s);
   - `ut2003_flyby_antalus` (30/60/90/120 s);

## 7. Outcomes, meaning and action

| outcome | meaning | action |
|---|---|---|
| a Session A frame shows the 11-12 defect at the same strength | the defect belongs to the HAL. The G05, G06, G17, G18 and G44 attributions stand | Those designs' A/B boots reuse these scene ids. Raise each gap's measured `games` list from the census |
| the defect is absent or much weaker in Session A, and returns in the post-Glide leg | leftover Glide/OpenGL state (G03), not the gap it was attributed to | G03's baseline (`Diag\D3DSafe` bit 1) is promoted ahead of the sibling it masked; the sibling's attribution is reopened |
| `cmdFifo0` is on after a **clean** Glide quit | G01's mechanism is wider than the not-idle close | G01 widens its trigger. No D3D title after any Glide session until G01 lands |
| the census shows a gap state used, but the frames show no visible defect | the state is rare, or harmless in that scene | Lower that gap's priority for that title. Keep the census line |
| a visible defect, with no gap state in the census for it | another mechanism, or a counter missing in G76 | `in_game_unexplained`: a new gap entry, plus a `FINDINGS.md` entry with frames, ring and census |

## 8. Tests

### 8.1 d3dprobe: `census` (explicit, never in the default list; windowed or fullscreen)

**What it draws.** A grid of 64x64-pixel cells in the 256x256 window. Each cell is one quad (2 triangles) drawn with exactly one state, and the state is reset to the baseline after its cell, so no state bleeds into another cell. Lines and points are drawn last.

| cell | state | census key |
|---|---|---|
| c0 | baseline: MODULATE(TEXTURE, DIFFUSE), 565 64x64 | none (the pixel check) |
| c1, c2 | stage 0 MODULATE2X / MODULATE4X | G05 |
| c3 | stage 1 MODULATE2X(TEXTURE, CURRENT), two textures | G05, stage 1 |
| c4, c5 | stage 0 TEXTURE\|ALPHAREPLICATE, TEXTURE\|COMPLEMENT | G13 |
| c6 | MODULATE(TEXTURE, TFACTOR) | G14 |
| c7 | stage 0 SUBTRACT | G12 |
| c8 | stage 1 BLENDCURRENTALPHA | G12 |
| c9 | SRCBLEND SRCCOLOR | G29 |
| c10 | DESTBLEND DESTALPHA | G28 |
| c11 | SHADEMODE FLAT | G24 |
| c12 | FILLMODE WIREFRAME | G24 |
| c13 | ZBIAS 4 | G22 |
| c14 | ZENABLE USEW | G23 |
| c15 | SPECULARENABLE with a specular FVF | G25 |
| c16 | ADDRESSU MIRROR | G33 |
| c17 | MIPFILTER LINEAR on a 64 chain | G26 |
| c18 | MIPMAPLODBIAS and MAXMIPLEVEL | G27 |
| c19 | STENCILENABLE | G35 |
| c20 | FOGTABLEMODE LINEAR, start 0.1, end 0.9 (Z units) | G31 |
| c21 | TEXTURETRANSFORMFLAGS COUNT2\|PROJECTED | G92 |
| c22 | DITHERENABLE, only in a 32 bpp run | G30 |
| last | 4 LINELIST lines and 4 POINTLIST points; one `ValidateDevice` call | G16, G15 |

**Pass criteria:**
- **The census equals `tools/d3dprobe_census_expect.json` exactly.** That means the key set, and the counts: 2 triangles per cell, 4 lines, 4 points, 1 validate.
- **Before G76 lands,** the expected table is:
  - the `log_combo` keys of c1-c8, one set-up each (c3 and c8 by their **stage-1 op** only, since stage-1 arguments are not logged);
  - c10's DSTALPHA **as programmed** (it survives the HAL's mapping, `vcrdd_d3d.c` `blend_dst`); c9's SRCCOLOR does not (it is already ONE), so its key reads `UNMEASURED`;
  - **every render-state key `UNMEASURED`**;
  - no other gap key. The total number of set-ups is not asserted, because cells whose state the HAL ignores share c0's set-up.

  The test therefore also proves the census never invents a zero.
- `context gone` triangles = the number drawn (computed by the probe and printed).
- 0 unparsed.
- `complete: true`.
- c0's pixels match the computed MODULATE reference within ±8 per channel at 565 (the `modulate` check's rule).

The other cells are **not** pixel-checked. Their output is known to be wrong today; each gap's own d3dprobe test owns its pixels.

### 8.3 `tests/python/test_gamerun_sweep.py` (offline, fake agent, no socket; beside G68's `test_gamerun_timedemo.py`)
