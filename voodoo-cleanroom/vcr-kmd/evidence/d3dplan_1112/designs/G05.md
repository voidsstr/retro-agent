## 0. Summary

- **The gap is real, and its fix is exact for every set-up UT2003 logged.**
  - 7 of UT2003's 26 logged combines use `D3DTOP_MODULATE2X` (op 5).
  - Combines 3, 8, 10 and 12 are single-stage `MODULATE2X(TEXTURE, DIFFUSE)`.
  - Combines 1, 5 and 6 are `SELECTARG1(TEXTURE)` followed by a stage-1 `MODULATE2X`: the UE2 lightmap.
  - The HAL draws both as `MODULATE` (`KMD/display/vcrdd_d3d.c:714`, `:862`).
- **The fix is one pass, and it uses only inputs the HAL already routes.**
  - On a state flush whose stage op is MODULATE2X/4X, the HAL writes `combineMode` on the FBI (stage 0) or on TMU0 (stage 1).
  - The word sets bit 31 (`USE_COMBINE_MODE`) and bit 30 (`DISABLE_CHROMA_SUBSTITUTION`). Its mux fields equal what the legacy `fbzColorPath`/`textureMode` already select, and its `OUTSHIFT` is x2 or x4.
  - Nothing else in the colour path changes.
- **Lazy, and bounded to one DP2 call.**
  - With the switch armed, a DP2 that never uses 2X/4X writes exactly what it writes today, byte for byte.
  - `combineMode` goes back to 0 at the next state flush that does not need it, and always at the end of the DP2 call.
- **Gating.** Default OFF, behind `Diag\D3DFeat` bit `CMSHIFT` (proposed: bit 6). With it off, register traffic and caps are unchanged. It graduates to default-on after one supervised armed boot passes (section 4).
- **TextureOpCaps** becomes `0x0000187f` when armed (adds `MODULATE2X` 0x10 and `MODULATE4X` 0x20).
- **Recommendation: land this before G12, as the first increment of the extended combine.** The gap's text says "land it with G12". That would tie a small, exact fix to a large rework:
  - G12 needs stage reordering, diffuse in the TMUs through packed `sARGB` (G58) and TFACTOR in the TMUs (G14).
  - G05 needs none of these.

  G12, G13 and G14 should then extend the header and the emission code this design adds.
- **Priority P0**: the lit world of two staged titles is half-bright in every in-game scene. **Effort M.**
- **Dependencies:**
  - G01 is a precondition for verification: a stale command FIFO makes every triangle vanish.
  - G03 is soft: G03 and G05 share the 12-NOP 2PPC exit and the rule that the HAL owns `combineMode`.

## 2. Hardware and reference facts the design rests on

1. **`combineMode` exists in each unit, and the chip field addresses it.**
   - `SST_CHIP(sst,n)` is `n*0x400` (`GL5/incsrc/h3defs.h:2087`), so FBI-only is `0x400`, TMU0 `0x800` and TMU1 `0x1000`.
   - Glide uses `eChipFBI = 0x01` (`GL5/glide3/src/fxcmd.h:585`) and writes the FBI word FBI-only (`GL5/glide3/src/distate.c:1966`).
   - The vendor HAL does the same, with chip fields 1, 2 and 4 (`VH5/D6DP2.C:6443-6452`).
   - **The FBI word must never be broadcast.** The TMUs read the same bits with other meanings. `KMD/include/vcr_3dregs.h:46` calls the register "FBI and every TMU". That comment needs fixing.
2. **FBI muxes with bit 31 set (SPEC §8.21, the mux table under "combineMode bit(31)=1"):**

   | mux | bit 31 = 0 | bit 31 = 1 |
   |---|---|---|
   | c_other | `{0, fbzColorPath[1:0]}` | `combineMode[2:0]` |
   | c_local | `{00, fbzColorPath[4]}` | `combineMode[5:3]` |
   | c_mselect_7 | `{000}` | `combineMode[8:6]` |
   | a_other | `fbzColorPath[3:2]` | `combineMode[17:16]` |
   | a_local | `{0, fbzColorPath[6:5]}` | `combineMode[20:18]` |

   The encodings agree:
   - `OTHERSELECT` IRGB/TRGB/C1/LFB is 0/1/2/3, the same as legacy RGBSEL.
   - `LOCALSELECT` IRGB/C0 is 0/1.
   - `CCA_OTHERSELECT` IA/TA/C1_A is 0/1/2.
   - `CCA_LOCALSELECT` IA/C0_A/IZ/IW is 0/1/2/3 (`GL5/incsrc/h3defs.h:385-465`).

   So **copying the legacy fields into `combineMode` reproduces the legacy routing exactly**. The SPEC's own `fbzColorPath` text confirms it: "RGB Select ... Only used if combineMode[31]=0".
3. **TMU muxes always come from `combineMode`.** SPEC: "For the Texture Combine and Texture Alpha Combine units (in each TMU), the other, local and mselect_7 ... always come from the combineMode register."
   - All-zero selects (OTHER_TRGB, LOCAL_TRGB, OTHER_TA, LOCAL_TA) are the legacy TMU routing.
   - `INVERT_LOCAL` 0 is `ZERO_MINUS_X`, the legacy subtract (`h3defs.h:504-509`).
   - Glide's own warning fits: "some of the combineMode bits still take effect even if SST_CM_USE_COMBINE_MODE is cleared" (`GL5/glide3/src/gtex.c:1204-1229`).
4. **The shift saturates.**
   - SPEC: "cc_outshift (0=no modulate, 1=modulate by 2, 2=modulate by 4, 3=reserved)". The TMU and alpha fields read the same.
   - The SPEC combine datapath figure orders it: a "13 1.4.8" sum, then "Modulate 1x, 2x, 4x", then "Clamp 0-FF", then the invert output. The 9-bit multiply is "Trunc LSBs No Round".
   - So the result is `min(255, (a*b) << s)`, which is D3D's MODULATE2X/4X.
5. **Bit 30 goes with bit 31.** SPEC, programming caveats: "When the new texture and color combine unit functionality of Napalm is required, combineMode[30] must be set to disable the use of the chromaKey and chromaRange for the texture color/chroma substitution function."
   - The vendor always writes `USE_COMBINE_MODE | DISABLE_CHROMA_SUBSTITUTION` together, on all three units (`VH5/D6MT.C:4412-4414`, `:4891-4893`).
6. **Leaving 2PPC needs 12 NOPs first.** SPEC: "send down at least 12 NOP commands with the chip field set to select both TMUs prior to the write to combineMode register clearing bit(29) ... (i.e. set chipField=0x6)". Selecting the FBI as well "will cause the entire pixel pipeline to be flushed".
   - Our HAL never sets bit 29.
   - Glide turns it on during normal single-texture drawing (`GL5/glide3/src/distate.c:1835-1848`) and off only in its own close (`GL5/glide3/src/gsst.c:3292-3296`). A client that was killed, or that closed through the not-idle path, can therefore leave it set.
   - The HAL already writes TMU0|TMU1 `nopCMD` at `V3D_TMU0 + V3D_TMU1 + V3D_NOPCMD`, i.e. 0x1920, before every compressed-texture state (`KMD/display/vcrdd_3d.c:111`). That address form has run on `.124` since 09-28.
   - SPEC also says that while 2PPC is on, "writes to either texture unit will be received by both". Hence the write order FBI, TMU0, TMU1 (3.4).
7. **The vendor recipe is the same.**
   - Modulate2x/4x is MODULATE plus `SST_CM_CC_OUTSHIFT_2X/4X` in the FBI CCU table (`VH5/D6MT.C:649-652`, built with `NEW_CCU` = 1: `.../H5/W2K/BUILD/STBPERF.INC:18, 49`).
   - In the TMU tables it is the same plus `SST_CM_TC_OUTSHIFT_2X/4X` (stage 0 `:864-867`, stage 1 `:913-916`).
   - The vendor writes `combineMode` "before all other 3D regs", after its 12-NOP 2PPC exit (`VH5/D6DP2.C:6406-6452`).
   - It lists `MODULATE2X` and `MODULATE4X` on Napalm (`VH5/D3INIT.C:3262-3290`).
8. **Glide re-initialises all three `combineMode` registers at every open.** `assertDefaultState` (`GL5/glide3/src/gsst.c:889-1039`, called at `:3122`) does `_grTex2ppc(FXFALSE)` and then the `grColorCombineExt`/`grTexColorCombineExt` defaults (`:913-950`). 3dfx's Napalm Glide 2 calls `_grTex2ppc(GR_TMU0, FXFALSE)` at open too (`.../H5/GLIDE/SRC/GSST.C:765-772`).
9. **FASTFILL does not pass through the combine units.** SPEC fastfillCMD: "FASTFILL will optionally clear the color buffers with the RGB color specified in color1[23:0]". A combine word that is live cannot change a clear. One probe cell still checks it (5.1).

## 3. Design

### 3.1 Scope

**In scope:**
- `COLOROP` and `ALPHAOP` MODULATE2X/4X on stage 0, which the FBI draws through `color_path`;
- the same two ops on stage 1, which TMU0 draws through `stage1_combine`;
- TextureOpCaps when armed.

**Out of scope, because it belongs to other items** (G05 only adds the shift):
- every other op that `color_path`/`stage1_combine` approximate (G12);
- the stage order (G12);
- `COMPLEMENT`/`ALPHAREPLICATE` (G13);
- TFACTOR inside a TMU (G14);
- an honest `ValidateTextureStageState` (G15).

**One pass, and no multipass anywhere.**

### 3.2 The register words

New header `KMD/include/vcr_combine.h`. It is integer only and Win32-free, like `vcr_3dseq.h`, so the native test compiles the code the driver runs.

```c
#define V3D_FBI               0x000400u   /* chip field 1: the FBI alone (h3defs SST_CHIP(..,1)) */
#define VCR_CM_USE            (1u << 31)  /* SST_CM_USE_COMBINE_MODE */
#define VCR_CM_NO_CHROMA_SUB  (1u << 30)  /* SST_CM_DISABLE_CHROMA_SUBSTITUTION: SPEC, with bit 31 */
#define VCR_CM_CC_OTHER(v)    ((v) << 0)  /* = fbzColorPath[1:0] when bit 31 = 0 */
#define VCR_CM_CC_LOCAL(v)    ((v) << 3)  /* = fbzColorPath[4] */
#define VCR_CM_CC_SHIFT(s)    ((s) << 14) /* cc_/tc_outshift: 1 = x2, 2 = x4 */
#define VCR_CM_CCA_OTHER(v)   ((v) << 16) /* = fbzColorPath[3:2] */
#define VCR_CM_CCA_LOCAL(v)   ((v) << 18) /* = fbzColorPath[6:5] */
#define VCR_CM_CCA_SHIFT(s)   ((s) << 26) /* cca_/tca_outshift */

static __inline unsigned vcr_cm_fbi_ext(unsigned cp, unsigned cs, unsigned as)
{   /* the legacy muxes copied (SPEC 8.21 table), inverts 0 = legacy, 2ppc 0 */
    return VCR_CM_USE | VCR_CM_NO_CHROMA_SUB | VCR_CM_CC_OTHER(cp & 3u) |
           VCR_CM_CC_LOCAL((cp >> 4) & 1u) | VCR_CM_CCA_OTHER((cp >> 2) & 3u) |
           VCR_CM_CCA_LOCAL((cp >> 5) & 3u) | VCR_CM_CC_SHIFT(cs) | VCR_CM_CCA_SHIFT(as);
}
static __inline unsigned vcr_cm_fbi(unsigned cp, unsigned cs, unsigned as)
{   return cs || as ? vcr_cm_fbi_ext(cp, cs, as) : 0u; }     /* 0: the legacy combine */
static __inline unsigned vcr_cm_tmu(unsigned cs, unsigned as)
{   return cs || as ? VCR_CM_USE | VCR_CM_NO_CHROMA_SUB | VCR_CM_CC_SHIFT(cs) | VCR_CM_CCA_SHIFT(as)
                    : 0u; }                                    /* selects 0 = legacy routing */
```

TMU1 always gets 0. In our layout it only `REPLACE`s stage 0's texel (`compute_regs`, `vcrdd_d3d.c:950-953`).

Worked values (each is asserted in 6.1):

| set-up | today | new words: FBI / TMU0 / TMU1 |
|---|---|---|
| UT2003 combines 3, 8, 10, 12: s0 `MODULATE2X(TEX, DIF)`, alpha `MODULATE` | `cp c482405`, no `combineMode` write | `C0014001` / `0` / `0` |
| the same with `MODULATE4X` | | `C0018001` / `0` / `0` |
| UT2003 combines 1, 5, 6: s0 `SELECTARG1(TEX)`, s1 `MODULATE2X`, s1 alpha `SELECTARG1` | `tm 800242cf` (`TM_TC_MULT`), FBI pass | `0` / `C0004000` / `0` |
| stage 1 `MODULATE4X` | | `0` / `C0008000` / `0` |
| stage-1 alpha op `MODULATE2X` | `TM_TCA_MULT` | `0` / `C4000000` / `0` |
| stage-0 alpha op `MODULATE2X` (colour x1) on `cp c482405` | | `C4010001` / `0` / `0` |

### 3.3 Where the shift is decided: `compute_regs`

Add `ULONG cc_shift, ca_shift, tc_shift, ta_shift` to `vcr3d_regs` (`KMD/display/vcrdd_3d.h:36-44`). `compute_regs` (`vcrdd_d3d.c:921-1029`) fills them when the switch is armed, right after `color_path` (`:977`), using pure decision functions from the header:

```c
static __inline unsigned vcr_cm_op_shift(unsigned op)       /* D3DTOP_MODULATE2X 5, 4X 6 */
{   return op == VCR_TOP_MODULATE2X ? 1u : op == VCR_TOP_MODULATE4X ? 2u : 0u; }
/* stage 0 (FBI): color_path's two-argument branch, which draws 2X/4X as MODULATE. Nothing where
 * color_path draws diffuse instead (a TEXTURE argument with no usable texture, :690, :725) */
static __inline unsigned vcr_cm_stage0_shift(unsigned op, unsigned a1, unsigned a2, int tex)
{   return !tex && (a1 == VCR_TA_TEXTURE || a2 == VCR_TA_TEXTURE) ? 0u : vcr_cm_op_shift(op); }
/* stage 1 (TMU0): stage1_combine's TM_TC_MULT / TM_TCA_MULT, only on the two-stage path */
static __inline unsigned vcr_cm_stage1_shift(unsigned op, int two)
{   return two ? vcr_cm_op_shift(op) : 0u; }
```

- **Arguments.** The caller passes `ARG_KIND(...)` (`:671`).
- **Constants.** `VCR_TOP_*` and `VCR_TA_TEXTURE` mirror d3dtypes.h (`D3DTOP_MODULATE2X` 5, `MODULATE4X` 6, `D3DTA_TEXTURE` 2). `vcrdd_d3d.c` pins them with a compile-time check against the DDK names.
- **SELECTARG1/2 and DISABLE** return 0, as `color_path` treats them.
- **A stage 1 that `compute_regs` drops** (`two` = 0, `:928`) gets nothing. That gap is G12's.

### 3.4 Emission: lazy, first in the state flush, and gone by the end of the DP2

New `BOOL VcrDd3dCombine(VCR_PDEV *pd, ULONG fbi, ULONG tmu0, ULONG nops)` in `KMD/display/vcrdd_3d.c`. It writes what `vcr_cm_seq` builds, after `VcrDdRoom(pd, n)` with n ≤ 15:

```c
#define VCR_CM_SEQ_MAX (VCR_3D_RESET_NOPS + 3)
static __inline unsigned vcr_cm_seq(unsigned fbi, unsigned t0, unsigned nops, vcr_regw *w)
{
    unsigned n = 0, i;
    if (nops)   /* SPEC: >= 12 nopCMD to TMU0|TMU1 (chip field 6) before a write that clears 2ppc */
        for (i = 0; i < VCR_3D_RESET_NOPS; i++) { w[n].off = V3D_TMU0 + V3D_TMU1 + V3D_NOPCMD; w[n++].val = 0; }
    w[n].off = V3D_FBI  + V3D_COMBINEMODE; w[n++].val = fbi;
    w[n].off = V3D_TMU0 + V3D_COMBINEMODE; w[n++].val = t0;   /* before TMU1: in 2ppc a TMU write reaches both */
    w[n].off = V3D_TMU1 + V3D_COMBINEMODE; w[n++].val = 0;
    return n;
}
static __inline int vcr_cm_must_write(unsigned armed, unsigned fbi, unsigned t0, unsigned live)
{   return armed && (fbi || t0 || live); }      /* nothing new unless a word is (or was) live */
```

**`prepare()`** (`vcrdd_d3d.c:1322-1365`). Immediately before `VcrDd3dTarget`/`VcrDd3dState` (`:1361`), which is after its own adjustments to `regs.textured`/`fbzColorPath` (`:1339-1356`), and only when `c->pd->cm_shift` is set:

```c
ULONG fbi = vcr_cm_fbi(c->regs.fbzColorPath, c->regs.cc_shift, c->regs.ca_shift);
ULONG t0  = c->regs.textured ? vcr_cm_tmu(c->regs.tc_shift, c->regs.ta_shift) : 0;
if (vcr_cm_must_write(1, fbi, t0, w->cm_live)) {
    if (!VcrDd3dCombine(c->pd, fbi, t0, !w->cm_nops))
        return FALSE;
    w->cm_nops = 1;                 /* this DP2 has now cleared 2ppc */
    w->cm_live = fbi || t0;
    if (w->cm_live) c->cm_states++; else c->cm_restores++;
}
```

**`D3d_DrawPrimitives2`** (`:1821-1871`). After `walk()` (`:1867`):

```c
if (w.cm_live)
    VcrDd3dCombine(c->pd, 0, 0, 0);
```

The extended combine is therefore never left on between DDI calls. The next caller of the chip finds the state the proven HAL leaves:
- Clear2;
- a DirectDraw blit;
- a Glide client, which resets it anyway (2.8);
- another context.

`dp2walk` (`:1244-1252`) gains `int cm_live, cm_nops`. The `memset` at DP2 entry zeroes both.

**Why the NOPs run once per DP2 and not once per context.**
- A Glide session can only run between DP2 calls. While it owns the board, DP2 draws nothing (`exclusive_pid`, `:1859`).
- So the first `combineMode` write of each DP2 is the only one that can find 2PPC left on.
- The NOPs go to chip field 6, as the SPEC asks. They cost 12 writes per DP2 that actually uses 2X/4X.

**Clears.** `clear_rects` needs no change (2.9).

### 3.5 Caps

At `vcrdd_d3d.c:2165-2168`:

```c
x.dwTextureOpCaps = <the 7 ops as today> | (pd->cm_shift ? D3DTEXOPCAPS_MODULATE2X | D3DTEXOPCAPS_MODULATE4X : 0);
```

This gives `0x184f` when off and `0x187f` when armed. Put it in the header as `vcr_cm_texopcaps(base, armed)` so the native test pins both values.

Nothing else changes:
- The DX5 TextureBlendCaps have no 2X mode.
- `ValidateTextureStageState` stays as it is. G15 must answer `D3DERR_UNSUPPORTEDCOLOROPERATION` for 2X/4X exactly when `cm_shift` is off.

### 3.6 Logging

- **Event 513, what 22** (`log_combo`, `:909-912`) gains ` sh %u%u/%u%u` (cc, ca / tc, ta). A LogLevel 2 run then shows, per combine, that 2X was applied. It stays within the 95-character message.
- **Event 513, what 24 (new):** "armed (Diag\D3DFeat %x): combine output shift for MODULATE2X/4X", logged once from `VcrDd2dInit` beside 513/16 and 513/18 (`KMD/display/vcrdd_2d.c:458-473`).
- **Event 513, what 25 (new),** at context-gone (`:1210-1216`), only when non-zero: "context %u combine: %u shift states, %u restores". The existing "gone" message is already near the 95-character limit.

### 3.7 The old path

The old path applies when the switch is off, on a Banshee/Voodoo3 or the 86Box bed (`pd->napalm` = 0), and with the switch armed when no 2X/4X op is drawn. In every one of these cases:

- **Registers:** `vcr_cm_must_write` returns 0, so no `combineMode` write and no NOP is added.
- **The state block:** `VcrDd3dState` is not touched at all.
- **Caps:** `0x184f`.

The proven 16 bpp lane, the 32 bpp lane and the 40/40, 42/42 and 83/0 matrices therefore send the same bytes as build 95678704. 6.1 pins it, and the off boot in section 7 measures it.

### 3.8 One known approximation, and it is not new

- **When it occurs.** Stage 0 uses 2X/4X and a second stage is active. The FBI applies stage 0's op *after* TMU0 has combined stage 1: G12's ordering, `vcrdd_d3d.c:949-956, 977`.
- **The error.** The result is `min(1, 2*t0*t1*d)` instead of `min(1, 2*t0*d)*t1`. The two are equal unless stage 0 saturates.
- **Exposure.** None of UT2003's 26 logged combines has that shape. It disappears when G12 reorders the stages.

## 4. Gating

### 4.1 Default OFF, then graduate

- **Switch:** `HKLM\SYSTEM\CurrentControlSet\Services\vcrmp\Diag\D3DFeat`, bit `VCR_D3DFEAT_CMSHIFT`.
  - Proposed bit 6, the first slot hal.md §10 Phase 3 gives the extended combine.
  - G12, G13 and G14 take their own bits and reuse this code.
- **Read time:** at boot (FindAdapter), like `D3D32` and `D3DBigTex`. The TextureOpCaps an application reads at the desktop then match its fullscreen PDEV's.
- **Hardware:** VSA-100 only, since `combineMode` does not exist on a Banshee or Voodoo3.
- **Arming:** `REGWRITE HKLM SYSTEM\CurrentControlSet\Services\vcrmp\Diag D3DFeat REG_DWORD 64`, then `REGREAD` it back, then `scripts/fleet/safe-reboot.py` after the activation check. One Diag change per clean boot.

**Is it safe to land default-on?** Not yet.
- **The case for:** the lazy rule leaves every title that does not use 2X/4X byte-identical even when armed. The only draws it changes are already drawn wrong.
- **The case against:** it is register state this HAL has never driven on silicon (bit 31/30 words, FBI-only chip-field writes from the display driver, the 12 TMU NOPs), and the project rule is default-off until one supervised boot proves it.
- **Graduation:** after the armed boot in section 7 passes, flip the default in a separate commit with its own test. Two ways to do it:
  - the miniport ORs a default mask into `D3DFeat`;
  - or a `D3DFeatOff` kill mask for graduated bits, as `Accel2DPattern`/`GdiGamma` became default-on with `= 0` as the kill switch.

  The plan picks one convention for all `D3DFeat` bits.

### 4.2 Transport: one raw word, not one flag bit per feature

`vcr_info.flags` is pinned full at `0x7fff` by `test_vcr_kmd_abi.c:118-138`. That test exists because three parallel branches took the same bit (0x200) on 2026-09-28.

Dozens of "fixable" items in this plan want D3D switches. If each takes a `vcr_info.flags` bit, that collision repeats.

**Proposal:** the miniport passes the whole `Diag\D3DFeat` DWORD in one appended `vcr_info.d3dfeat`. The bits are allocated in one header, `include/vcr_d3dfeat.h`, with a one-bit-each test like the flags test.

If the plan prefers flags, `VCR_INFO_F_D3DFEAT_CMSHIFT 0x8000` works too:
- `vcrmp.c`: `(x->d3dfeat & VCR_D3DFEAT_CMSHIFT) ? VCR_INFO_F_D3DFEAT_CMSHIFT : 0`;
- the ABI test's map becomes `0xffff`.

Either way, the display driver arms only on `pd->napalm`.

## 5. d3dprobe tests

### 5.1 The new tests

The tests go in `KMD/tools/d3dprobe.c` `run_test()`. They are explicit only (`--tests ...`), like the D3DBigTex tests, until the switch is default-on; then they join the default list.

Shared rules:
- Each test draws an analytic scene, locks the back buffer and compares pixels (`expect()`, `d3dprobe.c:328-342`).
- **Expected value:** `want = min(255, (k * t * d + 127) / 255)` per channel. `t` is the 565 (or DXT) expanded texel and `d` the second argument. The probe computes it rather than hard-coding constants. The values below are for orientation.
- **Diagnosis:** each cell also logs the x1 value MODULATE would give ("old"), so a FAIL says whether the shift was simply missing.
- **Tolerance:** 14 per channel at both depths, as `tex2mod`/`tex2add` use. The x1, x2 and wrap answers of every cell are at least 62 apart.

## 6. Host regression tests

### 6.1 `WT/tests/native/test_vcr_kmd_combine.c` (new; compiles `KMD/include/vcr_combine.h`)

Each check asserts the fixed value and the old, buggy one.

1. **Constants:**
   - `VCR_CM_USE` = `0x80000000`, `VCR_CM_NO_CHROMA_SUB` = `0x40000000`;
   - `VCR_CM_CC_SHIFT(1/2)` = `0x4000`/`0x8000`, `VCR_CM_CCA_SHIFT(1)` = `0x04000000`;
   - `V3D_FBI` = `0x400`.
2. **Op mapping:**
   - `vcr_cm_op_shift`: 5→1, 6→2;
   - 4, 2, 3, 7 and 16 →0. BLENDCURRENTALPHA stays G12's bug, pinned so that G12 has to change this test on purpose.
3. **Decisions:**
   - `stage0_shift(5, TEXTURE, DIFFUSE, tex=1)` = 1;
   - the same with `tex=0` = 0: `color_path` draws diffuse then;
   - `stage1_shift(5, two=1)` = 1; `two=0` = 0.
4. **The words:**
   - **fixed:** `vcr_cm_fbi(0x0c482405, 1, 0)` = `0xC0014001`, `vcr_cm_tmu(1, 0)` = `0xC0004000`; 4X `0xC0018001`/`0xC0008000`; alpha `vcr_cm_tmu(0, 1)` = `0xC4000000`;
   - **old:** `vcr_cm_fbi(0x0c482405, 0, 0)` = `0` and `vcr_cm_tmu(0, 0)` = `0`, i.e. nothing is written, as today.
5. **The mux translation is exact.** For every legacy `fbzColorPath` the HAL can produce (RGBSEL 0-2 × ASEL 0-2 × CP_LOCAL_C0 0/1, with the CC/CCA M, REVERSE, ADD, SUB and TEXTURE bits varied), `vcr_cm_fbi_ext(cp, 0, 0)` carries:
   - `c_other` = `cp[1:0]`, `c_local` = `cp[4]`;
   - `a_other` = `cp[3:2]`, `a_local` = `cp[6:5]`;
   - inverts 0, `mselect_7` 0, bit 29 0, bits 31 and 30 set.

   This is the SPEC table, row by row.
6. **Arithmetic, through a small model of one combine unit.** The model follows SPEC §8.20/8.21 and the datapath figure: muxes from `fbzColorPath` or `combineMode` by bit 31, `(A + B) * C + D` with the 9-bit factor truncated, then `<< outshift`, then clamp 0-FF.
   - Stage 0 (`cp c482405`, texel 0x84, diffuse 0x80): old word 0 → 0x42, fixed → 0x84.
   - Saturation (texel 0xff, diffuse 0xc0): fixed → 0xff, not 0xc0 (x1) and not 0x80 (wrap).
   - TMU (`TM_TC_MULT`, 0x84 x 0x84): old 0x44, fixed 0x88.
   - The same model gives identical outputs for `vcr_cm_fbi_ext(cp, 0, 0)` and legacy `cm = 0` over the cp set of check 5 and a grid of inputs. That is the exactness proof in arithmetic.
7. **The emission sequence, write for write:**
   - `vcr_cm_seq(0xC0014001, 0, 1, w)` = 15 writes: 12 × (`0x1920`, 0), then (`0x608`, `0xC0014001`), (`0xA08`, 0), (`0x1208`, 0);
   - with `nops = 0`, exactly the last three.
8. **The lazy rule:**
   - `must_write(armed=0, …)` = 0 for every input;
   - `must_write(1, 0, 0, live=0)` = 0: **byte-identical when armed without 2X**;
   - `must_write(1, w, 0, 0)` = 1; `must_write(1, 0, 0, live=1)` = 1: the restore.
9. **Caps:** `vcr_cm_texopcaps(0x184f, 0)` = `0x184f` (pinned old), `(0x184f, 1)` = `0x187f`.

### 6.2 `WT/tests/python/test_vcr_kmd_d3d.py` and `WT/tests/native/test_vcr_kmd_abi.c`

**New `test_modulate2x_4x_use_the_combine_shift_behind_a_default_off_switch`.** It asserts, in the source:

## 8. Risk to proven paths

- **Default 16 bpp lane, 32 bpp lane, the 86Box Voodoo3 bed, a fresh install:**
  - **None.** The switch is off and the Voodoo3 never arms it: no new write and caps unchanged.
  - Pinned by 6.1 (checks 4 and 8) and 6.2, and measured in boot A.
- **Armed, a title that never draws 2X/4X:** none. Its traffic is byte-identical (the lazy rule).
- **Armed, 2X/4X draws.** These draws are new register traffic, and every hazard has a reason behind its mitigation:

  | hazard | mitigation |
  |---|---|
  | a 2PPC exit left by Glide | 12 NOPs to chip field 6 before the first write of each DP2 (SPEC caveat) |
  | texture chroma substitution | bit 30 set with bit 31 (SPEC caveat) |
  | an FBI word reaching the TMUs | written FBI-only (chip field 1), never broadcast |
  | a TMU0 word copied to TMU1 while 2PPC is on | TMU0 is written before TMU1 |
  | combine state lingering between calls | 0 put back at the next flush that does not need it, and at the end of every DP2 |

  The words reproduce the legacy muxes exactly (6.1 checks 5-6).
- **Glide/OpenGL coexistence:** none in either direction from G05.
  - D3D to Glide: the HAL leaves 0 at every DP2 end, and Glide resets all three registers at open (2.8).
  - Glide to D3D: still G01/G03's. G05's armed draws are also protected by their NOPs and full writes.
- **SLI:** none. D3D draws on chip 0 only; snooping is off, so the writes reach chip 0 alone, like every other HAL write.
- **Flip:** none (untouched).
- **Clears:** none (2.9, `mod2x` cell 5).
- **Caps:** when armed, caps-checking titles may take their 2X path. That path then works (the probe proves it in the same boot first). Halo, Thief II NewDark, H&D and Max Payne are watched in boot B. **Fallback** if one gets worse: split the caps into their own `D3DFeat` bit and keep the drawing fix.
- **Performance:**
  - A 2X DP2 adds 12 NOPs, plus 3 writes per state flush while a word is live, plus 3 at the end.
  - Against about 27-45 writes per triangle (G48), that is noise.
  - The shift costs nothing per pixel (inferred).
- **Residual unknowns:**
  - CCA/TCA (alpha) shift and bit 30 on the FBI have no title evidence; the probe covers them.
  - The 2-stage stage-0 2X approximation (3.8) remains until G12.

## 10. Open questions

1. Which ops does UT2004 actually use? Not yet measured; boot B's LogLevel 2 run answers it.
2. Does FBI `combineMode[30]` change the FBI chroma-key test? This matters for G09's colour key while a 2X state is live. The vendor sets bit 30 on the FBI and ships a colour key (`VH5/D6DP2.C:6815-6967`), which suggests it is compatible (inferred).
3. The hardware's exact rounding (factor 0.1.8, truncation). The tolerances absorb it; record the measured values from boot B.
4. How should `D3DFeat` reach the display driver: the raw `vcr_info.d3dfeat` (recommended) or one `vcr_info.flags` bit per feature? And which convention graduates a `D3DFeat` bit to default-on? These are plan-level choices that every `D3DFeat` item shares.
5. Should TextureOpCaps widening get its own bit? Decide from Halo and Thief II in boot B.
6. Does UE2 call `ValidateDevice` for its 2X set-ups? This matters for G15's interplay, not for G05.
7. For G03: because TMU selects always come from `combineMode` (SPEC), a `combineMode` left non-zero by Glide in a TMU is live even with bit 31 clear. Today's two-stage path is exposed to it until G03 writes the TMU registers.
