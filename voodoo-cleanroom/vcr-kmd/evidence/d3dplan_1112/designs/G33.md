## 0. Verdict

- **The gap is real and trivially fixable, single pass, no CPU cost.** Per axis, `D3DTADDRESS_MIRROR` becomes
  tLOD bit 28 (S) or 29 (T). Today only CLAMP is mapped (textureMode bits 6/7), so MIRROR, BORDER and anything
  else draw as WRAP; the caps honestly omit MIRROR (`TextureAddressCaps` 0x15).
- **But no staged `.124` title is shown to use MIRROR, and the two titles named in the gap are refuted for their
  engine code** (section 3): Unreal Engine 2's texture clamp enum has only `TC_Wrap` and `TC_Clamp`, and Halo's
  address tables map to WRAP/CLAMP only, while it tests `TextureAddressCaps` for BORDER alone. Halo's D3DX effect
  file is encrypted, so its effect-set sampler states stay unknown, as do a few data-driven titles.
- **Priority P3.** Re-rate to P1 if the per-context counter (section 4.6) shows a staged title sending MIRROR.
- **Gating:** one positive `Diag\D3DFeat` bit (`MIRROR`), default OFF, read at boot, caps and drawing together.
  Off, the register stream and the caps are today's byte for byte. It is a strong candidate for default-ON after
  one supervised clean boot in which `d3dprobe mirror` and `mirror_ext` pass. It changes only requests that are
  drawn wrongly today.
- **Effort S.** About 40 lines of driver code, a pure header, a native test, two probe tests and one supervised boot.

## 1. What the HAL does today

- `tex_view` (`KMD/display/vcrdd_d3d.c:754-799`, the default path, also every Banshee/Voodoo3) and `tex_view_ext`
  (`:806-838`, the `Diag\D3DBigTex` path) each map addressing with the same four lines (`:792-795`, `:830-833`):

  ```c
  if (tss[D3DTSS_ADDRESSU] == D3DTADDRESS_CLAMP) v->textureMode |= TM_CLAMPS;
  if (tss[D3DTSS_ADDRESSV] == D3DTADDRESS_CLAMP) v->textureMode |= TM_CLAMPT;
  ```

  Every other value leaves the TMU in its default, wrap: WRAP (1), MIRROR (2), BORDER (4), D3D8's MIRRORONCE (5)
  and any garbage value. A mirrored tile then repeats instead of reflecting, which shows as hard seams at every
  odd repeat.
- The caps come from `prim_caps` (`:2013-2046`): `dwTextureAddressCaps` = WRAP | CLAMP | INDEPENDENTUV (`:2044-2045`),
  for both `dpcTriCaps` and `dpcLineCaps` (`:2071-2072`). D3D8 reports `TextureAddressCaps 00000015` on `.124`
  (`caps_124.txt`). The caps under-report; they do not over-claim.
- `D3DTSS_ADDRESS` (12) and the DX5 render states TEXTUREADDRESS/U/V (3/44/45) are stored but never applied (G08).
  A DX5/DX6 title's MIRROR therefore does not even reach ADDRESSU/V until G08 lands.
- What reaches the chip: `compute_regs` puts stage 0's view into `r->tLOD` (one texture, TMU0, `:963`) or
  `r->tLOD1` (two textures, TMU1, `:952`), and stage 1's into `r->tLOD` (TMU0, `:955`). `VcrDd3dState` writes the
  **whole** tLOD of every textured TMU at every state send (`KMD/display/vcrdd_3d.c:115, 123`). So a mirror bit
  set in the view reaches exactly the TMU that samples that stage, and no stale bit can survive.

## 2. What the hardware does

**The field.** tLOD bit 28 `tmirrors` and bit 29 `tmirrort`, "Mirror texture in S/T dimension" (SPEC §8.77
L3927-3928). The bit numbers are the same in the Napalm and the Banshee/Voodoo3 headers (`GL5/h5/incsrc/h3defs.h:731-732`,
`GL5/h3/incsrc/h3defs.h:281-282`, `H5/INCLUDE/H3DEFS.H:692-693`). Neither bit collides with a field we write
(LODMIN 0-5, LODMAX 6-11, LODBIAS 12-17, ODD 18, TSPLIT 19, S_IS_WIDER 20, ASPECT 21-22, TBIG 30).

**Glide.** `grTexClampMode` picks clamp or mirror per axis from one enum, so it never sets both on an axis. It
clears both mirror bits, then sets the requested ones (`GL5/h5/glide3/src/gtex.c:1097-1122`; the same in
`GL5/h3/glide3/src/gtex.c:645-661`). Both chips advertise `TEXMIRROR` (`GL5/h5/glide3/src/diget.c:872`,
`GL5/h3/glide3/src/diget.c:679`), and MesaFX turns it into `GL_ARB_texture_mirrored_repeat`
(`build/retro3dfx-gl/src/mesa/drivers/glide/fxdd.c:2026`, `fxddtex.c:394-414`). No `.124` OpenGL/Glide title is known
to use mirrored repeat, so **these bits have never run on this card (inferred)**.

**3dfx's V5 HAL.** MIRROR was added on 10/04/98 ("Add support for mirrored textures", `VH5/D6MT.C:412-413`,
`VH5/D3INIT.C:329`, `VH5/D6DP2.C:670`), with a stage-two typo fixed the same evening (`VH5/D6MT.C:409-410`).
- **Caps:** advertised in the line and triangle caps under `DX >= 6` (`VH5/D3INIT.C:2874`, `:3084`). MIRRORONCE is
  commented out of the DX8 caps (`:3528`), and BORDER is absent.
- **Single stage:** mirror goes into the context's common `sst.tLOD` (`VH5/D6MT.C:5692-5702`). That word is
  ORed into **both** TMUs' tLOD writes (`VH5/D6DP2.C:6521, 6588, 6672-6678, 6725-6731`), so a stage split across
  the two TMUs (trilinear, 2ppc) mirrors on both.
- **Two stages:** stage 0 → `tLODT1` (`VH5/D6MT.C:5936-5946`), stage 1 → `tLODT0` (`:6102-6111`).

**The exact semantics.** 3dfx's own chip simulator, `H5/CSIM/TREX.C`, defines them (point sampling `:1322-1344`,
bilinear `:840-865`, the per-level size `:738-788`). The diag reference model `H5/DIAGS/TREX/SSTTEX.C:1354-1395`
agrees. Per axis, at the **selected level's own size** (`maxU = (level width << 8) - 1`, or the TBIG table):
- **Mirror:** if the coordinate's bit `size` is set, it becomes `max - u`, and then the usual wrap mask applies.
  So every odd repeat is reflected, and a negative coordinate reflects about 0 (u in [-1, 0) reads as |u|). This
  is D3D's MIRROR.
- **Bilinear:** the two taps are mirrored **separately** (`u0`, `u1 = u0 + 1 texel`, `:840-850`). At a seam the edge
  texel is blended with itself, which is D3D's MIRROR again.
- **Mirror + clamp on one axis:** coordinates outside [0, 2·size) go to texel 0, and inside they mirror once
  forward (`:841-843`). **No D3D mode does that.** D3D's MIRRORONCE reflects about 0 and clamps beyond ±1. So
  this design never sets both on an axis. This refines hw.md Q6's "mirror and clamp together are undefined
  (inferred)".
- **Larger textures:** TBIG (2048-class) textures use the same rule with the TBIG masks (`:742`).
- **3dfx's own checks:** their TREX format diag flips both mirror bits at random on every test texture
  (`H5/DIAGS/TREX/FMT.C:166-170`), and the bit-level model widened its mask "for texture mirroring"
  (`H5/DIAGS/LIB/TREXFUNC.C:913, 940`). Mirror was a validated feature of the silicon family (inferred from the
  diag, not from its results).

**86Box (the project's Voodoo3 bed) is only partly faithful.** `86B/voodoo_render.c:306-313` mirrors on one
fixed bit (0x1000 = one repeat of the 256-unit wide axis) of the scaled coordinate, *before* its bilinear -0.5
offset and level shift:
- It is right for a square texture with point sampling.
- It is wrong for the narrow axis of a non-square texture, which it mirrors every 2^aspect repeats.
- It is wrong at a bilinear seam, where its taps wrap to the opposite edge.

**What the chip cannot do.** MIRRORONCE has no bit, and mirror + clamp is a different mode. BORDER has no
border-colour register (G86).

**Cost:** none. It is one register bit, with no extra pass, no per-vertex work and no LOD change. The coordinate
range is the same as WRAP's (G89).

## 4. Design

### 4.1 Register names: `KMD/include/vcr_3dregs.h`

```c
#define TL_MIRRORS  (1u << 28)  /* h3defs.h SST_TMIRRORS: S reflected every other repeat, at the level's own width */
#define TL_MIRRORT  (1u << 29)  /* SST_TMIRRORT; never together with TM_CLAMPS/TM_CLAMPT on one axis (CSIM TREX.C:841) */
```

These are pinned against the GPL header by the existing offsets test (section 7).

### 4.2 The mapping, as a pure header: `KMD/include/vcr_texaddr.h` (new)

The header is integer-only and Win32-free, like `vcr_rtfmt.h`, so that `tests/native` compiles it as it is.

```c
#ifndef VCR_TEXADDR_H
#define VCR_TEXADDR_H
#include "vcr_3dregs.h"

/* d3dtypes.h D3DTEXTUREADDRESS; MIRRORONCE is d3d8types.h only. vcrdd_d3d.c pins the DX7 four. */
#define VCR_TADDR_WRAP        1u
#define VCR_TADDR_MIRROR      2u
#define VCR_TADDR_CLAMP       3u
#define VCR_TADDR_BORDER      4u
#define VCR_TADDR_MIRRORONCE  5u

#define VCR_TADDR_F_MIRROR    0x1u    /* Diag\D3DFeat MIRROR is armed */

typedef struct vcr_texaddr {
    unsigned tm;      /* textureMode: TM_CLAMPS / TM_CLAMPT */
    unsigned tlod;    /* tLOD: TL_MIRRORS / TL_MIRRORT */
} vcr_texaddr;

/* One axis. CLAMP: clamp to the edge (unchanged). MIRROR, and MIRRORONCE, which
 * equals MIRROR for |u| <= 1 (negative coordinates reflect about 0) and is never
 * advertised: the mirror bit, only when armed. BORDER (G86), WRAP and anything
 * else: wrap. Clamp and mirror are exclusive by construction. */
static __inline void vcr_tex_address_axis(unsigned mode, unsigned flags, unsigned clamp_bit,
                                          unsigned mirror_bit, vcr_texaddr *a)
{
    if (mode == VCR_TADDR_CLAMP)
        a->tm |= clamp_bit;
    else if ((flags & VCR_TADDR_F_MIRROR) &&
             (mode == VCR_TADDR_MIRROR || mode == VCR_TADDR_MIRRORONCE))
        a->tlod |= mirror_bit;
}

static __inline vcr_texaddr vcr_tex_address(unsigned u, unsigned v, unsigned flags)
{
    vcr_texaddr a = { 0u, 0u };
    vcr_tex_address_axis(u, flags, TM_CLAMPS, TL_MIRRORS, &a);
    vcr_tex_address_axis(v, flags, TM_CLAMPT, TL_MIRRORT, &a);
    return a;
}
#endif
```

### 4.3 `KMD/display/vcrdd_d3d.c`

1. **Include and pins.** Add `#include "../include/vcr_texaddr.h"` beside `vcr_texlod.h` (`:38`), then
   `VCR_STATIC_ASSERT(taddr_wrap, VCR_TADDR_WRAP == D3DTADDRESS_WRAP);` and the same for MIRROR, CLAMP and BORDER.
2. **One helper** used by both views:

   ```c
   /* ADDRESSU/V -> textureMode clamp bits and tLOD mirror bits (vcr_texaddr.h);
    * MIRROR only with Diag\\D3DFeat MIRROR - without it, the mapping the HAL always had */
   static void tex_address(const VCR_PDEV *pd, const DWORD *tss, tmu_view *v)
   {
       vcr_texaddr a = vcr_tex_address(tss[D3DTSS_ADDRESSU], tss[D3DTSS_ADDRESSV],
                                       pd->tex_mirror ? VCR_TADDR_F_MIRROR : 0);
       v->textureMode |= a.tm;
       v->tLOD |= a.tlod;
   }
   ```

3. **`tex_view` gains `VCR_PDEV *pd`** (`view_of`, `:840-844`, passes it). In both views, the four CLAMP lines
   (`:792-795`, `:830-833`) become `tex_address(pd, tss, v);` at the same place. That is after `textureMode` is
   built, and after the LODMAX update (`:785`, `:823`), which masks bits 6-11 only.
4. **`compute_regs` does not change.** The bits ride in `v0`/`v1` to whichever TMU samples the stage (`:952`,
   `:955`, `:963`), so MIRROR works on stage 1 and in the two-texture arrangement with no extra code.
5. **`log_combo`** (`:882-919`). Add `(r->tLOD >> 28 & 3) + (two ? (r->tLOD1 >> 28 & 3) << 2 : 0)` to the hash
   (`:886`), so that an armed mirrored set-up is logged as its own combo. Event 23 already prints `tlod`, so bits
   28/29 show there. Off, the bits are 0 and the hash is today's.

### 4.4 Caps: `VcrDdD3dHalInfo`, after `:2071-2072`

```c
/* MIRROR (tLOD bits 28/29) only with Diag\\D3DFeat MIRROR: without it the caps
 * are the proven HAL's, byte for byte */
if (pd->tex_mirror) {
    d->dpcTriCaps.dwTextureAddressCaps |= D3DPTADDRESSCAPS_MIRROR;
    d->dpcLineCaps.dwTextureAddressCaps |= D3DPTADDRESSCAPS_MIRROR;
}
```

- `prim_caps` itself is not touched.
- D3D8/9 then report `TextureAddressCaps 00000017`; DX5/6/7 read `dpcTriCaps`.
- The line caps follow the triangle caps, as today and as 3dfx did (`VH5/D3INIT.C:2872-2878`). Drawing lines is G16.
- MIRRORONCE (0x20) and BORDER (0x8) are not advertised.

### 4.5 Switch plumbing: the shared `Diag\D3DFeat`

This follows the convention the other D3DFeat items propose (G05 §4.2, G08, G26, G28, G29): a POSITIVE bit
(absent = off), read **at boot** by the miniport, so that the caps an application reads at the desktop equal its
fullscreen PDEV's.

- **The bit:** `VCR_D3DFEAT_MIRROR` in `include/vcr_d3dfeat.h`, taking the next free bit when this lands.
  Provisionally that is bit 14 (`0x4000`): bits 0-13 are proposed by G15, G08, G22, G25, G16, hal.md's alignment
  item, G12/G05/G13, G24/G23, G26 and G28. That header's one-bit-each test is the arbiter.
- **Miniport:** `x->d3dfeat = VcrDiagGet(L"D3DFeat", 0);` beside `D3DBigTex` (`KMD/miniport/vcrmp.c:244`). It is
  carried in the appended `vcr_info.d3dfeat`, or as a positive flag if the plan picks flags.
- **Display:** in `VcrDd2dInit` (`KMD/display/vcrdd_2d.c:430-471`), `pd->tex_mirror` is reset to 0 with the other
  D3D flags before the IOCTL. Then `pd->tex_mirror = (info.d3dfeat & VCR_D3DFEAT_MIRROR) ? 1 : 0;`.
  - This applies on **every chip**: Banshee/Voodoo3 have the same bits (`GL5/h3`), so the 86Box Voodoo3 bed can
    pre-check it.
  - One INFO event (513, next free `what`): "armed (Diag\\D3DFeat): MIRROR texture addressing (tLOD bits 28/29)".
- **`VCR_PDEV`:** add `ULONG tex_mirror;` in `KMD/display/vcrdd.h` beside `tex_ext` (`:75`).
- **If no D3DFeat item has landed yet,** G33 creates the plumbing exactly as G05 §4.2 describes (header, appended
  field, ABI test).

### 4.6 Instrumentation (log only, default ON, no register change)

This is the hal.md §10 Phase 0 kind of change.

- **Counter:** a per-context `ULONG addr_seen`. In the DP2 TEXTURESTAGESTATE walk (`:1591-1611`), for
  `st == D3DTSS_ADDRESSU` or `D3DTSS_ADDRESSV` on stage 0 or 1:
  `c->addr_seen |= 1u << ((stage << 3) + (v < 7 ? v : 7));`
  - Bits per value: 2 = MIRROR, 4 = BORDER, 5 = MIRRORONCE, 7 = other.
  - It also counts TSS 12 if G08's `lgc_tss12` is not there yet.
  - It costs one OR per state change and nothing per triangle.
- **Reported once** per context, in `ctx_free`'s event 2 (`:1210-1215`), as "…, address s0 %x s1 %x".
  `gamerun.py`'s per-session ring tail keeps that summary (`onbox/README.md`, ring note).
- **If G76 lands first,** these bits go into its counter block instead.

### 4.7 What does not change (the old path)

- **Switch off:** `vcr_tex_address(u, v, 0)` is today's two lines for every value (native test 3), the caps are
  `prim_caps`' byte for byte, and the register stream is identical.
- **Switch on:** only a stage whose ADDRESSU/V is 2 or 5 changes, and only in tLOD bits 28/29.
- **In both states:**
  - no new register and no new write; the order and count of writes are unchanged;
  - no multipass and no CPU work per vertex;
  - no change to the 2D engine, the flip path, SLI or the Glide reset sequence.

### 4.8 Invariants for other items

Each of these should go into that item's design.

- **G26 (two-TMU trilinear) and G50 (2ppc, "texture in both TMUs").** A stage sampled on both TMUs carries the
  same `TL_MIRROR*` on both. This is 3dfx's common `sst.tLOD`, ORed into each TMU write (`VH5/D6DP2.C:6521, 6588`).
- **G51 (SLI).** Per-chip tLOD writes (3dfx's per-chip LOD bias) start from `r->tLOD` and never rebuild it.
- **G26/G27 (LOD bias, MAXMIPLEVEL).** They change only their own tLOD fields by masking, as `:785` masks only LODMAX.
- **G53 (register shadowing).** Compare tLOD whole, and drop the shadow after any Glide session. Glide's window open
  writes CLAMP/CLAMP to both TMUs, which clears the mirror bits (`GL5/h5/glide3/src/gsst.c:989, 1011` → `gtex.c:1121`).
- **G86 (BORDER).** Its approximation is one line in `vcr_tex_address_axis`, behind its own flag. The native test
  that pins BORDER → wrap then changes on purpose.
- **G08 (legacy states).** It copies raw values 1-4 into ADDRESSU/V, so a DX5/DX6 MIRROR reaches this mapping.
  Both bits are needed for those titles.
- **G15 (ValidateTextureStageState).** D3D's validation errors have no address-mode code, so it must not refuse
  ADDRESSU/V.

## 5. Gating

- **Default OFF**, behind `Diag\D3DFeat` `MIRROR`, read at boot. The caps and the drawing sit behind the same bit.
  - Caps without drawing would lie.
  - Drawing without caps would help only titles that ignore the caps, and none is known (section 3).
- **Proven on silicon** by one supervised clean boot (Boot B, section 8) with this bit as the only Diag change.
- **Safe to graduate to default-ON after that boot**, through the plan's shared D3DFeat default/kill-mask
  convention. The reason: with the bit off nothing changes, and with it on only requests that are drawn wrongly
  today change.
- **Not safe to land default-on before silicon.** The caps change moves any caps-checking title onto a path that
  has never run on this card.
- **Fallback** if a caps-checking title gets worse in Boot B: keep the drawing and withdraw the cap (one `if`).

## 6. d3dprobe tests (`KMD/tools/d3dprobe.c`)

### 6.1 `mirror`: added to the DEFAULT list; the expectation follows the cap

**Texture P.** 8x8 `R5G6B5`, `D3DPOOL_MANAGED` (D3D8 cannot lock a DEFAULT texture, `onbox/README.md` run 12).
- Texel (x, y) = R `32x+16`, G `32y+16`, B `0x80`. Each channel survives 565 within 7, and neighbours differ by
  32, against a tolerance of 12.
- It is 128 bytes, a 16-byte multiple, so it keeps the heap's alignment on the default path too (G21).

**State.** MIN/MAG POINT, MIPFILTER NONE, COLOROP SELECTARG1 TEXTURE, white diffuse.

**Geometry.** One quad from `Q0-0.5` to `Q0+192-0.5`, UV (-2,-2)..(2,2): 32x32 cells of 6x6 px. Every cell is
read at its centre, `Q0+6j+3`, the layout `test_dxt_decode` uses (`:743-761`).

**Scenes:**

| scene | ADDRESSU | ADDRESSV |
|---|---|---|
| S1 | MIRROR | MIRROR |
| S2 | MIRROR | WRAP (INDEPENDENTUV) |
| S3 | CLAMP | MIRROR |

**Reference** (D3D's definition, coded in the probe, never the HAL's). Cell j gives the unwrapped texel
k = j - 16, r = floor(k / 8), i = k - 8r.
- MIRROR: `r odd ? 7-i : i`
- WRAP: `i`
- CLAMP: `k < 0 ? 0 : k > 7 ? 7 : k`

**Expectation.**
- If `GetDeviceCaps` has `D3DPTADDRESSCAPS_MIRROR`, the MIRROR axes must read MIRROR.
- If it does not, they must read WRAP: vcr-kmd's fallback, i.e. the off path, which must stay exactly that.
- Boot A then proves the off path unchanged, and Boot B proves mirror.

**Pass:** 0 wrong of 1024 cells in each scene, tolerance 12.
- The JSON per scene: wrong count, `cap`, and the observed pattern of row/column 16 (mirror, wrap, clamp or other).
- On a failure the frame is dumped, as the decode test does.
- Afterwards ADDRESSU/V are restored to WRAP and the texture unbound.

### 6.2 `mirror_ext`: explicit, never default; the silicon cases

Each sub-case is skipped (named) when the HAL lacks what it needs. Each passes on 0 wrong cells. The expectation
follows the cap as in 6.1.

| sub | what | reads | why |
|---|---|---|---|
| E1 | 16x4 (S wider, aspect 4) and 4x16, MIRROR both, UV -2..2. Texel colour unique; x in R and B, y in G, neighbours ≥ 32 apart | every cell centre | mirror at each **axis's own** size (CSIM `:738-788`). **86Box fails here: an emulator limit, not a gate** |
| E2 | 8x8, columns 0-3 black and 4-7 white; MAG/MIN LINEAR; U MIRROR, V WRAP; u 0..2 over 128 px | u = 1.0 (seam), 1.25, 1.75, tolerance 40 | per-tap mirroring at a bilinear seam: MIRROR (W, W, B); WRAP (≈50 % grey, B, W); CLAMP (W, W, W). **86Box gives grey at the seam** |
| E3 | two stages: stage 0 = P MIRROR + stage 1 solid white MODULATE WRAP, then stage 0 white WRAP + stage 1 = P MIRROR | S1's cells, twice | the bits reach TMU1 (`tLOD1`, stage 0) and TMU0 in the two-texture arrangement. Skipped if MaxSimultaneousTextures < 2 |
| E4 | a 16x16 chain: level 0 grey, level 1 = P, levels 2+ magenta; MIPFILTER POINT; quad 32x32 px, UV -2..2 (2 texels/px at level 0, so level 1 is selected) | all 32x32 px at 1:1 | mirror at the selected level's period (8). Read it beside `mip` in the same run: a fail with `mip` failing too is G07, not this item |
| E5 | 512x512 single level, 8x8 cells of 64x64 texels coloured as P's texels, MIRROR both, UV -1..1 | 16x16 cell centres | TBIG + mirror (CSIM `:742`). Skipped if MaxTextureWidth < 512 (BigTex bit 0) |
| E6 | 128x128 DXT1 of solid blocks, 16x16-texel cells as above, MIRROR both, UV -1..1 | cell centres | compressed + mirror. Skipped if DXT1 is not offered |
| E7 | P with ADDRESSU = V = 5 (MIRRORONCE), UV -1..1 | 16x16 cells | armed: equals MIRROR inside ±1 (the mapping's claim); off: WRAP |

### 6.3 `caps`

The existing `TextureAddressCaps` field must read `00000015` with the bit off and `00000017` with it on.

## 7. Regression tests

### `WT/tests/native/test_vcr_kmd_texaddr.c` (new)

`run_all.sh` section [2] builds every `test_*.c`. It compiles `vcr_texaddr.h` and asserts:

1. **`mirror_sets_tlod_28_29_only_when_armed`.**
   - Fixed value: armed, `(2,2)` → `tm 0, tlod 0x30000000`.
   - Old-buggy value, which is also the switch-off value: `(2,2)` with flags 0 → `tm 0, tlod 0` (WRAP).
2. **`independent_uv`.**
   - `(2,1)` → `0x10000000`; `(1,2)` → `0x20000000`.
   - `(3,2)` → `tm 0x40` + `tlod 0x20000000`; `(2,3)` → `tlod 0x10000000` + `tm 0x80`.
3. **`off_is_todays_mapping_for_every_value`.** For u, v ∈ {0..6, 0x7ffffffe, 0x7fffffff, 0xffffffff}, flags 0
   gives exactly what a copy of today's two lines gives (`tm` = CLAMP bits only, `tlod` = 0).
4. **`never_clamp_and_mirror_on_one_axis`:** every value, both flags.
5. **`border_and_unknown_values_wrap`:** 4, 0, 6, ~0 → 0/0, armed or not. G86 changes this test deliberately.
6. **`mirroronce_is_mirror_only_when_armed`.**
7. **`the_bits_touch_no_other_tlod_field`.** `TL_MIRRORS|TL_MIRRORT == 0x30000000`, and the bits are disjoint from
   LODMIN/MAX/BIAS, ODD, TSPLIT, S_IS_WIDER, ASPECT and TBIG.
8. **`the_probe_reference_is_what_the_tmu_does`.**
   - A ~15-line model of the TMU's per-axis rule, our own code from CSIM's documented behaviour (section 2), is
     compared with the probe's D3D reference for n ∈ {1, 2, 4, 8, 16, 256, 2048} and k ∈ [-4n, 4n): mirror,
     wrap and clamp must agree.
   - Mirror + clamp differs from D3D MIRRORONCE at k = -2, which is why the mapping never sets both.
   - At E2's three read points the bilinear taps give white/white/black for mirror and grey/black/white for wrap.
   - So the probe's expected values are achievable by the chip, and its outcomes are distinct.

### `WT/tests/python/test_vcr_kmd_d3d.py`

`test_mirror_addressing_is_a_default_off_d3dfeat_bit` asserts that:
- `tex_view` and `tex_view_ext` no longer test `D3DTADDRESS_CLAMP` inline, and both call `tex_address(pd, tss, v)`;
- `vcr_tex_address(` appears once, fed `pd->tex_mirror ? VCR_TADDR_F_MIRROR : 0`;
- `prim_caps` still sets exactly `D3DPTADDRESSCAPS_WRAP | D3DPTADDRESSCAPS_CLAMP | D3DPTADDRESSCAPS_INDEPENDENTUV`;
- `D3DPTADDRESSCAPS_MIRROR` appears only inside `if (pd->tex_mirror)`;
- `pd->tex_mirror` is zeroed before the IOCTL and set once from the D3DFeat MIRROR bit;
- the miniport reads `D3DFeat` at boot with default 0;
- `addr_seen` is only ORed (in the TSS walk) and printed (in `ctx_free`), and never read by `compute_regs`.

`test_the_register_offsets_are_computed_from_the_gpl_header` gains
`Q("SST_TMIRRORS", SST_TMIRRORS == TL_MIRRORS); Q("SST_TMIRRORT", SST_TMIRRORT == TL_MIRRORT);`.
It already includes `vcr_3dseq.h`, and through it `vcr_3dregs.h`.

## 9. Risk to proven paths

- **The default 16 bpp path:** no risk with the bit off. The proof is the native test over every value, the Python
  call-site test, and Boot A's probe. With the bit on, only stages that ask for 2 or 5 change.
- **The caps change:** a caps-checking title could switch to a mirror path. The scanned titles do not use mirror,
  and Halo tests only BORDER (section 3). Boot B watches for it, and the fallback is to withdraw the cap.
- **Silicon:** the bits have never run on this card. A wrong mirror would still be a lookup *inside* the same level,
  because the result is masked to the level (CSIM `:851`, `:1332`). It cannot address outside the texture, and
  there is no hang mechanism. TBIG and compressed textures with mirror are unproven; E5 and E6 cover them.
- **Glide/OpenGL coexistence:** no risk. D3D writes the whole tLOD at every textured state send, and Glide's window
  open clears the mirror bits on both TMUs. MesaFX's mirrored repeat goes through Glide's own shadow.
- **SLI:** none today (D3D runs on chip 0, and no SLI register is touched). There is an invariant for G51
  (section 4.8).
- **Flip path:** untouched.
- **Texture flush:** the flush's texture-port write (`vcrdd_3d.c:253-271`) is not affected. The S/T addressing bits
  do not change host writes, and the data-swizzle bits 25/26 are never set.
- **The 86Box bed:** E1/E2 failures there are emulator limits. Do not read them as HAL bugs.
