# G01 - Glide's command FIFO left on: the stale-FIFO guard (design)

Lane: **clean-room `vcr-kmd`** (miniport `vcrmp.sys` + display DLL `vcrdd.dll`).
This is a design only. Nothing was built, deployed or run, and no box was contacted.

## 1. Verdict

**The gap is real and fixable, and it is P0.** When an OpenGL/Glide session ends without
`cmdFifo0.baseSize = 0`, every later Direct3D triangle is lost silently until something resets the
engine. This boot-wide state is hit in an ordinary sequence: Quake III in 4-chip SLI, then UT2004.

**One correction to the proposed fix.** The display reset (`IOCTL_VIDEO_RESET_DEVICE`, "SLI/AA off:
display reset") is the **wrong** trigger:
- It is also what an alt-tab or a console switch away from a **live** fullscreen Glide game produces.
- At that moment pid 1892 still held all 14 of its views. It released them 0.9 s later.

The first moment the FIFO is *provably* orphaned is when its owner's mappings are gone. Owners leave
in two ways:
- **Unmap.** The owner unmaps (hwcext 16 → `VcrUnmapGlide`).
- **Exit without unmapping.** The owner dies; a liveness check finds this.

So the design is a **stale-FIFO guard**:
- **The owner model.** Device-scope ownership in the miniport (its existing Glide mapping table plus
  a process-liveness check).
- **The cure.** The already-proven `VcrHwResetEngine`.
- **When it runs.** At four points: unmap, mode set, D3D context/DP2, and a 2D stall on `CMD0_BUSY`.
- **The switch.** It sits behind `Diag\D3DSafe` bit 0, default off.

## 3. The design

### 3.0 Switch and plumbing

- **`Diag\D3DSafe`** (DWORD, default 0): read once at boot in `VcrFindAdapter`, beside `D3D32`/`Reset3D`
  (`vcrmp.c:238-239`) → `x->d3dsafe`.
  - **Bit 0 = this guard.**
  - Bits 1 and 2 stay reserved for G03 (D3D 3D-state baseline) and G02 (visible give-up), as `hal.md` R2/R3 propose.
- `fill_info` sets a positive flag `VCR_INFO_F_FIFOGUARD 0x8000` (`include/vcr_ioctl.h`). An older miniport never sets it.
- `VcrDd2dInit` sets `pd->fifo_guard` from the flag (any Voodoo backend: the FIFO registers are the
  same on H3/H4/H5). It logs "armed: stale command FIFO guard" with the 513/16 line.
- **Off means off.** With bit 0 clear, no path reads or writes any CMDAGP register it did not read or
  write before. The register traffic is byte for byte today's.

### 3.1 Pure logic: `KMD/include/vcr_fifoguard.h` (Win32-free, host-tested)

```c
#define VCR_CMD_BASEADDR(n)   (VCR_MB0_CMDAGP + 0x20 + 0x30 * (n))   /* cmdFifo0/1 */
#define VCR_CMD_BASESIZE(n)   (VCR_MB0_CMDAGP + 0x24 + 0x30 * (n))
#define VCR_CMD_READPTRL0     (VCR_MB0_CMDAGP + 0x2c)
#define VCR_CMD_AMIN0         (VCR_MB0_CMDAGP + 0x34)
#define VCR_CMD_AMAX0         (VCR_MB0_CMDAGP + 0x3c)
#define VCR_CMD_DEPTH0        (VCR_MB0_CMDAGP + 0x44)
#define VCR_CMD_HOLES0        (VCR_MB0_CMDAGP + 0x48)
#define VCR_STATUS_FBI_BUSY   (1u << 7)   /* h3defs.h SST_FBI_BUSY  */
#define VCR_STATUS_TMU_BUSY   (1u << 8)
#define VCR_STATUS_GUI_BUSY   (1u << 10)
#define VCR_STATUS_CMD0_BUSY  (1u << 11)
#define VCR_STATUS_CMD1_BUSY  (1u << 12)
#define VCR_D3DSAFE_FIFO      1u          /* Diag\D3DSafe bit 0 */
#define VCR_FG_MAX_RECOVERIES 3u          /* 2D-stall recoveries per PDEV */

enum { VCR_FG_NOTHING, VCR_FG_RESET, VCR_FG_OWNED, VCR_FG_SLI, VCR_FG_UNARMED, VCR_FG_RESET_FAILED };
enum { VCR_FG_AT_UNMAP = 1, VCR_FG_AT_MODESET, VCR_FG_AT_CONTEXT, VCR_FG_AT_DP2,
       VCR_FG_AT_STALL, VCR_FG_AT_TOOL };

static __inline unsigned vcr_fifo_on(unsigned basesize) { return (basesize & VCR_CMDFIFO_EN) != 0; }

/* [lo, hi) in video memory. baseAddrL holds base >> 12; baseSize[7:0] = pages - 1
 * (Glide writes 0xfe for its 255-page FIFO; the GPL header's 4-bit SST_BASESIZE mask is
 * narrower - using 8 bits gives the larger, safe window). */
static __inline void vcr_fifo_window(unsigned baseaddr, unsigned basesize, unsigned *lo, unsigned *hi);
static __inline unsigned vcr_fifo_overlaps(unsigned lo, unsigned hi, unsigned off, unsigned len);

/* the decision; owners = live Glide processes still holding mappings */
static __inline unsigned vcr_fifo_guard(unsigned armed, unsigned bs0, unsigned bs1,
                                        unsigned owners, unsigned sli_chips)
{
    if (!vcr_fifo_on(bs0) && !vcr_fifo_on(bs1)) return VCR_FG_NOTHING;
    if (!armed)     return VCR_FG_UNARMED;   /* today: nothing written */
    if (owners)     return VCR_FG_OWNED;     /* a live client may still feed it */
    if (sli_chips)  return VCR_FG_SLI;       /* a master reset would reach snooping slaves */
    return VCR_FG_RESET;
}
/* a 2D/3D stall that is the command stream's, and may be recovered once more */
static __inline unsigned vcr_fifo_stall_recoverable(unsigned armed, unsigned status, unsigned n);
/* bounded pre-reset quiesce: FBI/TMU/2D idle and the PCI FIFO full, CMD bits ignored */
static __inline unsigned vcr_fifo_quiet(unsigned status, unsigned fifo_full);
```

### 3.2 Miniport (`vcrmp_map.c`, `vcrmp_hw.c`, `vcrmp.c`)

1. **`vcr_proc_alive(VCR_PROC *p)`.** It never dereferences the stored EPROCESS:
   - `PsLookupProcessByProcessId(pid)`;
   - alive means the same object (`ep == p->eprocess`) **and** the same create time **and**
     `PsGetProcessExitStatus(ep) == STATUS_PENDING`;
   - then `ObfDereferenceObject`.

   It is PASSIVE_LEVEL only. It is called from StartIO paths, never from `VcrTimer` or `HwResetHw`.
2. **`VcrGlideLiveOwners(x, &first_pid)`.** It counts slots with `nva > 0` whose process is alive.
   - It **forgets** dead slots, zeroing them without unmapping (their views died with the process), as
     `proc_find` already does when the table is full.
   - It logs each forgotten slot once: event 406 `VCR_EV_GLIDE_GONE`, a=pid, b=views.
3. **`VcrFifoGuard(x, req, res)`.** The steps:
   - read chip 0's `baseSize` 0/1, `baseAddr`, `readPtrL`, `aMin`, `aMax`, `depth`, `holeCount` and
     `status`, plus chips 1-3's `cmdFifo0.baseSize` (read-only, for the log and the investigation);
   - call `vcr_fifo_guard(x->d3dsafe & 1 || req->op == TOOL, bs0, bs1, owners, x->sli_chips)`;
   - on `RESET`, call `VcrHwResetEngine(x, 0, "stale command FIFO")`. A reset that stays busy reports `RESET_FAILED`.
   - Log event 309 `VCR_EV_FIFO_GUARD`: a = where | result << 8, b = `baseSize0`, c = `readPtrL`, d = owner pid.
   - Count resets and refusals since boot.
4. **`IOCTL_VCR_FIFO_GUARD`** (`VCR_CTL(0xa10)`). Its ops are QUERY (read only) and GUARD.
   - Structs `vcr_fifo_guard_req {size, op, where, pid, excl_pid}` / `vcr_fifo_guard_res {size, result,
     basesize[2], baseaddr[2], readptr0, amin0, amax0, depth0, holes0, status_before, status_after,
     owners, owner_pid, forgotten, sli_chips, slave_basesize[3], resets, refusals}`.
   - The escape is `VCR_ESC_FIFO = VCR_ESC_BASE + 12`; `supported()` is extended to it.
5. **(B) Mode set**, `voodoo_program` (`vcrmp_hw.c:571`). The busy line stays **exactly** as it is, and a branch is added:

   ```c
   if (!VcrHwWaitIdle(x, 0, 200000))
       VcrHwResetEngine(x, 0, "busy at mode set");          /* unchanged */
   else if (x->d3dsafe & VCR_D3DSAFE_FIFO)
       VcrFifoGuardKernel(x, VCR_FG_AT_MODESET);             /* idle, FIFO on, nobody alive owns it */
   ```

   `VcrSliOff(x, "mode set")` has already run before `voodoo_program` (`vcrmp_hw.c:674`), so `sli_chips` is 0 here.
   The display DLL has synced its 2D engine before every mode change (`DrvAssertMode(FALSE)`).
   A Glide app's **own** opening mode set sees its live mapping (GETLINEARADDR precedes it) and is left alone.
   The same holds for the `RESTORE_MODE` at its release. Its unmap (A) follows.

### 3.3 Display DLL (`vcrdd_2d.c`, `vcrdd_escape.c`, `vcrdd_d3d.c`)

**`ULONG VcrDdFifoGuard(VCR_PDEV *pd, ULONG where)`**, in `vcrdd_2d.c`:
- If `!pd->fifo_guard`, it returns NOTHING **before any read**.
- Otherwise it makes two reads (`cmdFifo0/1.baseSize`). Off means NOTHING, which is the normal case.
- If `pd->exclusive_pid` is set, it returns OWNED, except at the owner's own unmap.
- Unless `where == STALL`, it runs a bounded quiesce: `vcr_fifo_quiet` up to `SPIN_CAP`. A timeout does
  not give up; the reset that follows aborts at most one GDI op.
- It then calls the IOCTL. On `RESET` it:
  - sets `pd->fog_valid = 0` (the chip's fog table is no longer ours);
  - clears `g2d_busy`;
  - re-learns `g2d_fifo_full` with `VcrDd2dInit`'s 64-read loop (factored out);
  - bumps a global `g_vcr_eng_resets`.
- It logs once per (where, result) per PDEV.

| point | where | what changes |
|---|---|---|
| **(A) unmap** | `vcrdd_escape.c:203-206`, after `IOCTL_VCR_UNMAP_GLIDE` returns | `VcrDdFifoGuard(pd, VCR_FG_AT_UNMAP)`. This catches today's case 0.9 s after the close: pid 1892's views were gone, SLI was already off, and no other live mapping existed. The releasing process can no longer write the FIFO. `VcrUnmapGlide` itself is unchanged. |
| **(C) ContextCreate** | `D3d_ContextCreate`, before `target_of` (`vcrdd_d3d.c:1163`) | OWNED / SLI / RESET_FAILED → refuse with `DDERR_SURFACEBUSY` and log 513 what 24 ("Glide's command FIFO is on: owner %u, baseSize %x"); RESET or NOTHING → continue as today. |
| **(C') DP2 / Clear2** | the two `w.drawable` lines (`:1859`, `:1887`) | `... && !fifo_blocked(c->pd)`. `fifo_blocked` returns 0 at once when unarmed; armed, it makes one `cmdFifo0.baseSize` read per call (not per triangle). A FIFO that is on → guard; a reset lets the batch draw. OWNED skips the batch, as `exclusive_pid` already does. 513 what 25 logs once per context, and a per-context `fifo_blocked` counter goes onto "context gone". |
| **(D) 2D stall** | `give_up()` (`vcrdd_2d.c:83`), the cold path only | `if (vcr_fifo_stall_recoverable(pd->fifo_guard, status, pd->fifo_recoveries) && VcrDdFifoGuard(pd, VCR_FG_AT_STALL) == VCR_FG_RESET) { pd->fifo_recoveries++; log 512 a=10; return; }` keeps `g2d_ok = 1`. The stalled op is dropped (`VcrDdRoom` still returns FALSE); the next op works. `VcrDdRoom` and `VcrDd2dSync` keep the text `test_vcr_kmd_2d.py` pins. Without the switch, or past 3 recoveries, it gives up exactly as now. |
| **state re-send** | `prepare()` (`vcrdd_d3d.c:1322`) | Beside the existing `g_tex_writes` generation: `if (g_vcr_eng_resets != c->eng_resets_seen) { c->eng_resets_seen = g_vcr_eng_resets; w->prepared = 0; }`. That is one compare per triangle; it never changes when unarmed. |

### 3.4 Deliberately not done

- **No reset at `RESET_DEVICE` or `DrvAssertMode`**, for the reason in fact 7. This replaces the
  gap's "stop cmdFifo0/1 at the display reset". A test pins the absence.
- **No reset while a live Glide process holds mappings, or while SLI/AA is live** (a master reset
  reaches snooping slaves; `minihwc.c:2763-2775` refuses the same thing). D3D refuses instead:
  visibly, not silently.
- **No timer- or work-item-driven guard.** It would run without the display lock, under live GDI
  register sequences.
- **Slaves are read, never reset.** An SLI enable already resets each slave's command stream (the
  ring's `initSlave` steps).
- **`Reset3D` is untouched.** G03 owns the 3D state baseline.

### 3.5 Optional, separate switch value: keep DirectDraw surfaces out of Glide's window

The guard removes stale FIFOs before D3D/DirectDraw touch them. The remaining case is **live**
coexistence: a Glide game alt-tabbed while a windowed DirectDraw app writes surfaces at the bottom
of the heap.

- **The proposal.** Make `Diag\DdHeapFloor = 2` start the heap at `VCR_GLIDE_FIFO_END = 0x117000`
  on a VSA-100. That is Glide's default Napalm FIFO, `pad 96 KB + MAXFIFOSIZE_16MB 0xff000`
  (`GL5/minihwc/minihwc.c:1044, 2566-2592`).
- **How.** Through the existing `floor` argument of `vcr_dd_heap_range` (`KMD/include/vcr_ddheap.h`).
- **Side effect.** It also cures G63's offset-0 loss.
- **Cost.** About 1.1 MB of a 60 MB heap. Read at every mode change, as `DdHeapFloor` is now.
- **What it does not cover.** A Glide whose FIFO was moved by `FX_GLIDE_FIFOEXTRA`/`FX_GLIDE_V3FIFO`.
- **Proof.** Separate from bit 0: `ddlab vidmem` with the lowest block at 0x117000.

### 3.6 Tools

- **`vcrctl fifo`** (QUERY) prints:
  - chip 0's `cmdFifo0/1` (base, size, window, `readPtr`, `aMin`, `aMax`, `depth`, holes);
  - status decoded, including `CMD0_BUSY`;
  - the slaves' `baseSize`;
  - the slot table (live/dead owners);
  - the guard counters.

  **`vcrctl fifo --guard`** asks for the guarded reset: it resets only an ownerless FIFO with SLI off,
  which makes it safer than the unconditional `reset-engine`.
- **`d3dprobe`** reads `VCR_ESC_FIFO` QUERY before device creation and after release (a read only; it
  is skipped on other drivers). It puts `"cmdfifo":{"before":…,"after":…}` into every RESULT, and
  prints a banner when it was on before the run.
- **`tools/d3dprobe_run.py`.** If `before` had bit 8 set and the guard did not clear it, the run is
  reported as `STALE COMMAND FIFO (G01) - not a HAL result` and exits non-zero. A failure shows up
  as itself, not as 9/40.

### 3.7 Forward requirement (G47)

Our own future CMDFIFO must use this API. Before arming it calls `VcrDdFifoGuard(pd, ARM)`, and it
arms only on NOTHING/RESET. It must also **register itself as an owner** (an op `CLAIM`/`RELEASE` on
the same IOCTL), so that (A)/(B)/(C) never reset the display DLL's own FIFO.

## 4. Gating

- **Default OFF** (`Diag\D3DSafe` absent = 0). Off is byte-for-byte today's traffic:
  - every call site sits inside `pd->fifo_guard` / `x->d3dsafe & 1`;
  - `VcrDdFifoGuard` returns before its first read;
  - the existing busy reset line is unchanged.
- **Not safe to land default-on yet.** It adds a GRX/2D engine reset at three new points (unmap,
  context, stall) and a process-liveness check with new ntoskrnl imports. None of these has run on
  silicon.
- **Promote bit 0 to default-on** after session 2 of section 8 passes and one week of daily use,
  GL then D3D in the same boot, with the ring showing no guard action against a live client. It is a
  pure stability fix with a measured failure mode when it is missing, so default-on is the goal. That
  needs a `MOVED_DIAG` entry (`tests/python/test_vcr_kmd_integration.py:91`) with the evidence.
- **The floor value `DdHeapFloor = 2`** stays off independently, until its own `ddlab` run.

## 5. d3dprobe test

**Every RESULT** gains `cmdfifo.before/after` (QUERY), as described above.

**New explicit test `fifo`**. It is never in the default list, so the 40/40 gate is unchanged.

1. Record `cmdfifo.before`.
2. On the device, clear to blue `0000ff`.
3. Draw the `flat` quad (green `00ff00`, the existing geometry).
4. Create a 64x64 R5G6B5 2x2 checker texture **after** the device. On a windowed device it lands in
   the low heap, inside Glide's default window when the heap starts at 0. Draw it on a quad
   (cells `ff0000`/`0000ff`).
5. Lock the back buffer and read the points.
6. After release, record `cmdfifo.after` and `VCR_ESC_2D_STATS` flags.

**Pass:**
- flat centre `00ff00` (tolerance 8), both checker cells exact (tolerance 12; at 16 bpp, 565-rounded);
- **and** `after.size0 & 0x100 == 0`;
- **and** `VCR_2DS_F_ENGINE` is still set;
- **and**, when `before` was on, the guard's `resets` counter has risen by at least 1.

**The old (bug) signature it names.** Flat reads `0000ff` (the clear colour), the checker reads
`000000`, the 2D flag drops when windowed, and `after.size0 = 1fe`. Those are exactly
`ONBOX/d3dprobe_render_windowed_desktop32.txt`'s values.

The stale state for the test comes from the reproduction in section 7, E1. It is run windowed, then
`--full --bpp 16`, then `--full --bpp 32`.

## 6. Regression tests

**`tests/native/test_vcr_kmd_fifoguard.c`** (auto-found by `tests/run_all.sh`) compiles `vcr_fifoguard.h`.

**The measured window.**
- `vcr_fifo_window(0x18, 0x1fe)` = [0x18000, 0x117000).
- Today's windowed placements overlap it: 0x40000 (+256 KB), 0x80000, 0xc0000 (+8 KB).
- The fullscreen ones do not: 0x300000, 0x600000, 0x900000.

**The bug versus the fix.**
- Old: a model of today's mode-set rule, `old_resets(status) = !idle`, gives **0** (no reset) for
  status 0x1f with `baseSize` 0x1fe.
- New: `vcr_fifo_guard(1, 0x1fe, 0, 0, 0) == VCR_FG_RESET`.
- The busy reset is unchanged: `old_resets(0xa5f) == 1`.
- `vcr_3d_reset_blocked(3, 0x1fe) == VCR_R3D_CMDFIFO` stays as it is, which shows why `Reset3D`
  could never cure this.

**Never reset a live or SLI board.**
- owners 1 → OWNED;
- `sli_chips` 4 → SLI;
- unarmed → UNARMED.

**The enable bit alone decides.**
- 0x0fe → off;
- 0x100, 0x307 (AGP) and 0x5fe (holes disabled) → on;
- `cmdFifo1` on alone → on.

**The stall.**
- `vcr_fifo_stall_recoverable(1, 0xa1f, 0)` = 1;
- `(1, 0x21f, 0)` = 0 (busy, but not the command stream);
- `(0, 0xa1f, 0)` = 0 (old: give up);
- `(1, 0xa1f, 3)` = 0 (capped).

**Quiesce.** `vcr_fifo_quiet(0xa1f, 31)` = 1 (only CMD0 busy), `(0x29f, 31)` = 0 (FBI busy).

**(If 3.5 lands.)**
- `vcr_dd_heap_range(0x3b00000, …, floor 0x117000)` starts at 0x117000.
- Old floor 0 → 0, and floor 1 page → 0x1000: both inside the window.

## 9. Risk to proven paths

- **The default 16 bpp path and every unarmed path.** No change: guarded call sites, no new register
  access, pinned by the tests above.
- **Armed, normal case (no FIFO on).**
  - Two MMIO reads at ContextCreate and unmap, and one per DP2/Clear2 call, about 1 µs each. UT2003
    made 59,589 DP2 calls in 245 s, so about 0.02 % of a frame.
  - One compare per triangle in `prepare()`.
- **Glide/OpenGL coexistence.**
  - Never resets under a live mapping or live SLI.
  - The main residual risk is a **false "dead"** verdict on a live Glide process. It is mitigated by a
    strict liveness test (same object, same create time, exit status pending), by logging every
    forgotten slot, and by section 8 step 6.
  - An alt-tabbed Glide game now makes D3D **refuse** where today it would draw nothing or draw into
    its stream. A D3D game launched over a still-running Glide program fails to create its device.
    That failure is visible and logged.
  - A refused `CreateDevice` makes the D3D8 runtime switch modes twice (G11). This is rare by
    construction.
- **SLI state.**
  - The guard refuses while `x->sli_chips != 0`.
  - The reset is chip 0's `VcrHwResetEngine`, the same call as the proven mode-set reset.
  - Slaves are only read.
- **Flip path.** `VcrHwResetEngine` does not reset the video unit, so scan-out and a latched flip
  continue. A reset in the middle of a session drops that frame's queued 3D work, and `prepare()`
  re-sends target and state.
- **The 2D engine.** A reset can abort at most one in-flight GDI op. The pre-reset quiesce
  (CMD bits ignored) makes that unlikely. The 2D code rewrites its whole state on every op
  (`vcrdd_2d.c:201-244, 307-373`).

## 10. Effort, dependencies, priority

- **Effort: M.**
  - About 60 lines in the pure header, 150 in the miniport, 150 in the display DLL, and 120 in the tools.
  - About 250 lines of tests.
  - Two supervised on-box sessions.
- **Depends on: none.** G01 is the foundation.
- **It enables:**
  - **G02**: (D) is the first `recover_or_give_up` hook, which G02 generalises.
  - **G03**: its baseline then runs on a FIFO-free chip.
  - **G04**: it removes Max Payne candidate (a) and makes E0's "FIFO off" precondition automatic.
  - **G20**: it lifts D3D32 blocker (1) of `history.md` section 7.
  - **G46/G47/G78**: it gives every baseline its FIFO-off preflight, and G47 must reuse the guard.
  - **G63**: through the optional floor value 2.

  own resets.
- **Priority: P0.** It stops every D3D title started after any OpenGL/Glide title in the same boot,
  and its escalation removes the D3D HAL and 2D acceleration until a mode set. It is also a candidate
  freeze mechanism.

## 11. Open questions

1. Does an enabled FIFO idle at a **packet boundary** (a live, alt-tabbed Glide game) block PIO
   triangles too, or only a fetcher parked mid-packet? (E4) If not, OWNED could allow drawing.
2. Is `VcrHwResetEngine` needed, or does stop-fetch plus a command-stream reset suffice? Does the
   GRX reset also clear `combineMode`/`chipMask`/`aaCtrl`/stencil? That is relevant to G03. (E3)
3. How often does a 4-chip SLI GL close leave the FIFO on? Which Glide path does it: the not-idle
   `hwcRestoreVideo`, or a display drop under a live stream? (E0)
4. Should a D3D context in the **same** process as a stale Glide mapping be allowed to reset? An
   engine that probes OpenGL before D3D would hit this. The default here: no (OWNED).
5. After an unclean SLI close, do chips 1-3 keep an enabled `cmdFifo0`, snooped from the master's
   programming? Does a following 1-chip Glide or D3D session care? (`vcrctl fifo` reads them.)
6. For a terminated process that is still referenced (a zombie held by a handle, such as the agent's
   EXECW), XP returns its exit code, not `STATUS_PENDING`. Verify on the bed that such a process is
   classed as dead.
7. `SST_BASESIZE` is a 4-bit mask in the GPL header, but Glide writes 0xfe for 255 pages. Confirm
   that the window field is [7:0] (the design assumes the larger window).
8. Does any staged title ship a Glide that maps the board without `IOCTL_VCR_MAP_GLIDE`? That owner
   would be invisible to the guard. Search the library with `find -iname 'glide*.dll'` and inspect
   each one.
9. Can the OWNED refusal move earlier, to the D3D `GetDriverInfo` answers (`vcrdd_d3d.c:2136`)? That
   would avoid the G11 mode flap without hiding DirectDraw from 2D-only apps.
