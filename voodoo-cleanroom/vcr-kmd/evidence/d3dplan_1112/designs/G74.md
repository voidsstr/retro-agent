## 0. Verdict

1. **The gap is real, and the tool itself is the bigger half of it.** Besides the coverage list, d3dprobe has five
   ways to report a check that never ran as green. All five have the shape this project keeps paying for - success
   reported, nothing checked:

   | # | path | where | effect |
   |---|---|---|---|
   | a | an unknown `--tests` name is logged and counted nowhere | `d3dprobe.c:1240-1241` (and `:1189`) | `--tests mipdxt1` today is a run with 0 checks, `fail` 0, rc 0. The runner fails only **skipped** names (`d3dprobe_run.py:201-218`), and an unknown name is not a skip |
   | b | the list is copied into `char list[512]` | `:1538-1540` | a longer list is cut silently; its tail never runs, and a name cut in half becomes (a) |
   | c | a test whose `BeginScene` fails returns with no entry | every `if (!frame_begin(..)) return;`, e.g. `:919`, `:927`, `:936` | no check, no failure |
   | d | a failed back-buffer lock leaves the previous frame in `g_px`, and the next `expect()` compares it | `:300-311`, `:325-343` | a stale frame can pass |
   | e | `present` in a fullscreen run logs "windowed only" and records nothing | `:1039-1042` | harmless today (it is the 40 vs 42), but the same shape |

   Two more defects block growth:
   - The RESULT is built in a 16 KB static buffer with msvcrt's `_vsnprintf`, which returns -1 on truncation, so
     `g_jn` steps **back** (`:137-146`). The 83-check texture run already used 7.9 KB
     (`ONBOX/d3dprobe_textures_a_1024x768x32.txt`). At about 170 checks the RESULT becomes unparsable, and the host
     reports an error instead of the suite.
   - `tex2mod`/`tex2add` count a failure with no entry when a texture fails, and leak the other texture
     (`:1066-1069`).
2. **The coverage limits are as the gap says, and three of them block other items outright:**
   - **The top-left 256x256 window** (`:149-151`, `:291-323`) sees 5.3 % of a 1280x960 target. G51 (SLI: every chip's
     scan lines), G57 (the guard band at all four edges), G69 (Rainbow Six's 16-over-32 Z beyond one strip) and G10
     (D16 at 32 bpp) all need the whole target.
   - **The textures land where the probe's own allocation order puts them.** That is why it missed the 11-08
     alignment bug (`/home/voidsstr/development/retro-3dfx/FINDINGS.md:22-35`).
   - **The perf scene (200 triangles a frame) measures the 85 Hz refresh, not the HAL** (`ONBOX/d3dprobe_perf_*`:
     85.1 and 84.4 fps). G46-G51's performance work has no synthetic baseline.
3. **Fixable, tool-only, and safe to land default-on.** Nothing in `vcrdd.dll` or `vcrmp.sys` changes. The default
   test list, and every check it records, stay exactly as they are (§9).
4. **Priority P1.** No staged title gets better from this item alone. It is the measurement prerequisite of the P0
   work, though: twenty sibling designs specify their d3dprobe checks on top of it (G01, G06, G10, G12, G13 and G51
   among them).
5. **Shape:** five phases. Phase A, the framework and runner, lands first, because the other items' tests need it. B
   (caps), C (this item's own checks), D (perf modes) and E (a D3D9 path) follow.

## 3. Phase A: the framework

### 3.1 A registry instead of a string chain

- **The name table is a Win32-free X-macro list** in a new `KMD/tools/d3dprobe_core.h`:
  `DP_TESTS(X)` → `X(name, owner, flags)`. `d3dprobe.c` expands it into
  `{ "name", "owner", flags, t_name, est_ms }`. The native test expands it into names and flags only, and the
  runner's Python test parses it.
  - `owner` is `core` for the historical tests, `G74` for this item's, or the gap that specified the test.
  - flags: `IMPL` or `PLANNED`, `FULLONLY`, `WINONLY`, `NEEDS_Z`, `WHOLE` (reads the whole target), `LEGACY`
    (historical body).
- **The historical tests keep their code.** Their entries point at `legacy_run()`, which calls today's `run_test(name)`
  unchanged. Their code, their checks and the DP2 stream they produce are what produced 40/40 and 42/42.
- **Suites** expand inside `--tests`:
  - `@core` is exactly today's default string, which also stays the default. A native test pins it.
  - `@tex11` is the two 11-12 texture lists (`ONBOX/README.md` runs 11 and 12).
  - `@g74` (§5.1), `@whole` (the whole-target checks) and `@known` (§5.2).
  - `@Gnn` is every implemented test owned by Gnn. `@all` is everything implemented.
- **The list is validated before `Direct3DCreate8`, on the heap, at any length.**
  - An unknown name ends the run with `RESULT {"error":"unknown test mipdxt9"}` and rc 2. Nothing is created and
    nothing switches. That closes (a) and (b).
  - A planned name ends it the same way, naming the owner: `"zbias: planned by G22, not in this build"`.
- **A test that finished with no entry fails.** No check, no skip, no `na`: the framework adds
  `{"test":t,"error":"recorded no check","ok":0}`. That closes (c), and it covers every future test.
- **`--deadline S`.** Once S seconds of work have passed, the probe starts no new test. The tests left record
  `{"test":t,"not_run":"deadline"}`, which fails the run when the tests were named. The probe then releases its
  device through the paced path. The runner sets S below the EXECW's work budget, so the agent's tree kill, which
  reverts a fullscreen mode unpaced, can no longer land on a slow suite.

### 3.2 Outcomes: a known gap is not a new defect

This generalizes G12 §5.1's cell framework, with its `legacy` column, its self-check and its negative control, to
every domain.

| outcome | meaning | counted as |
|---|---|---|
| `ok` | the pixel is D3D's answer, within tolerance | pass |
| `xfail` | the pixel is the value a recorded gap predicts (`legacy`), and that gap is not declared fixed | not a failure; listed with the gap id |
| `fail` | anything else: a new defect, a wrong analysis, an armed fix that did not take | failure |
| `skip` | the HAL does not offer what the check needs (today's meaning) | a failure only when named, as today |
| `na` | the check cannot apply to this runtime or mode, and no HAL code is involved (a DEFAULT-pool lock under D3D8, `present` fullscreen) | never a failure |
| `note` | measured, no verdict (classification checks; a legacy value not yet measured) | never a failure |

- **The cell record** holds `want` (from the reference headers, §3.3), `legacy` (the prediction from the owning gap's
  design), `gap`, `tol16`/`tol32` and its layout: up to 64 cells, 24x24 quads on a 32x32 pitch, as in G12.
- **`dp_classify(cell, got, mode)`** lives in `d3dprobe_core.h`:
  - got ≈ want → `ok`;
  - got ≈ legacy → `xfail`, or `fail` when the gap is listed in `--fixed`;
  - otherwise → `fail`.
  - `--expect legacy` is G12's negative control: every discriminating cell must read its legacy value. It is run once
    on the deployed build when a test lands, to prove that the test sees the defect.
- **Self-check at start-up (G12's rule).** Every cell with a legacy value must differ from `want` by at least 3 × its
  tolerance in some channel. Otherwise the test is refused as a probe bug. The host test checks the same rule on the
  static tables.
- **A scenario-level legacy.** `--legacy-model clears-only:G01` gives every check in the run the legacy value "this
  frame's clear colour". The stale-FIFO scenario (§5.4) uses it, so a run with every triangle missing reads as
  `xfail G01`, not as 30 unrelated failures.
- **Reporting.**
  - Every entry gains `"outcome"`. Its `"ok"` keeps today's meaning (= D3D's answer), so an `xfail` entry is
    `"ok":0,"outcome":"xfail"`.
  - The summary keeps `pass`/`fail`/`skipped`, and `fail` excludes `xfail`, so every consumer of `fail` and rc
    (`silicon_battery.py`) stays correct.
  - It adds `xfail`, `na` and `notes`, and `gap_closed`: the gaps all of whose cells read `want` although nobody
    declared them fixed. That one means "the fix is live; flip the expectation". It is reported, not failed.

### 3.3 Reference values: `KMD/include/vcr_d3dref.h`

A Win32-free header, compiled into the probe and into the native test, so the on-box expectations and the host
assertions are one code. G12 §5.1 already puts its `vcr_texop_ref.h` (the texture-op formulas) in `KMD/include/`.
This one sits beside it.

- **What D3D does:**
  - `vcr_ref_q565/q1555/q4444` (quantize and expand exactly as `expand()` reads back);
  - `vcr_ref_blend` (every D3DBLEND factor, BOTH*, SRCALPHASAT, a target with or without alpha);
  - `vcr_ref_cmp` (Z and alpha functions);
  - `vcr_ref_fog_linear/exp/exp2` (W-based, as the existing `fogtable` check);
  - `vcr_ref_addr` (WRAP, CLAMP, MIRROR);
  - `vcr_ref_bilinear` with three named texel-centre models (D3D, +0.5, -0.5), for G81;
  - `vcr_ref_covers` (the top-left fill rule at D3D8's integer pixel centres);
  - `vcr_ref_d16` (`round(z × 65535)`, the HAL's own Z scale, `vcrdd_3d.c:153`, `:292`);
  - `vcr_ref_cell_rgb` (the whole-target pattern, §10).
- **What today's HAL draws:** `vcr_legacy_*`, each citing the `vcrdd_d3d.c` line it models.
  - MIRROR → WRAP (`tex_view` `:792-795`);
  - ZENABLE USEW → depth off (`:986`);
  - SRCCOLOR as a source factor and DESTCOLOR as a destination factor → ONE (`:630-663`).
  - These supply the `legacy` predictions of the cells the owners land (§5.2). G77 can later check them against the
    real translation functions on the host.
- **A Python test pins that no driver source includes `vcr_d3dref.h`, `vcr_texop_ref.h` or `d3dprobe_core.h`.**
  They are probe and test code.

### 3.4 Readback: any window, the whole target, alpha, Z, never stale

- **`readback_rect(x0, y0, w, h)`** makes the lock today's runs make: `LockRect(NULL, READONLY)` on the back buffer.
  - It then copies only the rectangle, one `memcpy` a row into system memory before `expand()`. That means fewer
    uncached reads over the PCI bridge, and the same values.
  - The buffer is on the heap, `W × H` entries of `0xAARRGGBB`. Alpha is kept for surfaces that have it: G28's
    `alphachan_rt` and G36's render targets read it. The X byte is masked, as today.
- **`readback()`, which every existing test calls, is `readback_rect(g_ox, g_oy, 256, 256)`.** At origin (0,0) that is
  byte for byte today's read.
- **`readback_full()`** serves the whole-target checks.
- **`readback_surface(surf, rect)`** reads any lockable surface:
  - a lockable render target (`CreateRenderTarget(..., Lockable TRUE)`);
  - the depth buffer when it is `D3DFMT_D16_LOCKABLE`, which gives exact Z values (`zread`, §5.1). runtime-27 §4.3:
    the PCI-id table grants a lockable D16 (inferred until `caps` prints it);
  - the image surface `GetFrontBuffer` fills (`presentfs`).
- **`px(x, y)` takes target coordinates.** A pixel outside the last rectangle read sets an error, and the `expect()`
  is `fail "outside the readback"`. It is never a compare against stale memory.
- **Frame validity.** `frame_end()` records whether the readback worked. An `expect()` on a frame whose lock failed
  is `fail "no readback"`. That closes (d).
- **Whole-target comparison: `cmp_region(rect, ref_fn, tol)`.** It produces ONE entry: `of`, `bad`, `bbox`, the first
  8 bad pixels, and up to 16 bad **row runs** and **column runs**. An SLI band, a 2-pixel column pair, a pitch error
  and a lost bottom half each leave a different run signature (G50, G51).
- **Dumps.** `--dump N` (default 4, 0 = off): the first N failing tests write their rectangle as a 24-bit BMP,
  `C:\vcr\d3dprobe\dump_<n>_<test>.bmp`. The runner's `--dumps` fetches them with `DOWNLOAD` and saves PNGs. A locked
  back buffer is the one fullscreen frame no GDI capture can give (onbox-11: GDI frames can be the back buffer or
  stale).
- **Cost.** A 1280x960x16 frame is 2.4 MB of uncached reads (inferred: well under a second). Every whole-target entry
  records `read_ms`, so phase A measures it.

### 3.5 Scene helpers

- **`--origin tl|br|c|X,Y`** (fullscreen or `--wsize` only):
  - every helper (`quad_c`, `quad_t`, `quad_t2`, `quad_fog`, `quad_uv`) adds `g_ox, g_oy`, and so does `expect()`;
  - at (0,0) every coordinate is today's;
  - `--origin br` reruns any 256x256 test at the far corner: pitch, the Z rows past 256, the far part of the target.
    This is G57's `readback_at`.
- **`--wsize WxH`** (windowed) uses a borderless window of that client size. A windowed device makes no mode switch,
  so the whole-target checks run at 1024x768x32 without touching the CRT. 16 bpp still needs `--full`, because the
  desktop is 32 bpp.
- **Baseline state.** Every NEW test starts from one baseline:
  - Z off, cull none, dither off;
  - blend, alpha test and fog off;
  - stage 0 SELECTARG1(DIFFUSE), stage 1 DISABLE, TFACTOR white, textures NULL;
  - CLIPPING TRUE, LIGHTING FALSE.

  The historical tests get no baseline between them, so their DP2 stream stays as it is.
- **Geometry paths.**
  - `quad_t2s`, two texture sets with a repeat each (G06 asks for it);
  - vertex and index buffers (MANAGED and DEFAULT, `WRITEONLY`), `DrawPrimitive`, `DrawIndexedPrimitive` and
    `DrawIndexedPrimitiveUP`;
  - an untransformed-XYZ path with identity world/view/projection, which is the software pipeline UE2 and Halo take
    (G57 `gbxyz`);
  - an A/B panel compare (G49: the same mesh as strips and as lists, which must read identical).
- **Placement control.** `spacers(bytes[], n)` creates DEFAULT-pool single-level textures. They are placed at
  creation and never locked.
  - `PreLoad()` places a MANAGED texture at once, so the order of placements is the test's.
  - The probe cannot read a texture's address itself. `--ring` takes it from the driver: event 513/20 "chain placed"
    at LogLevel 3, the level `.124` runs, and 513/23 for each new combine.

### 3.6 One paced device helper, and windowed devices per test

- **Every device creation goes through one `create_device(pp)`.** It is paced when fullscreen, as `main` does today
  (`:1464-1476`), and release keeps going through `release_device()` (`:194-204`).
  - Windowed creates switch nothing and are only logged.
  - **The monitor-safety pin changes deliberately in the same commit:** `IDirect3D8_CreateDevice` from "only in
    `main`" to "only in `create_device`" (`test_vcr_kmd_monitor_safety.py:386`), and `test_vcr_kmd_d3d.py:676`'s
    ordering assertion moves to `create_device(`.
  - The intent of those pins, one paced site per switch, is kept, and `IDirect3DDevice8_Reset` stays forbidden
    (`:387`). G43's `lost` mode will need a paced `reset_device()` and its own pin change.
- **`--device-per-test` (windowed only)** gives each test its own context, and with it its own `context N gone`
  totals in the ring. Once G76 lands, that includes its per-opcode counters, so a test can prove that the HAL path it
  claims was taken: `vcrdd_d3d.c:1210-1221` today counts DP2s, triangles, clears, unparsed commands and texture
  flushes.
  - **Fullscreen never gets more than one device per run:** each device would be two more CRT re-syncs.

- **The buffer grows** (doubling, `_vsnprintf` retried until it fits). If the memory runs out: `json_overflow: true`
  plus an `error`, never a truncated line. Today's keys keep their names and types.
- **`diag`** is read with `KEY_READ` from `HKLM\SYSTEM\CurrentControlSet\Services\vcrmp\Diag` (G15 §7.3 does the same
  for `D3DFeat`). It is what the registry says now. With `--ring`, the runner checks it against the boot's armed
  events (513/16-18), which say what the driver actually armed.
- **`opened_hz`** is `GetDisplayMode` after `CreateDevice`.

### 3.8 The `*_def` tests

- **With `D3DCAPS2_DYNAMICTEXTURES` in Caps2:** create the texture with `D3DUSAGE_DYNAMIC` and run the test for real.
  That is G94's DX8 DDI, if it ever comes.
- **Otherwise:** `na` "D3D8 locks a DEFAULT-pool texture only with D3DUSAGE_DYNAMIC; this DX7-DDI HAL has no
  DYNAMICTEXTURES". The VRAM copy of a DEFAULT texture is already checked by `*_upd` and `*_copy`.
- **New `def_lock`:** LockRect on a non-dynamic DEFAULT texture must return `D3DERR_INVALIDCALL`. The refusal is the
  runtime's, recorded as a fact (`ok`). If it ever succeeds, someone should look.
- **Result:** run 12 of 11-12 reads 37 pass / 0 fail / 3 na instead of 37/3.

### 3.9 The runner: `d3dprobe_run.py`

| change | why |

### 5.4 The after-Glide scenario (G01's E1, on this item's plumbing)

`d3dprobe_run.py --before glide-abandon --attended` does the following:

1. Runs `glidelab_run.py <host> abandon` (open, draw, exit with no close: `glidelab.c:34`), paced at 5 s.
2. Reads `vcrctl reg 80024` and `80020` (read-only, chip 0). **If `cmdFifo0.baseSize` bit 8 is clear, the scenario
   did not reproduce.** The run ends as an error, never a pass.
3. Runs the probe **fullscreen only, at 1024x768x32**. 11-12 placed that mode's surfaces at `0x300000` and above,
   outside the stale window `0x18000-0x117000`, whereas the windowed device's surfaces landed inside it and cost the
   2D engine and the HAL (onbox-02). It uses `--legacy-model clears-only:G01`.
4. Runs `--ring`. A surface placed inside the window read in step 2 is flagged as a 2D give-up risk.
5. Runs `vcrctl reset-engine` (`VcrHwResetEngine`, `miniport/vcrmp_hw.c:181-201`: stops the FIFO fetch, resets
   the engine, no mode switch). It is the same reset the miniport runs at a busy mode set, which `KMD/README.md:721-725`
   records on silicon with the desktop intact. The on-demand escape itself has no run on record, so its first use is
   attended. It then reads `80024` again and fails the cleanup unless it is 0.

**Expected before G01:** every triangle check `xfail G01`, every clear `ok`. **After G01:** 40/40.

## 6. Phase D: `perf --mode` (code owned here, modes specified by G46)

- **`--mode classic`** is today's scene and today's RESULT keys, and stays the default (`silicon_battery.py:256-258`

## 10. The d3dprobe test for this item: `wgrad` (with `selfcheck`)

- **What it draws:** the whole target, `--full` at its mode or `--wsize` windowed, as a grid of 32x32 cells. Each cell
  is one flat untextured quad (two triangles) at integer pixel coordinates, so with D3D8's integer pixel centres and
  the top-left rule every pixel belongs to exactly one cell.
  - The frame is cleared to `0xff00ff` first. No cell can have that colour at 63 columns or fewer, so a missing
    triangle shows as the clear.
  - Z, dither, blend and fog are off.
- **Reference:** `vcr_ref_cell_rgb(cx, cy)`: R5 = `cx & 31`, G6 = `cy & 63`, B5 = `((cx >> 5) & 1) << 4 |
  ((cx ^ cy) & 15)`, expanded as `expand()` expands 565.
  - The values are 565-exact, so a 32 bpp target reads them exactly too.
  - Example: cell (39, 29) is **`0x3975d6`**; cell (0, 0) is `0x000000`.
- **Pass criterion:** **0 mismatched pixels over the whole target** (tolerance 0, dither off). The entry gives `of`,
  `bad`, `bbox`, the first 8 bad pixels, and the bad row/column runs.
- **Old-buggy value (the tool's own):** the 256x256 window can see 64 of 1,200 cells at 1280x960 (5.3 %), and 64 of
  768 at 1024x768. The new readback sees all of them. The native test asserts both numbers.
- **Where it pays:**
  - G51's SLI (each chip's bands);
  - G50's column band;
  - G10/G69's Z storage, through its sibling `wz`;
  - G57's edges;
  - the 16-over-32 strip that is today's only evidence for Rainbow Six (G69).
- **`selfcheck`** (§5.1) runs at the start of every non-default suite. A framework that can only say "ok" is the
  failure this project keeps paying for. It must show `fail` for a planted wrong value, and `xfail` for a planted
  legacy value, before anything else is believed.

## 13. Risks

| risk | to | mitigation |
|---|---|---|
| more mode switches on a 1998 CRT | the monitor | pace ≥ 5 s by default with the budget to match; whole-target work runs windowed through `--wsize`; several tests and perf modes share one device; exact `--hz` gating; the refused-pair guard removes the one known **unpaced** double switch the probe could cause |
| the after-Glide scenario breaks D3D until reset | the box's 2D and D3D for that PDEV | attended only; fullscreen at a mode whose surfaces sit above the stale window; the window is read first; `reset-engine` (no switch) after, with a read-back; never windowed (onbox-02's 2D give-up) |
| whole-target reads are slow over the PCI bridge | run time | `read_ms` measured in phase A; `--deadline` keeps a slow suite off the agent's tree kill |
| spacers and VB/IB use video memory and handles (G42: 4096 entries) | the probe's own run | small counts, released in reverse, never across tests |
| a `--ring` fetch is an escape | D3D under a held device | only after the probe has exited (onbox-11, `KMD/README.md:156`) |
| `GetFrontBuffer` and `zread` lock the primary and the Z on a HAL that drains the engine at every lock (G56) | timing only | correctness checks, never timed |
| pins move (the monitor-safety CreateDevice site) | review | the same intent, one paced site; changed in the same commit with the reason |
| the default 16 bpp path, Glide/OpenGL coexistence, SLI state, the flip path | - | **untouched**: no driver code changes. The probe's perf `--novsync` uses the FLIPNOVSYNC path `silicon_battery`'s d3dperf already uses |
| a C2 `xfail` cell is wrong about the old value | an owner's design | that is the point: it is caught on the deployed build before the fix exists, not after |

## 15. Open questions

1. Does XP's D3D8 runtime clip XYZRHW geometry that crosses the viewport (no `D3DPMISCCAPS_CLIPTLVERTS`), and send the
   result as TRIANGLEFAN_IMM? It matters for `clipfan`, `vbib` and G57. G76's counters answer it, or a single-test
   windowed run with `--ring` once 513 per-opcode counters exist.
2. Is `D3DFMT_D16_LOCKABLE` offered, and does our DdLock on a Z surface return D3D's D16 layout? Runtime-27 §4.3 infers
   the lockable D16 from the PCI-id table. **Cross-item:** G10's 32-bit storage of a D16 at 32 bpp would hand a locked
   D16_LOCKABLE 32-bit rows. `zread` at 32 bpp after G10 detects that, and G10 should decide it.
3. A per-test ring mark (`VCR_ESC_LOG_MARK`, `vcrctl mark`) from the probe's own thread, between tests, holding no
   lock: is it safe while its own device is up? The rule against escapes comes from another process parking behind a
   game that holds the display lock (`KMD/README.md:156`). Default **off** (`--marks`); try it on the bed, then once on
   `.124` attended. Without it, fullscreen tests are told apart in the ring by texture shapes, and windowed ones by
   `--device-per-test`.
4. Can D3D8 give a DX7-DDI driver dynamic textures? Expected no, so the `*_def` checks are `na`. `caps` Caps2 says.
5. How long does a whole-target read take on `.124`? Phase A measures it (`read_ms`).
6. Which reference box is powered for step 0? The fleet is powered on demand, and the cards move.
7. Should `--pace 5000` be the default on every real box (LCD boxes included)? It is harmless, and the rule exists for
   `.124`'s CRT. This design says yes, for one rule everywhere.
8. Does `glidelab abandon` leave `cmdFifo0` on deterministically, or only sometimes (G01 E1)? §5.4 refuses to call a
   run that did not reproduce it a pass, either way.
9. Phase E: does the D3D9 runtime forward D3D9 sampler states for stage 1 to a DX7 driver as DP2 TSS exactly as D3D8
   does? Inferred from runtime-27 §3. `@core` through `--api 9` answers it on the first run.
