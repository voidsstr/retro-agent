# G53: register shadows for the D3D HAL (`Diag\D3DShadow`), design

**Gap.** The full state and render target are re-sent at the first triangle of every DrawPrimitives2 call
and on every change, and no register is shadowed (perf-08).

**Lane:** clean-room (`vcr-kmd`, our DX7-level NT D3D HAL in `vcrdd.dll`). This is a design only. Nothing
was edited, built or deployed, and no fleet box was contacted.

## 0. Verdict

- **The gap is real, exactly as stated.** At the first triangle of every DP2 call, and after every state change,
  `prepare()` reruns `compute_regs()` and re-sends the whole target and state. That is 15-26 uncached writes and
  2-4 status reads. Only the fog table is cached.
- **It is worse than the write count suggests.** 11 of those writes at 16 bpp, and 13 at 32 bpp, are SPEC
  "sync" registers: *"the graphics processor will flush the data pipeline before loading the register"*
  (SPEC L2225). So every DP2 call and every texture bind also drains the pixel pipeline, even when nothing
  changed.
- **It is not a large share of today's frame times.** The triangle path dominates (G47/G48/G49): UT2003's
  flyby spends 116.7 ms of a 123 ms frame in DrawPrimitive at ~18,500 triangles per frame. From the rings,
  re-sends cost roughly 0.2-0.5 ms per frame (inferred, §1.3). The share grows several-fold once the triangle
  path is fixed, and the drains matter more once a command FIFO lets the CPU run ahead.
- **The fix, `Diag\D3DShadow`, default OFF:**
  - **Bit 0 (skip).** A per-PDEV, **write-through record of what chip 0's 3D registers hold**. Every state
    write the HAL makes is recorded by any writer: target, state, clear, texture flush. The target/state
    emission then skips every write whose value the chip already holds.
  - The record is **forgotten** at every event that may let something else write the chip. Those are G41's
    fog-cache forget points, plus a Reset3D's end, an SLI/AA request, a 2D give-up and engine init (§3.6).
  - A PDEV that ever granted a Glide register mapping **never skips**.
  - Texture binds mark the context dirty only when the handle changes.
  - **Bit 1 (audit).** Today's register traffic, unchanged, plus a read-back of the 15 readable state registers
    against the record at every DP2/Clear2 call. It proves the record on silicon before anything relies on it.
- **Why a value record rather than the vendor's per-group dirty flags.**
  - The vendor needs a hand-kept list of "who clobbers what". Examples: `SC_TEXTUREFACTOR` after a fastfill
    (`VH5/D7DP2.C:744-745`) and `_D3(last).changed` (`:612`, `:979`).
  - Four other designs here already carry such constraints for G53: clears clobber `c1` (G14), `zaColor`
    (G22) and stencil (G35), and Glide clears the tLOD mirror bits (G33).
  - A write-through record satisfies all of them by construction, and keeps interleaved contexts correct
    (hal.md §8) because it describes the chip, not a context.
- **Not safe default-on.** It changes the register traffic of every D3D draw, and the TMU half of the record is
  write-only, so it cannot be read back.
- **Effort M. Priority P2:** a measurable gain, small in today's games, and the building block G03 §2.9 and
  G47 (state in packets) need. **Dependency: G41** (one shared forget hook). **Unblocks no title.**

## 1. What the code does today

### 1.1 The re-send path

| step | where | what |
|---|---|---|
| every DP2 call starts unprepared | `KMD/display/vcrdd_d3d.c:1835` (`memset(&w, 0, sizeof w)`) | `w.prepared = 0` |
| first triangle | `prepare()` `:1322-1365` | `if (w->prepared && !c->dirty) return TRUE;` (`:1335-1336`) fails, so `compute_regs(c)` (`:1337`), then `VcrDd3dTarget` + `VcrDd3dState` (`:1361`) |
| `compute_regs` | `:921-1029` | 2 `handle_get` hash lookups (`:924-925`), `view_of` → `vcr_texlod_compute` + a mip-chain walk (`:754-844`), `color_path`, `log_combo` (hash + scan of up to 64, `:882-919`, called `:1027`) |
| TEXTUREHANDLE | `set_rs` `:1393-1406` | `c->tex_handle = v` and `dirty = 1` **unconditionally** |
| TSS TEXTUREMAP | `:1600-1604` | `*th = v; c->dirty = 1;` **unconditionally**, plus a DEBUG event (`:1603`, G52) |
| any other RS/TSS | `:1402-1405`, `:1605-1608` | dirty only on a changed value (already filtered) |
| DP2 CLEAR / Clear2 | `clear_rects` `:1408-1421` | `VcrDd3dTarget` (full target), `VcrDd3dClear`, then `c->dirty = 1; w->prepared = 0;` |
| Clear2 | `:1873-1906` | `clear_rects` once **per rectangle** (`:1890-1899`), so the target is re-sent per rectangle |
| SETRENDERTARGET | `:1725-1752` | `dirty = 1; prepared = 0` (`:1741-1742`) |
| texture written | `prepare()` `:1327-1334` | flush (`VcrDd3dTexFlush`), then `prepared = 0` ("the flush moved texBaseAddr") |

### 1.2 One re-send, write by write (`KMD/display/vcrdd_3d.c`)

| part | writes | status reads | SPEC sync registers among them |
|---|---|---|---|
| `VcrDd3dTarget` (`:45-70`, sequence `KMD/include/vcr_3dseq.h:56-78`) | 6 Banshee/V3; 7 VSA-100 16 bpp; 9 at 32 bpp (+stencilMode/Op) | 1 (`VcrDdRoom(n > 7 ? n : 7)`, `:64`) | renderMode, (stencilMode, stencilOp), colBufferAddr, colBufferStride, auxBufferAddr, auxBufferStride, clipLeftRight, clipBottomTop: 7 / 9 (SPEC L2306-2339) |
| `VcrDd3dState` FBI part (`:76-85`) | 8: fbzColorPath, fbzMode, alphaMode, fogMode, fogColor, c0, c1, sSetupMode | 1 (`VcrDdRoom(12)`) | fbzMode, fogColor, color0, color1: 4 (SPEC L2306, L2314, L2320-2321) |
| fog table (`:86-101`) | 32, only on a new key (the one existing shadow) | 5 | fogTable: yes |
| compressed nop (`:102-112`) | 1 broadcast `nopCMD`, on every state write of a DXT texture | 1 | yes |
| TMU0 (`:113-118`) / TMU1 (`:119-126`) | 4 / 4: textureMode, tLOD, tDetail = 0, texBaseAddr | 0 / 1 | none (SPEC L2380-2383: "No") |

**Totals per re-send** (no fog reload):

| case | writes | status reads | sync writes |
|---|---|---|---|
| untextured, 16 bpp | 15 | 2 | 11 |
| one texture, 16 bpp | 19 | 2 | 11 |
| two textures, 32 bpp | 25 | 3 | 13 |
| two textures, 32 bpp, DXT | 26 | 4 | 14 |

The gap's "about 19-30 uncached writes and 2-4 status reads" is right in shape: 15-26 writes without a fog
reload (58 with one), and 2-4 reads.

**Sync means a pipeline flush.** SPEC L2225: *"The sync column indicates whether the graphics processor must
wait for the current command to finish before loading a particular register from the FIFO. A 'yes' ... will
flush the data pipeline before loading the register."* A pure texture bind changes only TMU registers (all
"No"), yet today it drains the pipeline up to 11-13 times in a row.

### 1.3 How much it costs today (inferred, from the rings of 2026-11-12)

The cost model is perf report §4.1 (inferred): t_w ≈ 45-150 ns per uncached write, t_r ≈ 1 µs per status read.

- **Per re-send (one texture, 16 bpp):** 19 × t_w + 2 × t_r ≈ **2.9-4.9 µs**, plus the drains and ~0.5-1.5 µs of `compute_regs` (inferred).
- **DP2 calls per frame** (`ctx gone` lines, `ONBOX/session_log.md`):

  | session | DP2 calls | frames | per frame |
  |---|---|---|---|
  | UT2003 flyby | 59,589 | 1,998 | 29.8 |
  | UT2004 botmatch | 26,145 | 1,069 clears | 24.5 per clear |
  | Halo timedemo | 32,670 | 764 clears | 42.8 per clear |

- **State changes per frame:** not counted anywhere. An upper bound comes from the ring's event rate, since the
  per-bind DEBUG event dominates D3D's ring traffic. Each count below also includes CreateSurfaceEx and loading
  events (inferred):

  | session | ring sequence span | events | per frame (or clear) |
  |---|---|---|---|
  | UT2003 flyby | 97,382 → 207,568 | ~110 K | ≲ 55 |
  | Halo timedemo | 207,568 → 306,116 | ~98.5 K | ≲ 129 |
  | UT2004 statfps | 306,116 → 323,653 | ~17.5 K | ≲ 42 |

- **Total:** about (30-43 + 42-129) × ~3 µs ≈ **0.2-0.5 ms per frame** (inferred). That is under 1% of UT2003's
  123 ms frame, but 2-10% of a 15-25 ms frame after G47-G49.
- The measured triangle density shows why it is small today: UT2003 runs ~620 triangles per DP2 call, and Halo
  ~800 (`26,070,025 / 32,670`).

## 2. Vendor and Glide

### 2.1 3dfx's V5 HAL

- **Per-context group flags.**
  - `hwStateChanged` with `SC_SOMETHING`, `SC_TEXTUREFACTOR`, `SC_ZBIAS`, `SC_FOG`, `SC_BUFFERS`,
    `SC_ALPHABLEND`, … (`VH5/D3GLOBAL.H:1166-1196`).
  - State is written only `if (HW_STATE_CHANGED)` (`VH5/D6DP2.C:1871-1873`) and cleared after
    (`RESET_HW_STATE`, `:7278`).
  - Consecutive DP2 calls with no change write no state at all.
- **A shadow of the chip, `_D3(last)`.** The buffer address and clip are compared before they are written
  (`bufferStateSetup`, `VH5/D6DP2.C:5010-5071`, compare at `:5029-5031`), and the last FBI values are saved at
  `:7050-7069`.
- **`lastContext`.** A different context forces fog, TFACTOR, Z bias and a NOP (`:6373-6386`).
- **Who resets `lastContext`:**
  - Glide execution (`VH5/HWCEXT.C:1302-1310`);
  - 3D-app enter and exit, "since we may have entered SLI mode" (`VH5/DDFXNT.C:2446-2449`, `:2498-2501`);
  - SetRenderTarget (`VH5/D7DP2.C:138`);
  - context destroy (`VH5/D3CONTXT.C:598-603`).
- **The clear clobbers are kept by hand:**
  - FastFill sets `_D3(last).changed = TRUE` (`VH5/D7DP2.C:612`, `:979`), and the next draw re-writes the four
    FBI registers, combineMode, renderMode, stencil and chromaKey from `last` (`VH5/D6DP2.C:7189-7275`);
  - `c1` is restored only because FastFill also raises `SC_TEXTUREFACTOR` ("This flag only needs to be set if
    TMU0/1 color1 reg changes", `VH5/D7DP2.C:744-745`);
  - `zaColor` is restored by hand at the end of each clear (`:604-610`, `:971-977`).
- **Lesson (G95):** precedent that skipping identical state writes, buffer-address writes included, is fine on
  this silicon with D3D and DirectDraw mixed. **Do not copy the bookkeeping.** Every new writer must remember
  which flag to raise, and one forgotten flag is a silent wrong colour.

### 2.2 Our h5 Glide

- **Invalid-bit groups validated lazily** (`GL5/glide3/src/fxglide.h:2811-2819` `INVALIDATE`;
  `GL5/glide3/src/distate.c:1889`, `_grValidateState`), written "in register order" (`:1917`).
- **Two transition rules judged against its own shadow:**
  - a `nopCMD` on a texture-enable change (`distate.c:2006-2011`);
  - a TMU idle on a switch **to** a compressed texture only:
    `(texMode ^ oldTexMode) & SST_COMPRESSED_TEXTURES & texMode` (`GL5/glide3/src/gtex.c:2978-2983`).
- **The HAL today:**
  - sends the compressed nop before **every** state write of a DXT texture, a superset of Glide's rule;
  - never sends the texture-enable nop.
  - G53 keeps both behaviours (§3.4); the record makes Glide's exact rules cheap to adopt later (§10 Q7).

## 3. Design

### 3.1 Model

- **One record per PDEV, of chip 0** (`VCR_PDEV.sh`), not per context.
- **Updated on every store the HAL issues to a recorded register, by every writer:**
  - `VcrDd3dTarget`, `VcrDd3dState`, `VcrDd3dClear`, `VcrDd3dTexFlush`;
  - later G03's baseline, G22's zaColor, G35's stencil and G12's combineMode.
- **Skipping happens in only two places: the target and state emissions.**
  - Clears, flushes and commands are always written.
  - A store issued is a store recorded. A give-up stops both.
- **Zeroed when the PDEV is born** (`EngAllocMem(FL_ZERO_MEMORY)`, `vcrdd.c:397`): nothing known.
  - XP builds a new PDEV at every mode change, and every Glide session runs on a PDEV of its own (G41 §2,
    Facts 1-2). So the common cross-API cases start empty by construction.
- **Locking:** DP2, Clear2, DrvEscape and DrvAssertMode on a PDEV are serialised by the display device lock, so
  the record needs no lock of its own (inferred from the DDI contract; G04 already treats escapes as lock
  holders).

### 3.2 `KMD/include/vcr_3dshadow.h` (new; Win32-free, host-tested)

```c
#include "vcr_types.h"
#include "vcr_3dregs.h"
#include "vcr_3dseq.h"                  /* vcr_regw */

#define VCR_SH_SKIP     1u              /* Diag\D3DShadow bit 0 */
#define VCR_SH_AUDIT    2u              /* Diag\D3DShadow bit 1 */

/* which units keep a copy (SPEC L2225-2383, "Chip" column) */
#define VCR_SHK_FBI     1u              /* "FBI": taken from chip field 0 or FBI */
#define VCR_SHK_ALL     2u              /* "FBI+TREX%": every unit takes every write: one copy */
#define VCR_SHK_TMU     3u              /* "TREX*": one copy per TMU by chip field (0 = both) */
#define VCR_CF_MASK     0x3c00u         /* address bits 13:10 (vcr_3dregs.h:9-11) */
#define VCR_CF_FBI      0x0400u
#define VCR_CF_TMU0     0x0800u         /* V3D_TMU0 */
#define VCR_CF_TMU1     0x1000u         /* V3D_TMU1 */

typedef struct vcr_3dsh {
    vcr_u32 val[32];                    /* 26 used today; G03/G12 grow it to 64, `known` to 2 words */
    vcr_u32 known;                      /* bit s: val[s] is what chip 0 holds */
    vcr_u32 tainted;                    /* this PDEV granted a Glide mapping: never skip again */
    vcr_u32 twoppc;                     /* a TMU's combineMode[29] last written 1: SPEC L6236 mirror */
    vcr_u32 barrier;                    /* a DP2/Clear2 call began: its first target write is made */
    vcr_u32 written, skipped, forgets, last_why;
    vcr_u32 audits, audit_bad, audit_logged;
} vcr_3dsh;

static __inline vcr_u32 vcr_sh_slots(vcr_u32 off, vcr_u32 twoppc); /* slots a write reaches; 0 = not recorded */
static __inline void     vcr_sh_note(vcr_3dsh *s, vcr_u32 off, vcr_u32 v);   /* a store WAS issued */
static __inline int      vcr_sh_need(const vcr_3dsh *s, vcr_u32 off, vcr_u32 v);
static __inline unsigned vcr_sh_filter(const vcr_3dsh *s, const vcr_regw *in, unsigned n,
                                       vcr_regw *out);                     /* order kept */
static __inline void     vcr_sh_forget(vcr_3dsh *s, vcr_u32 why);         /* known = 0 */
static __inline void     vcr_sh_taint(vcr_3dsh *s, vcr_u32 why);          /* forget + tainted = 1 */
static __inline int      vcr_sh_audit(vcr_3dsh *s, unsigned slot, vcr_u32 chip); /* 1: mismatch, slot forgotten */
```

**The rules:**
- **`need`.** A write is needed when the PDEV is tainted, when any slot it reaches is unknown or holds another
  value, or when it reaches no slot at all.
- **`note`.** Each reached slot gets the value and its known bit.
- **Only the table below is ever recorded or skipped.** Everything else is "needed, not recorded": commands
  (nopCMD, fastfillCMD, swapbufferCMD, sBeginTriCMD, sDrawTriCMD, triangleCMD), the vertex and parameter
  registers, and the fog table, which keeps G41's keyed cache.
- **The slot map is a switch on the offset** (a jump table), not a scan.
- **2PPC (for G50).** While a TMU's last recorded combineMode has bit 29 set, a TMU0 or TMU1 write reaches both
  TMU slots. SPEC L6236: *"any write to either TMU unit will be received by both ... regardless of the chip
  field value"*. Until G50 adds combineMode to the table, `twoppc` stays 0.
- **chipMask (for G03).** A recorded chipMask without chip 0's bit forgets everything, because the chip then
  ignores the writes after it (`vcr_3dseq.h:87-100`).

**The table today** (`rmask` = what the audit compares; 0 = write-only, not audited):

|---|---|---|---|---|---|
| fbzColorPath | 0x104 | ALL | 0 | L2303 (R/W, No) | 0xffffffff |
| fogMode | 0x108 | FBI | 1 | L2304 (R/W, No) | 0x0000ffff |

### 3.3 The state sequence as data (`KMD/include/vcr_3dseq.h`)

- **`vcr3d_regs` moves here** from `KMD/display/vcrdd_3d.h:36-44`, with the same layout, its fields `vcr_u32`
  (G41 already changes `fog_table` that way). `vcrdd_3d.h` includes it.
- **Two pure builders, beside `vcr_3d_target_seq`:**
  - `vcr_3d_state_fbi_seq(r, w)`: the 8 FBI writes in today's order (`vcrdd_3d.c:78-85`);
  - `vcr_3d_state_tmu_seq(r, w)`: TMU0's 4 then TMU1's 4, each only when `textured`/`textured1`
    (`:113-126`).
- **Why:** they make today's emission host-testable, write for write. That is the emission half of G77, not
  `compute_regs`.

### 3.4 `KMD/display/vcrdd_3d.c`

**1. A recording writer.**

```c
/* a 3D STATE register: the same single store as w3(), then - with Diag\D3DShadow
 * armed (skip or audit) - the record learns it. Never for a vertex, a command or a
 * fog-table entry. */
static void w3r(VCR_PDEV *pd, ULONG off, ULONG v)
{
    *(volatile ULONG *)(pd->pjRegs + V3D_BASE + off) = v;
    if (pd->d3d_shadow)
        vcr_sh_note(&pd->sh, off, v);
}
```

- `VcrDd3dTarget`, `VcrDd3dState` (FBI and TMU writes), `VcrDd3dClear` (fbzMode, c1, zaColor, the clip writes)
  and `VcrDd3dTexFlush` (the three texBaseAddr writes) change `w3` → `w3r`.
- `vertex()`, `VcrDd3dTriangle`, `fastfillCMD`, `nopCMD`, the fog table and the 2D NOPs keep `w3`.
- With the switch off, every function issues the same stores in the same order. The extra branch is not taken.

**2. The flush is recorded as what it is.**
- `VcrDd3dTexFlush` writes texBaseAddr with **chip field 0** (`:259`, `:261`), so both TMUs take it, then TMU0
  alone (`:265`).
- The record therefore ends with **both** TMU slots = `base`.
- In two-stage mode the flush of stage 0's texture (TMU1's) leaves TMU0 pointing at it. The next emission sees
  TMU0's slot ≠ stage 1's base and re-writes it, which is exactly what today's `prepared = 0` full re-send buys.
  This is the most dangerous case in the design, and has its own tests (§5, §6).

**3. Shadowed branches, only with bit 0.** The proven bodies stay below the early `return`, text unchanged
except `w3` → `w3r`:

```c
BOOL VcrDd3dTarget(VCR_PDEV *pd, const vcr3d_target *t)
{
    if (pd->d3d_shadow & VCR_SH_SKIP)
        return target_sh(pd, t);
    ... today's body (vcr_3d_target_seq, VcrDdRoom(n > 7 ? n : 7), w3r) ...
}
BOOL VcrDd3dState(VCR_PDEV *pd, const vcr3d_regs *r)
{
    if (pd->d3d_shadow & VCR_SH_SKIP)
        return state_sh(pd, r);
    ... today's body ...
}
```

- **`target_sh`.**
  - `n = vcr_3d_target_seq(...)`; `n == 0` → FALSE (a refused format, as today).
  - `k = vcr_sh_filter(...)`.
  - **The call barrier:** if `pd->sh.barrier` is set, the sequence's **first** write (renderMode on a VSA-100,
    colBufferAddr on a Banshee/V3) goes out even when the record matches, and the flag is cleared.
  - Then `emit()`.
- **`state_sh`.**
  - The filtered FBI list.
  - The fog table, **unchanged** (G41's key rule).
  - The filtered TMU list. When it is non-empty and the new state is compressed (today's condition,
    `:107-108`), the `V3D_TMU0 + V3D_TMU1 + V3D_NOPCMD` nop goes out before it.
  - So the nop is sent whenever a compressed TMU state is **written**. That still covers Glide's transition rule:
    a switch to compressed always changes textureMode, so it is always written.
- **`emit()`.**
  - Reset3D's proven chunking: `(i & 7) == 0 && !VcrDdRoom(pd, k - i < 8 ? k - i : 8)` (`vcrdd_2d.c:418-422`).
    The typical k ≤ 4 costs one status read, and k = 0 costs none.
  - Then `w3r` each write; `g2d_busy = 1` only when k > 0; `sh.written += k`, `sh.skipped += n - k`.

**Why the call barrier.**
- At a call boundary, 2D, DirectDraw and GDI work may have run: a Blt into the back buffer, a windowed present.
- Today's first write of each call is renderMode, a sync register. Whether a 3D sync register also waits for an
  in-flight **2D** command is not established. SPEC §20.3 needs a 2D NOP to order the other direction
  (L6185-6188), and hal.md §8 already lists 3D→2D as a watch item.
- Keeping one sync write per call keeps the old path's ordering at the only points where 2D can interleave, for
  ~30-43 writes per frame. Dropping it needs Q3's experiment first.

**4. The audit (`vcrdd_2d.c`, beside the other register readers).**

```c
ULONG VcrDd3dAudit(VCR_PDEV *pd)            /* mismatches */
{
    if (!pd->g2d_ok) return 0;
    VcrDd2dSync(pd);                        /* reads see the FIFO's END state only when it is empty (SPEC L2225) */
    if (!pd->g2d_ok) return 0;
    for each table row with rmask != 0 whose slot is known:
        if (vcr_sh_audit(&pd->sh, slot, rd(pd, V3D_BASE + off)))
            once per slot per PDEV: VcrDd(VCR_LV_WARN, VCR_EV_DD_D3D, 46, off, chip, shadow,
                "shadow audit: reg %x chip %x record %x (last forget %u)", ...);
    pd->sh.audits++;
}
```

### 3.5 `KMD/display/vcrdd_d3d.c`

### 3.6 Forget points (`VcrDd3dForget(pd, why)`, inline in `vcrdd.h`)

**The hook.**
- `VcrDd3dForget = vcr_sh_forget(&pd->sh, why)` + G41's `VcrDdFogForget(pd, why)` (before G41:
  `pd->fog_valid = 0`). It touches only PDEV fields, never a register.
- The reasons extend G41's `VCR_FOGC_*`.
- One DEBUG line is written only when a known record is dropped (G41's 513/40, reworded to "3D state forgotten").

## 4. Gating

- **Default OFF.** `Diag\D3DShadow` absent or 0:
  - every D3D register write is byte-for-byte today's sequence, room checks included;
  - the shadowed branches are never entered, `w3r` records nothing, and binds stay unconditionally dirty.
- **Default-on, but CPU only:**
  - the forget calls (PDEV fields);
  - the per-context counters and their single 513/45 INFO line.
  - A Python test pins that no register write depends on them.
- **The values:**

  | value | register traffic | purpose |
  |---|---|---|
  | 2, audit | today's writes, unchanged; plus a sync and 15 register reads at every DP2/Clear2 call | proves the record |
  | 1, skip | only the writes chip 0 does not already hold, plus one barrier write per call | the performance mode |
  | 3 | both | skipping, audited |

  Read at boot. One Diag change per clean boot (§7).
- **Not safe to land default-on:**
  - it changes the register traffic of every D3D draw;
  - its correctness rests on the completeness of §3.6;
  - the TMU half is write-only.
- **Candidate for default-on later,** in its own commit, after boots A and B pass and normal play with value 3
  logs 0 audit mismatches.

## 5. d3dprobe tests (new; `KMD/tools/d3dprobe.c`, explicit `--tests`, not in the default gate)

**Common to all five:**
- each passes on **today's** driver, which keeps the invariants by brute force;
- each fails, with its own wrong colour, on a record that misses the case;
- each is run with D3DShadow 0, 2 and 1;
- each uses the existing analytic `expect()` (back-buffer `LockRect`, 256x256 window, `BB`/`Q0`/`Q1` at
  `d3dprobe.c:149-151`).

**`shadow_clear`: a clear clobbers c1, fbzMode and the clip.**
- Stage 0 colour and alpha = `SELECTARG1(TFACTOR)`, so the colour comes from `c1`. Vertex diffuse is magenta,
  which marks a lost colour path.
- Z on, LESSEQUAL, Z writes on.
- The draw sequence:

  | step | what | where | z | colour |
  |---|---|---|---|---|
  | 1 | TFACTOR blue, quad N | (32,160)-(128,224) | 0.25 | blue |
  | 2 | TFACTOR green, quad A | (32,32)-(224,96) | 0.5 | green |
  | 3 | `Clear(1 rect, TARGET)` | (96,112)-(160,144) | - | red |
  | 4 | quad B, **no state change** | (32,160)-(224,224) | 0.5 | (green) |

- Expect (tol 8):

  | point | what it checks | want |
  |---|---|---|
  | (64,64) | A | green |
  | (128,128) | the box | red |
  | (192,192) | `c1` restored | green (**red** = `c1` lost; **black** = clip left narrowed) |
  | (220,192) | the clip | green |
  | (64,192) | fbzMode restored (B fails Z) | blue (**green** = fbzMode lost) |
  | (128,104) | nothing spilled | black |
  | (8,8) | outside | black |

- `--noz` skips N and the (64,192) point.

**`shadow_flush0`: the flush's broadcast reaches TMU0.**
- Two stages, as `tex2mod` (`d3dprobe.c:1058-1096`): stage 0 A = checker(64, red, blue) on TMU1, stage 1
  G = solid grey 0x808080 on TMU0, MODULATE.
- Frame 1 draws the full quad: expect (tpx(4,64), tpx(4,64)) ≈ 0x840000, tol 14.
- Frame 2 **re-fills A in place** (LockRect level 0: a green/blue checker) with **no binding or state change**,
  then draws: expect ≈ 0x008200 (green × grey), tol 14.
- A record that ignores chip field 0 still believes TMU0 holds G's base and skips the write. The chip's TMU0
  keeps A's base from the flush, samples A', and the read is 0x00ff00.

**`shadow_flush1`: the mirror case, TMU1 restored.** Re-fill G with 0x404040 instead.
- Expect red × 0x42 ≈ 0x420000, tol 14.
- A miss gives G' × G' ≈ 0x111111.

**`shadow_bind`: binds in one call.**
- Single stage, MODULATE with white diffuse, point filtering, `quad_t(…, uv 0.25)`, so each 48-row band shows
  2×2 cells of 96×24 pixels. A = checker(64, red, blue), B = checker(64, green, yellow).
- Bands at y0 = 32, 80, 128, 176:

  | band | state | expect (tol 12) |
  |---|---|---|
  | 1 | bind A | (80,44) red, (176,44) blue |
  | 2 | bind B | (80,92) green, (176,92) yellow |
  | 3 | bind A | (80,140) red (**green** = TMU not rewritten) |
  | 4 | A stays bound, COLOROP `SELECTARG2(DIFFUSE)`, diffuse cyan | (80,188) 0x00ffff (**red** = an FBI-only change skipped) |

**`shadow_frames`: flips.** Meaningful with `--full`.
- No state call inside the loop.
- Three frames clear red, green and blue and draw the same white quad.
- Expect each frame's centre white and corner = its clear colour.
- A stale colBufferAddr draws into the buffer on screen, and the back buffer then reads the clear colour.

**Measurement mode: `d3dprobe perf --full --novsync --state none|tex|blend|z [--per-frame 500]`.**
- Each frame is Clear, then `per-frame` × (the change, then one 2x2-pixel triangle), then Present.
- The changes:
  - `tex`: alternate two 64x64 textures;
  - `blend`: toggle ALPHABLENDENABLE (alphaMode, no sync);
  - `z`: toggle ZWRITEENABLE (fbzMode, sync).
- The `none` phase runs first, for the same number of frames.
- `RESULT {"mode":"perf_state","change":…,"per_frame":…,"fps":…,"ms_frame":…,"ms_frame_none":…,"us_per_change":…}`.
- **Expected (inferred):** today ≈ 3-5 µs per change. With bit 0 ≈ 1-1.5 µs for `tex`/`blend`, and `z` slightly
  more (one sync write).
- The `z`/`blend` difference isolates a drain's cost (Q2).

**What proves it:**

## 8. Risk

| proven path | with the switch off | with it on |
|---|---|---|
| default 16 bpp D3D lane | none: byte-for-byte stores and room checks, pinned | fewer writes; covered by M at 16 bpp |
| D3D32 / BigTex lane | none | the same; the DXT nop now only when a TMU write follows (still ⊇ Glide's rule) |
| Glide/OpenGL coexistence | none (forget calls are CPU only) | Glide never runs on a D3D PDEV (G41 Facts 1-2); every Glide escape forgets; a mapped PDEV is tainted; boot A/B's Q3 step |
| SLI | none | none today (D3D is chip 0); G51 must forget around SLI |
| flip path | none | none: flips write no 3D register; the target is still read every call; `shadow_frames` |
| 2D / DirectDraw | none | the call barrier keeps the old first-write ordering per call |

**The real risks with it on, and their mitigations:**
1. **A writer the forget list misses.** Mitigated by boot A's audit and the classification test. The **TMU half
   cannot be audited**: covered by `shadow_flush0/1` and `shadow_bind`.
2. **A chip that does not take a write the HAL issued** (chipMask residue, a stale command FIFO). Then nothing
   draws today either; the record is forgotten at the mode set that cures it.
3. **G03/G12/G22/G35 land later and add registers.** The table is the deliberate entry point, with its native
   tests.

## 10. Open questions

1. **How many state flushes per frame do the staged titles make, and how many binds are redundant?** Boot 0's
   default-on 513/45 answers this before anything is armed. If binds_same is near 0 and flushes ≈ DP2 calls,
   G53's gain before G47 is the ~0.1 ms per frame of the DP2 starts.
2. **What does one sync-register write cost on a busy VSA-100 pipeline?** `perf --state z` against `blend`.
3. **Does a 3D sync register wait for an in-flight 2D blit?**
   - The experiment: a `shadow_blt3d` probe (CopyRects into the back buffer, then a blended quad over it, 50 per
     frame, read back) under an experimental bit that drops the call barrier.
   - If it never races in 10⁴ iterations, the barrier can go. Until then it stays.
4. **Do the R/W registers read back exactly?** The masks: renderMode bits 21-25 against the table's 20:0; the
   clip fields. Boot A's audit, or a constant XOR pattern in 513/46, says so.
5. **Is there any writer of chip 0's 3D block on a D3D PDEV beyond §3.6?** Boot A, across games, idle desktop and
   screensaver time.
6. **Does a GRX engine reset clear the 3D register file?** Irrelevant to correctness, since the record is
   forgotten at every reset. The audit cannot answer it, because the forget comes first. G02/G41's question is
   answered by a one-off supervised read of the R/W rows before and after `vcrctl reset-engine` on an idle
   desktop.
7. **Is Glide's texture-enable `nopCMD`** (`GL5/glide3/src/distate.c:2006-2011`), which the HAL has never sent,
   needed on silicon? G06's block noise is an unexplained texturing artifact. With the record, the exact
   transition (CP_TEXTURE flipping against the recorded fbzColorPath) is a one-line test. Not part of G53; a lead
   for G06.
8. **Does the D3D8 runtime filter redundant SetTexture before the DDI?** `binds_same` answers it.
