# G77: host tests that execute the Direct3D state-to-register translation

**Gap.** G77 (tooling, fixable). Source: `reports/history.md` §6.3 (history-43), with §5.4 and §6.1.

**Verdict.** The gap is real and fixable. The fix is a pure refactor plus a test harness.

- The translation moves out of the DDI file into Win32-free headers.
- A native test executes those headers on the host. It compares them, input for input, against the **verbatim source of the deployed build**, compiled on the host against a small fake DDI.
- A d3dprobe test (`statemap`) and a ring check prove on silicon that the box computes the same words the host test executes.

**Gating.** No register word, caps bit, Diag switch or event changes, so no switch is needed (§4). The work lands default-on once the host proofs hold. It is deployed to `.124` in one supervised clean boot.

**Priority P1.** It is the prerequisite for the old-versus-fixed regression tests of G05, G08, G09, G12-G15 and G22-G35.

**Effort L.** The core (steps 1-3) is M. The d3dprobe half (steps 4-5) is M.

## 0. Summary

1. **What exists.**
   - `test_vcr_kmd_d3d.py` and `test_vcr_kmd_bigtex.py` assert that particular lines of text exist. Examples:
     - `r->fbzColorPath = color_path(c, tex) | CP_PARMADJUST;` (`WT/tests/python/test_vcr_kmd_d3d.py:189-201`);
     - `if (c->target.z_on && c->rs[D3DRENDERSTATE_ZENABLE] == D3DZB_TRUE)` (`:422-424`);
     - `return pd->tex_ext ? tex_view_ext(...) : tex_view(...)` (`test_vcr_kmd_bigtex.py:78-85`).
   - Nothing executes `blend_src`/`blend_dst` (`:630-663`), `cmp` (`:665-668`), `color_path` (`:676-745`), `tex_view`/`tex_view_ext` (`:754-843`), `stage1_combine` (`:849-874`), `compute_regs` (`:921-1029`), `fvf_layout` (`:1254-1284`) or the binding half of `prepare` (`:1337-1363`).
   - The reason: `vcrdd_d3d.c` needs `vcrdd.h` (`windef.h`, `winddi.h`, `ntddvdeo.h`) and Microsoft's `d3dnthal.h`. That header is deliberately not committed (`WT/tests/python/test_vcr_kmd_ddraw.py:91-97`).
2. **What the fix is.**
   - Move today's translation, unchanged, into four Win32-free headers: `vcr_d3denum.h`, `vcr_cmb_legacy.h`, `vcr_blend.h` and `vcr_d3dstate.h`. These follow the pattern of `vcr_rtfmt.h`, `vcr_3dseq.h` and `vcr_texlod.h`.
   - The HAL keeps only surface lookups, logging and float calls. A Python guard forbids the HAL from composing a register word itself.
3. **How it is proven unchanged.**
   - **On the host:** the old functions are kept as a committed, **verbatim** slice of be58b7d's `vcrdd_d3d.c` (the oracle). It is compiled against a test-only fake DDI. A Python test re-derives that slice from git.
   - The native test asserts header == oracle over the whole input domain:
     - colour and alpha halves exhaustively;
     - 200k random whole states;
     - views, FVFs and binding.
   - It also reproduces the 34 set-ups the driver itself logged on silicon (Appendix A).
   - **On silicon:** the render matrices must give the same results as 95678704, and the ring's logged words must be identical.
4. **What later fixes get.**
   - One place per register word, a `feat` input (the shared `Diag\D3DFeat` bits) that is 0 today, and an oracle test that keeps `feat = 0` write-for-write the proven translation for every later item at once.
   - A **gap ledger** that pins today's wrong words with their gap ids (Appendix B).
   - A d3dprobe `statemap` whose 53 cells pin, on silicon, the ideal value or the documented degradation of each op, argument and blend factor.

### 1.2 Why it matters now

- **The mapping is stable, and old values are on record only in silicon logs.**
  - `color_path`, `blend_*` and `cmp` date from 56e0bc1. `stage1_combine` is from 8c190d3.
  - `compute_regs` last changed meaningfully in 7d2779b (09-28, `view_of`). 481acfd only added the `log_combo` call (`git blame`).
  - Every silicon run since 09-28 used this mapping. The only record of what it computes is `log_combo` (event 513/21-23):
    - `ONBOX/ring_after_probe_ii_decoded.txt`, seq 24863-24944, and `ring_after_probes_decoded.txt`, seq 29447 (d3dprobe on 11-12);
    - `KMD/evidence/d3dtune_1014/sweep_1108/UT2003_combos_unaligned.txt` (26 UT2003 set-ups on 11-08).
- **Nineteen fixable gaps change this code:** G05, G08, G09, G12-G14, G22-G35. The project rule is that each lands with a test asserting the fixed and the old value. Without an executable translation, the only "old value" a test can assert is a line of text.

### 1.3 Two facts found while checking, recorded for the items that follow

- **The D3D8 runtime hands a DX7 DDI DX7 filter numbers (inferred).**
  - d3dprobe `mip` passed on silicon on 11-12 (`ONBOX/d3dprobe_textures_a_1024x768x32.txt`: levels 0/1/2 by size). It sets `D3DTSS_MIPFILTER = D3DTEXF_POINT`, which is **1** in DX8.
  - The HAL mipmaps only when `tss[MIPFILTER] > D3DTFP_NONE` (1) (`:779`, `:814`). The value must therefore have arrived as `D3DTFP_POINT` (2).
  - So the translation's input domain is DX7 `d3dtypes.h` numbering, even for D3D8 titles. This matters for G26/G27. The history report's "no `mip` run is on record" is out of date as of 11-12.
- **`fvf_layout` has undefined behaviour for a texture count of 9-15.** `(fvf >> (16 + 2 * i)) & 3` is computed for `i` up to 15 (`:1274`), a shift of 32 or more. A valid runtime never sends `TEXCOUNT > 8`, so it is unreachable. The extraction keeps `ntex <= 8` exactly and, in a separate follow-up commit, refuses `ntex > 8` (§3.4).

- the handle table;

- the DP2 opcode walker and primitives (G16/G24/G49: `vcr_dp2prim.h`, `vcr_3dstrip.h`);

### 3.2 The header API (sketch; integer only, C89 style, no library calls)

```c
/* include/vcr_d3dstate.h - the Direct3D HAL's state -> register translation.
 * Integer only and Win32-free: display/vcrdd_d3d.c (-mgeneral-regs-only) runs it,
 * tests/native/test_vcr_kmd_d3dstate.c and tools/d3dprobe.c compile the same text.
 * feat == 0 IS BUILD 95678704 (be58b7d) WRITE FOR WRITE - the native test compares
 * it with that build's verbatim source over the whole input domain. */
#define VCR_D3D_RS_MAX   256u
#define VCR_D3D_TSS_MAX  32u
#define VCR_TP_EXT  1u          /* pd->tex_ext: the VSA-100 texture path (Diag\D3DBigTex) */
#define VCR_TP_BIG  2u          /* pd->tex_big */
#define VCR_TP_DXT  4u          /* pd->tex_dxt */
#define VCR_TP_32   8u          /* pd->tex_32 */

typedef struct vcr_d3d_texdesc {        /* the HAL fills it from the DD_SURFACE_LOCAL */
    vcr_u32 in_vidmem;                  /* s && s->lpGbl && !DDSCAPS_SYSTEMMEMORY; nothing else is read without it */
    vcr_u32 has_pixfmt;                 /* has_pixfmt(): the flag OR a non-zero dwRGBBitCount */
    vcr_u32 is_fourcc, fourcc;          /* DDPF_FOURCC, dwFourCC - kept apart: pf_kind tests the flag */
    vcr_u32 bits, rmask, amask;
    vcr_u32 w, h, pitch, offset;
    vcr_u32 mip_top;                    /* SF_IS(s, SF_MIP_TOP) */
    vcr_u32 levels;                     /* 1 + the levels next_mip reaches, counted to 12 */
} vcr_d3d_texdesc;
typedef struct vcr_tmuview { vcr_u32 textureMode, tLOD, texBaseAddr, w, h; } vcr_tmuview;

static __inline vcr_u32 vcr_d3d_cmp(vcr_u32 f)  /* D3DCMP_* - 1 = the LT|EQ|GT bits; else ALWAYS */
{
    return f >= VCR_D3DCMP_NEVER && f <= VCR_D3DCMP_ALWAYS ? f - 1 : 7;
}
/* MAG/MIN LINEAR-or-better -> bilinear; ADDRESSU/V CLAMP -> clamp (MIRROR, BORDER: wrap) */
static __inline vcr_u32 vcr_d3d_sampling(const vcr_u32 *tss);
/* today's tex_view (tp without VCR_TP_EXT) and tex_view_ext (with it); 1 = sampleable */
static __inline int vcr_d3d_view(const vcr_d3d_texdesc *d, const vcr_u32 *tss, vcr_u32 tp,
                                 vcr_tmuview *v);
static __inline int vcr_d3d_stage1_on(const vcr_u32 *tss1)
{
    return tss1[VCR_D3DTSS_COLOROP] != VCR_D3DTOP_DISABLE;
}

typedef struct vcr_d3d_in {
    const vcr_u32 *rs, *tss0, *tss1;    /* the context's arrays, unchanged storage */
    vcr_u32 tex, two;                   /* v0 valid; v1 valid (two implies tex) */
    vcr_tmuview v0, v1;
    vcr_u32 z_on;                       /* vcr3d_target.z_on */
    vcr_u32 feat;                       /* Diag\D3DFeat translation bits; 0 = build 95678704 */
} vcr_d3d_in;
typedef struct vcr_d3d_out { vcr_u32 fog_vertex, tex_w, tex_h, tex1_w, tex1_h; } vcr_d3d_out;

static __inline void vcr_d3d_regs(const vcr_d3d_in *in, vcr3d_regs *r, vcr_d3d_out *o)
{
    const vcr_u32 *rs = in->rs;
    vcr_u32 cull = rs[VCR_D3DRENDERSTATE_CULLMODE];
    o->tex_w = o->tex_h = o->tex1_w = o->tex1_h = 0;    /* always written: §3.4 rule 2 */
    r->textured1 = in->two;
    if (in->two) {                      /* TMU1 samples stage 0, TMU0 stage 1 and combines */
        r->textureMode1 = in->v0.textureMode | TM_TC_REPLACE | TM_TCA_REPLACE;
        r->tLOD1 = in->v0.tLOD;
        r->texBaseAddr1 = in->v0.texBaseAddr;
        r->textureMode = in->v1.textureMode | vcr_cmb_stage1(in->tss1);
        r->tLOD = in->v1.tLOD;
        r->texBaseAddr = in->v1.texBaseAddr;
        o->tex_w = in->v1.w; o->tex_h = in->v1.h; o->tex1_w = in->v0.w; o->tex1_h = in->v0.h;
    } else if (in->tex) {
        r->textureMode = in->v0.textureMode | TM_TC_REPLACE | TM_TCA_REPLACE;
        r->tLOD = in->v0.tLOD;
        r->texBaseAddr = in->v0.texBaseAddr;
        o->tex_w = in->v0.w; o->tex_h = in->v0.h;
    }
    r->textured = in->tex;
    r->fbzColorPath = vcr_cmb_color_path(in->tss0, in->tex) | CP_PARMADJUST;
    r->fbzMode = FZ_RECTCLIP | FZ_RGBWRITE;
    if (rs[VCR_D3DRENDERSTATE_DITHERENABLE])
        r->fbzMode |= FZ_DITHER;
    if (in->z_on && rs[VCR_D3DRENDERSTATE_ZENABLE] == VCR_D3DZB_TRUE) {
        r->fbzMode |= FZ_DEPTH | FZ_ZFUNC(vcr_d3d_cmp(rs[VCR_D3DRENDERSTATE_ZFUNC]));
        if (rs[VCR_D3DRENDERSTATE_ZWRITEENABLE])
            r->fbzMode |= FZ_ZAWRITE;
    }
    r->alphaMode = 0;
    if (rs[VCR_D3DRENDERSTATE_ALPHATESTENABLE])
        r->alphaMode |= AM_ATEST | AM_AFUNC(vcr_d3d_cmp(rs[VCR_D3DRENDERSTATE_ALPHAFUNC])) |
                        AM_AREF(rs[VCR_D3DRENDERSTATE_ALPHAREF] & 0xff);
    if (rs[VCR_D3DRENDERSTATE_ALPHABLENDENABLE])
        r->alphaMode |= vcr_blend_alphamode(rs[VCR_D3DRENDERSTATE_SRCBLEND],
                                            rs[VCR_D3DRENDERSTATE_DESTBLEND], 0);
    /* fog: fog_table untouched while fog is off, as today; the four entries
     * written one by one (no memset in a header the host and the kernel share) */
    r->fogMode = 0;
    o->fog_vertex = 0;
    if (rs[VCR_D3DRENDERSTATE_FOGENABLE]) { /* ... exactly :1004-1017 ... */ }
    r->fogColor = rs[VCR_D3DRENDERSTATE_FOGCOLOR] & 0xffffff;
    r->c0 = 0;
    r->c1 = rs[VCR_D3DRENDERSTATE_TEXTUREFACTOR];
    r->setupMode = SM_RGB | SM_A | SM_Z | SM_WFBI | (in->tex ? SM_W0 | SM_ST0 : 0) |
                   (in->two ? SM_W1 | SM_ST1 : 0);
    if (cull == VCR_D3DCULL_CCW)
        r->setupMode |= SM_CULL | SM_CULL_NEGATIVE;
    else if (cull == VCR_D3DCULL_CW)
        r->setupMode |= SM_CULL;
}

typedef struct vcr_d3d_fvf { vcr_u32 stride, diff, tex, spec, nsets, set_off[8]; } vcr_d3d_fvf;
static __inline int vcr_d3d_fvf_layout(vcr_u32 fvf, vcr_d3d_fvf *l);   /* :1254-1284 */

typedef struct vcr_d3d_bind { vcr_u32 textured, textured1, set0, set1, fog_vertex; } vcr_d3d_bind;
/* prepare's :1339-1363: which coordinate set each TMU reads; a vertex without the
 * sets draws untextured (and the words say so); vertex fog without a specular
 * colour is no fog */
static __inline void vcr_d3d_bind_sets(vcr3d_regs *r, const vcr_u32 *tss0, const vcr_u32 *tss1,
                                       vcr_u32 tex_ok, vcr_u32 fog_vertex, vcr_u32 nsets,
                                       vcr_u32 has_spec, vcr_d3d_bind *b);

/* the DX7 caps of build 95678704, as the DRIVER reports them (D3D8 rewrites some:
 * caps_124.txt shows RasterCaps 0x00100191 without SUBPIXEL, ShadeCaps 0x4008 without the
 * FLAT bits, TextureCaps 0x4007 without TRANSPARENCY and with MIPMAP added) */
#define VCR_D3DCAPS_MISC       0x00000072u     /* MASKZ CULLNONE CULLCW CULLCCW */
#define VCR_D3DCAPS_RASTER     0x001001b1u     /* DITHER ZTEST SUBPIXEL FOGVERTEX FOGTABLE WFOG */
#define VCR_D3DCAPS_ZCMP       0x000000ffu
#define VCR_D3DCAPS_ALPHACMP   0x000000ffu
#define VCR_D3DCAPS_SRCBLEND   0x00001f33u
```

### 3.4 What "unchanged" means, rule by rule

The move is checked against these rules. Each one is a place where a careless extraction would differ from build 95678704:

1. **Stale fields stay stale.**
   - The TMU0 fields are written only when `tex`, and TMU1's only when `two`.
   - `fog_table` is untouched while FOGENABLE is 0.
   - `VcrDd3dState` sends a TMU's words only when its `textured` flag is set, and `fog_table` only with `FM_ENABLE`, so stale values never reach the chip.
   - The differential test still compares the **whole** struct from a shared 0xA5 sentinel, so a field the old code left alone is checked as left alone.
2. **The scale sizes are always written** (0 when unused), where the old code left them stale. `prepare` reads them only when `tex_ok` (and `tex1_*` only when `textured1`), so the difference cannot be observed. It is the one non-register difference, and the test compares them only when textured.
3. **The stage-1 view is computed lazily**, as before (`two = tex && COLOROP != DISABLE && handle && view`). The decision rule is in the header (`vcr_d3d_stage1_on`); the order of evaluation stays in the HAL.
4. **The chain count.**
   - Today the default path counts up to 9 levels and the VSA-100 path up to 12 (`:782`, `:817`).
   - The HAL now counts to 12 once, and the header takes `min(levels, 9)` on the default path. The walk is pure, so the result is identical.
   - The HAL walks even when MIPFILTER is NONE (at most 11 attach-list hops). This is a cost difference, not a behaviour difference.
5. **`has_pixfmt` keeps its NT exception.** On NT a texture is trusted on a non-zero bit count alone (`:166-169`; `test_vcr_kmd_d3d.py:49-55`). `texdesc_of` computes it exactly so, and reads `lpGbl` only when `in_vidmem`.
6. **The FOURCC flag and the code stay apart.** A surface with `DDPF_FOURCC` set and code 0 is `KIND_NONE` in `pf_kind` but "no FOURCC" in `surf_fcc` (`:280-309`). The descriptor carries both.
7. **No library calls, no floats, no `long`.**
   - The fog-table clear is four assignments, not a memset.
   - The kernel build is `-mgeneral-regs-only` (`KMD/Makefile:26`), so any float in a header is a compile error there. The Python test also compiles the headers with host `gcc -mgeneral-regs-only`.
   - `unsigned long` is 64-bit on the host, so the headers use `vcr_u32` only.
8. **`fvf_layout`'s undefined case** (§1.3) is defined in a follow-up commit, not in the move: `TEXCOUNT > 8` is refused (the vertex buffer is not drawn). The oracle comparison covers `ntex <= 8`, and a separate test pins the refusal. It cannot be reached from a valid runtime.

### 3.6 Alternatives considered

- **Build the whole `vcrdd_d3d.c` on the host against a fake DDI.**
  - It would make the walker testable too.
  - But every test would then rest on a hand-written second copy of Microsoft's DDI (DP2 records, `DD_SURFACE_*`, callbacks) for code that changes often. And it goes against the project's established pattern.
  - The fake is confined instead to the **frozen** oracle slice, which never changes.
- **Keep the source-text assertions and add a native test beside them.** The text assertions break the moment the code moves. They are replaced by behavioural assertions that are strictly stronger (§5.3).
- **Hand-transcribe the oracle**, the way `old_target` is transcribed in `test_vcr_kmd_d3dseq.c`.
  - The verbatim slice removes transcription error.
  - It is cheap because the be58b7d text is fixed forever, and the provenance test proves it is that text.
- **A Diag switch selecting old or new code.** Rejected: both sides produce identical output by construction, and the switch would keep two copies of the translation alive.

## 4. Gating

- **No switch.** The move changes no register word, caps bit, event or Diag default. The claim "byte-for-byte the proven path" is proven twice:
  - on the host, over the whole input domain, against the deployed build's own source;
  - on silicon, by the render matrices and by the words the driver logs (§7).
- **Safe to land default-on** once `bash tests/run_all.sh` is green and the HAL builds with `HAVE_DDI=1` (the static asserts compile). Push to `master` at that checkpoint.
- **The `.124` deploy is a separate supervised step:**
  - a normal vcr-kmd DLL swap, keeping 95678704 for rollback;
  - `scripts/fleet/safe-reboot.py`, which checks activation;
  - one clean boot with no Glide/OpenGL client before the D3D runs (G01's stale command FIFO voids any 32 bpp result after one).
  - It changes no Diag value, so it is that boot's only change.
- **Two later commits are behaviour changes and are gated on their own:**
  - the `ntex > 8` refusal (unreachable, host-proven, may ride along);
  - adding `statemap` to d3dprobe's default list, which waits until it has passed once on silicon so the published pass counts change with evidence.

## 6. d3dprobe: `statemap` (steps 4-5)

### 6.1 What it does

**Purpose.** Prove on silicon that the box computes the words the host test executes. At the same time, measure each op, argument and factor against D3D: the ideal value where it is advertised and exact, the documented degradation where it is not. This is the silicon twin of the gap ledger, and the state-matrix half of G74.

**Run.** `d3dprobe_run.py 192.168.1.124 render --full --res 640x480 --bpp 16 --tests statemap --ring-check`. It also runs at `--full --res 1024x768 --bpp 32` and windowed.
- `statemap` runs **alone**: one device, so one context, and `log_combo` keeps the first 64 set-ups per context (`:897-899`).
- The runner records the ring's `next_seq` before launch, paces mode switches 5 s apart (`--pace`, as `ONBOX/d3dprobe_paced.py`), and fetches the ring **after** d3dprobe has exited (`vcrlog.py fetch --after`).
- It never runs an escape tool while a D3D client is up.

**What it draws.** 53 cells, each a 16x16 quad on a 24 px grid inside the 256x256 readback window, over one clear. Each cell sets its whole state explicitly: both stages' ops, arguments, filters and addressing, the blend enable and factors, and the alpha test.

**Inputs.** All are exactly representable:
- clear C = 0x406000;
- diffuse D = 0x80C08040;
- TFACTOR F = 0xC0204080;
- stage-0 texture T: 8x8 A4R4G4B4 0xA48F, which is 0xAA4488FF;
- stage-1 texture U: 0x6C48, which is 0x66CC4488;
- specular S = 0x0000FF00 (one cell).

T's blue is 0xFF over C's blue 0, so the alpha-op cells read alpha directly in blue. At start-up d3dprobe checks every ledger cell's ideal and documented values differ by at least 24 in some channel; a cell that cannot tell them apart fails the run instead of passing silently.

### 6.3 Pass criterion (all four must hold)

1. **Words, against the reference computed by the same header.** For each cell, the driver's 513/21 + 513/22 pair matches d3dprobe's own `vcr_d3d_regs` for that state, given `--feat` and `--texpath` from the box's `Diag\D3DFeat` and `Diag\D3DBigTex` (absent = 0, and the RESULT says so).
   - Compared: `cp`, `tm`, `tm1`, `am`. `tLOD`/base depend on placement and are excluded.
   - Pairing: the 22 event's stage-0 ops/args and stage-1 ops, plus `am`.
   - 53/53 are required. A missing combo, an extra combo or a wrapped ring fails, and each is named.
2. **Ops as sent.** The logged stage-0 ops and arguments equal what d3dprobe set. This tells "the runtime rewrote the state" apart from "the driver computed a different word".
3. **Pixels.**
   - `exact` cells must read the D3D formula, after target quantization, within ±12 (±14 for groups D and F) at 16 bpp, and ±6/±8 at 32 bpp.
   - `documented` cells must read the documented value within the same tolerance.
   - A pixel that matches neither fails.
   - A `documented` cell that reads the **ideal** also fails, with "ledger stale - Gxx's cell now draws the ideal; flip it". A behaviour change never passes unrecorded.
4. **Fix bits.** Each documented cell carries the `D3DFeat` bit of the item that fixes it (0 for all in G77). With `--feat` containing that bit, the cell's expectation becomes `exact`. That is how each later item asserts both its old and its fixed value on silicon.

The RESULT lists every cell with `got`, `ideal`, `documented`, `verdict`, `gap` and the four words.

## 8. Risk to proven paths

- **The default 16 bpp path, and the 32 bpp/BigTex paths.** Identical words by construction, proven exhaustively against the deployed source and re-proven on silicon in §7. The realistic residual risk is a slip in the HAL glue (`texdesc_of`'s field copies, the lazy `two`). The render matrices' texture tests and the ring's `tex` lines (base/tlod per combo) catch that.
- **Build.**
  - `static __inline` code is inlined differently, so the DLL's md5 changes and timing may shift by nanoseconds per state change.
  - The header is integer-only; a float would fail the `-mgeneral-regs-only` build, which is the FPU-bracket rule held by the compiler.
  - No new imports (`check_imports.py`): there are no library calls.
  - The struct type changes (`ULONG` and `DWORD` to `vcr_u32`) have the same size and layout on i686, and are asserted. No IOCTL or escape structure changes.
- **Glide/OpenGL coexistence, SLI, the flip path, the miniport.** Not touched.
- **d3dprobe.** The new test is explicit. Existing tests and the default list are unchanged. The new build links `vcr_texlod.c`.
- **Docs drift.** The README's and tests README's descriptions of where the mapping lives change in the same commit (G80).
- **Coordination.** The `vcr3d_regs` move (G53) and the shared file names (G12/G13/G14/G15/G28/G29) are first-lander-creates. §3.1 names the files, so a later item extends rather than duplicates them.

## 10. Open questions

1. **Header names.** `vcr_cmb_legacy.h` (G15's name) and `vcr_blend.h` (G28/G29's) are proposed as the shared names. G13 (`vcr_xcomb.h`) and G14 (`vcr_d3dcomb.h`) should adopt them, and the blend `flags` bits should be allocated once (SAME for G29, RT_ALPHA for G28).
2. **`in.feat` stays 0 until an item adds `Diag\D3DFeat`.** That item wires `pd->d3dfeat` into the glue and into d3dprobe's `--feat`.
3. **`log_combo` limits.**
   - It runs before `prepare`'s binding, so a draw whose vertex lacks its coordinate set is logged with `CP_TEXTURE` but drawn untextured. Should it log after the binding? That is logging only, a follow-up.
   - It does not log `fbzMode`/`fogMode`/`sSetupMode`. Silicon word checks for G22/G23/G30-G32/G35 need either G76's counters or a new 513 `what`. Codes 24-29 are contended by G05/G16/G24/G35, so the event table's owner should assign it.
4. **DX8-only numbers.** Does the D3D8 runtime forward D3DTOP 25/26, D3DTA_TEMP or TSS 25-28 to a DX7 DDI at all? The domain covers the raw numbers (they fall to today's defaults); G76's counters would answer it.
5. **The filter-number translation** (§1.3) is inferred from one pass. A `statemap` cell with MIPFILTER POINT on a two-level chain would show it directly in the 513/23 `tlod` (LODMAX > LODMIN). Should it be added to group F?
6. **The 64-set-up cap.** If later items make `statemap` exceed it, split it into pages, each with its own device (`statemap:1`, `statemap:2`).
7. **Native test run time.** About 0.5 s at `-O0` is within the suite's habits. If `run_all.sh` time matters, should the random counts be cut to 50k?
