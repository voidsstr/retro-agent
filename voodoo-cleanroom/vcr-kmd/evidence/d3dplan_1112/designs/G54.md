# G54: every flip drains the engine and moves the scan-out by IOCTL - a hardware swap queue (design)

Design for one item of the Direct3D plan for the Voodoo 5 6000 on `.124` (vcr-kmd HAL).
Written 2026-11-12 from code, docs, the vendor source and the Napalm spec. No fleet box was contacted;
nothing was built or run.

`VH5` = `retro-3dfx/3dfx Driver Code/H5/W2K/Src/Video/Displays/H5` (3dfx's W2K/XP display driver, guidance

## 0. Verdict

The gap is real, small today, and becomes the frame-boundary serialiser the moment the CMDFIFO (P6, G47)
lands. The cure is the hardware swap that 3dfx's D3D HAL and our own Glide already use on this silicon:
`leftOverlayBuf` + a direct `swapBufferPend` write + `swapbufferCMD`, queued behind the frame,
throttled on the chip's own pending count `status[30:28]`, with at most 6 swaps outstanding.

**What it costs today (read, inferred cost):** a successful vsync'd `Dd_Flip` does one `VcrDd2dSync`
(a full idle wait: today about one triangle's rasterisation, because the PCI FIFO holds 31 writes), then
three IOCTLs (the flip, a TRACE log line, a vblank read). Every `DDERR_WASSTILLDRAWING` retry is a fourth
IOCTL. That is roughly 20-50 µs per frame (0.2-0.4 % of an 85 Hz frame) plus the last primitive's fill.
**Measured on silicon:** nothing isolates it; the one perf scene is fill-bound (`EV/reports/perf.md` §3.2).

**What it will cost after P6:** with a ring of up to ~1 MB of commands in flight, the drain at the flip
waits for the whole GPU tail of the frame, and the GPU then idles while the CPU starts the next frame.
Frame time stays near CPU + GPU instead of max(CPU, GPU), which removes most of P6's gain at the frame
boundary (perf-09).

**Five facts this design adds to the brief:**

1. **A vsync'd swap blocks the 3D command processor unless `dramInit1` bit 11 is set.** "If vertical
   retrace synchronization is enabled for double buffered applications, the graphics command processor
   blocks on a SWAPBUFFER command until the monitor vertical retrace signal is active" (SPEC 5492). Bit 11
   ("triple buffering", `GL5/incsrc/h3defs.h:1607`) lets the core run on while "one or fewer swaps is
   pending" (SPEC 3960). A queued swap is therefore **also the hardware fix for the render-after-flip
   hazard (G55)**: the next frame's draws into the old front buffer wait in the chip, not in the CPU.
   3dfx sets bit 11 per flip chain: on for 3D chains of more than two surfaces, off otherwise
   (`VH5/DDSURF.C:371-393`, cleared again at `:1337-1345`). Our Glide sets it from its own buffer count
   (`GL5/minihwc/minihwc.c:2444`, `:5159-5166`) and nothing restores it at close, so a 3-buffer Glide
   session can leave it set for a later 2-buffer D3D chain (inferred). The design forces it per chain.
2. **Correct double buffering quantises a vsync'd frame rate; today's driver escapes that only by
   drawing into the scanned-out buffer.** Today `Dd_Flip` returns as soon as the previous flip has
   latched, and the next frame renders at once into the buffer that stays on screen until the next
   retrace (`KMD/display/vcrdd_ddraw.c:330-361`; `vcrdd_d3d.c:2068` advertises `CANRENDERAFTERFLIP`).
   A title needing 12 ms per frame at 85 Hz therefore runs at ~83 fps today, with the screen showing the
   next frame being drawn. With any correct fix (this one, or G55 clearing the cap) it runs at 42.5 fps
   with a 2-buffer chain, and at ~83 fps only with 3 buffers. That is the behaviour of every other
   driver, including 3dfx's own blocking swap. It must be measured per title (§5, §8) before any
   default changes.
3. **`fbiSwapHistory` (3D 0x258) records the number of vsyncs between each of the last 8 executed swaps**
   (SPEC 5012-5026). Once flips are hardware swaps, the driver gets an exact frames-per-refresh
   histogram for one register read every 8 flips. That is the vsync-on measurement G78 asks for.
4. **The desktop layer is not the route.** 3dfx wrote "Desktop flipping can't be pipelined, so the video
   overlay is borrowed to display the primary flipping chain for 3D, exclusive-mode, full-screen
   applications" (`VH5/DDFXNT.C:2410-2414`). Napalm does have `leftDesktopBuf` + `SST_SWAP_DESKTOP_EN`,
   but both 3dfx and Glide use them only for the AA secondary buffer, and only with `vidScreenSize`
   bit 23 (`desktop_addr_fifo_enable`) set (`VH5/DDFXNT.C:2598-2604`;
   `GL5/minihwc/minihwc.c:5024-5033`). A plain (non-AA) desktop swap has never run on this box, and
   neither reference driver uses one. The overlay route
   is the one this silicon runs every Glide session on our kernel (`KMD/README.md:156`). It is also the
   route SLI needs (`VH5/DDFXNT.C:2528-2529`; G51).
5. **The spec contradicts itself on who increments the pending count.** One paragraph says
   `swapbufferCMD` increments it on arrival (SPEC 3956). Two say the driver must write `swapBufferPend`
   first (SPEC 3959, 5493). 3dfx's code writes `swapBufferPend` before every swap
   (`VH5/DDFLIP.C:77`, `:274`, `:394`), except at overlay promotion, where it swaps without it
   (`VH5/DDFXNT.C:2711-2712`). Our Glide never writes it: it counts swaps by FIFO position instead
   (`GL5/glide3/src/gglide.c:2792-2810`, `:3109-3205`). A double count would freeze the throttle, and an
   unpaired swap could wrap the 3-bit field. **Nothing may rely on the count before experiment E1/E2
   (§5.2) settles this on `.124`.**

**Plan, in four stages, each behind `Diag\D3DHwSwap` and off by default:**

| stage | what | needs | gain |
|---|---|---|---|
| S0 | flip-path counters plus the render-after-flip self-test on today's path (bit 7) | G76's counter plumbing | numbers: time in Flip, retries, and whether G55 is real |
| S1 | swap-register experiments on an idle desktop, run as bounded miniport probe ops (bit 3) | none | settles the count semantics, the overlay recipe, the recovery |
| P7a | hardware swap over today's PCI FIFO, overlay scan-out (bit 0) | S1 | no drain or IOCTL per flip, exact completion, G55 closed by hardware ordering, hardware frame histogram; small fps gain |
| P7b | the same swap emitted into the CMDFIFO ring | G47 (P6) proven | CPU/GPU overlap across frames: the real performance payoff |

**Priority P2** (performance with a measurable gain, once P6 exists; P7a alone is mostly correctness and
hygiene). **Effort L.** Not safe to land default-on: it moves the scan-out layer, programs video
registers, and changes frame pacing.

## 3. Design

### 3.0 Switch, plumbing, numbers

`HKLM\SYSTEM\CurrentControlSet\Services\vcrmp\Diag\D3DHwSwap` (DWORD, read once at boot like `D3D32`,
`KMD/miniport/vcrmp.c:238-244`, VSA-100 only, **absent = 0 = today's path for every flip**):

| bit(s) | meaning |
|---|---|
| 0 (`0x01`) | arm the hardware swap for **fullscreen 3D primary chains** (P7a, overlay scan-out) |
| 2 (`0x04`) | honour triple buffering: `dramInit1` bit 11 = 1 for a 3D chain of 3 or more surfaces. Off: always 0 |
| 3 (`0x08`) | allow the miniport probe ops of §5.2 (`vcrctl swapprobe`). Changes nothing on any flip path |
| 4-6 | maximum swaps outstanding, **including** the one being queued: 0 → default 2; 1-6 as given; 7 → 6 |
| 7 (`0x80`) | the ordering self-test (§3.5), on whichever path bit 0 selects. **Test boots only** |

The field reaches the display DLL as an **appended** `vcr_info.d3dhwswap` (the whole DWORD, 0 on a
Banshee/Voodoo3), not a flag bit: sibling designs already collide on `VCR_INFO_F_*` 0x8000/0x10000 (G02
§3.7). One new IOCTL, `IOCTL_VCR_DDOVERLAY` (proposed `VCR_CTL(0xa12)`; 0xa10/0xa11 are claimed by
G01/G02). One miniport event, `VCR_EV_DD_OVERLAY` (proposed 320). DLL lines go on event 511 with
a=15-19, after the flip lines a=12-14. The integrator re-checks every number against the sibling designs.

### 3.1 Pure logic: `KMD/include/vcr_swapq.h` (Win32-free, host-compiled)

Like `vcr_flip.h`: no OS headers, no floating point. The DLL and the miniport are glue around it.

- **Constants (computed, not transcribed):**
  - offsets from `offsetof(SstRegs, …)` over `GL5/incsrc/h3regs.h`, cross-checked against
    `VINC/H3REGS.H:358-417`: `V3D_SWAPBUFFERCMD 0x128`, `V3D_FBIPIXELSOUT 0x15c`,
    `V3D_LEFTDESKTOPBUF 0x218`, `V3D_SWAPBUFFERPEND 0x24c`, `V3D_LEFTOVERLAYBUF 0x250`,
    `V3D_FBISWAPHISTORY 0x258`, `V3D_FBITRIANGLESOUT 0x25c`. These go into `vcr_3dregs.h` beside
    `V3D_NOPCMD 0x120` (`:28`).
  - `VCR_STATUS_SWAPPEND(s) ((s) >> 28 & 7)` (`h3defs.h:112-113`).
  - the `swapbufferCMD` bits: `VSYNC 1u`, interval `[8:1]`, `DONT_SWAP 1u<<9`, `DESKTOP_EN 1u<<10`
    (`h3defs.h:1702-1706`).
  - `VCR_SWAPQ_HANG_CAP 6u`, `VCR_SWAPQ_DEFAULT_CAP 2u`, `VCR_SWAPQ_STALL_MS 500u`.
- **`vcr_swapq_cap(diag)`** → 1..6, from bits 4-6.
- **`vcr_swapq_word(novsync)`** → `0x001` vsync'd, `0x000` immediate. The interval stays 0: "for highest
  performance when syncing-to-vsync, set the swapbuffer interval to zero" (SPEC 3957). Overlay layer,
  so bits 9-10 are clear. The probe-only fence `vcr_swapq_fence(vsync)` is `0x201` / `0x200`:
  "the outstanding swap count will be decremented, but no video swaps occur" (SPEC 3958).
- **`vcr_swapq_may_queue(status, cap)`** → `SWAPPEND(status) + 1 <= cap`. A field reading 7 is refused
  for every cap.
- **`vcr_swapq_seq(addr, word, out[4])`** → the four writes, kind and order fixed:
  `{FIFO, LEFTOVERLAYBUF, addr & 0x03fffff0}`, `{DIRECT, SWAPBUFFERPEND, 0}`,
  `{FIFO, SWAPBUFFERCMD, word}`, `{FIFO, NOPCMD, 0}`. P7a writes all four straight to the registers.
  P7b sends the FIFO ones as packets; `swapBufferPend` stays direct ("available only through direct
  access", SPEC 4992).
- **`vcr_swapq_hist(hist, completed, bins[5])`** → adds the newest `min(completed, 8)` nibbles of
  `fbiSwapHistory` to bins 0/1/2/3/4+. `completed` = swaps executed since the last sample
  = queued since then − (pending now − pending then).
- **`vcr_swapq_stalled(pending, last_progress_ms, now_ms)`** → pending > 0 and no progress for
  `VCR_SWAPQ_STALL_MS`. Progress means `status[30:28]` dropped, `status[4:0]`/busy changed (P7a), or the
  ring's read pointer moved (P7b). A slow frame is never a stall.
- **`vcr_ovl_promote(in, out)`** → the overlay register file for a linear chain. Inputs: `vidProcCfg`,
  stride register, bpp, w, h, pitch, chain address. Outputs:
  - `vidProcCfg' = (vpc & ~(DESKTOP_EN | CHROMA_EN | CHROMA_INVERT | VIDEOIN_AS_OVERLAY | OVERLAY_STEREO_EN | OVERLAY_CLUT_BYPASS | OVERLAY_CLUT_SELECT | H/V_SCALE_EN | FILTER_MODE | OVERLAY_PIXEL_FORMAT | OVERLAY_TILED_EN | DEINTERLACE_EN)) | OVERLAY_EN | fmt`.
    `fmt` is RGB565U (`1<<21`) at 16 bpp or RGB32U (`3<<21`) at 32. The filter is POINT, so the output
    is pixel-identical to today's desktop scan-out.
  - VP-enable, 2X, half-mode, cursor, desktop format and CLUT bits are kept as they are.
    (Bit list: `h3defs.h:1201-1250`.)
  - `stride' = (stride & 0x7fff) | (pitch << 16)`.
  - `vidOverlayStartCoords 0`; `vidOverlayEndScreenCoord ((h-1)<<12)|(w-1)` (the vendor's
    `GETOVERLAYADDR`, `VH5/DDGLOBAL.H:534-535`).
  - `vidOverlayDudx 0`, `vidOverlayDvdy 0`, `vidOverlayDvdyOffset 0`.
  - `vidOverlayDudxOffsetSrcWidth (w*Bpp) << 19` (`h3defs.h:1423-1424`; `VH5/DDFXNT.C:2646`).
  - **Refuses** (old path): bpp not 16/32; `HALF_MODE` (doublescan needs a vertical stretch the vendor
    does at `DDFXNT.C:2586-2593`; P7a leaves it out); `2X_MODE` (Glide proves the overlay there, but a
    linear one is untested, and no staged D3D mode is 2X by `KMD/common/vcr_modes.c:239-248`);
    `w*Bpp > 8191`; `pitch > 0x3fff` or not 16-aligned; an address not 16-aligned.
- **`vcr_ovl_demote(saved)`** → the exact saved values.
- **`vcr_dram1_triple(di1, chain_len, honour)`** → `di1` with only bit 11 changed (on iff
  `honour && chain_len >= 3`). Restored at demote.

### 3.2 Miniport (`KMD/miniport/vcrmp_dd.c`, `vcrmp.c`, `vcrmp_hw.c`, `vcrmp.h`)

The miniport owns every video register, so promotion and demotion live there. Each is one bounded,
logged sequence under the miniport's own serialisation. `x->ovl` keeps the promoted flag and every saved
register.

`IOCTL_VCR_DDOVERLAY` with `vcr_dd_overlay {op, addr, pitch, w, h, bpp, chain_len, flags}` → result plus
the registers read back.

- **PROMOTE.** Refused unless all of these hold (one reason code each, logged):
  - a Voodoo VSA-100 backend with `cur_mode` valid;
  - no SLI session (`sli_active == 0`) and no exclusive owner;
  - chip 0 `cfgInitEnable` bit 17 (the SLI swap algorithm) clear, by config read (`vcr_sli.h:283`;
    the SLI teardown clears it, `vcrmp_sli.c:1178-1183`);
  - `cmdFifo0.baseSize` `SST_CMDFIFOEN` clear unless the ring is ours (P7b) (`vcr_3dseq.h:165`; the
    stale-FIFO case is G01);
  - `status[30:28] == 0`, the chip idle (`VcrHwWaitIdle`), and `vcr_ovl_promote` accepting.

  Then, in order:
  1. Save `vidProcCfg`, the stride register, the six overlay registers and `dramInit1`.
  2. Load the overlay address without showing it: `leftOverlayBuf = addr`, direct
     `swapBufferPend`, `swapbufferCMD = 0` (immediate). Poll, bounded to 50 ms, until
     `status[30:28] == 0` and `vidCurrOverlayStartAddr` (I/O 0xfc) reads `addr`.
  3. Write the geometry, stride and fetch width; apply `vcr_dram1_triple`.
  4. Wait for the start of vertical blank (bounded), then write `vidProcCfg'` in one store.
  5. Read everything back and compare. Any mismatch → demote, refuse.
  6. Log event 320 a=1.
- **DEMOTE (idempotent).** Bounded wait (`VCR_SWAPQ_STALL_MS`) for `status[30:28] == 0`. On a stall:
  `VcrHwResetEngine(x, 0, "swap stalled")` (`vcrmp_hw.c:181-200`, the existing engine-only reset, video
  untouched) and log at ERROR. Then:
  1. `vidDesktopStartAddr` = the requested address (the GDI primary's), and `x->dd_scan` too.
  2. At vertical blank, restore `vidProcCfg`.
  3. Restore the overlay registers, the stride and `dramInit1` bit 11.
  4. Log event 320 a=2 with a reason code.
- **Demote is called by the miniport itself** at `IOCTL_VIDEO_RESET_DEVICE`, at every mode set (before
  `voodoo_program`; the full `vidProcCfg` write at `vcrmp_hw.c:614` already turns the overlay off, but
  `dramInit1` needs restoring), at `HWCSETEXCLUSIVE` (a Glide open), and in the bugcheck/shutdown
  callback beside the SLI clock restore. **No DLL path can leave the overlay up**: the worst case is a
  missed DLL hook, cleaned at the next mode change.
- **PROBE_*** (only with bit 3; refused otherwise): the §5.2 sequences, each bounded, returning raw
  status words and timings to `vcrctl swapprobe`.

### 3.3 Display DLL (`KMD/display/vcrdd_ddraw.c`, `vcrdd.h`, `vcrdd_2d.c`, `vcrdd_d3d.c`, `vcrdd.c`, `vcrdd_escape.c`)

`VCR_PDEV` gains `struct { armed, cap, honour3, selftest, active, broken, chain_len, last_addr,
queued, hist_at, hist_pend_at, last_progress, counters… } swq`. It is read from `vcr_info.d3dhwswap` in
`VcrDd2dInit` (`vcrdd_2d.c:440-470`) and reset per PDEV.

**`swq_takes(pd, p)`** is true only when all of these hold: armed and not broken; `pd->napalm`;
`g2d_ok`; no `exclusive_pid`; the target has `DDSCAPS_3DDEVICE` and `DDRAWISURF_PARTOFPRIMARYCHAIN`
(the vendor's test, `VH5/DDSURF.C:1282`; D3D8 chains carry `0x1000601c`, G02 §3.3); `pd->bpp` is 16 or
32.

**`Dd_Flip`.** The new branch sits at the top, after G02's lost-engine answer. With the switch off,
everything below it is today's code byte for byte.

1. If not `active`: walk the chain's attach ring from `lpSurfTarg`, bounded to 8 (`vcrdd_d3d.c:1915-1918`
   already walks such rings). Every surface must be in video memory, 16-aligned, with the same pitch.
   Then `IOCTL_VCR_DDOVERLAY PROMOTE` with `lpSurfCurr`'s address, which is the picture on screen now.
   A refusal sets `broken` with its reason (511 a=18, once per PDEV); the flip then takes the old path.
2. One status read through `pd->pjRegs` (no IOCTL). If `!vcr_swapq_may_queue(status, cap)`, return
   `DDERR_WASSTILLDRAWING`. Count it, run the stall check (§3.5), and never spin under the display lock.
3. If `status[4:0] < 4`, `VcrDdRoom(pd, 4)`. On a give-up the flip answers as G02 specifies.
4. Emit `vcr_swapq_seq(target addr, vcr_swapq_word(novsync))` with `w3()`; set `g2d_busy = 1`.
   **No `VcrDd2dSync`, no `flip_to`, no per-flip `VcrDd`.**
5. `flip_from` = the old front, as today. Bump `queued`. Every 8th flip, sample `fbiSwapHistory`
   (§3.5). If the queue was empty at step 2, read `vidCurrOverlayStartAddr` and compare it with
   `last_addr` (the swap-verify counter). Return `DD_OK`.

**`flip_done(pd)`.** While `active`: `status[30:28] == 0`, one register read. Otherwise unchanged
(IOCTL rule).

**`Dd_GetFlipStatus`.** While `active`:
- `DDGFS_CANFLIP` → `may_queue`;
- `DDGFS_ISFLIPDONE` → `DD_OK`, as 3dfx does for 3D apps (`VH5/DDFLIP.C:697-725`). The driver's own
  Lock/Blt guards below keep it safe, and a counter records how often the runtime asks (open question 5).

**`Dd_Lock`.** A surface of the active chain while `status[30:28] > 0` → `WASSTILLDRAWING` (the runtime's
`DDLOCK_WAIT` retries with the lock released; 3dfx spins instead, `DDSURF.C:1787-1801`). Then
`VcrDd2dSync` as today.

Note: with bit 11 clear a pending vsync'd swap blocks the FIFO, so **any** `VcrDd2dSync` now also waits
for that swap. A texture Lock right after Present therefore waits up to one refresh in P7a. This is the
price of hardware ordering without per-surface fences (P8, G56).

**`Dd_Blt`.** Unchanged code. Its `flip_from` rule now uses the hardware `flip_done`; engine blits are
ordered behind the swap by the FIFO anyway.

**Exits.** Each of these calls `IOCTL_VCR_DDOVERLAY DEMOTE` with the GDI primary's offset when
`active`, then clears `active`:
- `Dd_FlipToGDISurface`;
- `Dd_SetExclusiveMode(0)`;
- `Dd_DestroySurface` of a chain member;
- `Dd_DestroyDDLocal` of the flipping pid;
- `DrvDisableDirectDraw`;
- `DrvAssertMode(FALSE)` (before `RESET_DEVICE`; the miniport would demote anyway);
- the `HWCSETEXCLUSIVE` escape (`vcrdd_escape.c`);
- a 2D give-up while active (`give_up()`, `vcrdd_2d.c:83-89`): mark `broken`, then demote.

**Caps.** `CANRENDERAFTERFLIP` stays set and is now true. If G55 clears it on the old path first, it is
set again only while `armed`, because the caps are built per PDEV.

### 3.4 P7b: the CMDFIFO transport (after G47)

When G47's ring is armed and owned by this PDEV, step 4 sends `leftOverlayBuf`, `swapbufferCMD` and
`nopCMD` as one-register packets through G47's emitter (3dfx: `CMDFIFO_BUILD_PK1(1, 0, reg, 0xF)`,
`VH5/DDFLIP.C:441-446`). `swapBufferPend` stays a direct uncached store.

The ring is then **fenced and made visible before `Dd_Flip` returns** (`sfence` plus G47's bump rule). A
swap left in a write-combining buffer never executes, the queue never drains, and the stall rule would
fire. The stall check gains the ring read pointer as its progress signal.

Two rules G47 must carry for this item:
- its "every direct register access drains and disarms the ring" rule **exempts** `swapBufferPend` and
  status reads;
- the drain it adds to `VcrDd2dSync` must include `status[30:28] == 0`. Under bit 11 = 1 the core does
  not block, so an empty ring does not mean the swaps have run.

The same Diag bit selects P7b automatically when the ring is live; a 511 a=15 field says which
transport ran. The combination is new code, so it gets its own proving boot (§8).

### 3.5 Self-test, counters, stall recovery

- **Ordering self-test (bit 7), on the first clear after each flip** (`clear_rects`, `vcrdd_d3d.c:1408`,
  the function DP2 CLEAR (`:1756`) and Clear2 (`:1898`) share). If a flip is pending at entry (hardware count, or the old
  rule):
  1. Read a 4-byte sentinel at (0,0) of the target through `pvRamBase`. The target is the buffer still
     on screen.
  2. Issue the clear as usual.
  3. Spin up to 2 ms. Each iteration reads the sentinel first, then status. A sample counts only while
     the flip is still pending.
  4. Record `measured` and `moved`.

  On the hardware path the fastfill is held behind the swap, so `moved` must stay 0. On the old path
  `moved` > 0 is the G55 hazard, measured directly.

  In self-test mode the hardware `Dd_Flip` drains before queuing, so the previous frame's tail cannot
  move the sentinel. A memory sentinel is used rather than `fbiPixelsOut`, because a 3D register read
  may itself wait for the FIFO (open question 4). It only reads: no register write is added.
- **Counters, logged at the existing four session-end points** (`vcrdd_ddraw.c:277-291`):
  - 511 a=15: hardware swaps, refused (queue full), maximum pending, cap, verify mismatches, stalls,
    transport;
  - 511 a=16: vsyncs per frame from `fbiSwapHistory` (bins 0/1/2/3/4+);
  - 511 a=17: self-test (`measured`, `moved`, path);
  - 511 a=18 (WARN): a promotion refused, with its reason;
  - 511 a=19: GetFlipStatus calls by flag.
- **`fbiSwapHistory` sampling** happens only when `status` shows the FIFO empty and the core idle, so
  the read cannot wait (open question 4). A sample that misses is just taken at a later flip, because
  `vcr_swapq_hist` takes at most 8 nibbles.
- **Stall.** Seen in `Dd_Flip`'s refusal loop (P7b) or as a `VcrDdRoom`/`VcrDd2dSync` give-up (P7a).
  The response is ERROR 511 a=18 with the status, `vidCurrOverlayStartAddr` and history; DEMOTE (which
  resets the engine if needed); `broken` = 1 until the next PDEV; the old path for the rest of the
  session. The game loses at most a frame or two; the box keeps its desktop.

### 3.6 The old path

With bit 0 clear (absent included):
- `Dd_Flip`, `GetFlipStatus`, `Lock`, `Blt`, `FlipToGDISurface` and the miniport write exactly what they
  write today;
- no new register is read or written, except the bit-7 sentinel reads in a test boot;
- DirectDraw 2D titles (StarCraft, Warcraft II, RA2/YR, TS, the DOSBox `ddraw` output) **never** take
  the hardware path, even when armed, because their chains have no `DDSCAPS_3DDEVICE`.

`test_vcr_kmd_flip.c` keeps pinning `vcr_flip.h` to the tick.

### 3.7 Considered and rejected

- **Desktop-layer swap (`leftDesktopBuf` + `SST_SWAP_DESKTOP_EN`) as the main route.** It touches no
  video layer, but it has never run outside AA. It may need `vidScreenSize` bit 23, a register the mode
  set owns, with unknown effects on direct `vidDesktopStartAddr` writes. 3dfx records an A0 erratum
  ("the desktop does not flip at the same time as the overlay", `VH5/DDFLIP.C:412-413`), and it leaves
  no SLI path. It is kept only as a fallback if E4/E5 fail, behind a new bit with its own experiments.
- **Spinning in `Dd_Flip` on the count, as 3dfx does.** That was the `.143` hard-freeze vector, and it
  holds the display lock. `WASSTILLDRAWING` lets the runtime retry with the lock released.
- **Glide's FIFO-position counting as the primary rule.** It needs the ring (P7b only) and readPtr reads.
  It stays the fallback if E1/E2 show the hardware count is unusable.
- **A fence only** (keep the drain and the direct `vidDesktopStartAddr` write, then add a `0x201`
  fence). It still drains, so it does nothing for G54. It is a possible cheap G55 fix, and it races at
  the latch boundary.
- **Forced driver-side triple buffering** (a hidden third buffer behind a 2-surface chain, like 3dfx's
  `retroFlipPresent` ping-pong, `VH5/DDFLIP.C:491-546`). It would avoid the quantisation, but it swaps
  DirectDraw surface memory behind the runtime's back, and 3dfx's first version hard-wedged the chip
  (`retro-3dfx/FINDINGS.md:10770-10775`). Left as an open question.

## 4. Gating

- **Default OFF**, read at boot, VSA-100 only. Arming takes a reboot through `safe-reboot.py` after the
  activation check, with **one Diag change per clean boot**: S0 (`0x80`), then S1 (`0x08`), then P7a
  (`0x81` for the test runs; `0x01` for games), then P7b (`D3DCmdFifo` already proven plus `0x01`).
- **Not safe to land default-on.** It changes the scan-out layer and frame pacing, and it programs video
  registers.
- **The default flip** comes after P7a and P7b are proven, the per-title pacing is measured (§8), and
  the user agrees. Correct double buffering can lower the fps of a 2-buffer title that sits between 1
  and 2 refreshes per frame. Triple-buffer settings in the staged configs (UT2003/UT2004
  `UseTripleBuffering`, Max Payne's option; G65) are the remedy.
- **With the switch off, the proven paths are byte for byte unchanged**, pinned by the tests in §7.

### 5.1 S0: today's path, measured (boot with `D3DHwSwap = 0x80`)

These go with G76's counters (no register write is added):
- time inside `Dd_Flip`;
- `WASSTILLDRAWING` retries per frame;
- `VcrDd2dSync` spins at the flip, and the longest;
- IOCTLs per flip;
- flip-to-flip intervals in refresh units;
- the bit-7 self-test.

Runs: `d3dprobe render --full --tests flipdraw` (§6) at 640x480x16 and 1024x768x32, then one title
in-game (§8).

| outcome | meaning |
|---|---|
| `measured` ≈ frames, `moved` ≈ `measured` | G55 is real: every vsync'd D3D frame draws into the visible buffer |
| `measured` ≈ 0 | the runtime waits on its own; G55 is not real, and P7a is hygiene only |
| drain spins in the ms range | a big last primitive; P7a gains that much per frame even before P6 |

### 5.2 S1: swap registers on an idle desktop (boot with `D3DHwSwap = 0x08`, user at the box)

Each probe is a bounded miniport op run from `vcrctl swapprobe <name>`. None changes the display mode.
The display lock is held for the length of the probe, so GDI cannot trip a give-up.

| # | sequence (chip 0) | observe | outcome → decision |
|---|---|---|---|
| E1 | idle chip, count 0; direct `swapBufferPend = 0` | `status[30:28]` | 1 → 3dfx's model holds. 0 → `swapBufferPend` does not count; see E2 |

## 6. d3dprobe tests (`KMD/tools/d3dprobe.c`)

All three are new; the first two are render-list tests that run in fullscreen only.

- **`flipdraw`** (ordering; settles G55).
  - **Draws:** 60 frames. Frame k is `Clear(target, C[k mod 5])` (five distinct colours, so a buffer
    never already holds its new colour, with 2 or 3 buffers), one full-screen untextured quad, then
    Present with vsync on.
  - **Evaluation:** in the runner, from the driver's 511 a=17 line read by `vcrctl log` after the device
    is released and the mode restored (a new `--ring` option of `KMD/tools/d3dprobe_run.py`; never
    while the device is live).
  - **Pass with `0x81`:** `measured >= 50` and `moved == 0`.
  - **Reference (old-buggy) value:** the same run with `0x80`. Expect `moved ≈ measured` if G55 is real,
    or `measured == 0` if the runtime waits; the run reports which. d3dprobe's own RESULT must still
    show 60 frames and no focus loss.
- **`flipseq`** (bookkeeping and scan-out).
  - **Draws:** 24 frames. Frame k is a clear to C[k mod 5] plus an 8x8 quad whose grey encodes k.
    After each Present, `GetFrontBuffer` into a system-memory A8R8G8B8 surface; read the corner and
    the quad.
  - **Pass:** 24/24 frames match frame k on both paths (the reference). On the hardware path the 511
    a=15 line must also show `hw swaps >= 24`, `verify mismatches == 0`, `max pending <= cap` and
    `stalls == 0`.
- **`perf --mode overlap --work-us N --fill L`** (the payoff).
  - **Draws:** per frame, L full-screen textured quads; then `busy_us(N)` of CPU after Present (the
    "D3D pattern" `ddlab --work-us` already models). Reports fps and the 511 a=16 histogram.
  - **Reference values from the same build:** `G` = the frame time with `--work-us 0`; `C` = the frame
    time with `--fill 0`.
  - **Pass (P7b, `--novsync`):** frame time ≤ 1.15 × max(C, G).
  - **Old-buggy value:** ≈ C + G (the drain).
  - **P7a:** both ≈ C + G, by design (no overlap without the ring). The test records that as expected,
    not as a failure.
- **`ddlab flip --3d`** (small change to `tools/ddlab.c`): the existing frame-numbered flip test with
  `DDSCAPS_3DDEVICE` on the chain, so the hardware path runs with no D3D device at all. It must stay
  0 mismatch with first/max/slow/fast frame stats. At 16 bpp it also says whether G59's half rate exists
  on the overlay swap.

## 9. Risk to proven paths

- **Default 16 bpp D3D path and every DirectDraw 2D title:** none while off. When armed, 2D chains still
  take the old path.
- **Glide/OpenGL coexistence.**
  - Promotion is refused while an exclusive owner, SLI or an enabled command FIFO exists.
  - The miniport demotes at `HWCSETEXCLUSIVE`, `RESET_DEVICE` and every mode set, and restores
    `dramInit1` bit 11, so the next Glide open finds its registers as before.
  - Glide programs the overlay and bit 11 itself at open (`minihwc.c:4869-4964`, `:5159-5166`).
- **SLI state.** Only chip 0 is touched, and only with SLI off and chip 0's swap-algorithm bit clear
  (E7). Otherwise a vsync swap could wait for an `sli_syncin` that never comes.
- **The flip path, when armed:**
  - **Stuck swap.** A swap that never completes blocks the shared PCI FIFO, so GDI's 2D stalls too.
    Bounded by `SPIN_CAP` and `VCR_SWAPQ_STALL_MS`, then engine reset, demote and fallback (E8 proves
    the reset clears it).
  - **Missed demote.** The last game frame stays over the desktop until the next mode set. The
    miniport's own hooks make that a backstop case only.
  - **Display-lock holds (P7a only).** The first draw or Lock after a flip waits up to one refresh
    inside the driver (`VcrDdRoom`), where today the wait happens in Flip retries. Measure it with the
    longest-spin counter; P7b removes it.
  - **Pacing change.** Correct double buffering quantises (§0, fact 2).
- **Monitor.** No mode switch, no timing change. The overlay toggles at vertical blank, so at worst one
  blip at session start and end.
- **Tools.** Agent and GDI screenshots stay blind in exclusive mode, as today. `fbshot` reads the
  overlay through `vidCurrOverlayStartAddr`; its linear-overlay decode (`include/vcr_fbshot.h`,
  `VCR_FB_M_LINEAR`) must be confirmed once in P7a.

## 11. Open questions

1. Who increments the pending count, whether it saturates or wraps, and whether an engine reset clears
   it (E1, E2, E2b, E8).
2. Is the hardware cursor still drawn with the desktop layer off under a full-screen overlay? Glide
   turns the cursor off; 3dfx's promotion leaves it alone. Check it in a title that shows the Windows
   pointer.
3. Per title, how many frames fall between 1 and 2 refreshes (S0)? That decides whether staged configs
   should turn triple buffering on before a default flip (UT2003/UT2004 `UseTripleBuffering`, Max
   Payne; G65), and whether bit 2 should default on.
4. Do 3D register reads (`fbiSwapHistory`, `fbiPixelsOut`) wait for the PCI FIFO (E3)?
