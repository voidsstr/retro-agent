## 1. Verdict

1. **The line is UT2004's own picture, and every GPU draws it.**
   - **What draws it.** The main menu's full-screen backdrop is `2K4Menus.MainMenu.mmbgnd`, a 1024x1024 DXT5 texture of which only rows 0-767 are image.
     - Rows 0-766 are opaque (alpha 255 in every texel).
     - **Row 767 has alpha 32** in all 1024 texels.
     - Rows 768-1023 are fully transparent black.
   - **How it is drawn.** The menu draws `mmbgnd` **alpha-blended** over the whole page (§2.3).
   - **Why the bottom shows something else.** At 1280x960 the last two screen rows sample that nearly transparent edge. So they show whatever lies under the menu, and under UT2004's main menu that is white. **This is true on NVIDIA hardware too.**
2. **The reference proves it.** UT2004's main menu at 1280x960, captured on 09-29 on two different NVIDIA GPUs (.171 GeForce FX 5500 and .143 GeForce 6800), shows the same bright line on the same two rows (§2.2).
   - The two NVIDIA frames are **pixel-identical** in rows 950-959 (12,800 of 12,800 pixels).
   - Our 16 bpp frame matches them within 0-3 levels on every row except row 958, which is +11.
   - A third reference, .133's GeForce4 Ti 4600 at 1280x960 (08-31), shows the line as well.
3. **Our HAL draws this edge as D3D specifies** (§2.4).
   - From the decoded texture, the D3D bilinear rules and our pixel geometry, I predicted every pixel of rows 957-959.
   - Row 957 matches to 0.1 level (correlation 0.999 along the row).
   - Rows 958/959 need an underlay share of **0.300/0.906**. The D3D model gives **0.300/0.900**.
   - Two alternatives the frames reject: a TMU without the half-texel subtraction would give 0.8/0.4, and the pre-fix pixel centre would give 0.70 plus an uncovered row 959.
4. **visual-09's mechanism is refuted.**
   - "Bilinear sampling across a WRAP edge" would put at most 10 % of a wrapped row on row 959 and none on row 958.
   - `mmbgnd` is CLAMP in both axes anyway (`UClampMode` = `VClampMode` = 1), and the sample never leaves the texture: its 10 % partner is texel row 768, inside the 1024-row texture.
   - The line "moved with the half-pixel fix" because the fix made our output **match the reference**.
     - Before it, row 958 carried 61 % of the underlay and row 959 was not drawn at all (§2.1).
5. **Decision: close G45 as not ours. No driver change. Priority P3.**
   - **Do not "fix" it.** Forcing CLAMP, adding a texel-centre offset, or editing the game's art would each move us *away* from the reference.
   - What is worth landing is cheap and optional, and it guards the property this evidence proves (pixel centre + texel centre + clamp + alpha blend at a magnified edge):
     - a d3dprobe check, `edgeblend` (§5);
     - a host test (§6).
   - Both also serve G81 ("texel-centre half … unverified"): this frame is silicon evidence that the texel centre is right to within ~0.05 texel (§2.5).
6. **By-products for other gaps** (§9):
   - **G18:** the reference frame confirms G18's prediction that the menu ticker band (`iPanSmall` = `ScrollSmall`, 1024x32, 32:1) is textured on NVIDIA and drawn flat on ours. It also answers G18's open question 4: the bottom line is *not* a 2K4Menus strip drawn untextured.
   - **G81:** a measured ~+0.05-texel residual.

### 2.3 The game data: what is drawn at the bottom, and how

The packages were read with a throwaway UE2 package reader (Appendix A; the format as G18 Appendix B describes it). Every package is the staged copy `.124` runs.

- **The menu class.** `UT2004.ini` names `MainMenuClass=GUI2K4.UT2K4MainMenu` and `LocalMap=NvidiaLogo.ut2`.
- **The intro ends in a `disconnect`.** The intro map's Matinee ends with `Action_ConsoleCommand` `CommandStr="disconnect"` (export 164), so the menu runs over UT2004's near-empty `Entry` level, not the intro scene.
- **The backdrop:** `UT2k4MainMenu.PageBackground`, `GUI2K4.u` export #13002, class `BackgroundImage`:
  - `Image=mmbgnd`;
  - `ImageStyle=2` (ISTY_Scaled by enum order, inferred);
  - `ImageRenderStyle=5` (MSTY_Alpha by enum order, inferred);
  - texture sub-rect `X1=0 Y1=0 X2=1024 Y2=768`.

  So texel rows 0-768 of a 1024-row texture are stretched over the whole 960-row screen: k = 0.8 texel per pixel, magnified, filtered bilinear.
- **The texture:** `2K4Menus.MainMenu.mmbgnd`, export #192:
  - 1024x1024, `Format` 8 (TEXF_DXT5), 11 mips;
  - `UClampMode` = `VClampMode` = 1 (clamp).

  Mip 0 decoded:

| texel rows | RGBA |
|---|---|
| 0-3 | (36.3, 87.7, 46.7, 255) etc. Equal to the frames' top rows, so this is the industrial-bay backdrop |
| 0-766 | alpha **255** in every texel |
| 766 | (0.2, 18.0, 35.7, 255) |
| **767** | **(23.9, 38.6, 51.7, 32)**: alpha 32 in all 1024 texels |
| 768-1023 | (0, 0, 0, 0) |

- **Nothing in the menu draws beneath the backdrop.** The menu's other components are `iPanHuge`/`iPanBig`/`iPanSmall` (`ScrollHuge` 1024x256, `ScrollBig` 1024x128, `ScrollSmall` 1024x32 panners), `ImgBkChar`, the logo, `ImgTV` and the buttons.
  - The visible ticker band proves they draw *after* the backdrop: anything drawn before it would be covered by its opaque rows.
  - Nothing in `UT2K4MainMenu` fills the screen beneath the backdrop.
  - `Engine.BlackTexture` (8x8 RGBA8) is used only by in-game HUD functions (`HudBase.DrawInstructionGfx`, `HudCDeathmatch.ZoomFadeOut`, …), not by the GUI.
- **The world is not rendered behind the menu** (inferred from the class defaults). `GUIPage.bRenderWorld` is declared in `XInterface.u`, and only `GUIQuestionPage` (XInterface) and `PopupPageBase` (GUI2K4) serialize it True. Their class-default tails are the only places it appears, so `UT2K4MainMenu` inherits False.
- **So what is beneath the backdrop's last rows is whatever UE2 leaves in the frame before the GUI draws** (§8 Q1). On the reference it is white (§2.2). The exact engine call is not needed to close this item.
- `XInterface.GUIPage`'s defaults hold `BackgroundColor` = (255,255,255,255) and `BackgroundRStyle` = 1. That is a plausible but unproven connection (§8 Q1).

### 2.4 The composite, predicted and fitted

- **The model.**
  - The quad covers D3D y from −0.5 to 959.5 with v 0 → 768/1024: UE2 maps the 1024x768 GUI with D3D's half-pixel convention (inferred, and pinned by the fit below).
  - D3D samples pixel row y at t = (y + 0.5)·0.8 − 0.5 texels and filters colour and alpha bilinearly (non-premultiplied).
  - The result is blended SRCALPHA/INVSRCALPHA over an underlay U.
- **Per-row underlay share** (1 − alpha), from the decoded texture:

| model | row 957 | row 958 | row 959 |
|---|---|---|---|
| **D3D-exact** (our post-fix HAL: xy_bias 0.5, TMU subtracts half a texel) | 0 | **0.262** (texel 767 weight 0.30) | **0.887** (texel 767 0.90, texel 768 0.10) |
| pre-fix HAL (pixel r sampled at y = r + 0.5) | 0 | 0.612 | not covered (the edge at 959.5 is excluded by the fill rule) |
| TMU without the half-texel subtraction | 0 | 0.70 | 0.95 |
| quad 0..960 instead of −0.5..959.5 | 0 | 0 | 0.612 |
| "WRAP bleed" (visual-09) | 0 | 0 | ≤ 0.10 wrapped, and the wrapped row 0 is not white |

- **Predicted against observed**, per pixel along the row from the decoded texture, with U = white:

| | row 957 | row 958 | row 959 |
|---|---|---|---|
| predicted, U white | (0.5, 18.2, 35.8) | (72.3, 84.7, 96.8) | (228.6, 230.1, 231.5) |

- **Solving each channel for the underlay share** (U = 255) gives ours **0.906/0.903/0.906** on row 959 and **0.299/0.302/0.292** on row 958. Three channels agree, so the underlay is achromatic white.

### 2.5 Our HAL on this path, and the vendor's

- **Pixel centre.** `VcrDd3dDrawInit` sets `d->xy_bias = 0.5f` and `vertex()` adds it to x and y (`KMD/display/vcrdd_3d.c:304`, `:190-191`). This is pinned by `test_vertices_get_the_half_pixel_centre_offset`.
- **Texel centre.** `vertex()` writes `S/W = uv·s_scale·oow` and `T/W = uv·t_scale·oow` with no additive term (`vcrdd_3d.c:213-214`, stage 1 at `:219-220`). `VcrDd3dTexScale`/`VcrDd3dTexScale1` make the wide side span 256 (`:273-285`).
  - The fit shows the VSA-100 TMU itself puts texel i's centre at i + 0.5: the "no half-texel subtraction" model is rejected by 0.4-0.5 in weight.
  - **The vendor HAL agrees in effect.** With `PIXELCENTER=1` it adds `textureCenter[slog]` = 1/2^(slog+1) to S and T after scaling by 256 (`VH5/D3TXTR.C:804-808`, `:2209-2218`; `VH5/D6FANI.C:878-895`). One texel is 256/2^slog S-units, so that is **1/512 of a texel at every size**: a rounding nudge, not a half-texel shift.
- **Addressing.** `D3DTADDRESS_CLAMP` → `TM_CLAMPS`/`TM_CLAMPT` on both texture paths (`vcrdd_d3d.c:792-795`, `:830-833`). At this edge it never matters, because the sample stays inside the texture.
- **The residual.** Ours is +11 on row 958 (Δ texel-767 weight ≈ +0.045) and +3 on row 959. Both are what a sample about **0.04-0.05 texel further along +T** would give.
  - The reference is 2-7 levels the other way.
  - The cause is not identified (§8 Q2). It is a G81 measurement, not a G45 defect. At magnification 0.8 it is ≈ 0.06 px, invisible; at 1:1 it does not move a point sample off a texel (`rgb565_decode1` passes 1024/1024).

## 4. The fix: none, and what NOT to do

- **No driver change.** Caps, registers, the DP2 walker, the default 16 bpp path, the BigTex path, Glide/OpenGL coexistence, SLI and the flip path are all untouched.
- **Do not act on visual-09's original inference.** Each of these would move a correct HAL away from the reference:
  - forcing CLAMP on screen-sized textures;
  - adding a texel-centre offset (`+0.5` texel to S/T), or copying the vendor's `textureCenter` (which is ~0 anyway);
  - special-casing the last row or column.
- **Do not edit `2K4Menus.utx` in the library.** The line is the game's look on every machine. "Fix the library" is the project's rule for a broken *staged* title; this title is not broken, and a patched GUI package would also diverge from every other UT2004 install.
- **Documentation to update** (by whoever lands this item; I may only write this file):
  - the plan's status table: G45 → *closed, not ours, matches NVIDIA reference*;
  - a one-line correction beside visual-09 in `docs/v56k-benchmark-plan.md` (the WRAP inference is refuted);
  - one `retro-3dfx/FINDINGS.md` entry, labelled **clean-room vcr-kmd**: "UT2004's main-menu bottom line is the game's (mmbgnd row 767 alpha 32 over a white underlay), identical on GeForce FX 5500/6800 at 1280x960; our HAL's edge matches to ±3 levels (row 958 +11): silicon evidence that pixel centre and texel centre are right".

## 6. d3dprobe tests (`KMD/tools/d3dprobe.c`, explicit-only)

### 6.1 `edgeblend`: the G45 composite, reproduced inside the 256x256 readback window

- **Purpose.** Make §2.4's result repeatable on silicon, and on any reference driver ("d3dprobe … for any other driver, as the reference"). It is also the magnified texel-centre check G81 lacks; `rgb565_decode1` covers only 1:1.
- **Texture.** 64x128 **A4R4G4B4**, MANAGED, one level, filled by Lock. A4R4G4B4 is offered on every path, including fresh installs, the Banshee/Voodoo3 and the 86Box bed.

  | texel rows | colour | alpha |
  |---|---|---|
  | 0-62 | white | 15/15 |
  | **63** | white | **2/15 (≈ 34/255)**: the analogue of `mmbgnd` row 767 |
  | 64-127 | black | 0 |

- **Stage and state.**
  - Stage 0: `COLOROP MODULATE(TEXTURE, DIFFUSE)`, `ALPHAOP MODULATE(TEXTURE, DIFFUSE)`, diffuse `0xffffffff`.
  - `MAGFILTER`/`MINFILTER` LINEAR, `MIPFILTER` NONE.
  - `ALPHABLENDENABLE` TRUE, `SRCALPHA`/`INVSRCALPHA`.
  - `DITHERENABLE` FALSE (the HAL may still dither; the tolerance covers it).
  - Z off.
- **Geometry.** One XYZRHW quad (`quad_t`'s shape, with its own u/v):
  - x from −0.5 to 255.5;
  - **y from 159.5 to 239.5** (80 rows: 160-239);
  - u 0 → 1, **v 0 → 0.5**: 64 texel rows over 80 pixel rows, **k = 0.8, exactly UT2004's 1280x960 ratio**.
  - Rows 238/239 then sample texel 63 at weights 0.3/0.9, the same phase as UT2004's rows 958/959.
- **Frame A: underlay blue, CLAMP.** Clear to `0x000000ff`; `ADDRESSU`/`ADDRESSV` CLAMP.
  - Each R/G check reads the blended alpha directly: R = 255·a(y), B = 255.
  - Checks at x = 8, 128 and 248 (`expect`, tolerance **16**):

| row | D3D expected R (= G) | B | pre-fix HAL (xy_bias 0) | no TMU half-texel |
|---|---|---|---|---|
| 159 (above the quad) | 0 | 255 | **255** (top edge 159.5 then covers it) | 0 |
| 160 (top edge) | 255 (CLAMP: texel 0) | 255 | 255 | 255 |
| 237 | 255 | 255 | 255 | 255 |
| **238** | **188** (a = 0.7 + 0.3·0.133 = 0.740) | 255 | 99 (a = 0.39) | 78 (a = 0.31) |
| **239** | **31** (a = 0.9·0.133 = 0.120) | 255 | **0** (not covered) | 14 (a = 0.053) |
| 240 (below) | 0 | 255 | 0 | 0 |

- **Frame B: underlay blue, ADDRESSV WRAP.** Identical except row 160: t = −0.1 wraps 10 % of texel 127 (alpha 0), so R = 229.5 (WRAP) against 255 (CLAMP).
  - This proves the HAL honours both modes at a magnified edge, the case visual-09 suspected.
  - Rows 238/239 are unchanged, because the sample never reaches the edge.
- **Pass criterion.** Every check within ±16 of the D3D value.
  - Ours is expected to pass with margin: §2.5's residual predicts row 238 ≈ 178 and row 239 ≈ 29 against 188/31.
  - The two failure models fail by 90-110 on row 238 and by 31 on row 239.
  - Row 159 discriminates the pixel centre: 255 against 0.
  - Frame B row 160 (229.5) against frame A row 160 (255) is the address check (Δ 25 > 16).
- **The "old" values on silicon.** The pre-fix build would fail rows 159, 238 and 239; that is the xy_bias regression this test catches.

### 6.2 `edgeblend_dxt5`: the same, in UT2004's own format (Diag\D3DBigTex bit 1; SKIPPED without it)

- **Texture.** 64x128 DXT5.
  - Block rows 0-14: white, alpha a0 = a1 = 255.
  - **Block row 15** (texel rows 60-63): white, a0 = 255, a1 = 32, 3-bit indices 0 for rows 60-62 and 1 for row 63, so row 63's alpha is exactly 32, as in `mmbgnd`.
  - Block rows 16-31: black, alpha 0.
- **Expected values.** Row 238 R = 255·(0.7 + 0.3·32/255) = 188; row 239 R = 255·0.9·32/255 = 29. Everything else as in §6.1.
- **Why it exists.** It ties the composite to the DXT5 alpha path UT2004 actually uses.

### 6.3 Placement in `d3dprobe.c`

- A branch in `run_test` beside `blend`.
- A small helper `tex_alpha_rows(fmt, w, h)` to build both textures, plus a `quad_tuv(x0, y0, x1, y1, c, u1, v1)`, because `quad_t` sets u = v.
- The header comment's test list gains both names.
- The RESULT checks carry the row and x, as `expect` already does.

## 12. Open questions

1. **What makes UT2004's main-menu underlay white on every GPU?** Candidates:
   - a clear to white while the world is not rendered (`GUIPage.bRenderWorld` False);
   - `GUIPage`'s white `BackgroundColor` drawn by native GUI code;
   - another engine fill.

   This does not matter for the driver: the reference shows the same white. It matters only to someone who wants the game's look changed, which this design advises against.
2. **The ~+0.045-texel residual at row 958 (+11 levels against NVIDIA).**
   - Candidates:
     - the TMU's bilinear-weight precision or rounding (a 4-bit fraction, or a half-texel subtraction of 7/16 rather than 8/16 would give about this);
     - setup-unit start-value precision;
     - the 16 bpp blend path.
   - Neither the 16 bpp dither nor 565 quantization explains it: rows 952-957 agree to ±2.
   - `edgeblend` at several sub-texel phases (v1 = 0.5 ± small deltas) would characterise it. It belongs to G81 and is cosmetic.
3. **Does V3 (d3dprobe on NVIDIA) reproduce the analytic values to ±16 as expected?** If a reference driver misses by more, the tolerance or the expected-value arithmetic needs revisiting before `edgeblend` is used as a gate.
4. **Should a G79 sweep keep per-title reference frames** (like the `REF` ones here) for every staged D3D title, so "looks wrong" can be checked against "looks like that everywhere" before a gap is opened? This item would not have been opened with one.

**Packages.** A minimal UE2 reader (package version 127/128; the format is as G18 Appendix B describes it):

```python
import struct
def ci(b, p):                                  # FCompactIndex
    b0 = b[p]; p += 1; v = b0 & 0x3f
    if b0 & 0x40:
        s = 6
        while True:
            x = b[p]; p += 1; v |= (x & 0x7f) << s; s += 7
            if not x & 0x80: break
    return (-v if b0 & 0x80 else v), p
class Pkg:
    def __init__(s, f):
        b = s.b = open(f, 'rb').read()
        _, ver, _, _, nc, no, ec, eo, ic, io = struct.unpack_from('<IHHIiiiiii', b, 0)
        s.names = []; p = no
        for _ in range(nc):
            n, p = ci(b, p); s.names.append(b[p:p + n - 1].decode('latin1')); p += n + 4
        s.imports = []; p = io
        for _ in range(ic):
            a, p = ci(b, p); c, p = ci(b, p); pk = struct.unpack_from('<i', b, p)[0]; p += 4
            o, p = ci(b, p); s.imports.append((s.names[c], s.names[o]))
        s.exports = []; p = eo
        for _ in range(ec):
            c, p = ci(b, p); _, p = ci(b, p); pk = struct.unpack_from('<i', b, p)[0]; p += 4
            o, p = ci(b, p); fl = struct.unpack_from('<I', b, p)[0]; p += 4
            sz, p = ci(b, p); off = 0
            if sz > 0: off, p = ci(b, p)
            s.exports.append(dict(cls=c, pkg=pk, name=s.names[o], size=sz, off=off))
    def props(s, e):                           # tagged properties; returns (dict, end)
        b = s.b; p = e['off']; out = {}
        while True:
            n, p = ci(b, p); name = s.names[n]
            if name == 'None': return out, p
            info = b[p]; p += 1; t = info & 15; st = (info >> 4) & 7
            if t == 10: _, p = ci(b, p)        # struct name
            size = {0: 1, 1: 2, 2: 4, 3: 12, 4: 16}.get(st)
            if st == 5: size = b[p]; p += 1
            elif st == 6: size = struct.unpack_from('<H', b, p)[0]; p += 2
            elif st == 7: size = struct.unpack_from('<i', b, p)[0]; p += 4
            if info & 0x80 and t != 3: p += 1   # array index (small)
            raw = b'' if t == 3 else b[p:p + size]
            out[name] = (bool(info & 0x80) if t == 3 else raw[0] if t == 1 else
                         struct.unpack('<i', raw)[0] if t == 2 else raw)
            p += 0 if t == 3 else size
    def mip0(s, e):                            # TArray<FMipmap>, first entry
        _, p = s.props(e); n, p = ci(s.b, p); p += 4   # lazy-array skip pos
        cnt, p = ci(s.b, p); return s.b[p:p + cnt]
```

- **Find:**
  - `2K4Menus.utx` export named `mmbgnd`: USize/VSize 1024, Format 8, U/VClampMode 1;
  - `GUI2K4.u` export `PageBackground` under `UT2k4MainMenu`: `ImageRenderStyle` 5, X2/Y2 1024/768.
- **Decode mip 0 as DXT5** (16-byte blocks, 256 per block row, alpha block first): texel row 767 alpha = 32 everywhere, rows ≥ 768 = 0.

**The model (§2.4):** for pixel row y at 1280x960, the D3D sample is t = (y + 0.5)·768/960 − 0.5. Bilinear between floor(t) and floor(t)+1, CLAMP, then out = a·c + (1 − a)·U.
