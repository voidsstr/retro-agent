# fleet-roster.txt - the boxes that are EXPECTED to publish a hardware record.
#
# scripts/fleet/inventory.py renders docs/fleet-inventory.md from the records
# each agent drops on the share.  This file is what makes "never seen" sayable:
# without a roster, a machine that has never reported is indistinguishable from
# a machine that does not exist, and the document would quietly shrink by one
# box instead of telling you one box is missing.
#
# It is a ROSTER, not a description.  Nothing measured belongs here - no CPU,
# no card, no resolution.  Those come from the machine itself and putting them
# here is exactly the hand-maintained table this whole mechanism exists to
# retire.  What does belong here is the per-box prose a probe cannot discover:
# the traps, the "answers slowly", the dual-boot layout.
#
# Format, tab- or multi-space separated:
#   <ip>   <expected hostname>   <one-line note, may be empty>
#
# The note is rendered under that machine's section verbatim.  Longer traps
# live in CLAUDE.md's "Known Machines" section, which keeps the prose and
# points here for every measured field.
